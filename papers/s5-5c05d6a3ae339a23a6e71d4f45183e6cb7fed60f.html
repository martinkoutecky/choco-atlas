What the mirror covers

The proposed direction does not cover a named result; it leaves the paper’s three axiomatizations and finite-player payoff examples without a computational mirror.

The case FOR (proponent)

The best positive case is a research direction, not a paper-anchored computational mirror: the paper contains no named result classifying a computational problem as tractable, hard, or parameterized. Its main results are axiomatizations of allocation rules.

The closest named hook is Lemma 4.3, proved in this paper. It states that the Expected Myerson Value \(\Psi^m(v,\rho)\) equals the Shapley value of the cooperative game
\[ \omega_{(v,\rho)}(S)=\sum_{g\in\mathbb G(\rho)}\rho(g)\,v(g|S). \]
The paper computes examples using these values, but the lemma gives a representation, not a complexity result. Proposition 2.4 gives formulas for deleting a link or player from a formation distribution; Proposition 3.2 decomposes expected wealth by components. Neither is a computational classification either. The cited finite-player characterizations are axiomatic results, not complexity anchors.

A plausible scenario for a *new* mirror would be a large collaboration or trade network with a small number of roles. A type would specify an agent’s role and all relevant interaction and payoff characteristics; mass would be the fraction of agents of that type. One could ask whether the typewise average Expected Myerson payoff has a well-defined, computable limit as the population grows while the number of types stays small. That is the strongest positive lead I see: the paper’s expected allocation is a natural object to try to extend.

But the paper does not define that limit problem. Its players are individually distinguished by their positions in a finite network, and its value uses finite-player Shapley marginals. A population mirror would need to specify how typed masses form networks, how network games become functions of a continuum network, and what allocation per unit mass means. Those definitions could be sensible co-modifications, but supplying them would create the computational question rather than mirror a named computational result of this paper.

The scope distinction is also clear: \(\rho\) is a probability distribution over finite networks, while \(N\) remains finite. The paper’s probabilistic network formation is therefore not itself continuization of the population. Lemma 4.3 is the strongest candidate hook, but it cannot serve as an admissible anchor here. Without a valid anchor, I cannot honestly state a prover-ready continuous problem per anchor or predict its place in the tractability–hardness trichotomy.

The case AGAINST (opponent, writing after the proponent)

The decisive problem is that this paper has no named computational result to continuize. Its results characterize allocation rules by axioms; none classifies the complexity of a computational problem. The paper specifies neither an input encoding nor an algorithmic task whose running time could be studied. Under ChoCo’s criteria, that leaves no paper-anchored computational mirror.

Lemma 4.3 is the strongest possible hook. It represents the Expected Myerson Value as a Shapley value for an expected cooperative game. But it is an identity using linearity, not a result about computing that value. Propositions 2.4 and 3.2 likewise give formulas for restrictions and component decomposition, not complexity bounds. A continuous question about computing a limiting payoff would therefore need to supply the algorithmic problem the paper never poses.

The role-based scenario is plausible, but a fixed list of roles does not by itself make the paper’s model high-multiplicity. Here both the network game \(v\) and formation distribution \(\rho\) can depend on the labeled players and networks. Role fractions alone need not determine expected payoffs. An exact type-based mirror would need assumptions such as symmetry within roles, a scaling rule for wealth, and a specified sparse or dense network limit. It would also need a definition of the limiting Myerson allocation and an input representation for the resulting computational problem. Those choices could support a separate project in large-network cooperative values; they do not follow from Lemma 4.3.

The paper’s probabilities are over networks on a fixed finite player set. That makes network formation stochastic, but it does not make the population continuous. A question that instead continuizes the distribution over networks would change the wrong axis for this programme.

I can’t establish the broad claim that no plausible large-population network model could be worthwhile. The negative case is strongest as a verdict on this paper as a ChoCo mirror: even its best hook does not anchor a complexity question, and making one requires substantial new modelling before there is anything to classify.
