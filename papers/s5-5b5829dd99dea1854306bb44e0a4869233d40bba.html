The continuous mirror question

Given \(m\) recurring project classes with rational sizes \(s_j>0\), values \(v_j\ge 0\), and per-capita supplies \(q_j\ge 0\), plus \(\tau\) agent types with rational masses \(\mu_t\) summing to \(1\) and budgets \(B_t>0\), can one compute in time polynomial in \(m,\tau,L\) an allocation with polynomial-size support, where \(L\) is the input bit length? A bundle is an integral vector \(b\in\mathbb Z_{\ge 0}^m\) with \(s(b)=\sum_j s_jb_j\le B_t\), and \(x_{t,b}\ge 0\) is the mass of type \(t\) receiving bundle \(b\); require \(\sum_b x_{t,b}=\mu_t\) and \(\sum_{t,b}x_{t,b}b_j\le q_j\) for every class \(j\). For every pair of positive-mass bundles \(b,c\) assigned to types \(t,u\), respectively, and every nonempty integral subbundle \(z\le c\) with \(s(z)\le B_t\), require some \(j\) with \(z_j>0\) such that \(v(b)\ge \tfrac12(v(z)-v_j)\). Apply the same condition to charity comparisons, where \(z\) may use only classes with positive residual supply \(r_j=q_j-\sum_{t,b}x_{t,b}b_j>0\).

The model it lives in

A population of mass \(1\) split among budget types, receiving integral bundles of recurring indivisible project classes. Rational per-capita supplies scale with the population; the allocation is a finite list of rational masses \(x_{t,b}\), and EF1 comparisons apply across supported bundles and against residual charity stock.

The objection that survived

The finite theorem is polynomial only in the explicit numbers of agents and project copies; rational denominators can make a replica exponentially larger than the input, and the paper gives no polynomial support or batching bound.

fatal: False

What the mirror covers

The main mirror covers Theorem 4.4’s \(1/2\)-EF1 guarantee with common additive values and heterogeneous budgets; the uniform-budget exact-EF1 version also mirrors Theorem 5.1. It leaves the fixed two-agent setting of Theorem 5.2 and the NSW result of Theorem 6.2 without a stated mirror; Theorem 6.1’s large-budget guarantee is a possible refinement.

Open questions for a prover

  • Does a polynomial-time algorithm in \(m,\tau,L\) produce a polynomial-size rational allocation satisfying the \(1/2\)-EF1 conditions?
  • Can the density and virtual-budget structure be batched over repeated project classes while preserving comparisons against every supported bundle and the charity?

The case FOR (proponent)

The strongest mirror is a market with many subcontractors operating under a few standardized budget levels. Projects recur in standardized classes: a class \(j\) project has size \(s_j\) and value \(v_j\), and the available number of projects of that class grows with the workforce. Most importantly, an individual still receives a whole bundle of indivisible projects. The continuum describes how much of each subcontractor type receives each bundle; it does not give anyone a fractional project.

There is no numbered hardness theorem in the supplied paper to anchor. My lead is Theorem 4.4, proved here: the paper’s algorithm runs in polynomial time and returns a budget-feasible allocation that is \(1/2\)-EF1. In full, for every agent \(i\), every other agent or the charity \(j\), and every subset \(T\) of \(j\)’s bundle with \(s(T)\le B_i\), some item \(e\in T\) satisfies \(v(X_i)\ge \tfrac12 v(T\setminus\{e\})\). The paper assumes common additive values for items and allows budgets to differ between agents.

I would hand a prover the following search problem, Continuous \(1/2\)-EF1 Configuration Allocation. An instance has \(m\) project classes, with rational sizes \(s_j>0\), values \(v_j\ge0\), and per-capita supplies \(q_j\ge0\); agent types \(t=1,\ldots,\tau\), with rational masses \(\mu_t\) summing to one and budgets \(B_t>0\); and common additive item values \(v_j\), as in the paper. A type is complete for this model: its members share the same budget and valuation. A bundle is an integral vector \(b\in\mathbb Z_{\ge0}^m\), with size \(s(b)=\sum_j s_jb_j\) and value \(v(b)=\sum_jv_jb_j\).

The requested solution is a finite-support collection of rational masses \(x_{t,b}\ge0\). It must satisfy \(\sum_b x_{t,b}=\mu_t\), and use no more than the per-capita supply of any project class: \(\sum_{t,b}x_{t,b}b_j\le q_j\). Only bundles with \(s(b)\le B_t\) may receive positive mass for type \(t\). The residual supply \(r_j=q_j-\sum_{t,b}x_{t,b}b_j\) belongs to the charity.

For every two positive-mass bundles \(b,c\) assigned to types \(t,u\), respectively, and every nonempty integral subbundle \(z\le c\) with \(s(z)\le B_t\), the condition is that some project copy \(e_j\) in \(z\) can be removed so that \(v(b)\ge \tfrac12\bigl(v(z)-v_j\bigr)\). The same condition applies when \(c\) is replaced by a subbundle of the charity’s residual stock. In the replica interpretation, a project class with positive residual per-capita supply has enough copies for any fixed budget-feasible comparison bundle as the population grows; a class with zero residual supply is unavailable to the charity. This definition preserves the paper’s “up to one item” comparison against both agents and charity, rather than replacing it with a comparison of average utilities.

The regime is a large outsourced-project market: perhaps hundreds of thousands of contractors, but only a few dozen standardized budget levels, so the population is much larger than \(\tau\). The projects are recurring units from a finite catalog, with supply scaled to the workforce. Individual identities and idiosyncratic prices are not needed: an agent’s type records the budget and valuation the problem uses. This is a plausible high-multiplicity version of the paper’s contractor story, though it depends on recurring project classes rather than a one-off collection of unique projects.

I expect the search problem to be tractable (Class A). The paper’s density and bundle-reassignment structure is a reason to look for an aggregate algorithm, possibly one that batches repeated project classes and represents only a compact number of bundle configurations. Theorem 4.4 does not prove that result: its polynomial running time is measured on an explicit finite instance. A useful check on the formulation is that rational masses and supplies can be scaled to a finite replica, to which Theorem 4.4 applies; this gives an exact EF1-style existence witness for the \(1/2\) condition, but the replica may be exponentially large in the input bit length. The continuous algorithmic question is whether one can find a compact witness in time polynomial in \(m,\tau,L\), where \(L\) is the rational input’s bit length. The natural follow-ups are a support bound for \(x\), an efficient way to search or price bundles, and whether the large-budget guarantee in Theorem 6.1 has an equally compact aggregate form.

A second, narrower anchor is Theorem 5.1, also proved here: when all agents have the same budget, the paper’s greedy algorithm runs in polynomial time and returns an exact EF1 allocation. That means for every agent \(i\), every other agent or charity \(j\), and every \(T\subseteq X_j\) with \(s(T)\le B_i\), some \(e\in T\) satisfies \(v(X_i)\ge v(T\setminus\{e\})\). Its mirror, Uniform-Budget Continuous EF1 Configuration Allocation, is the same search problem with a common budget \(C\) for every type and the fairness condition strengthened from \(1/2\)-EF1 to exact EF1. The regime is a large workforce on a common budget contract, hence one agent type under the paper’s common-valuation assumption. I also expect this problem to be tractable (Class A), given the paper’s early-stop greedy structure; the open algorithmic issue is again a compact computation over rational aggregate supplies, independent of the replica size. Theorem 5.2’s two-agent result is not an anchor for this case: a fixed population of two does not describe the large-population regime.

The soft spot is the bridge from finite agents to a compact continuous computation. In the continuous model, each bundle is still indivisible, but the fairness requirements range over every bundle that appears in the support. The paper’s proof neither bounds the number of supported bundles nor shows that its algorithm can be batched in \(m,\tau,L\); scaling the input only establishes existence, not an efficient aggregate algorithm. That is a real gap for a tractability claim. I still think the mirror itself is strong: the only continuum is the population, bundles remain integral, the charity remains part of the fairness test, and the type records exactly the distinctions the source problem uses. A referee could reasonably recognize these as high-multiplicity versions of the paper’s allocation problems.

The case AGAINST (opponent, writing after the proponent)

The strongest case against is that neither anchor carries over computationally just by replacing agents with masses. In the paper, \(m\) counts explicit items and \(n\) counts explicit agents. For a useful population limit with recurring project classes, the input instead gives rational per-capita supplies; a finite replica of size \(N\) contains \(Nq_j\) copies of class \(j\). If the rational data have denominators as large as \(2^L\), that replica can be exponential in the succinct input length \(L\). Theorem 4.4’s polynomial running time is in the expanded instance, so running it on replicas does not establish a polynomial-time algorithm for the proposed continuous problem.

That is a real limit on what Theorem 4.4 supports, but it does not defeat its mirror. The stronger configuration-allocation formulation is coherent: agents receive integral bundles, while rational masses describe how many agents receive each bundle. Its open computational question—whether one can find a compact aggregate allocation without expanding the replica—is precisely the missing result. It could be a worthwhile question even if its answer were that the finite algorithm cannot be batched efficiently.

The same objection applies to Theorem 5.1. Under the paper’s common-valuation assumption, uniform budgets give a single agent type. The continuous problem then asks for a distribution over integral bundles that respects per-capita supplies and is exactly EF1 across the bundles in its support. The finite greedy algorithm gives no compact aggregate algorithm for this problem either. But the one-type restriction makes it a narrower mirror, not an invalid one; exact EF1 with indivisible bundles remains well-defined.

The practical concern is that a convincing high-multiplicity scenario must scale both the contractor population and the supply of recurring project classes. Bespoke projects in a finite outsourcing contract would not support this regime. Standardized recurring tasks and a large workforce could. Since that scenario is plausible, the need to scale project supply is not a fundamental objection. Nor does the paper’s large-budget analysis already answer the mirror: it keeps the agent population finite.

So the anti-case can say that the paper’s theorems do not imply the aggregate algorithms the proponent hopes for, and that the scenario requires a specific repeated-project regime. It cannot honestly rule out either mirror as a worthwhile computational question. This negative case is weak against the universal claim.
