The case FOR (proponent)

There is no eligible named computational anchor in this paper: it contains no numbered Theorem, Lemma, Corollary, or Proposition asserting a complexity result. It defines the collective knapsack in Eqs. Those are not named complexity results of this paper. So strictly, there is no paper-result anchor for a problem-per-anchor mirror.

The strongest plausible *unanchored* mirror is a population version of the paper’s central knapsack model. Consider a citywide participatory-budgeting process with many residents but a relatively small set of repeated, complete project-evaluation profiles. A type \(\theta\) is a resident profile containing an evaluation \(a_{i\theta}\) for each project \(i\), together with any expertise or other attributes used by the aggregation rule. Its mass \(\mu_\theta\) is its fraction of residents. Given projects with costs \(w_i\), budget \(W\), and rational evaluation profiles and masses, define the population-weighted score \(\bar v_i=\sum_\theta\mu_\theta a_{i\theta}\). The problem, Mass-Weighted Collective Knapsack, is to find \(x\in\{0,1\}^{N_p}\) maximizing \(\sum_i \bar v_i x_i\), subject to \(\sum_i w_i x_i\le W\); a solution is an optimal portfolio. This is close to the paper’s own model: Eq. (6) explicitly allows aggregation weights proportional to a group’s number of constituents.

I would expect this problem to be Class B: with one type it contains ordinary binary knapsack, so the hard combinatorics remain in the number of projects. That expectation comes from the underlying knapsack problem, however—not from a named result proved in this paper. The mirror covers the portfolio-selection setup and a population-weighted direct aggregation rule; it does not cover the paper’s reported performance comparisons among aggregation protocols or their trends in \(N_s\) and \(\beta\).

The weakest point is that the paper treats stakeholder groups as decision-making units and studies noisy group evaluations at finite \(N_s\). A resident-mass model changes the unit being aggregated, and population averaging may wash out the finite-group noise central to those comparisons. The weighted-aggregation option in Eq. (6) makes the extension recognizable to the authors, but it does not supply the missing computational anchor.

The paper’s Eq. (6) even mentions weighting groups by their constituency, and a citywide participatory-budgeting setting with many residents and few repeated profiles is plausible. I cannot honestly reject it because the project choices remain binary or because its complexity resembles ordinary knapsack; the programme explicitly allows a continuous question to have that answer.
