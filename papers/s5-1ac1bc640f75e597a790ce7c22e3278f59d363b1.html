What the mirror covers

The proposed LP captures only the maximum-matching outcome in Theorem 1; it leaves equilibrium uniqueness, sequential requests, and rejection incentives aside. Theorem 2 and Lemma 1 are also structural rather than computational.

The case FOR (proponent)

The strongest positive angle is the efficiency result in Theorem 1, proved in the paper. For a fixed finite network \(G\) and sufficiently high discount factor \(\delta\), the game has a unique pure-strategy subgame-perfect equilibrium. In that equilibrium, an under-demanded player is rejected by every neighbor and remains single; a perfectly matched player is rejected until only one efficient partner remains, who accepts; and an over-demanded player is rejected until an under-demanded neighbor accepts. Essential players always get favors when they need them, while an under-demanded player remains single with probability at least \(1/n\). Exactly \(\mu(G)\) partnerships form with probability \(1\), so the long-run matching is maximum.

That is a strong named result about equilibrium and welfare, but it is not a named computational result: the theorem does not classify the complexity of a problem or present an algorithm for computing the equilibrium. Here “efficient” means socially efficient, not efficient in running time. Theorem 2 and Lemma 1 also concern equilibrium structure or graph structure, not computational complexity. So under the requested anchor rule, this paper has no qualifying computational anchor.

If that rule were relaxed, the most credible positive candidate would be the maximum-partnership-mass problem. Take finitely many compatibility types \(A\), give each type a rational population share \(\mu_a\), and specify which pairs of types can partner. Let \(x_{ab}\) be the mass of partnerships between types \(a\) and \(b\). Find feasible \(x\) maximizing total partnership mass, subject to each type’s mass being used at most once. This is a natural high-multiplicity version of the maximum-matching outcome in Theorem 1, and the mass-allocation problem is an LP. A plausible regime would be a large labor or support network with many agents in a small number of compatibility classes.

The weakness is that this mirrors only the efficient outcome, not the paper’s central problem of decentralized favor requests and equilibrium incentives. In the finite game, rejecting a request deletes a link between two particular people; with many interchangeable agents, rejecting one pair may have negligible effect on the aggregate network. Deleting a whole type-to-type connection instead would impose a much larger effect than the paper’s model does. So this is a plausible continuous welfare benchmark, but I would not present it as a convincing computational mirror of the paper’s main result.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is the proponent’s strongest anchor, but it is not a computational result in ChoCo’s sense. It characterizes subgame-perfect equilibria and establishes social efficiency: “efficient” means that a maximum matching forms, not that an algorithm runs efficiently. The theorem gives no complexity classification or algorithmic bound for a computational problem. Lemma 1 describes how the Gallai–Edmonds classes change as links are removed; it does not supply a missing complexity result either. On the paper’s own terms, there is no named computational result here to continuize.

The proposed maximum-partnership-mass LP does not repair that gap. It asks for a static allocation of partnership mass. Theorem 1 is about a different object: whether sequential requests, rejections, link deletion, and continuation incentives lead to a maximum matching in equilibrium. An LP over type-pair masses has no state for those histories or incentives. To preserve them, types would need to retain enough information about each agent’s neighborhood and evolving position in the network. With a small number of types, that information is generally lost; with types that encode individual neighborhoods, the support can grow with the network.

There is a particularly strong limit problem for the natural dense version of that LP. If every agent in one class can partner with every agent in another, rejecting a single request removes one link from a vast set of opportunities. The original game’s central threat—rejections eventually leaving someone with no partner—then changes fundamentally. A continuum version could model partnership formation through mass flows or hazards, but that requires specifying new dynamics; it does not follow from the finite game’s equilibrium theorem. This is not a complaint about literal notation or tie-breaking. It is the problem of preserving the pivotal effect of one agent’s rejection when individuals have zero mass.

The best repair would be a population made of many copies of a small network motif. That can preserve finite neighborhoods and rejection incentives within each copy. But if the copies are independent, the strategic problem remains the original finite game within each motif; the continuum tracks how many copies occupy each state. If the copies interact, describing the relevant neighborhood structure and correlations again becomes part of the model. This is a coherent possible research direction, but it is a new mean-field model of network games, not a computational question already posed by this paper.

So I would argue against treating this paper as a worthwhile continuous *mirror*: its principal result is not computational, and the natural aggregate matching LP does not preserve the theorem’s subject. The negative case is weaker against the broader claim that ChoCo could build a new computational programme around continuum network games. Repeated motifs or a carefully specified graphon game might be worth studying. The paper alone, though, neither asks that computational question nor identifies a canonical continuous version of its decentralized game.
