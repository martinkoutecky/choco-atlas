The case FOR (proponent)

I can’t identify a qualifying anchor in this paper. It has no named result classifying a computational problem as tractable, hard, or parameterized-tractable. Its numbered results are decompositions of the finite-dimensional space of TU-games and axiomatic characterizations of allocation rules.

The closest result to a computational anchor is Proposition 8, proved here: for a fixed player \(i\), the kernel of the Shapley payoff map \(Sh_i\) is \(W_i\oplus D_i^0\), where \(D_i^0\) is the subspace of games in which \(i\) is null. Thus \(Sh_i(v)=\alpha\) exactly when \(v=v_1+\alpha u_i\) for some \(v_1\in W_i\oplus D_i^0\). Proposition 15, also proved here, characterizes the Shapley value by Strong addition invariance and the Inessential game axiom, and describes its payoff level sets. These are algebraic and axiomatic results; neither gives a complexity classification.

There is a plausible population-level object nearby: a large cooperative organization with finitely many interchangeable roles, represented by their population masses; a coalition is then described by its mass of each role, and its worth is a function of that mass vector. An allocation could assign each role a per-capita payoff. But this restricts the paper’s general TU-games: arbitrary \(v:2^N\to\mathbb R\) need not depend only on coalition composition. It also leaves open how to extend the finite Shapley value and the paper’s transfer invariance to a continuum. Asking for the inverse set of games that give a type a specified payoff would be a reasonable new question, but it would not be a continuous version of a named computational result in this paper.

So there is a conceivable continuous-population cooperative-game model, but no honest anchor from which to state the requested prover problem or predict its complexity class. The weakest point is decisive: the paper studies axiomatic characterizations for finite player sets, not computational questions about populations.

The case AGAINST (opponent, writing after the proponent)

The strongest negative case is that the paper supplies no computational problem for continuization to mirror. Proposition 8 comes closest: it describes the games \(v\) for which \(Sh_i(v)=\alpha\). But its input is an arbitrary vector of coalition worths, and the result gives an algebraic description of a level set of a linear map. The paper specifies no search or decision task, input encoding, or complexity bound. Proposition 15 is an axiomatic characterization of the Shapley value. Neither is a complexity result of the kind this programme sets out to continuize.

The role based organization proposed by the other analyst is plausible, so its restriction to games whose worth depends only on role counts is not, by itself, a decisive objection: it defines a sensible high multiplicity regime. But it changes the paper’s domain from arbitrary functions on \(2^N\) to functions of role masses. A continuous Shapley analogue could then use a path integral for a differentiable worth function. To turn Proposition 8 into a computational question, however, one must also choose how that function is represented, what constraints it satisfies, and whether the target is an individual payoff, a type’s aggregate payoff, or a payoff per unit of mass. Those choices determine the problem’s computational content; the paper does not motivate or constrain them.

This also disposes of the other nearby result the proponent mentions. Proposition 15 could inspire a continuous axiomatic characterization, but that would continuize an axiomatic question. It would not create a computational mirror. Likewise, asking for the inverse set of worth functions that produce a given continuous Shapley payoff would be a new functional level set problem. Any complexity landscape would come from the added representation and restrictions, rather than from a computational result in this paper.

I would not claim that no continuous cooperative game question could ever be worthwhile: the organization scenario could motivate one. The negative case is narrower and stronger. This paper’s results do not anchor such a question as a continuous mirror within ChoCo’s computational programme. The case is weakest if “mirror” includes a substantially redesigned cooperative game model with a newly specified computational task; the material here cannot rule out that separate project.
