What the mirror covers

The proposed model extends Eq. (9)'s utilization objective, asset-fairness condition, and meta-type constraints to workload types with masses; it does not mirror the baseline comparisons or empirical findings as computational results.

The case FOR (proponent)

The strongest plausible mirror is a cloud provider serving a very large population of tenants whose jobs fall into a relatively small number of recurring workload classes. A type would specify everything GAF-MT uses about a tenant: its per-task demand vector and the acceptable subtypes within each meta-type, plus any tenant-specific prices or weights if the model includes them. The mass \(\mu_t\) is the fraction of tenants of type \(t\). This is plausible where many tenants submit jobs with the same resource requirements and hardware compatibility; it need not describe a small, bespoke cluster.

Call the candidate Continuous GAF-MT Allocation. Given rational type masses \(\mu_t\), resource capacities \(c_r\) per capita, demands \(d_{tl}\), acceptable subtype sets \(g_{tl}\), and meta-type prices \(p_l\), choose each type’s per-tenant task rate \(x_t\) and resource allocation \(a_{tr}\). Require
\[ \sum_t \mu_t a_{tr}\le c_r,\qquad \sum_{r\in g_{tl}}a_{tr}\ge d_{tl}x_t, \]
and equal per-tenant asset spending across supported types,
\[ \sum_l p_l d_{tl}x_t=q\quad\text{for every }t\text{ with }\mu_t>0. \]
Maximize \(\eta\), subject to \(\eta\le\sum_t\mu_t d_{tl}x_t\) for every meta-type \(l\). A solution is an optimal set of type-level rates and allocations. This preserves the paper’s fairness and utilization objective while replacing the finite user list with a population distribution. The natural expectation is Class A: with explicit finite type and resource lists, this is a rational linear program whose size depends on the support \(\tau\), rather than the number of tenants.

There is a serious qualification: the paper contains no numbered theorem, lemma, corollary, or proposition asserting a computational result. Its plausible anchor is the GAF-MT formulation in Eq. (9), which it solves using Gurobi and evaluates experimentally. That is a numbered LP formulation, but not one of the named formal results your anchor rule requires. The paper reports scalability experiments, not a complexity classification. So I cannot honestly present this candidate as a mirror of a qualifying anchor.

That is also the mirror’s weakest point substantively: the paper already formulates finite-user allocation as an LP, so grouping repeated users by type is a natural high-multiplicity compression, but it does not expose a discrete hardness result whose fate in the continuum would be at stake. The positive case is that the authors would likely recognize the type-level LP as their own allocation objective in a large, repeated-workload regime. The case remains modest because it has no eligible named result to anchor it.

The case AGAINST (opponent, writing after the proponent)

The strongest case against this mirror is that the paper supplies no qualifying computational result to mirror. It defines GAF-MT’s linear program in Eq. (9), gives a scheduling algorithm, and reports experiments, but states no theorem or other formal result about computational complexity. The proposed continuous allocation is therefore not a continuization of a named complexity result; it is a new formalization of the paper’s objective.

The best version of that formalization is still quite close to Eq. (9): group interchangeable tenants by complete workload type, weight their resource use by type mass, and express capacities per capita. That is a coherent model. But the paper already casts its finite-user allocation as an LP over fractional resource shares and task rates. The type-level version adds population weights; it does not expose a distinct algorithmic obstacle such as a pricing problem or an unclassified complexity boundary. This makes the mirror’s likely contribution a bridge or modeling result, rather than a computational result the paper itself established.

I cannot make the universal negative case compelling. Large cloud populations with recurring workload classes are plausible, and the paper’s fairness and utilization objective can be stated over those classes. That is a sensible high-multiplicity regime, which counts in the mirror’s favor. So the defensible negative is narrow: under the requested anchor standard, this paper has no named computational result for the proponent’s candidate to inherit. Claiming that no worthwhile mirror exists in any scenario would go beyond what the paper supports.
