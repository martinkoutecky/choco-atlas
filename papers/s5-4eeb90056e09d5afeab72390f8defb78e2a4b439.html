The case FOR (proponent)

I can’t make an anchor-compliant case for a computational mirror from this paper. Its main result, Theorem 1, proved here, characterizes the mechanisms that are balanced, Pareto efficient, and group strategy-proof: for \(n\ne3\), exactly the Top Trading Cycles mechanisms from individual endowments; for \(n=3\), those mechanisms and the TC mechanisms with three brokers. That is a mechanism-design characterization, not a result about an algorithm’s complexity or a problem’s hardness. Lemmas 1–4 support the characterization; they do not supply a computational anchor.

A nearby research question would be to characterize efficient, group strategy-proof allocation mechanisms for a continuum of households with ranking types and per-capita supplies of house types. But carrying over balancedness would require specifying a new ex-ante probability model: the paper defines it by counting finite preference profiles. And if a mechanism depends only on type masses, an individual in an atomless population cannot change those masses by misreporting, so the incentive condition changes substantially. That makes this a possible extension of the paper’s mechanism-design question, not a defensible mirror of a named computational result.

The case AGAINST (opponent, writing after the proponent)

The proposed case concedes the decisive point: its only candidate anchor, Theorem 1, is not a computational result. It characterizes which finite-agent mechanisms satisfy balancedness, efficiency, and group strategy-proofness. Lemmas 1–4 establish that characterization; they give no complexity question, algorithmic bottleneck, hardness result, or approximation problem. The paper defines TTC and TC procedures, but describing a mechanism is not the same as studying the complexity of a computational problem.

The strongest nearby model would make the population a distribution over complete preference-and-endowment types, scale house supplies per capita, and ask whether continuum allocation mechanisms satisfying suitable versions of the paper’s axioms must have a TTC-like structure. That may be a coherent mechanism-design question, but it remains an axiomatic classification. To make it a ChoCo mirror, one would need to add a computational task—such as finding or testing a mechanism—and specify its input representation. The paper supplies neither. Any resulting complexity problem would be newly introduced, not the continuous version of a named result.

Balancedness also does not supply the missing computational target. In the paper it counts outcomes across a uniform set of finite preference profiles. A continuous population distribution over types is not that probability model. One could define a new rank-balance condition for type masses, but that would be a new axiom; comparing individual agents in an atomless population would require retaining identities that a mass description erases. Either way, the central question would still be about which mechanisms satisfy axioms, not about computing an outcome or solving an optimization problem.

So no computational anchor survives, including the best reconstruction of the case for. There could be worthwhile continuous mechanism-design work adjacent to this paper, but calling it a continuous computational mirror would stretch the programme’s scope beyond its stated question.
