The continuous mirror question

Given a finite creator set \(N\) and a finite support \(T\) of user types, where type \(t\) has rational mass \(\mu_t>0\), an integral stream vector \(v^t\in\mathbb{Z}_{\ge 0}^{N}\), and reservation price \(r_t>0\), with \(\sum_{t\in T}\mu_t=1\), define \(p_N=\min_{t\in T} r_t\sum_{i\in N}v_i^t\) and \(R(S)=\max_{p>0}p\sum_{t:\,r_t\sum_{i\in S}v_i^t\ge p}\mu_t\). Assume every nonempty proper coalition \(S\subsetneq N\) has an optimal price at which all user mass subscribes. Compute a per-capita core allocation \(x\in\mathbb{R}_{\ge0}^{N}\) satisfying \(\sum_{i\in N}x_i=p_N\) and \(\sum_{i\in S}x_i\ge R(S)\) for every nonempty proper \(S\subsetneq N\).

The model it lives in

A streaming-platform game over a continuum of users represented by finitely many complete stream-and-price types with rational masses. Coalition revenue is the best price times the mass that would subscribe; core allocations divide grand-platform revenue per capita among creators. For a type \(t^*\) attaining \(p_N\), the paper's construction becomes \(x_i=r_{t^*}v_i^{t^*}\).

Open questions for a prover

  • What is the complexity of core nonemptiness for arbitrary rational type distributions outside the inclusive-market promise?
  • Can the inclusive-market condition be recognized efficiently when it quantifies over all creator coalitions?

The case FOR (proponent)

The honest positive case is narrow, and it has an anchor problem: the paper reports no named computational-complexity result. Propositions 1–4 are proved structural claims about core stability; the numerical experiments are not complexity theorems. So none meets the requested standard of a named result asserting, for example, that a problem is in \(P\) or NP-hard. I can give a plausible continuous mirror of the paper’s stability question, but I cannot honestly present it as anchored by a qualifying computational result.

The strongest named result to support that mirror semantically is Proposition 2, proved in this paper. It says that every streaming platform situation in an inclusive market is stable: for each nonempty proper group of content creators, there is an optimal price for its standalone platform at which all users subscribe, and the core of the associated streaming-platform game is nonempty. This is a structural stability theorem, not a complexity classification.

A faithful mass-user version would take a finite set \(N\) of content creators and a finite support of user types \(t=(v^t,r_t)\). Here \(v^t\in\mathbb{Z}_{\ge 0}^{N}\) is a user’s complete vector of stream counts over the billing period, and \(r_t\in\mathbb{Q}_{>0}\) is that user’s reservation price per stream. Each type has positive rational mass \(\mu_t\), with \(\sum_t\mu_t=1\); require every creator to be streamed by positive mass. Users of a type are identical in every attribute the paper’s model uses. For a creator group \(S\subsetneq N\), define its users at price \(p\) and its best standalone revenue per capita by
\[ q_S(p)=\sum_{t:\,r_t\sum_{i\in S}v_i^t\ge p}\mu_t, \qquad R(S)=\max_{p>0}p\,q_S(p). \]
The grand platform charges
\[ p_N=\min_{t:\,\mu_t>0}r_t\sum_{i\in N}v_i^t, \]
so its revenue per capita is \(R(N)=p_N\). The continuous problem is: given these data, decide whether there is an allocation \(x\in\mathbb{R}_{\ge0}^{N}\) with \(\sum_{i\in N}x_i=p_N\) and \(\sum_{i\in S}x_i\ge R(S)\) for every nonempty proper \(S\subset N\). A yes-solution is such an allocation; a no-solution is a proof that no such allocation exists. The continuous version of Proposition 2 says that if each proper coalition has an optimal price with \(q_S(p)=1\), this core is nonempty. Its proof carries over by replacing sums over users with sums weighted by type mass.

The regime would be a large subscription service with many listeners but a small number of recurring, exactly shared usage-and-price profiles: for example, a standardized digital catalog used by large cohorts whose members have the same stream vector and reservation price over the relevant period. It could have millions of users and only tens or hundreds of supported types. The type must include the full stream vector and price; grouping merely similar listeners would change the model. The continuous interpretation is plausible because the paper already asks whether groups of creators can leave, set a price, and attract the users willing to pay it. Replacing repeated user columns with their masses preserves that question. This mirrors the paper’s core-stability results, not its entire analysis.

My initial expectation would be Class B: finite-user instances embed exactly by setting \(\mu_t=n_t/n\), and the core constraints and revenues then scale by \(1/n\), which preserves core nonemptiness. Thus any hardness for the corresponding finite-user stability problem would transfer. That is a prediction, not a result of this paper. The computational questions left open include the complexity in \(|N|\), support size \(\tau\), and input bit length; whether violated core constraints can be found efficiently over coalitions; and whether small \(\tau\) yields useful algorithms. For each fixed coalition, its revenue can be computed by checking the finitely many type-specific willingness-to-pay thresholds. The difficult part may instead be the exponential family of coalition constraints.

The weakest point is the exact-type regime. Full stream vectors are high-dimensional, so in ordinary listener data the number of distinct types could approach the number of users. And because the original rule sets \(p_N\) by the least willing-to-pay supported type, even a very small positive-mass type can determine the price charged to everyone. That behavior is faithful to the paper’s model, but makes the continuum interpretation delicate. The positive case survives for services with genuinely repeated user profiles; it does not justify treating arbitrary heterogeneous audiences as a small-type continuum.

The case AGAINST (opponent, writing after the proponent)

The strongest case against starts with a mismatch: this paper has no named computational result to continuize. Its Propositions 1–4 are structural claims about core stability, and its numerical experiments describe how stability changes with the model’s parameters. Proposition 2—the proponent’s anchor—says that inclusive markets are stable; it makes no claim about the complexity of deciding stability or finding a core allocation.

The proposed mass-user model is coherent. If type \(t\) has stream vector \(v^t\), reservation price \(r_t\), and mass \(\mu_t\), then a coalition’s revenue per capita is
\[ R(S)=\max_{p>0}p\sum_{t:\,r_t\sum_{i\in S}v_i^t\ge p}\mu_t. \]
For a finite audience grouped by type, setting \(\mu_t=n_t/n\) scales every coalition value by \(1/n\), so core nonemptiness is preserved. That is good evidence that the model is sensible. It also shows why Proposition 2 is a weak anchor for this programme: its proof transfers directly. If \(t^\ast\) attains the grand platform’s minimum willingness to pay, the allocation \(x_i=r_{t^\ast}v_i^{t^\ast}\) gives the continuous version of the same core argument. The theorem does not become a computational result through that substitution.

One could instead study the complexity of testing whether the general mass-user game has a nonempty core. That is a genuine new question, but it is not a computational question this paper poses or answers. The core still ranges over coalitions of content creators, while replacing users with type masses changes how each coalition’s value is calculated. That calculation can be done by checking the supported types’ willingness-to-pay thresholds. The algorithmic project would therefore be about a newly chosen core-feasibility problem, not a complexity landscape revealed by a result in this paper.

The best audience scenario is also less direct than the mass formulation makes it appear. A user’s type must include their complete stream vector across the creators in \(N\), as well as their reservation price. In a large catalog, exact repeated profiles may be rare, so the support could grow with the audience. A small standardized catalog or service with recurring user cohorts is a plausible counterexample, though; it prevents this from being a decisive objection. If such cohorts are accepted, the continuous game is meaningful—but Proposition 2 still supplies only a structural theorem, not the computational anchor ChoCo seeks.

So the negative case is strongest as a case against this paper’s fit for the programme: its one proposed anchor is outside the programme’s computational remit, and the richer computational problem would be new work rather than a mirror of a computational result here. The case is weak as a universal claim that no worthwhile continuous mirror exists. A mass-user version is readily definable, and a suitable high-multiplicity audience is plausible. I cannot honestly rule out that this could support a useful separate complexity study.
