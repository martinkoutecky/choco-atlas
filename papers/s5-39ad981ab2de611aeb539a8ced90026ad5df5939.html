The continuous mirror question

Given finitely many types \(t=(s_t,e_t,d_t)\) with rational masses \(\mu_t\), a fixed type order refining increasing \(d_t\), and a rational piecewise-constant per-capita capacity profile \(b(x)\), choose measures \(\lambda_t\) over starts \(a\in[s_t,e_t-d_t]\). Each unit of mass assigned at \(a\) receives the whole interval \([a,a+d_t]\); require \(\lambda_t([s_t,e_t-d_t])\le\mu_t\) and \(\sum_t\lambda_t([x-d_t,x]\cap[s_t,e_t-d_t])\le b(x)\) almost everywhere. What is the exact computational complexity of lexicographically maximizing the served-mass vector in the given type order?

The model it lives in

A continuous population of standardized computing requests, with each type carrying mass and receiving whole uninterrupted service intervals; per-capita capacity scales with the population, and type-level allocation measures determine served mass and lexicographic priority.

The objection that survived

Lexicographically maximizing served mass by type, especially with a fixed order among equal-demand types, need not be the fluid limit of SSD's randomized agent-by-agent order, so the theorem's scheduling hardness does not directly carry over.

fatal: False

What the mirror covers

The mirror covers the interval-allocation computational question anchored by Theorem 4.3; it leaves the paper's impossibility results, strategy-proofness and false-name-proofness guarantees, other mechanisms, and experiments aside.

Open questions for a prover

  • Does this mass-allocation problem have an exact algorithm polynomial in the support size, input bit length, and number of capacity-profile breakpoints?
  • Under what conditions, if any, does the type-level priority rule arise as a limit of SSD with randomized tie-breaking?

The case FOR (proponent)

The strongest case I believe is a mirror of Theorem 4.3, the paper’s hardness result for computing an SSD allocation.

Theorem 4.3, proved in this paper, states that finding an allocation satisfying Pareto efficiency under SSD is NP-hard. SSD orders agents by increasing required length \(d_i\), then considers them one at a time, preserving earlier agents’ utility while trying to give the current agent a qualifying interval. The paper’s proof reduces the question of whether the current agent can be served to a scheduling problem with start times and deadlines, invoking the NP-hardness result of Garey and Johnson (1977). That is the anchor: the combinatorial question is whether a set of interval-constrained requests can be served while honoring earlier service decisions.

I would call the continuous problem Mass-SSD Window Allocation. A type is \(t=(s_t,e_t,d_t)\): agents of this type accept service in \([s_t,e_t]\) and each needs one uninterrupted interval of length \(d_t\). The society is a rational distribution \(\mu\) over a finite support \(T\), with \(\mu_t\) the fraction of users of each type. Use a declared order \(\prec\) on types that refines increasing \(d_t\); this is the type-block version of SSD’s priority order.

A single fixed cake and a growing population would make this mirror degenerate: with positive minimum demands, only finitely many agents could be served. So the regime I would defend is a large shared computing service whose capacity is provisioned with its user base. Let \(b(x)\) be a rational, piecewise-constant *per-capita* capacity profile over the normalized service period: a population of size \(N\) has about \(N b(x)\) simultaneous slots at time \(x\). This fits the paper’s computing-resource motivation while making the resource-supply scaling explicit.

For each type \(t\), let \(\lambda_t\) be a nonnegative measure over feasible start times \(a\in[s_t,e_t-d_t]\). The mass \(\lambda_t\) assigns to \(a\) receives the whole interval \([a,a+d_t]\); \(y_t=\lambda_t([s_t,e_t-d_t])\) is the served mass, with \(0\le y_t\le\mu_t\). Feasibility requires, for almost every \(x\), \(\sum_{t\in T}\lambda_t([x-d_t,x]\cap[s_t,e_t-d_t])\le b(x)\). The problem is to choose feasible \((\lambda_t)_{t\in T}\) lexicographically maximizing \((y_{t_1},\ldots,y_{t_\tau})\), where \(t_1\prec\cdots\prec t_\tau\). A solution is the assignment measures and their optimal served-mass vector. Each individual still gets either a qualifying contiguous interval or nothing; only the type-level served mass is fractional.

The plausible setting is a large cloud or HPC service with many requests but relatively few standardized job classes: each class shares an availability window and a minimum uninterrupted run time. The number of agents can be large while \(\tau\) stays modest. This is a credible high-multiplicity object, and the authors could recognize it: it preserves their all-or-nothing interval utility and contention over compute time, while extending their one-shot finite-agent setting to recurring, capacity-scaled service. The paper’s cake is already continuous as an *outcome space*; this mirror continuizes the *population*.

My working expectation is Class A, tractable, not a claimed result. The individual allocation remains integral, but type mass can be split among start times. The resulting feasibility constraints are linear interval-coverage constraints, suggesting a continuous packing LP or configuration-LP approach. A prover’s concrete question is whether Mass-SSD Window Allocation has an exact algorithm polynomial in \(\tau\), the input bit length, and the number of capacity-profile breakpoints. The core technical obligation would be to establish an efficient finite representation or pricing method for the start-time measures. Further questions include whether the discrete-to-mass approximation has a bounded integrality gap, and whether a comparable truthfulness guarantee can survive aggregation.

The weak point is real: Theorem 4.3 concerns a fixed cake and named agents, while this mirror scales capacity with the population and uses type-block priorities. The reduction in the paper may rely on many distinct jobs, so its hardness need not persist when the support is small and type mass is divisible. I would not claim this is an immediate extension of their theorem. I would claim it is a plausible continuous version of the same interval-allocation problem in the high-volume computing regime the paper itself motivates, and that deciding whether the discrete hardness dissolves there is precisely the useful computational question.

The case AGAINST (opponent, writing after the proponent)

Theorem 4.3 is a real computational anchor, so I can’t dismiss it for lack of a named result. The strongest objection is that Mass-SSD changes the hard object. SSD processes individual agents in order, preserving each earlier winner’s utility while testing whether the next agent can receive a whole interval. Mass-SSD instead lets each type’s mass be split across start times and lexicographically maximizes the served mass by type. Its output need not correspond to any prefix of the paper’s serial process. That makes it a plausible priority-allocation problem, but a less direct mirror of the theorem’s scheduling question.

The more faithful version has its own problem. SSD’s order among agents with equal \(d_i\) is randomized. Replacing those agents with nonatomic mass removes the individual dictators; adding a priority mark to each agent would require defining a fluid limit of the randomized process. Either version could be studied, but neither follows automatically from Theorem 4.3. And when exact windows and demands define types, support may grow with the population, weakening the high-multiplicity benefit.

These points don’t defeat the better mirror, though. A large computing service with standardized job classes is credible, and scaling capacity with population is an allowed co-modification. Its mass-allocation problem preserves all-or-nothing service for each user while making the population continuous. Whether that model has an efficient exact algorithm is a worthwhile computational question, even if it is not a direct translation of SSD’s NP-hardness result.

So the honest negative case is weak: the type-block model changes the paper’s serial mechanism, but I can’t show that the resulting question is one the authors would reject. Theorem 4.3 remains a surviving anchor.
