The case FOR (proponent)

This paper has no qualifying named computational result. It contains no numbered theorem, lemma, corollary, or proposition establishing that a label aggregation problem is in P, NP-hard, FPT, or otherwise classifying its complexity. Algorithm 1 describes the proposed network; the accuracy tables report experiments. Section 4.3 gives unnumbered operation counts for its layers—\(O(|E|d_t d_{t+1})\) for MP1, \(O(|E|(d_t+d_e)d_{t+1})\) for MP2, and \(O((n^2+m^2)d_t d_{t+1})\) for COR—but these are costs for processing a finite graph, not a complexity result about the underlying label aggregation problem. I can’t honestly name any of these as an anchor or invent a continuous problem “per anchor.”

There is a plausible *research direction* here. Imagine a large annotation platform where many workers share complete, stable profiles: the same task-domain skills, assignment patterns, and response behavior. Let \(W\) be those worker types and \(\mu_w\) the fraction of the workforce in type \(w\). For each task \(q\), the input could record the fraction of its annotations supplied by each worker type and the resulting label distribution; some tasks have known truth labels. The proposed continuous question would be to infer labels for the remaining tasks from this weighted worker–task data, with predictions as the solution. That gives mass a clear meaning and makes a large workforce with relatively few worker types a credible regime.

But it is only a candidate, not a mirror anchored in this paper’s results. The paper does not define a worst-case prediction objective or prove a computational property of label inference. Nor is type aggregation automatically faithful to its method: the COR layer learns interactions among individual worker and task nodes, so collapsing nodes can discard structure unless members of each type are genuinely indistinguishable in all the graph information the model uses. That is my weakest point, and it limits how confidently I would claim the authors would recognize this as their problem.

So the strongest honest positive case is that crowdsourced label aggregation has a conceivable continuous-population formulation. This paper itself supplies no named computational anchor for that case.

The case AGAINST (opponent, writing after the proponent)

The proponent names no anchor, and that is decisive for the requested mirror: this paper proves no complexity classification of label aggregation. Algorithm 1 describes a neural network, the tables report predictive accuracy, and Section 4.3 gives per-layer operation counts for a finite graph. None supplies a named computational result whose continuous counterpart could reveal whether complexity changes. A continuous version of the model might be interesting, but it would not mirror a result in this paper.

The strongest version of the proponent’s proposal would group workers and tasks into types, retain their mass and label frequencies, and replace COR’s pairwise attention with attention over type distributions. That runs into a choice the paper’s task cannot avoid. Its output is a predicted label for each particular task, and its training loss uses the known truth of particular tasks. If the types preserve each task’s full assignment neighborhood, observed labels, and supervision status, many tasks and workers will remain distinct; in ordinary sparse assignment graphs, the continuum may buy little. If types instead pool tasks with different neighborhoods or truths, the output becomes a class distribution for a task group rather than the label of each item. That could suit a prevalence-estimation problem, but it changes the prediction target.

There is a coherent nearby project: study label inference on a large population with repeated worker profiles and task families, using mass-weighted message passing. But making that an algorithmic question requires choosing a finite representation of the population, a notion of prediction quality, and an inference objective. A finite list of weighted types is still a finite graph computation; an unrestricted distribution calls for a specified kernel or oracle model. The paper supplies none of these, and a result about optimal task assignment or workforce recruitment would add a decision problem the paper does not study.

So the negative case is strongest on the absence of a computational result to mirror and the task-specific nature of the prediction target. It is weaker as a claim that no useful continuum formulation could exist: repeated, genuinely interchangeable workers and tasks are plausible. But that formulation would motivate a new population-level label-inference problem, not continue a computational result established here.
