The continuous mirror question

Given a feasible rate set \(\mathcal R\subseteq[0,1]^k\) with the sphere access and regularity assumptions of Theorem 1, a rational distribution \(\mu\) over \(\tau\) stakeholder types, and for each type \(t\) a pairwise-comparison oracle for an unknown normalized quadratic metric \(\phi_t(r)=a_t^\top r+\tfrac12 r^\top B_t r\), what worst-case number of feasible queries suffices to output estimates \(\hat\phi_t\) whose mass-weighted aggregate \(\hat\Phi_\mu(r)=\sum_t\mu_t\hat\phi_t(r)\) approximates \(\Phi_\mu(r)=\sum_t\mu_t\phi_t(r)\) to a specified error under the paper's feedback-noise model?

The model it lives in

A population of stakeholders with complete preference types \(t\), rational masses \(\mu_t\), and a shared feasible classifier-rate set \(\mathcal R\). Each type supplies pairwise comparisons according to its own normalized quadratic metric \(\phi_t\); the collective objective is the mass-weighted metric \(\Phi_\mu=\sum_t\mu_t\phi_t\), and the computation estimates the type metrics and their aggregate.

The objection that survived

The type-specific query tasks can be run independently, with masses used only after elicitation, so the mirror does not show that continuous mass itself reduces query complexity.

fatal: False

What the mirror covers

The mirror extends Theorem 1's quadratic metric elicitation guarantee to \(\tau\) stakeholder types and their mass-weighted aggregate; it does not establish a type-resolved lower bound or mirror the fairness-specific and higher-degree polynomial results.

Open questions for a prover

  • Can aggregate-only error requirements reduce the \(O(\tau k^2\log(1/\epsilon))\) type-by-type query bound when some types have small mass?
  • What common cardinal normalization across types is justified for interpreting the mass-weighted objective from ordinal comparison feedback?

The case FOR (proponent)

The strongest mirror I see is a type-resolved version of Quadratic Performance Metric Elicitation, for stakeholder populations evaluating classifiers. The paper already treats classifier rates as probabilities over data and even allows the oracle to be a group of experts or a user population. I would not count those rates alone as the continuization: the new continuous object is the population supplying preferences.

Suppose there are \(N\) stakeholders in \(\tau\) preference types, with \(N\) large and \(\tau\) moderate. A type is a fixed constituency or operating context whose members share the same trade-offs over classification rates. The society is a distribution \(\mu\) over those types, with rational masses \(\mu_t\) summing to one. For the paper’s \(k\)-dimensional feasible rate set \(\mathcal R\), type \(t\) has an unknown normalized quadratic utility
\[ \phi_t(r)=a_t^\top r+\tfrac12 r^\top B_t r, \]
where \(B_t\) is negative semidefinite, with the paper’s regularity assumptions. A feasible classifier pair gives a pairwise comparison query to a type-specific oracle. The decision is one classifier for the population, scored by
\[ \Phi_\mu(r)=\sum_t\mu_t\phi_t(r). \]
A solution outputs estimates of every type’s coefficients, hence an estimate of \(\Phi_\mu\), and a feasible rate maximizing that estimated population objective.

This is plausible as an extension of the authors’ problem: they explicitly allow a group of experts or an entire user population to serve as the oracle, and the task remains eliciting their quadratic metric from comparisons of feasible classifiers or rates. A plausible regime is a large deployed classification service with many users but a modest number of stable stakeholder constituencies—say, patients, clinicians, and several affected communities. The headcount can be large while the support size \(\tau\) remains small. The type-level objective is a co-modification needed to make heterogeneous preferences usable; the population, rather than the rate space, is what is being continuized.

My lead anchor is Theorem 1, proved in this paper. Under the paper’s distribution, smoothness, and regularity assumptions, for a \(1\)-Lipschitz quadratic metric and parameters \(\epsilon,\epsilon_\Omega\ge 0\), Algorithm 1 uses \(O(k^2\log(1/\epsilon))\) pairwise queries and returns estimates satisfying
\[ \|a-\hat a\|_2 =O\!\left(\sqrt{k}\left(\epsilon+\sqrt{\varrho+\epsilon_\Omega/\varrho}\right)\right), \qquad \|B-\hat B\|_F =O\!\left(k\sqrt{k}\left(\epsilon+\sqrt{\varrho+\epsilon_\Omega/\varrho}\right)\right). \]
Here \(\varrho\) is the radius of the local query balls and \(\epsilon_\Omega\) is the feedback-noise parameter. The paper proves this result, using local linear approximations and its LPME routine.

The continuous question anchored by Theorem 1 is: Type-Resolved Population QPME. Given \(k\), a feasible-rate query space with the sphere access assumed in the paper, a support of \(\tau\) stakeholder types with masses \(\mu_t\), and type-specific pairwise comparison oracles for unknown regular quadratic metrics, recover each type’s metric to the stated error and return a feasible rate maximizing the mass-weighted metric. The expected direction is tractable in the oracle-query and postprocessing model: run the paper’s elicitation algorithm for each type, giving \(O(\tau k^2\log(1/\epsilon))\) queries at uniform tolerance, then combine the estimates by their masses. Summing the typewise errors controls the error in \(\Phi_\mu\). This is a proposed extension; Theorem 1 itself proves the \(\tau=1\) case, not the type-resolved bound.

The paper’s result measures query complexity, not a conventional P-versus-NP running-time classification. That makes this a softer fit to ChoCo’s usual complexity questions, and I would not present it as an NP-hardness or polynomial-time result. Still, it is a named algorithmic guarantee about eliciting a metric, and the extension gives the prover a concrete population problem rather than just the phrase “many stakeholders.”

The weakest point is the move from one oracle metric to several type-specific metrics. The paper does not establish that segmented stakeholders have a shared metric within each type, or that averaging separately normalized utilities is the right collective objective. That normalization fixes a cardinal scale that pairwise comparisons alone do not supply across types. The mirror is most credible when the constituencies and equal per-capita weighting are part of the application’s agreed model. It covers the paper’s quadratic metric-elicitation guarantee; it does not mirror the polynomial extension or claim new complexity results for them.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is a real algorithmic result: it bounds the number of oracle queries needed to elicit a quadratic metric. So I would not argue that the paper has no computational result to mirror. The problem is that its proposed continuous population is already built into the theorem’s setup, while the proposed stakeholder population either disappears into the oracle or changes the problem.

The paper defines rates using \(\mathbb P(X,Y)\), proves its main guarantee assuming access to population rates, and treats the finite sample as a way to estimate those rates. In that sense, the classified examples already contribute through their aggregate distribution. Calling them a continuous society would relabel the paper’s existing model, not create a new mirror. They also are not preference-bearing agents in the elicitation problem: the oracle supplies the preferences, and the examples determine which rates are feasible.

The stronger alternative is a population of stakeholders grouped into \(\tau\) preference types. But it splits into two different models. If one aggregate oracle reports comparisons according to a population-level quadratic metric, then the paper’s QPME applies to that single metric; the type masses and support are invisible to its query bound. The paper already allows a group of experts or a user population to serve as the oracle. If instead each type gets its own oracle, the proposal adds \(\tau\) separate elicitation problems. The type masses only enter afterward, when combining the estimates; they do not make population multiplicity part of the computational task.

That second version also needs an aggregation rule the paper does not provide. A majority of type-specific comparisons need not correspond to any quadratic metric. A weighted sum of type-specific metrics is coherent, but comparison queries identify each type’s metric only up to scale unless the model fixes a cardinal convention across types. Normalizing each type separately, as the proposed mirror suggests, supplies such a convention by assumption. With it, the mirror is definable, but its theorem is essentially repeated type by type; without it, the mass-weighted objective is not identified by the stated feedback.

So the strongest negative case is that Theorem 1 has no unused continuous society axis to exploit: the data population is already aggregated, and adding a separate evaluator population either reduces to the paper’s existing single-oracle problem or requires a new model of heterogeneous preferences and cardinal aggregation. The universal claim is not airtight: a programme that includes oracle-query complexity could reasonably study that new model. But that would be a neighbouring preference-learning problem, rather than a high-multiplicity relaxation of the computational problem this paper analyzes.
