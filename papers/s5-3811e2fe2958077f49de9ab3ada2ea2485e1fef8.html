The continuous mirror question

Given candidates \(C\) and an explicit support of \(\tau\) strict-partial-order ballot types with positive rational masses \(\mu_t\) summing to one, compute a Schulze-maximal candidate and determine whether it is unique.

The model it lives in

Each type \(t\) is a ballot and carries mass \(\mu_t\). Set \(\Delta_\mu(x,y)=\sum_t\mu_t(\mathbf 1[x\succ_t y]-\mathbf 1[y\succ_t x])\), treating an incomparable pair as contributing zero. Use these margins as graph weights, compute beatpath strengths, and return a maximal candidate and its uniqueness status; there is no optimization objective.

What the mirror covers

Covers the winner and uniqueness computation in Lemma 5 with Theorem 1’s expected-time bound, and the all-maxima computation in Theorem 3. It does not develop Theorem 2’s high-probability analysis, Theorem 4’s representability result, or the paper’s structural barriers.

Open questions for a prover

  • Can the randomized winner and all-maxima bounds be derandomized for rational type-mass inputs?
  • What are the exact winner-stability regions when the type masses \(\mu_t\) vary?

The case FOR (proponent)

My best case is a continuous Schulze winner problem. Let the candidates be \(C\), and let each type \(t\) be a ballot: a strict partial order over \(C\), with complete rankings as a special case. The instance is an explicit support of \(\tau\) types, each with a positive binary rational mass \(\mu_t\), where \(\sum_t\mu_t=1\). For each pair \(x,y\), set the edge weight to the per-capita margin
\[ \Delta_\mu(x,y)=\sum_t\mu_t\bigl(\mathbf 1[x\succ_t y]-\mathbf 1[y\succ_t x]\bigr). \]
An incomparable pair on a partial ballot contributes zero. From these weights, form the beatpath strengths and Schulze order exactly as in the paper. The output is a candidate, or a set of candidates, satisfying the relevant Schulze maximality condition; there is no separate optimization objective.

This has a plausible high-multiplicity regime: for example, a large party or organization election with millions of voters and a support-compressed ballot file containing hundreds or thousands of distinct rankings. The voters sharing a type have the same preferences for every comparison the method uses. Thus \(n\) can be far larger than \(\tau\), and the type masses give the honest input quantities: fractions of the electorate. This is a scenario for this instance regime, not a claim that every election has low support.

The main anchor is Theorem 1, proved in this paper. For an \(m\)-candidate weighted majority graph, the authors’ randomized algorithm has expected iteration count \(R(m)=\ln m+O(1)\) and expected running time \(T(m)=O(m^2\log m)\). The correctness result it relies on, Lemma 5, is also proved here: the algorithm returns a maximal element of the Schulze order and correctly determines whether it is the unique maximal element. My lead mirror is Continuous Schulze Winner: given the rational type distribution above, return a Schulze-maximal candidate and report whether it is the unique maximal candidate. The algorithm first builds the pairwise-margin graph from the support, then applies the paper’s algorithm. This is expected \(O(\tau m^2+m^2\log m)\) arithmetic operations, with bit complexity polynomial in the input length \(L\). I expect this problem to be tractable, in Class A.

A second, narrower anchor is Theorem 3, also proved here: if the Schulze order has \(k\) maximal elements, the paper’s algorithm finds all of them in expected time \(O(km^2\log m)\) on the weighted graph. Its mirror, Continuous Schulze Maximal Set, has the same distribution input and asks for the exact set of Schulze-maximal candidates. Including aggregation, the bound is expected \(O(\tau m^2+km^2\log m)\) arithmetic operations, again with polynomial bit complexity in \(L\). This too is Class A. Theorem 1 is the stronger anchor; Theorem 3 adds the useful all-winners case. The paper has no comparable hardness result to anchor.

I think the authors could recognize these as mirrors of their problem because the continuous distribution produces precisely the weighted majority graph on which their algorithm operates. Normalizing an election’s integer margins by its voter count only multiplies all beatpath strengths by the same positive factor, so it preserves the Schulze order, including ties. Conversely, clearing the denominators of a rational distribution gives a finite electorate with exactly those proportions. That gives a direct high-multiplicity dictionary: the mirror changes the representation of society while preserving the winner question. The support representation also makes the work depend on \(\tau\), rather than on a potentially enormous voter count.

The scope is deliberately just winner computation and, in the second problem, finding all maximal candidates. The paper’s algorithm starts from the pairwise-outcome graph, so the \(O(m^2\log m)\) theorem itself does not exploit voter multiplicity; the support-dependent aggregation bound is the straightforward preprocessing needed to state the mirror on a society distribution.

That is also the weakest point: a referee could say this is an input reformulation of an algorithm that already takes the population’s sufficient statistic, not a new continuous-complexity question. The mirror is credible because the paper’s graph is generated by the population and the normalized mass model preserves exactly the paper’s winner relation. But it does not expose a discrete hardness that might disappear in a continuum; it carries an existing tractable graph algorithm over to an explicit high-multiplicity population input. Further questions include whether the randomized bound can be derandomized, how sharply the all-maxima cost depends on \(k\), and what exact winner-stability guarantees follow from small perturbations of the type masses.

The case AGAINST (opponent, writing after the proponent)

The case against is not that the continuous problem is ill-posed. It is that the paper’s computational problem has already discarded the population: its input is the weighted majority graph, and its output depends only on that graph. A rational distribution over ballot types supplies such a graph by summing pairwise margins. Once those \(m^2\) values are known, the number of voters and the support size no longer matter.

That makes the proposed mirror of Theorem 1 and Lemma 5 perfectly coherent: given rational type masses, compute the Schulze-maximal candidate and test uniqueness. But the paper’s algorithm already handles the resulting graph. Clearing denominators turns the rational margins into integer margins; conversely, normalizing an election’s margins preserves every beatpath comparison. Aggregating an explicit support costs \(O(\tau m^2)\) arithmetic operations, after which Theorem 1 gives the existing graph algorithm. This leaves no population-dependent complexity question in the result itself. The algorithm’s random pivots and path computations operate on candidates and graph edges, not on voters or types.

Theorem 3 has the same limitation. Asking for all maximal candidates from a distribution is also well-posed, and the paper’s graph algorithm answers it once the margins are computed. A better formulation that keeps the full support, handles ties explicitly, or asks for the exact maximal set does not recover a population-level obstacle: Schulze’s output ignores all support information that does not affect pairwise margins. Winner stability under changes to the masses might be a worthwhile separate topic, but it is not a mirror of the cited results.

So the mirror is admissible, but it offers little for this programme to chart. The continuous input is a population distribution; the computational core is already a graph problem whose instance has size \(O(m^2)\). The continuous model adds a routine route to that instance, not a new tractability boundary or a problem that calls for continuous-optimization machinery. This is a case against prioritizing the mirror, not a decisive case that no worthwhile version exists: because the authors explicitly study winner computation from a graph built from votes, a reader could reasonably count the support-to-graph formulation as their problem.
