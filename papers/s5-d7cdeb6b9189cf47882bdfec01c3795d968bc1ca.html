The case FOR (proponent)

Under the required anchor rule, this dissertation has no eligible numbered computational anchor. Its named algorithms, G-BNL and GRank-BNL, and their runtime analyses are computational contributions, but the analyses are not numbered Theorems, Lemmas, Corollaries, or Propositions asserting a complexity classification. The nearest numbered results do not qualify: Theorem 3.1 proves that the weak preference relation is a strict partial order under its stated consistency and acyclicity conditions; Theorem 3.2 says the strong order is contained in the weak order; Theorem 3.3 gives a sufficient consistency condition, drawing on Wilson’s result. None classifies the complexity of a problem. So I cannot honestly supply a question *per anchor*.

The strongest unanchored lead is a continuous batch version of the dissertation’s SelectK-Best query. Consider a product or medical-image service handling millions of people making the same query against the same catalog, where users fall into a modest number \(\tau\) of preference types. Each type is a complete CPref-SQL preference theory, including its order semantics and any query-specific parameters; type \(t\) has rational mass \(\mu_t\), with \(\sum_t\mu_t=1\). Given the filtered relation \(R\) and a shared \(K\), compute each type’s \(\operatorname{TopK}_{\Gamma_t}(R)\) using the dissertation’s level definition and tie-breaking rule, then return the results with their type masses. Equivalently, report for each item \(a\) the fraction \(\sum_{t:a\in\operatorname{TopK}_{\Gamma_t}(R)}\mu_t\) of users whose top-\(K\) list includes it. This is query evaluation, not an optimization problem, so there is no objective function.

That regime is plausible: repeated preference templates can describe a large customer cohort or users of a clinical retrieval system. The population size \(N\) may be millions while the number of distinct complete types \(\tau\) is much smaller. The population dimension then reduces to evaluating one query per type and aggregating the results. This is tractable with respect to \(N\) once types are grouped, but it does not settle the dissertation’s per-type complexity: its dominance-based algorithms have exponential worst-case dependence on the number of preference rules. The continuous version therefore does not, on the evidence here, establish a full Class A result.

The soft spot is also the reason this remains only a lead: the dissertation studies one user’s query over database alternatives, not collective choice among a population. Authors might recognize cohort batch evaluation as a natural extension of their preference-query machinery, but it adds a population-level output and no new preference algorithm. Without an eligible numbered computational anchor, this is not a compliant anchored case for a continuous mirror.

The case AGAINST (opponent, writing after the proponent)

There is no eligible numbered computational result here to anchor a mirror. The numbered Theorems 3.1–3.3 concern preference-order properties and consistency; they do not classify the complexity of a computational problem. G-BNL and GRank-BNL are named algorithms with runtime analyses, yet those analyses appear as part of the implementation discussion, not as numbered complexity results. The proponent is right that their batch-query proposal is unanchored.

The strongest version of that proposal is still coherent: a service has a shared catalog and query, and millions of users fall into a small number \(\tau\) of complete preference types. For each type, run SelectK-Best and report either its list with mass \(\mu_t\), or each item’s total mass across lists. That is a sensible workload model. Its weakness for ChoCo is what the model asks: it batches independent personal queries. The dissertation’s computational problem is ranking database tuples for one user’s preference theory. It does not choose a common social outcome, compare users’ claims, or change an agent’s behavior. The user population is added around the query engine; it is not part of the problem the paper studies.

A stronger collective version could ask for a shared set of \(K\) items favored by the cohort. That requires specifying how partial, conditional preferences from different users combine into a collective ranking or choice rule. The dissertation supplies no such rule: its operators return each user’s preferred tuples, including incomparabilities. A support rule based on users’ personal top-\(K\) lists is possible, and the proposed mass totals could implement it, but that formulates a new collective recommendation problem rather than continuizing a result in this dissertation.

So the negative case is strongest on scope: the plausible continuous population is a distribution of query demand, while a genuine collective-choice mirror needs an added aggregation problem. It is weaker as a universal claim. The cohort workload is plausible and may be useful to database researchers; the evidence here supports calling it a new application of CPref-SQL, not showing that no worthwhile continuous mirror could be built.
