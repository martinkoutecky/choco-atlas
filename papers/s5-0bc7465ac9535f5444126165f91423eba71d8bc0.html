What the mirror covers

The case FOR (proponent)

The paper contains no qualifying computational result to anchor a continuous mirror on. Its closest named result is Theorem 1, proved here: it characterizes the mechanisms for land acquisition that are strategyproof, strongly budget balanced, and ex-post individually rational, using threshold functions of other agents’ reports. That is a mechanism-design characterization, not a result about an algorithm or a problem’s complexity. The discussion of trade becoming likely as the number of sellers grows points to an argument in Sarkar (2018), rather than a numbered computational result of this paper.

There is a plausible high-multiplicity setting behind the subject: a large redevelopment area with many small parcels, where types capture location class and reservation value, and mass represents the share of parcels in each type. But turning Theorem 1 into a continuous-population characterization of mass allocations and transfers would be a new mechanism-design question. It would not be a computational mirror anchored in this paper, and its connected-land feasibility condition would need to be specified carefully.

So the positive case is limited: land assembly has a believable large-population regime, but this paper supplies no named computational anchor and no anchor-specific continuous computational problem. Its Bayesian distributions over agents’ private valuations do not themselves make the population continuous.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is the strongest possible anchor, and it is not a computational result. It characterizes DSIC, strongly budget balanced, ex-post individually rational mechanisms through threshold functions \(g_i(v_{-i})\). It gives no algorithm, complexity bound, or computational problem whose continuous counterpart could be asked. A continuous version of that characterization would be a new mechanism-design theorem, not a computational mirror of this paper.

The best setting for a mirror is easy to imagine: take the complete-graph case, make sellers with the same reservation value interchangeable, let \(k/n\) approach a fixed fraction, and represent sellers by a distribution of value types. That is a credible large market. But it does not supply the missing computational anchor. One could ask which threshold functions maximize expected welfare for a given distribution, or optimize a posted price. Section 5.5 already points toward such economic questions, but the paper does not formulate their algorithmic complexity. To turn them into computational problems, one must newly choose how the distribution, mechanism, and objective are encoded. That could be worthwhile work; it would not be a continuous version of a computational result in this paper.

The land-acquisition framing makes the mirror less direct. A seller’s site determines which feasible paths contain them, and critical sellers matter precisely because of that position. Grouping sellers by valuation alone loses the assembly structure. Including location in the type can preserve it, but as the graph grows the type space and connectivity constraints grow with the network; there is no fixed finite set of interchangeable types to which this paper’s result naturally reduces. The complete-graph model avoids that obstacle, but in doing so it becomes the large-market procurement model above, with a new computational agenda.

Nor do the paper’s Bayesian distributions over valuations make its population continuous: they describe uncertainty about finitely many individually indexed agents. The cited asymptotic trade result likewise concerns probability as the number of sellers grows, not a computational result over a continuous society. Existing high-multiplicity work would support the plausibility of a large-market regime, but it would not create a computational anchor here.

So the negative case is strongest as a judgment about fit to ChoCo’s computational programme, not as a claim that continuous market design has no value. A continuous assembly-market project is plausible. What this paper offers is no named computational result for it to mirror, and defining one would amount to starting a neighboring project rather than continuizing this paper’s computational contribution.
