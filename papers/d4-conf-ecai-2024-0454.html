The case FOR (proponent)

There is no eligible complexity anchor in the paper as provided: it has no numbered theorem, lemma, corollary, or proposition asserting that one of its problems is in P, NP-hard, or in another complexity class. Property 1 is a mathematical property, not a computational result. The closest named computational contribution is the authors’ Algorithm 2, which proposes an exact method for finding a minimum-cost Lorenz-optimal solution. It starts from a minimum-cost feasible solution, tests Lorenz optimality, then searches for cheaper candidates outside the Lorenz-dominated region found so far, checking candidates and solutions with the same Lorenz vector along the way. The paper evaluates the method experimentally, but does not give it a polynomial-time guarantee or a complexity classification. So Algorithm 2 can motivate a mirror, but it is not an anchor of the kind your rules require.

The strongest mirror I see is the paper’s multi-agent knapsack problem. Imagine a large public agency choosing a portfolio of projects under a budget, where millions of residents value the projects additively. A type \(t\) is a complete project-valuation profile: residents of that type value every project identically. Let \(\mu_t\) be the fraction of residents of type \(t\), with \(\sum_t\mu_t=1\). This is plausible in a large population with a modest number \(\tau\) of distinct valuation profiles; the type records every preference the model uses.

For a precise continuous problem, let the instance give projects \(i\in I\), weights \(w_i\), type-specific utilities \(u_{ti}\), project costs \(c_i\), and budget \(W\), all with rational encodings. Choose a project set \(x\in\{0,1\}^{I}\) satisfying \(\sum_i w_i x_i\le W\). Type \(t\)’s utility is \(U_t(x)=\sum_i u_{ti}x_i\), so the resulting population has utility distribution \(\rho_x=\sum_t\mu_t\delta_{U_t(x)}\). Let \(Q_x\) be its nondecreasing utility quantile function, and define the lower-tail Lorenz curve
\[ \Lambda_x(a)=\int_0^a Q_x(s)\,ds,\qquad 0\le a\le1. \]
Call \(x'\) Lorenz-dominant over \(x\) if \(\Lambda_{x'}(a)\ge\Lambda_x(a)\) for every \(a\), with strict inequality for at least one \(a\). The problem is to return a feasible project set of minimum cost \(\sum_i c_i x_i\) among all sets not Lorenz-dominated by another feasible set. The item choices remain discrete; it is the population whose utility distribution is continuous. With rational type masses, this curve is the normalized Lorenz vector of a finite population at its cumulative-mass breakpoints.

The authors could plausibly recognize this as their problem: it keeps the common knapsack decision, additive utilities, Lorenz fairness, and the independent linear cost, replacing a list of agents with a distribution over complete valuation types. This case covers the multi-agent knapsack problem only; I would not stretch it to cover every result in the paper.

I would investigate Class B first for the unrestricted version. Setting each of \(p\) finite agents as its own type with mass \(1/p\) embeds the finite-agent problem exactly, so any hardness of that problem carries over. The paper itself does not prove such a hardness result, so this is a prediction, not an anchor it supplies. Whether restricting to small \(\tau\) changes the complexity is a further question; the discrete project choices may remain the main source of difficulty. Other questions include whether the problem is fixed-parameter tractable in \(\tau\), and whether its lower-tail constraints admit an efficient exact or approximation method.

The weakest point is the one the anchor requirement exposes: the paper’s strongest relevant contribution is an exact algorithm, not a named complexity result. There is also a modeling bet in the mirror: a shared portfolio for a large population with repeated valuation profiles is credible, but narrower than the paper’s full assignment and knapsack remit.

The case AGAINST (opponent, writing after the proponent)

The strongest case against starts with the anchor requirement: the paper gives no numbered complexity result. Algorithm 2 is an exact method, but it is a sequence of ILP solves with no worst-case complexity guarantee; the experiments report performance on selected instances. A continuous question would therefore extend the method to a new model, rather than mirror a complexity finding this paper establishes. Under the programme’s stated standard for anchors, that is a serious gap.

That gap does not defeat the proposed knapsack mirror. A public agency choosing projects for residents with repeated valuation profiles is a credible high-multiplicity setting. Each type can record its complete vector of project utilities, and the Lorenz curve over type masses preserves exactly the distribution relevant to fairness. The shared project decision means individual identity is not needed. Rational masses also correspond exactly to a finite cohort after choosing a common denominator. The paper’s discrete project choices do not undermine this population continuization.

The best substantive objection is about research priority: with finite support \(\tau\), the new model is a weighted version of the paper’s multi-agent knapsack problem. It may invite a weighted Lorenz formulation and adapted algorithms, but the paper supplies no complexity result whose behavior under continuization could be classified. That makes the connection less direct than the programme’s strongest examples. Still, claiming that no worthwhile mirror exists would go too far. The proposed mirror is well-posed and plausible, and arguments based on unchanged hardness or a discrete outcome space would not defeat it. My negative case is strongest on anchor eligibility and weak on the broader claim that the question is not worth asking.
