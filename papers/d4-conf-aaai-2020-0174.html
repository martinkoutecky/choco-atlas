The continuous mirror question

Given a finite item set \(X\), a slate size \(k\), type utilities \(u_t\), response models \(R(r\mid q,t)\), and rational type masses \(\mu_t\) summing to \(1\), apply one common slate \(q=(x_1,\ldots,x_k)\) to the cohort and recommend to each member according to that member's response. For each response \(r\), let \(p_r=\sum_t\mu_tR(r\mid q,t)\) and \(V_\mu(q)=\sum_r\max_{y\in X}\sum_t\mu_tR(r\mid q,t)u_t(y)\). If each \(x_i\) is replaced by \(y_i^*\in\arg\max_{y\in X}\sum_t\mu_tR(x_i\mid q,t)u_t(y)\), does the resulting slate \(q'\) satisfy \(V_\mu(q')\ge V_\mu(q)\) for noiseless responses and the Theorem 2 lower bound \(V_\mu(q')\ge V_\mu(q)-\Delta_\mu\) for logistic responses, with its stated noise bound evaluated under \(\mu\)?

The model it lives in

A high-volume service serves a cohort whose types \(t\) encode complete utility and response parameters, with mass \(\mu_t\). It chooses one \(k\)-item query slate for everyone; each member responds independently, then receives a recommendation based on that response. The objective is expected recommendation utility per member, \(V_\mu(q)\), and the decision is whether deep retrieval preserves Theorem 2's guarantee under this population measure.

The objection that survived

The cohort guarantee follows from the same expected-utility calculation as the single-user Bayesian model, so it introduces no population-specific computational structure; the concrete shared-query cohort scenario makes this a limit on novelty rather than a fatal objection.

fatal: False

What the mirror covers

The mirror covers Theorem 2's slate-replacement guarantee; it leaves the paper's item-space relaxations, partial-query method, and empirical comparisons unaddressed.

The case FOR (proponent)

The strongest honest case is narrow. The paper contains no numbered theorem that classifies a problem as NP-hard, polynomial-time solvable, or similar. Its closest named computational result is Theorem 2, which the authors cite from Viappiani and Boutilier (2010), rather than prove here. It says that if \(q=(x_1,\ldots,x_k)\) is a query slate and \(q'=\operatorname{DeepRetr}(q)=(y_1^*,\ldots,y_k^*)\) replaces each query item with the best recommendation after that response, then under noiseless responses \(\operatorname{EVOI}(q')\geq\operatorname{EVOI}(q)\); under logistic responses, \(\operatorname{EVOI}(q')\geq\operatorname{EVOI}(q)-\Delta\), with \(\Delta\) the paper’s stated bound on the loss from response noise. This is an algorithmic quality guarantee, not a complexity classification.

A plausible population mirror is Cohort EVOI Slate Selection. Consider a large service cohort with a finite set \(T\) of preference types. Type \(t\) has a complete utility vector \(u_t\) over the service’s item set \(X\), and \(\mu_t\) is the fraction of cohort members of that type. A service chooses one \(k\)-item slate \(q\in X^k\) to present to each member; members respond independently according to the paper’s response model, and the service gives each person a recommendation based on that person’s response. The objective is to maximize expected per-person recommendation utility:
\[ \sum_{r} p_r\max_{y\in X} \frac{\sum_{t\in T}\mu_t R(r\mid q,t)u_t(y)}{p_r}, \qquad p_r=\sum_{t\in T}\mu_tR(r\mid q,t). \]
A solution is a maximizing feasible slate \(q\), together with the best recommendation for each possible response. Subtracting the cohort’s pre-query expected utility gives the corresponding per-capita EVOI objective.

The regime would be a high-volume service applying the same query protocol to a stable cohort—say, users of a particular market or locale—with many users but relatively few recurring preference profiles. Types must capture everything the model uses, including utility and response-noise parameters. This is plausible when the service repeatedly serves a large population from a shared catalog and wants a common opening query while still personalizing the follow-up recommendation to each answer. The population reading is doing real work: \(\mu\) is the cohort’s type mass, not just uncertainty about one named user.

Under that interpretation, Theorem 2 extends directly: replace the probability distribution over possible utilities with the cohort’s type masses. The guarantee applies to a randomly selected cohort member, so it is also a per-capita guarantee for the cohort. For the underlying slate-optimization problem, I would investigate hardness transfer first: finite rational type distributions retain the item-slate search, and population scaling does not remove that combinatorial choice. The paper does not prove such hardness, however; this is a prediction for the mirror, not a result of Theorem 2. Natural follow-ups are complexity in the support size \(\tau\), slate size \(k\), and item dimension \(d\), and whether continuous query optimization yields useful approximation guarantees after projection to feasible items.

The weakest point is that the paper already represents user heterogeneity with a distribution over utility functions, so this mirror may be judged a population reinterpretation of its existing model rather than a distinct continuization. Its continuous relaxation also concerns item attributes, not the population. The positive case stands only if the cohort-wide deployment—with mass over actual users and a shared query objective—is accepted as the problem’s high-multiplicity regime.

The case AGAINST (opponent, writing after the proponent)

The strongest objection is that the proposed cohort problem is exactly the paper’s existing Bayesian problem with a different interpretation of its distribution. For a cohort with types \(t\), masses \(\mu_t\), and response probabilities \(R(r\mid q,t)\), the expected utility after query \(q\) is

\[ \sum_r \max_{y\in X}\sum_t \mu_t R(r\mid q,t)u_t(y). \]

That is the paper’s posterior expected utility with prior \(P(t)=\mu_t\). The equivalence holds for any slate and any response model in the paper. It even gives the proponent’s strongest scenario its intended reading: one shared opening query, followed by a recommendation based on each person’s response.

So Theorem 2 transfers—but only because it applies to a distribution over utilities regardless of whether that distribution represents uncertainty about one user or the composition of a cohort. The guarantee is for expected utility, and therefore also for average cohort utility. It supplies no new population-specific result. Moreover, the paper cites Theorem 2 from earlier work; its own contributions are continuous optimization methods and empirical evaluations, not a complexity classification of a named problem. The paper already optimizes expected query value over sampled user utilities, including in its experiments. Encoding the cohort as finite rational type masses would change the interpretation and input representation, but not the optimization problem.

Other versions do not rescue this anchor. If users can receive independent queries and recommendations without shared constraints, the cohort objective separates into individual elicitation problems. A genuinely collective version could add a shared query budget, fairness constraints, or interactions among users; those might create new population-computational questions, but they would no longer mirror Theorem 2 or the paper’s results.

I cannot establish the universal claim that no worthwhile continuous mirror exists in any scenario. A shared-query cohort is coherent, and exact complexity questions about EVOI may remain open. The narrower negative case is stronger: this anchor does not justify a *new continuization*—the cohort formulation is already the same expected-utility problem the paper studies. Any new contribution would need to come from added collective structure, not from making the population continuous.
