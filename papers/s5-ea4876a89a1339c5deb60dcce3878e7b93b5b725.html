The continuous mirror question

For fixed \(\sigma\), given rational type masses \(\mu_t\) over machine processing vectors \(p_t\) and rational supplies \(\rho_q\) of \(\sigma\) task classes per machine, is there an algorithm polynomial in \(\tau\), the input bit length \(L\), and \(1/\epsilon\) that outputs a finite, efficiently implementable mechanism? Each machine must receive an integral bundle; the mechanism must be feasible for every aggregate report distribution, \(\epsilon\)-BIC, and ex-post individually rational, and have expected makespan at most \(2\mathrm{OPT}_\infty+\epsilon\), where \(\mathrm{OPT}_\infty\) is the best value among mechanisms satisfying those conditions.

The model it lives in

An atomless population of machines has type masses \(\mu_t\) over complete processing-time vectors \(p_t\). There are \(\sigma\) repeated task classes, with supply \(\rho_q\) per machine. A mechanism maps aggregate reports to feasible mass allocations over lotteries of integral bundles \(B\in\mathbb{Z}_{\ge 0}^{\sigma}\) and transfers; it must respect each task supply for every report distribution. Incentives are measured by type-level BIC constraints, IR holds for each truthful realized bundle and transfer, and the objective is expected makespan over the assigned population.

The case FOR (proponent)

The strongest anchor is Theorem 9, proved in this paper as a corollary of its mechanism-to-algorithm reduction and its makespan algorithm. It gives a polynomial-time \(2\)-approximation for truthfully minimizing makespan on unrelated machines: for every \(\epsilon>0\), the output mechanism is \(\epsilon\)-BIC, feasible, ex-post IR, and has expected makespan at most \(2\mathrm{OPT}+\epsilon\), with polynomial running time. The paper states a high-probability guarantee too; the excerpt prints its bound as \(1-\exp(\operatorname{poly}(\cdot))\), apparently missing a minus sign. The paper’s NP-hardness claims are in prose rather than numbered results, so I do not use them as anchors.

A plausible mirror is Mass-BIC Unrelated Scheduling. Take a unit-mass population of machines with a finite support \(T\) of complete types. Type \(t\) has mass \(\mu_t\), where \(\sum_t\mu_t=1\), and processing-time vector \(p_t=(p_{tq})_{q\in Q}\) for a fixed set \(Q\) of \(\sigma\) repeated task classes. Class \(q\) has supply \(\rho_q\) jobs per machine. An individual machine must receive an integral bundle \(B\in\mathbb Z_{\ge0}^{\sigma}\); only the mass of machines assigned each bundle can be fractional. A truthful allocation is feasible when type-\(t\) machines have total mass \(\mu_t\) and, for every class \(q\), total assigned job mass is \(\rho_q\). All input masses and processing times are binary rationals.

For each report \(r\), a direct mechanism gives a machine a lottery over integral bundles and a transfer. Write \(a_{rq}\) for its expected number of class-\(q\) jobs and \(R_r\) for its expected transfer. A type-\(t\) machine has utility \(R_r-\sum_q p_{tq}a_{rq}\) from reporting \(r\). Require \(\epsilon\)-BIC,
\[ R_t-\sum_q p_{tq}a_{tq}\ \geq\ R_r-\sum_q p_{tq}a_{rq}-\epsilon, \]
and ex-post IR: under a truthful report, every realized transfer \(P\) covers that machine’s realized processing cost \(p_t\cdot B\). The objective is expected makespan, where the makespan of an allocation is the essential supremum of \(p_t\cdot B\) over the assigned population.

The concrete question is: for fixed \(\sigma\), given \((\mu_t,p_t)_{t\in T}\) and \((\rho_q)_{q\in Q}\), is there an algorithm polynomial in \(\tau=|T|\), the input bit length \(L\), and \(1/\epsilon\) that outputs a finite, efficiently implementable mechanism with these feasibility, incentive, and IR conditions and expected makespan at most \(2\mathrm{OPT}_\infty+\epsilon\)? Here \(\mathrm{OPT}_\infty\) is the best expected makespan among feasible BIC, IR mechanisms for the mass instance.

The regime is a large fleet of contractors or cloud machines with a few repeated hardware and operating-cost profiles, processing repeated classes of tasks. As the number \(n\) of machines grows, \(\tau\) stays small and the number of class-\(q\) jobs grows proportionally to \(n\rho_q\). Types group machines only when their processing costs and all other relevant private parameters agree. Every machine still gets an integral bundle; fractional quantities appear only as population masses over those bundles. The paper’s Bayesian priors concern finite, named machines, so they do not themselves make the population continuous. This mirror makes the population proportions the input object.

For the fixed-\(\sigma\) question, I would tentatively expect Class A. A configuration LP can use integral bundles as columns, while its pricing problem has fixed dimension \(\sigma\); that makes continuous-optimization machinery a plausible route to a compressed algorithm. This is a conjecture about the mirror, not a consequence of Theorem 9. If \(\sigma\) is unrestricted, pricing may expose knapsack-type hardness, so whether the result extends to that regime is a further question. Another is whether the finite theorem’s \(2\)-approximation and incentive guarantees survive directly for rational mass inputs, without expanding them into a population whose size may be exponential in \(L\). This case covers Theorem 9’s makespan mechanism result; it does not attempt to mirror the fairness result or the paper’s full general reduction.

The weakest point is the model change around Bayesian uncertainty. In the paper, each named machine has a distribution over types; in the mirror, a negligible machine faces a fixed aggregate type mass, and job supplies scale with the population. That changes the mechanism’s information structure. The case survives because the objective, strategic machines, truthfulness constraints, and integral per-machine schedules remain recognizable, while the mass proportions give a precise high-multiplicity regime for the same scheduling problem.

The case AGAINST (opponent, writing after the proponent)

Theorem 9 is a real computational anchor: it gives a polynomial-time approximation guarantee for a named mechanism-design problem. The strongest negative point is that its computational object is a finite mechanism over \(k\) named machines. Each machine has a private type, and the mechanism must produce a feasible global schedule. A literal limit in the number of machines, with the job set fixed, would leave most machines idle and make that limit uninformative.

But the proposed mirror repairs that problem by scaling repeated task supplies with the fleet. That is a substantial modeling choice, yet it is exactly the kind of co-modification the programme allows. The resulting model still has strategic machines, private processing costs, truthful reporting, integral per-machine bundles, and a makespan objective. A large fleet handling recurring workload is a plausible high-multiplicity regime. Nor does the fixed number of task classes seem essential: one can use a repeated workload template with distinct job classes and preserve unrelated processing times across classes.

There is a genuine formal burden around feasibility. In the finite paper, the mechanism must output a feasible schedule for every report profile. In an atomless population, a single deviation changes no aggregate mass, so a mass model must specify how allocations remain feasible under report deviations and how its allocation rule can be implemented. Defining feasibility only at the truthful mass profile would leave that part of the mechanism underspecified. A finite-population approximation followed by a carefully defined limit could address it, though, so this is a modeling task rather than a fundamental obstruction.

I cannot make the negative case persuasive on the available grounds. The repaired mirror is well-posed enough to ask, and its configuration-LP pricing question gives it a plausible computational payoff. The main weakness is that the paper’s theorem does not itself supply the continuous model or guarantee that its approximation and incentive bounds survive the limit. That makes the result uncertain, not the question unworthy.
