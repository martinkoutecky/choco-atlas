The case AGAINST (opponent, writing after the proponent)

The case against a mirror of this paper is strongest at the programme’s entry gate: it names no computational result to mirror. Theorem 4.1 characterizes an allocation rule; Theorems 5.1 and 5.2 prove incentive properties under restrictions on the cost domain and compensation function. None studies the complexity of a computational problem. The introduction’s polynomial-time statement concerns finding an MCST, cited as background, not computing or classifying these induced rules. So the proponent has raised no qualifying anchor, and there is no named result for a continuous question to inherit.

The best rescue would be to ask how hard it is to compute an induced allocation from an edge-cost instance. For the paper’s explicit rules, that looks thin: find the tree using a standard polynomial-time algorithm, then evaluate the formula in Theorem 4.1. For an arbitrary base rule, the paper gives no finite input representation or computational assumptions for its compensation function, so its complexity is not defined. A more substantial question—say, testing merge-proofness across all instances—would need a new encoding and problem formulation. That might be a research project, but it would be one built from the paper’s setting, not a continuous mirror of a computational result in the paper.

There is also a real obstacle to carrying the paper’s main domain directly into a high-multiplicity regime. Its key theorems use a unique MCST, and Theorem 5.1 further requires all tree-edge costs to be distinct. Agents with identical complete cost descriptions are symmetric. Swapping two such agents preserves costs; uniqueness would then require the tree to be invariant under their swap, which is incompatible with a tree using distinct edge costs for both. Breaking the symmetry with individual cost perturbations restores the paper’s assumptions but can make the number of types grow with the population. One could extend the rules to handle tied trees, but that requires new definitions and proofs rather than simply replacing counts by masses.

That is a case against *this paper* as a direct ChoCo anchor, not against every possible continuous-population MCST problem. A symmetric high-multiplicity network model could be sensible, and existing high-multiplicity work would support that regime rather than count against it. Nor does the paper establish that such a model would be uninteresting. The honest negative conclusion is narrower: the article offers allocation characterizations and stability results, while a computational mirror requires a computational question the article does not pose. A blanket claim that no scenario could ever be worthwhile would go beyond the evidence.
