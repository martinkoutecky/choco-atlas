The continuous mirror question

Given a finite type set \(T\), positive rational masses \(\mu_t\) summing to \(1\), and a directed relation \(E\subseteq T\times T\) describing which type classes give feedback to which others, compute a total preorder \(\succeq\) on \(T\). For each target type \(u\), let \(\rho_u(t)=\mu_t\) when \((t,u)\in E\), and \(0\) otherwise. Require that whenever there is a transport \(\pi_{y,x}\ge 0\) from \(v\)'s supporter mass to \(u\)'s supporter mass, with \(\sum_x\pi_{y,x}=\rho_v(y)\), \(\sum_y\pi_{y,x}\le \rho_u(x)\), and \(\pi_{y,x}>0\) only when \(x\succeq y\), then \(u\succ v\) if the transport leaves some of \(u\)'s supporter mass unused or sends positive mass to a strictly higher-ranked type. The computational question is whether such a ranking can be found for every instance in time polynomial in \(|T|\) and the input bit length.

The model it lives in

A finite population of feedback types carries rational mass \(\mu\), with a class-level directed feedback relation \(E\). The decision variable is a total preorder on types, with mass-transport certificates expressing the paper’s supporter-set comparison; the task is to find any preorder satisfying mass-Transitivity on every instance, with no separate optimization objective.

The mirror covers Theorem 2’s positive-feedback construction for satisfying Generality and Transitivity while relaxing Weak Monotonicity. It leaves the impossibility results and the negative-feedback, mixed-feedback, and strong-connectivity variants outside the proposed question.

The case FOR (proponent)

My lead is a continuous, weighted version of the construction in Theorem 2. The paper’s main results are axiomatic impossibility and possibility results; it gives no named NP-hardness or other standard complexity result. Theorem 2 is the computational foothold: proved in this paper, it says that any pair of Generality, Transitivity, and Weak Monotonicity can be satisfied. I rely on the pair Generality and Transitivity. For every positive-feedback graph, the paper’s algorithm constructs a ranking satisfying both: it starts by ranking nodes by the size of their supporter sets, then repeatedly refines ties to enforce Transitivity. It terminates after at most \(O(|V|)\) refinement rounds. The proof in the paper is a sketch, with formal details deferred.

Here is the mirror I would hand to a prover: Mass-Transitive Reputation Ranking. An instance consists of a finite set \(T\) of types, positive rational masses \(\mu_t\) summing to \(1\), and a positive-feedback relation \(E\subseteq T\times T\), with no self-loops. Every member of type \(t\) gives feedback to every member of type \(u\) exactly when \((t,u)\in E\). The output is a total preorder \(\succeq\) on \(T\), extended to all agents by ranking members of the same type together. The question is whether one can compute such a ranking that satisfies Generality and Transitivity for every instance.

For a target type \(u\), its supporter mass from type \(t\) is \(\rho_u(t)=\mu_t\) if \((t,u)\in E\), and \(0\) otherwise. Say \(u\)’s support is more important than \(v\)’s if there is a mass transport from all the supporter mass of \(v\) into available supporter mass of \(u\), matching each source type \(y\) only to a type \(x\succeq y\), and either leaving some of \(u\)’s supporter mass unused or sending positive mass to strictly higher-ranked types. Transitivity requires \(u\succ v\) whenever \(u\)’s support is more important than \(v\)’s. The solution is the ranking itself; there is no separate optimization objective. Weak Monotonicity is deliberately not required, matching the pair of axioms used from Theorem 2.

The regime is a large, replicated reputation system: for example, a platform with many accounts or pages in a modest number of standardized classes, where members of each class use the same feedback policy toward each other class. Mass is the fraction of accounts or pages in each class. The population \(N\) can be very large while the number of distinct types \(\tau=|T|\) stays modest. With rational masses, one can view the instance as a high-multiplicity sequence of finite block graphs whose class proportions stay fixed. This preserves the paper’s central mechanics—agents assess agents, supporters’ ranks affect a target’s rank, and the output ranks the agents—while replacing unit-by-unit matching with a mass transport.

I expect this mirror to be tractable: adapt the paper’s tie-refinement algorithm, comparing supporter masses through capacitated matching or ordered cumulative masses. There are at most \(\tau\) rounds that split ranking ties, and the comparisons involve rational capacities, so a \(\mathrm{poly}(\tau,L)\) algorithm looks plausible. That bound is a prediction for the continuous problem, not a result proved by Theorem 2: the prover must establish that weighted refinements preserve the consistency argument and give a bit-complexity bound. It also raises useful follow-ups: can Weak Monotonicity be retained on meaningful graph classes, and do the negative-feedback and mixed-feedback constructions admit the same mass-based treatment?

The mirror is plausible because it follows the exact problem Theorem 2 computes on: ranking reputation nodes from recursively compared supporter sets. Treating identical agents as a type is precisely the high-multiplicity regime, and fractional supporter mass is the natural extension of the paper’s supporter-set comparison. I would not use Theorems 1 or 3–5 as additional anchors: they are axiomatic impossibility claims, and continuizing those claims would leave the programme’s computational scope.

The weak point is the regime’s structure. Requiring everyone in a type to share the same class-level feedback pattern can be a strong assumption for real reputation networks. If one must refine types until each individual has a distinct neighborhood, \(\tau\) may approach \(N\), and the high-multiplicity advantage disappears. I still think this is a defensible, narrower mirror: templated pages, platform-defined classes, or replicated institutions can make class-level feedback patterns meaningful, and Theorem 2 gives a concrete algorithmic question for that regime.

The case AGAINST (opponent, writing after the proponent)

The only plausible anchor is Theorem 2. It proves that a ranking satisfying Generality and Transitivity exists, and gives an iterative refinement procedure for constructing one. It does not state a complexity result for a named computational problem. That leaves a possible mirror, but most of its computational motivation would have to come from the new model itself.

For the proposed type model, the computational task looks like a direct weighted version of that procedure. Once the types are ranked, comparing two support sets amounts to checking whether one distribution of supporter mass can be matched to the other in rank order. With finitely many types, that can be checked by a small flow computation or by comparing cumulative masses across rank classes. Each refinement splits a tie, so there can be at most \(\tau\) rounds; the arithmetic on rational masses is polynomial in \(\tau\) and \(L\). Rational masses also describe normalized blow-ups of finite block graphs. This makes the mirror a credible high-multiplicity problem, but suggests its answer is a straightforward tractability result, without an optimization barrier or an unresolved algorithmic boundary for the programme to map.

There is a regime tradeoff. In sparse, identity-specific systems such as page links or transaction feedback, faithfully encoding each agent’s incoming and outgoing relationships can leave few repeated types. If instead one normalizes each agent’s supporter count by population size, bounded-size support sets tend toward zero mass, making the comparison vacuous. A nondegenerate model with few types needs many agents to share a class-level interaction pattern, often giving every member of one class feedback about every member of another. That can describe some cohort-based systems, but it is a restrictive dense block structure for the paper’s examples.

A more general kernel over agent types could represent finer variation in feedback. If the kernel has a finite-step description, the problem returns to the weighted type quotient. If it is an arbitrary measurable object, the paper supplies no finite input representation or computational task to solve. Random link kernels would also change the input from a reputation graph to uncertainty about one.

So the strongest negative case is about payoff, not well-posedness: the class-based mirror is coherent, and the high-multiplicity regime is evidence in its favor. Theorem 2’s construction makes a short, likely easy algorithmic extension plausible. If the programme considers such an extension worthwhile, I cannot honestly rule the mirror out; my case against it is weak at that point.
