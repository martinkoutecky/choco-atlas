The case for says it finds no eligible anchor. That is the strongest point against a continuous mirror: this poster reports no named computational result whose complexity could be carried into a population model. It proposes two kinds of query feedback and describes a pilot study with four users. It gives no formal problem definition with an algorithmic guarantee, hardness result, or complexity analysis. A continuous version could be invented, but it would not mirror a computational result established by this paper.

The best candidate is computing a minimal conflicting set of constraints or suggestions for relaxing one. A high-volume recommendation service could have many users with identical query states, so a population of user types is plausible. But each type’s diagnostic is determined by that query and the finite catalog. Assigning the type a mass lets the system count how many users share the query; it does not change which constraints conflict or which relaxations restore matches. The computation remains one query at a time, with repeated queries reusable. To make mass affect the answer, one would need a shared objective—such as choosing one relaxation policy to serve a target fraction of users. That is a new pooled service-design problem, not a computational result or objective in this paper.

The pilot study offers no stronger anchor. Aggregating confidence or interaction-time measurements across a larger user population would be an empirical study of user responses. The paper reports preliminary observations, not a computational problem about that population. Treating catalog items as the continuum would put continuity in the outcome space, while modeling users’ changing sessions would center the interaction process; neither supplies the population-level computational question the programme targets.

A large population of similar recommendation users is therefore conceivable, and a new collective service problem built around them might be worthwhile. That is the honest opening in the negative case. It does not rescue a mirror of this paper: the paper’s computational suggestions are per-query features, and its results are pilot observations.
