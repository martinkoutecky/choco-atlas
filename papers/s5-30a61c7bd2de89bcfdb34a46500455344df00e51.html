The case FOR (proponent)

I cannot make an honest ChoCo-positive case from this paper: it contains no named computational result to anchor a mirror. Theorem 12, proved here, says that if \(D\in\mathcal{D}^{\mathrm{PT}}\cap\mathcal{D}^{\mathrm{DT}}\), then every unanimous IIA social welfare function on \(D\) is dictatorial. Theorem 3, also proved here, establishes equivalence between Arrow-inconsistency and the paper’s chromatic simplicial-map formulation. Both are axiomatic results; neither classifies an algorithmic problem by complexity or gives an algorithm or hardness result. The simplicial maps are a representation used in the proof, not a computational problem the paper solves.

One can imagine a population mirror with types equal to strict rankings and mass \(\mu_r\) on each ranking, asking whether a social ranking rule on such distributions can satisfy unanimity and IIA without being dictatorial. That would continuize the population, but it remains an axiomatic question. It also requires choices about what dictatorship means for a continuum, and the paper gives no computational anchor for those choices. Under the programme’s scope, it is an angle to note in prose, not a defensible continuous computational mirror.

The weakest point is decisive: the required kind of anchor is absent. There is consequently no per-anchor continuous problem here that I can responsibly hand to a prover.

The case AGAINST (opponent, writing after the proponent)

The paper’s decisive weakness as a ChoCo mirror is that it proves no computational result. Theorem 1 is Arrow’s axiomatic impossibility theorem; Theorem 3 shows that a topological representation is equivalent to the classical one; Theorem 12 extends the impossibility to a class of domains. The simplicial maps and the \(2\)-skeleton are proof machinery. None of these results classifies an algorithmic problem, gives an algorithm, or proves computational hardness. So the proponent’s named theorems do not provide computational anchors.

The strongest population version would take rankings as types and represent a society by masses over them, then ask whether a unanimous IIA social welfare function can be non-dictatorial. That is a coherent continuous axiomatic question, but it still asks which rules exist, not how hard a computational task is. To turn it into a complexity problem, one would need to specify a finite input for the rule or domain and an algorithmic task—perhaps deciding Arrow-consistency for an encoded domain. Such a project could be interesting, but it would introduce the computational question rather than mirror a result in this paper. If the rules are encoded as circuits, for example, the complexity would depend on that additional model.

There is also a modeling wrinkle: the conclusion identifies a particular voter as dictator. A distribution over rankings records how much mass has each ranking, but not which person is the dictator; in an atomless society, an individual has zero mass. A mass-level version would need to restate dictatorship or add information about individuals. That does not by itself rule out a recognizable mirror, but even after resolving it, the result would remain axiomatic and outside the programme’s computational scope.

The negative case is therefore strong for this paper, though it is not a proof that no related continuous computational question could ever be worthwhile. Large electorates with repeated rankings are a sensible high-multiplicity regime, and studying the complexity of recognizing Arrow-consistent domains could be a new direction. It is simply not a computational result—or a computational problem—the paper supplies.
