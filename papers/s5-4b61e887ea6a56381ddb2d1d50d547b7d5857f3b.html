What the mirror covers

Proposition 2 is the only computational candidate; the paper's allocation properties, axiomatic characterizations, and equivalences among rules are not computational results.

The case FOR (proponent)

The strongest positive case is a plausible high-multiplicity setting: a utility network serving many customers grouped by standardized service-location and connection-cost profiles. A type would be a complete cost profile, and \(\mu_t\) the fraction of customers in that class. A network would connect the source to the occupied types, with each edge built once; type-level charges could then be divided among the mass of customers in that type. The paper’s towns, villages, power and water examples make that setting recognizable as cost sharing in a spanning-tree problem, though treating a class as one service node is a substantive model choice.

But the paper has no named computational-complexity result to anchor a ChoCo mirror. Proposition 2 gives a construction of the canonical matrix, while Theorem 1 lists allocation properties, Theorem 2 characterizes a rule axiomatically, and Theorem 3 equates several cost-allocation rules. None asserts that an underlying computational problem is in P, NP-hard, or has another complexity classification; in Theorem 3, \(P\) denotes the P-value. So I can’t give the required per-anchor computational problem without inventing an anchor. The possible utility-network model is a lead for a new question, not a continuous mirror of a named computational result in this paper.

The case AGAINST (opponent, writing after the proponent)

The proponent’s utility-network setting is plausible: many customers can share standardized location and connection-cost profiles, and the paper itself motivates cost spanning trees with towns and villages. I would not reject that setting just because high multiplicity is possible or because related high-multiplicity work exists. The problem is that it does not supply a result to mirror.

The paper’s numbered results concern canonical matrices, allocation properties, axiomatic characterizations, and equivalence among rules. None gives a complexity classification for a computational problem. Proposition 2’s canonicalization procedure is the closest candidate, but the paper does not claim a running-time result for it. Theorem 3’s \(P\) is the P-value, not polynomial time. So the proponent’s actual anchor is the absence of a computational result, rather than a named result with a continuous question attached.

The strongest repair would be to put a distribution \(\mu\) over customer types and ask for the canonical form or the rule’s allocation. If a type is represented by one network node and mass only divides that type’s charge, \(\mu\) does not enter the canonical form or the paper’s allocation theorems. If instead each type represents many network terminals, pairwise costs and network structure must be specified for those terminals; that defines a new input family. Studying its complexity could be worthwhile, but it would be a new computational result, not a mirror of one established here.

So the negative case is strong for the paper-as-written: its contribution is cost-sharing theory, not computational complexity, and a continuous cost-sharing model would need its own computational question and results. I cannot honestly rule out every worthwhile continuous project in this area; the proposed setting may support one. The weaker point is whether such a new project deserves ChoCo’s time, rather than whether this paper provides a computational mirror for it.
