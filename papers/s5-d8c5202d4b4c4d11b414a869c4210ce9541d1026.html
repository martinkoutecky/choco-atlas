What the mirror covers

The proposed construction targets Theorem 2’s feasibility and construction result across workflow types; it leaves Theorem 1’s single-mechanism structural result and the paper’s responsibility definitions and variants outside the mirror.

The case FOR (proponent)

The strongest honest case is a high-multiplicity deployment version of Theorem 2. This paper has no named hardness result to anchor a “does hardness dissolve?” question; its computational anchor is tractability.

Theorem 2, proved in this paper, says that for any finite decision mechanism \(M\) and integer \(k\ge 1\), one can decide in polynomial time whether there is a structurally equivalent mechanism that ensures \(k\)-oversight, and construct such a mechanism when one exists. Structurally equivalent mechanisms keep the same nodes, edges, initial nodes, and harmful sinks; the control of decision nodes is what gets redistributed. \(k\)-oversight means that at least \(k\) distinct agents are responsible along every path from an initial node to a harmful sink.

A plausible regime is a large fleet of independently operating, standardized multi-agent decision workflows: for example, many copies of an AI-supported safety or approval process. The workflow copies are the population. A type \(t\) specifies the complete mechanism—its graph, initial and harmful nodes, and control permissions—so two copies of a type are interchangeable for this design question. It is plausible to have millions of workflow instances but only a small support of recurring designs. Mass \(\mu_t\) is the fraction of the fleet with workflow type \(t\). This fits the paper’s stated concern with trustworthy multi-agent systems, though it places multiplicity across workflow instances rather than inside one mechanism.

Call the resulting problem High-Multiplicity Peer-Oversight Coverage, for a fixed \(k\). An instance consists of finitely many workflow types \(t\), rational masses \(\mu_t\ge 0\) summing to \(1\), and the mechanism for each type. Let \(\Pi_t^k\) be the set of control allocations that preserve type \(t\)’s mechanism structure and give it \(k\)-oversight under the paper’s responsibility definitions. Choose \(x_{t,\pi}\ge 0\), the mass of type-\(t\) workflows assigned allocation \(\pi\), subject to \(\sum_{\pi\in\Pi_t^k}x_{t,\pi}\le\mu_t\). The objective is to maximize \(\sum_t\sum_{\pi\in\Pi_t^k}x_{t,\pi}\): the largest fraction of the fleet that can be redesigned to achieve \(k\)-oversight. A solution gives those mass allocations and a witnessing control assignment for each one. The decision version asks whether the optimum is \(1\), meaning the entire fleet can receive oversight.

I expect this mirror to be tractable. Run Theorem 2 on each supported mechanism type: if a type admits a \(k\)-oversight allocation, assign all its mass to a witness; otherwise none of its mass is coverable. Thus the optimum is the total mass of feasible types, computable in time polynomial in the explicit supported graphs, the support size, and the input bit lengths. The continuum is over workflow mass; each workflow still receives an ordinary discrete control allocation, and responsibility is still evaluated path by path. This is not a fractional-agent reinterpretation of the authors’ definition.

The authors could plausibly recognize this as their mechanism-redesign problem in a high-multiplicity deployment regime: the unit-level question and the action being redesigned are unchanged, while mass summarizes repeated identical units. The main weakness is also the boundary of the case: the paper studies redistribution *within one mechanism*, while this mirror distributes mass *across many mechanisms*. If the programme requires the continuous population to be the decision-makers inside a single mechanism, this is a weak fit. It is strongest as a batch deployment mirror, not as evidence that fractional control agents or continuous paths belong in their model.

A natural next question is what happens when workflow types compete for a shared controller pool or redesign budget. That would couple the per-type decisions and create a less immediate continuous optimization problem, but it goes beyond Theorem 2’s stated result.

The case AGAINST (opponent, writing after the proponent)

Theorem 2 is the paper’s computational anchor. It takes one finite graph \(M=(V,E,Q,H)\) and asks whether its decision nodes can be repartitioned among agents so every harmful path has at least \(k\) responsible agents. The agents are not interchangeable voters whose frequencies describe the input: each agent’s strategic power comes from the particular set of nodes they control, and responsibility counts distinct agents along each path. For a fixed graph, at most \(|V\setminus Sink|\) agents can have nonempty control sets. Adding a continuum of people around that mechanism adds no continuum of decision-makers.

The proponent’s fleet construction gets multiplicity by making whole workflows the units. But then a “type” is an entire mechanism, not an agent type, and the objective asks what fraction of a portfolio of separate systems can be redesigned. Applying Theorem 2 to each supported graph is a sensible deployment calculation; it is not a continuous-population version of the paper’s question about responsibility within a mechanism. The typewise check is not itself a reason to reject the mirror because its answer is easy. The issue is that workflow mass sits outside the object whose oversight the theorem defines.

A stronger attempt would put many interchangeable controllers inside one large mechanism and require a positive fraction of them to be responsible on every harmful path. That runs into the model’s pathwise, identity-based structure. A controller’s complete type must include its full set of controlled nodes, since its strategy coordinates choices across that set. But control sets are disjoint, so repeated agents with the same exact role cannot simply be added to a fixed mechanism. If types instead describe local roles, their masses omit which nodes lie together on which paths—the information that determines responsibility. And in a fixed finite graph, only finitely many agents can be responsible on any path; an atomless population gives that finite set measure zero. Avoiding that degeneration requires scaling and restructuring the graph along with the population, which is a new mechanism model rather than a continuization of the theorem’s input.

That leaves a real but narrower opening: a large, structured mechanism family might support a useful density-of-oversight question. I cannot rule out that a formulation of it would be worthwhile. But the proposed fleet mirror does not establish one, and the paper’s results provide no natural agent-type population over which to pose it. The negative case is strongest against this anchor and weaker as a universal claim about every possible scaled-up mechanism.
