The case FOR (proponent)

I can’t make a qualifying anchored case from this paper: it has no numbered result about computational complexity. Theorem 1 says the induced finite cost game is balanced when an efficient network has the same number of components as the demand graph. Theorem 2 says it is balanced when the demand graph has at most two components. Those are structural existence results, not claims that a problem is in P, NP-hard, or otherwise computationally classified. The introduction’s statement that finding an MCCN is NP-hard cites the earlier Steiner tree result; it is not a numbered result of this paper. Under your anchor rule, there are no eligible anchors.

There is a plausible continuous model behind the paper. Think of many users of a data-center network, with each user requesting a connection between a pair of locations. A type is that pair; \(\mu_t\) is its share of the users; and the number of distinct demanded pairs \(\tau\) can be small compared with the population. Given rational edge costs, ask for a minimum-cost network and per-user type charges \(r_t\) such that total charges equal the network cost and every coalition with mass vector \(0\leq\nu\leq\mu\) pays at most the minimum cost of connecting the types represented in that coalition. This is recognizably the paper’s cost-sharing and core-stability question, and its data-center traffic examples make the scenario credible. Theorem 2 is relevant background for this model, but it does not establish a computational result for it.

The soft spot is that, with congestion-free costs, a coalition’s network cost depends on which demand types it contains, not on how much mass each type contributes. So the continuous version may largely lift the finite type game rather than create a new complexity landscape. I would offer that as a plausible mirror, but not as a result anchored to a qualifying theorem in this paper.

The case AGAINST (opponent, writing after the proponent)

There is no computational result in this paper for a continuous mirror to anchor to. Theorem 1 and Theorem 2 are structural balancedness results: they give conditions under which a finite cost game has a nonempty core. The paper’s statement that finding an MCCN is NP-hard cites earlier work; it is not a complexity result proved here. One could turn core computation into an algorithmic follow-up, but that would add a computational question the paper does not study.

The data-center scenario is the strongest proposed mirror, but the population measure drops out of its model. Let \(T\) be the positive support of demand types, \(\mu_t\) each type’s mass, and \(r_t\) its per-unit charge. A coalition with mass vector \(\nu\) costs \(c(\operatorname{supp}\nu)\): under the paper’s congestion-free network costs, even a tiny positive mass creates the same connection demand as the whole type. Core allocations have nonnegative type charges, so for each support \(S\), the tightest coalition constraint uses all available mass of each type. Setting \(y_t=\mu_t r_t\), the constraints reduce to
\[ \sum_{t\in S} y_t\le c(S),\qquad \sum_{t\in T}y_t=c(T). \]
Those are just the finite core constraints over the support types. The masses affect the per-unit presentation of charges, but not the stability question or network cost. The continuum is therefore a reparameterization of the finite type game, not a population-dependent computational problem.

A more promising version would make edge costs depend on traffic volume or capacity. But that changes the paper’s fixed, congestion-free cost structure; it is a different network-design problem, not a co-modification forced by replacing the population with a continuum. So the paper offers no qualifying computational anchor, and its best continuous reinterpretation loses the population variable that ChoCo is meant to continuize. This is a strong case against a ChoCo mirror of this paper, though it cannot rule out a worthwhile adjacent project on algorithms for finite-support core computation.
