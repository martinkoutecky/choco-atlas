The continuous mirror question

Given a finite tuple catalog \(X\) and a finite support of user types \(T'\), each with positive rational mass \(\mu_t\) summing to \(1\) and a complete revision profile \((P_t,Q_t)\) of compatible SPOs, at least one having the single-chain property, find an SPO refinement \(R_t\) for each type that minimizes \(\sum_{t\in T'}\mu_t|R_t\setminus P_t|\), subject to \(P_t\cup Q_t\subseteq R_t\).

The model it lives in

Types are groups of users with the same old and new preference relations on \(X\). Each type receives its own revised relation \(R_t\); the objective is the mass-weighted number of added comparisons, \(\sum_t\mu_t|R_t\setminus P_t|\).

What the mirror covers

The mirror covers the least-SPO-refinement construction of Theorem 3.1, with Proposition 3.1 supporting computability for equality and rational-order formulas. It leaves the other overriding-revision and weak-order results, as well as symbolic infinite-domain complexity, aside.

The case FOR (proponent)

The strongest honest mirror is a narrow batch version of the paper’s least SPO refinement problem. The paper has no named NP-hardness, P, or parameterized-complexity result. My anchor is Theorem 3.1, proved in the paper with a sketched proof: for compatible preference relations \(\succ\) and \(\succ_0\), both strict partial orders and with at least one having the single-chain property, \(TC(\succ\cup\succ_0)\) is the least strict partial order refinement of \(\succ\) with \(\succ_0\). The paper’s Proposition 3.1 supplies computational support: for relations defined by equality or rational-order intrinsic preference formulas, computing \(TC(\succ\cup\succ_0)\) and \(TC(\succ\rhd\succ_0)\) terminates; the paper attributes this to Constraint Datalog techniques. Neither result gives a running-time bound.

Call the mirror Mass-Weighted Least SPO Refinement. Fix a finite catalog \(X\) of database tuples. An instance is a finite support \(T'\) of user types with positive binary-rational masses \(\mu_t\) summing to \(1\). Each type \(t\) specifies a complete revision profile \((P_t,Q_t)\): the user’s old preference relation and the new preference information, both explicitly given as relations on \(X\). Require that both are SPOs, are compatible, and that at least one has the single-chain property. A type is thus a group of users indistinguishable for this task: they have the same catalog and the same old and new preferences. The question is to return an SPO \(R_t\) for every supported type, with \(P_t\cup Q_t\subseteq R_t\), minimizing
\[ \sum_{t\in T'} \mu_t\,|R_t\setminus P_t|. \]
Because these are refinements, the number of added comparisons is exactly the symmetric-difference change from the old relation. A solution is the list of revised relations, one per type. Theorem 3.1 gives \(R_t=TC(P_t\cup Q_t)\) for each type and guarantees it is the least feasible refinement.

A plausible regime is a large product or travel platform whose users revise saved preference queries after a shared update. Millions of users might use a few dozen standard preference profiles and receive one of a small number of updates, so the number of users \(N\) is much larger than the number of distinct revision types \(\tau=|T'|\). Each person still gets a complete relation; mass records the share of users receiving that profile. For \(n_t\) discrete users of type \(t\), the same objective is the total number of added comparisons divided by \(N=\sum_t n_t\). This is a direct high-multiplicity batch interpretation, and the paper’s motivating database-user scenario makes it plausible that its authors would recognize the underlying revision task.

For the stated finite, explicit representation, the mirror is tractable: compute a transitive closure per type, in polynomial time in \(\tau\) and \(|X|\), then evaluate the rational-weighted objective. This is a consequence of the mirror’s finite encoding and Theorem 3.1’s construction, not a polynomial-time claim made by the paper. The scope is just this least-SPO-refinement slice; it says nothing about all the paper’s overriding revisions, weak-order results, or symbolic infinite-domain inputs.

The weak point is substantial: types are revised independently, so the masses weight the reported cost but do not couple the decisions. Continuization therefore compresses a batch of repeated user revisions; it does not reveal a new optimization phenomenon or show that discrete hardness dissolves. I would present this as a faithful, modest mirror for one constructive result, not as a major computational-complexity contribution.

The case AGAINST (opponent, writing after the proponent)

The paper’s main results do not give a computational complexity result. Theorem 3.1 characterizes the least SPO refinement; Proposition 3.1 says that certain transitive-closure computations terminate using Constraint Datalog. Neither states a complexity bound for a revision problem. The proposed mirror therefore starts from a structural characterization and adds a batch-computation question.

A large platform could plausibly have many users sharing the same old and new preference relations, so the proposed type space is sensible. But under Theorem 3.1’s conditions, every type’s revised relation is already fixed: \(R_t=TC(P_t\cup Q_t)\). For explicit relations on a finite catalog \(X\), compute one graph transitive closure per type, in \(O(\tau |X|^3)\) time, then sum the rational weights. The masses affect the reported aggregate cost, but they cannot affect any revision or trade one type’s result against another’s. Leastness makes the weighted objective select the same closure for every type regardless of the weights. This is a valid batch interpretation; its population distribution is bookkeeping around independent jobs, not a computational object the revision problem uses.

A closer population-level extension would count what fraction of users retain each tuple under winnow after their revisions. That still runs the closure and query for each type, then adds the masses. To make population mass shape the decision, one could instead require a shared revised relation, a consensus, or a quota on collective query outcomes. Those could be worthwhile new problems, but they add an aggregation rule or a cross-user constraint absent from the paper’s model of revising one preference relation. Theorem 3.1 would then supply, at most, a per-type subroutine; it would not anchor the new optimization question.

The paper’s symbolic, potentially infinite tuple domains do not rescue the population axis. With finitely many supported user types, the masses still only weight outputs; any harder computation comes from the symbolic relation language and its closure procedure. Giving a continuum of user types a compact parametric description could make integration or representation complexity interesting, but that complexity would come from a new encoding of the type distribution.

So the strongest case against is that the only paper-faithful mirror is a plausible but thin batching exercise: the paper has no complexity theorem to transfer, and the proposed continuous population does not couple or alter the revision decisions. The universal claim remains the weak point. A richer platform-wide revision problem might be worth studying, but it would need new collective structure before it becomes a meaningful ChoCo mirror of this paper.
