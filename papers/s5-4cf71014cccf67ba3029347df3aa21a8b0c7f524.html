The case FOR (proponent)

I can’t make a qualifying computational case from this paper: it contains no numbered result asserting that a problem is in P, NP-hard, FPT, or otherwise computationally classified. Theorem 1, proved here, is the closest result: the set \(C\) of corewise-stable payoffs is nonempty if and only if it equals \(S^*\), the set of Pareto-optimal payoffs among tradewise-stable outcomes. Thus optimal t-stability always supplies outcomes, and it coincides with the core when the core exists. That is a structural existence result, not an algorithm or complexity result. Theorem 3 also characterizes when the core is empty, but gives no computational analysis. There is therefore no eligible anchor for a ChoCo complexity mirror, and no A/B/C prediction to make from this paper.

There is a plausible high-multiplicity analytic analogue. Take a large market of firms forming pairwise R&D partnerships, with many firms in a few capability classes. A type \(\theta\) would specify a firm’s full surplus profile \(a_{\theta\eta}\) against every type \(\eta\), and \(\mu_\theta\) would be that type’s population mass. A continuum outcome could be a measurable matching of agents, with each matched pair’s payoffs summing to its surplus and unmatched agents receiving zero. T-stability would require that no matched agent can form a blocking pair with anyone else. One could then ask whether the Pareto-maximal t-stable outcomes coincide with the pairwise-stable, core-type outcomes whenever those exist—the continuum counterpart suggested by Theorem 1.

That scenario is credible as a population limit: a large pool of firms can contain many firms with the same partnership opportunities, and the number of firms can greatly exceed the number of types. But it would be a new analytic question, not a mirror of a computational result in this paper. Its weakest modeling point is that firms of one type may receive different payoffs because they partner with different types or negotiate different splits. A single payoff \(u_\theta\) per type would erase that variation, so the continuum model would need to retain payoff variation within types. That is manageable, but it reinforces why the paper’s results do not provide the computational anchor the programme requires.

The case AGAINST (opponent, writing after the proponent)

The strongest case against a ChoCo mirror is that the paper supplies no computational result to mirror. Theorem 1 says that \(S^*=C\) exactly when the core is nonempty; Theorem 3 characterizes an empty core through non-solvable blocking pairs. Both are structural results. Section 5 also expressly says its partnership formation process is not an algorithm for finding optimal t-stable outcomes. None of these results classifies the complexity of a decision, search, approximation, or parameterized problem.

The proponent’s firm-types scenario is plausible as a high-multiplicity market, and retaining payoff variation within types is a reasonable modeling choice. Its proposed analogue of Theorem 1 is still an analytic existence question about whether a continuum version preserves the relationship between t-stability and the core. That may be interesting matching theory, but it does not add the computational axis ChoCo is meant to study.

One could pose a stronger computational question: given rational masses on firm types and a surplus matrix between types, decide whether a core exists or compute an optimal t-stable outcome. That is well-posed, but it adds an algorithmic task the paper neither states nor analyzes. Theorem 1 does not anchor its complexity; it supplies a structural equivalence that such a new study could use. Theorem 3 has the same limitation.

So the negative case is strong for this paper under ChoCo’s stated remit: its natural continuous analogue is analytic, while a computational version would be a new project rather than a mirror of a result here. The universal claim remains less secure: a researcher could reasonably find that new computational project worthwhile, even though the paper itself gives no computational anchor for it.
