The case FOR (proponent)

There are no eligible computational anchors in the paper as supplied. It has numbered definitions, including Definition 2.3’s Shapley value, and named algorithms for exact enumeration, sampling, and clustering. But it has no numbered theorem, lemma, corollary, or proposition asserting a complexity result. The claim that exact computation becomes infeasible above 25 customers is descriptive, and the runtime and accuracy findings are empirical. They cannot serve as the required result anchors.

There is a plausible population regime: many residential meters represented by a modest number of complete load-profile types, with mass recording each type’s share. One could define coalition costs from the aggregate load profiles and the paper’s probabilistic Turvey calculation. But extending this to a continuous allocation requires specifying how Shapley shares behave for infinitesimal customers; replacing them with an Aumann–Shapley allocation would change the solution concept unless a convergence result justified it. The paper supplies no such result.

So that is a possible new research direction, but I cannot honestly present it as a continuous mirror anchored in this paper’s named computational results.

The case AGAINST (opponent, writing after the proponent)

The strongest negative case is about fit. The paper supplies no named computational result to mirror. Definition 2.3 defines the Shapley value, and the Exact, Sampling, and Clustering sections describe algorithms. The claim that exact computation becomes infeasible above 25 customers is descriptive; the runtime and error claims are empirical. None is a numbered complexity result. The other analyst raised no eligible result anchor, so there is no anchor to defeat.

The best candidate mirror is still plausible: represent customers by complete load-profile types, give each type its population share, and define coalition cost from the aggregate profile using the Turvey calculation. A proper continuum version would use a limit of finite Shapley allocations, or a corresponding mass-allocation rule. For a differentiable cost \(w\) on type masses \(\mu\), the limiting allocation to type \(t\) has the form
\[ \Phi_t=\int_0^1 \mu_t\,\partial_t w(\lambda\mu)\,d\lambda. \]
For the paper’s aggregate peak model, write \(D(z)=\max_r\sum_t z_t\ell_{t,r}\), where \(\ell_{t,r}\) is type \(t\)’s load at interval \(r\), and let \(w(z)=g(D(z))\). With a unique peak interval, the limit allocation to each type is proportional to its load at the grand coalition’s peak. As the population grows with fixed type shares, random predecessor coalitions concentrate around the same proportional path \(\lambda\mu\). The finite coalition variation that drives the paper’s exponential enumeration therefore disappears in this limit.

That is a real degeneracy in the paper’s central computation: the continuum allocation reduces to evaluating a profile and a one-dimensional path integral, rather than classifying a difficult coalition computation. A richer network model could restore complexity, but adding network optimization or battery dispatch would pose a new problem beyond the cost function studied here.

This is a strong reason to doubt that this paper offers a complexity mirror for ChoCo. It does not establish the universal claim that no worthwhile mirror exists. A discrete-to-continuous convergence result for this cost allocation could itself be useful, and the authors might recognize it as their problem. The honest negative case is therefore weaker than the requested universal conclusion: the paper lacks an eligible result anchor, while its strongest natural continuum limit largely removes the computational structure that motivates the paper.
