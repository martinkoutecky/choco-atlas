Even if Theorem 2 is recast as a value-computation problem, its natural input is the full characteristic-function table, containing \(2^n\) worths. Collecting terms in its formula, the coefficient of \(v(U)\), for \(u=|U|\), is
\[ \begin{cases} \displaystyle \gamma^{(k)}_{u-1}\sum_{t=0}^{\min(k,u-1)}\binom{u-1}{t}, & i\in U,\\[1.2ex] \displaystyle -\sum_{t=0}^{\min(k,n-1-u)}\binom{n-1-u}{t}\gamma^{(k)}_{u+t}, & i\notin U. \end{cases} \]
So the value is a linear transform computable for all players in \(O(n2^n)\) arithmetic operations from that explicit table: polynomial in the input length. A succinct encoding could create a harder computation, but choosing that encoding would define a new problem rather than mirror a computational result in this paper.

The best population-based proposal would restrict attention to games with finitely many player types and worths determined by type-count vectors, then define a continuum worth function and a per-type allocation density. That can be a coherent model. The obstacle is that the paper supplies no such type structure or compact worth representation: for general TU games, coalition worths are arbitrary across subsets, so there is no canonical continuum worth function to calculate. Scaling group size \(k\) with population and converting individual payoffs to densities can address the limit’s units, but it still yields a new allocation model. Theorem 4 is an asymptotic statement about individual payoffs; it does not supply a computational question for that model.
