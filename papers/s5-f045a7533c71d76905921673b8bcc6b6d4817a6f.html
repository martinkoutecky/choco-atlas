Why no mirror

The proposed mass-weighted DRFH model is a plausible population mirror, and its LP is tractable. But the only anchor raised, Proposition 2, proves Pareto optimality; it does not assert that computing an allocation is possible or hard, nor give a computational formulation result. Under the required named-result gate, the inferred tractability of the LP cannot make this anchor computational.

The case FOR (proponent)

The best honest case is a population-compressed version of DRFH allocation. There is an important qualification: the paper has no numbered result classifying a problem as polynomial-time, NP-hard, or otherwise. Its closest named algorithmic anchor is Proposition 2 (Pareto optimality), proved in this paper. It states that the allocation obtained by solving (6) is Pareto optimal: no feasible allocation can let some user schedule strictly more tasks while every other user schedules at least as many. That is an allocation result, not a complexity theorem; the tractability claim below is an inference from the LP the paper computes with.

A plausible high-multiplicity setting is a large cloud whose many tenant or project queues draw from a small catalogue of workload templates. A type is the complete per-task resource-demand vector, along with any other parameters that affect allocation, such as weight or task limits. Queues of the same type are interchangeable for this problem. The regime is \(N\) queues and \(\tau\) supported types, with \(N\) much larger than \(\tau\)—for example, millions of queues using tens or hundreds of standard CPU, memory, and storage profiles. Holding per-capita server supply fixed as the population grows is a natural scaling for a cloud that grows with its tenant base.

The mirror I would hand to a prover is Mass-DRFH Allocation. Its input is a finite set of server configurations \(l\), resources \(r\), and supported user types \(t\); rational type masses \(\mu_t>0\) summing to \(1\); each type’s positive task-demand vector \(D_t\); and rational per-capita server capacities \(c_{lr}\). For the baseline result, users have equal weight and an unlimited supply of divisible tasks, as in the paper’s main DRFH analysis.

Let \(d_{tr}=D_{tr}/\max_q D_{tq}\). For each type and server, choose \(x_{tl}\geq 0\), the dominant-resource share allocated there per member of that type. Find the maximum common share \(g\) satisfying \(\sum_t\mu_t x_{tl}d_{tr}\leq c_{lr}\) for every server and resource, and \(\sum_l x_{tl}=g\) for every type. The induced per-member allocation is \(A_{tlr}=x_{tl}d_{tr}\); a solution is the exact rational \(g\) and these allocations. This is the paper’s DRFH optimization with the sum over users replaced by a mass-weighted sum over types.

The expected classification is tractable: this is a rational LP with \(O(\tau k)\) allocation variables and \(O(km+\tau)\) constraints, so it can be solved in time polynomial in the input bit length and the numbers of types, servers, and resources. That is a consequence of the displayed LP, not a complexity result claimed by the paper. Proposition 2 supplies the named result being mirrored: the computed allocation should be Pareto optimal for the population. In the atomless model, I would state that as a type-level claim—no feasible allocation can raise the per-capita task rate of any positive-mass type without lowering that of another—so a zero-mass individual cannot create a vacuous Pareto objection.

The match to the authors’ problem is strong: the types are still users with the same resource demands, the servers and per-capita allocation objective are retained, and the mechanism still equalizes global dominant shares. The population is what changes. The mirror covers the paper’s divisible-task DRFH allocation and its Pareto-optimality result, not the Best-Fit heuristic, the trace simulations, or the indivisible-task implementation.

Further questions follow naturally: do envy-freeness and group strategyproofness extend when a positive-mass coalition can split by report? Does the weak sharing-incentive guarantee survive with a mass-based equal-partition benchmark? What approximation guarantees remain for indivisible tasks when \(N\) is large but \(\tau\) stays small?

The weakest point is also clear: this paper offers no discrete hardness result whose difficulty might dissolve in the continuum, and its allocation is already formulated as an LP. So the case is not that population continuization resolves a known hard problem. It is that repeated users of a small number of complete types yield a natural high-multiplicity input, and the resulting allocation problem can be stated and solved using \(\tau\), rather than the raw population size. If the number of distinct workload types grows with \(N\), that compression largely disappears.

The case AGAINST (opponent, writing after the proponent)

The case for is right that a population-compressed DRFH model is coherent. A cloud with many interchangeable queues and a small catalogue of complete workload types is plausible, and the mass-weighted LP is a faithful way to allocate resources per type. I cannot honestly argue that no worthwhile continuous mirror exists in any scenario.

But Proposition 2 is not the computational anchor ChoCo requires. It proves Pareto optimality of DRFH’s allocation; it does not classify the complexity of a computational problem. The paper’s other named propositions likewise establish allocation properties. Its heuristic and trace simulations do not supply a named approximation or complexity result. So the proposed type-level Pareto claim mirrors an axiomatic property, while the polynomial-time claim is inferred from the LP rather than from a computational result in the paper.

The strongest repaired version remains a legitimate high-multiplicity allocation problem: replace individual users in the LP with masses of complete types and ask whether type-level Pareto optimality holds. But that creates a new continuum version of an allocation property; it does not uncover a computational question this paper left unresolved. The model already writes DRFH as an LP, so the mirror’s computational formulation adds little beyond compressing repeated rows by type.

One could instead study how well progressive filling or Best-Fit performs for many users with indivisible tasks. That might be worthwhile, but the paper offers heuristics and simulations rather than a named complexity or approximation result to mirror. It would be a new scheduling problem, not a stronger version of Proposition 2. Thus the negative case is strong against this paper as a ChoCo computational anchor, but weak against the broader claim that some continuous-population study of DRFH could be worthwhile.
