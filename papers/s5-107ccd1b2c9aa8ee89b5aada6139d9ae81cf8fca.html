The case FOR (proponent)

Strictly, this paper has no named complexity result saying that a problem is in P, NP-hard, or otherwise classifying its complexity. Its strongest nearby anchor is Theorem 3, proved in the paper: a choice rule satisfies maximal accommodation of horizontal reservations, no justified envy, non-wastefulness, and compliance with vertical reservations if and only if it is the two-step meritorious horizontal (\(2\mathrm{SMH}\)) choice rule. In the theorem’s terms, maximal accommodation means an unassigned eligible applicant cannot increase the number of protected positions filled by joining a category; no justified envy means a higher-merit rejected applicant can replace a selected one only if that reduces protected-position use; non-wastefulness rules out leaving a position idle while an eligible applicant remains; and compliance with vertical reservations gives the open positions priority over using a protected-category position when the open-category HR criteria can still be met. This is a characterization of the allocation rule, not a complexity claim. It is the best anchor available because the paper computes with that rule using matching.

A plausible high-multiplicity setting is a large annual public recruitment round: many applicants compete for jobs under vertical category quotas and horizontal guarantees, while the allocation rule uses only merit score, vertical category, and the applicant’s full set of horizontal traits. A type \(t\) is the tuple \((s_t,\rho_t,A_t)\) of merit priority, vertical category, and trait set; \(\mu_t\) is its fraction of applicants. When the number of applicants is large relative to the number \(\tau\) of such types, the mass description is natural. Job capacities and HR guarantees become per-capita shares \(\alpha_v\) and \(\eta_{v,h}\) for \(v\in\{o\}\cup R\), where \(o\) denotes open jobs and \(R\) the protected vertical categories. Scaling these supplies with the cohort is a co-modification needed to make a population limit meaningful.

The corresponding problem is Two-Step Meritorious Horizontal Allocation\(_\infty\). Given rational masses \(\mu_t\), merit priorities, categories and trait sets, and rational capacities \(\alpha_v,\eta_{v,h}\), compute the continuous \(2\mathrm{SMH}\) allocation. Its output is \(y_{t,v}\), the mass of type \(t\) receiving a job in category \(v\), together with \(z_{t,v,h}\), the mass counted toward trait \(h\)’s HR guarantee there. Feasibility requires \(0\leq\sum_v y_{t,v}\leq\mu_t\), \(y_{t,c}=0\) unless \(\rho_t=c\), and \(\sum_t y_{t,v}\leq\alpha_v\). The HR matching is one-to-one: \(z_{t,v,h}=0\) unless \(h\in A_t\), \(\sum_h z_{t,v,h}\leq y_{t,v}\), and \(\sum_t z_{t,v,h}\leq\eta_{v,h}\).

For each vertical category, the rule first selects a maximum-mass subset that can be matched to HR positions, choosing lexicographically by merit priority among such subsets. It then fills remaining jobs from the remaining mass in merit order, splitting a score tier if needed. Run this first for open jobs using the whole population; then run it for each protected category using only the residual mass in that category. There is no separate monetary or welfare objective in the paper: the operative ordering is maximum HR utilization, then merit. The \(z\) values provide a matching certificate for the resulting allocation. This states a concrete question: compute that allocation exactly for the given rational instance.

I expect this mirror to be tractable—Class A. With finitely many types and traits, its matching step is a bipartite flow problem with rational capacities; merit-order selection and filling can be done by sorting and lexicographic optimization over the same network. That suggests polynomial time in \(\tau\), the number of traits and vertical categories, and the input bit length. The paper explicitly identifies polynomial-time maximum matching as the tool, though it does not state this continuous complexity result as a named theorem. The mirror covers Theorem 3’s overlapping-HR model under the paper’s one-to-one convention; the non-overlapping case is a specialization, not a second anchor.

The case is plausible because the paper already defines a choice rule over applicants and uses a matching problem to implement its horizontal protections. Here the continuous object is the applicant population; fractional \(y\) and \(z\) describe type-level totals, while each unit of mass still represents a person receiving at most one integral job. Further questions include how closely the mass allocation approximates the finite rule after rounding, whether exact discrete-to-continuous identities or error bounds hold, and what happens under the paper’s alternative one-to-all convention.

The soft spot is that the paper assumes distinct merit scores, using tie-breaks to impose a strict order. A useful high-multiplicity type needs many applicants with the same priority-relevant attributes, so this mirror groups applicants into shared score tiers and permits mass to split within a tie. If individual tie-breaks materially affect the allocation, preserving them may force nearly every applicant into a separate type and erase the computational benefit. The other weakness is fit: the paper’s named result is an axiomatic characterization, not a complexity result, and the flow computation is already standard. So this is a credible continuous form of the paper’s allocation problem, but a modest complexity contribution rather than evidence that continuization reveals a deep new complexity boundary.

The case AGAINST (opponent, writing after the proponent)

The strongest objection is that Theorem 3 is not a computational result. It characterizes a choice rule: exactly the rules satisfying four axioms are the \(2\mathrm{SMH}\) rule. The other main results are also characterizations or properties of rules, not complexity classifications. A continuous version of that theorem would continuize an axiomatic question, which is outside ChoCo’s scope.

The proponent’s better mirror—compute the \(2\mathrm{SMH}\) allocation from population masses—is coherent, but it asks a different question. The paper already specifies the allocation procedure, including the maximum-matching step. Studying a mass version of that procedure may be useful, but it does not mirror the theorem’s result about which rules satisfy the axioms.

There is also a high-multiplicity obstacle in the paper’s exact model. Merit scores are distinct, and the authors say ties are broken to obtain a strict ranking. Since merit affects selection, the complete type must include that priority. Each applicant is therefore a separate type: \(\tau=n\). Scaling the applicant pool does not create repeated types. Keeping the number of jobs fixed makes the selected share vanish; scaling jobs with the pool avoids that degeneration, but leaves the distinct-priority problem intact.

The best repair is to group applicants into shared merit-score tiers, allow a tier’s mass to split, and scale capacities per capita. That yields a sensible adjacent model and could be implemented with flow. But it changes the strict merit ordering that the paper assumes; restoring individual tie-breaks returns to singleton types. A distribution over continuously varying merit scores is another possible repair, but it requires a new input and complexity model rather than the paper’s finite support of binary-rational masses.

This negative case is not airtight: the authors might recognize a tie-neutral, tier-based version as a useful extension, and the flow formulation gives it a concrete computational question. But that possibility supports a new model-specific project, not a continuous mirror of Theorem 3. The case against is strongest if ChoCo requires a computational result in the paper to anchor the mirror; it weakens if the programme also treats the implementation of an axiomatic rule as sufficient.
