The continuous mirror question

Given a finite latent state set \(\Theta\), prior \(\pi\), supported provider/report types \(t\) with masses \(\mu_t\), supplied posterior summaries \(q_t\) and \(r_t\) for each type and its peers, and valid score bounds \(\ell<u\), compute \(K_t=\sum_{\theta\in\Theta}q_t(\theta)r_t(\theta)/\pi(\theta)\), the per-unit log-PMI payment \(\rho_t=b(\log K_t-\ell)/(u-\ell)\), and the total payout \(\sum_t\mu_t\rho_t\), exactly where possible and otherwise to a requested precision.

The model it lives in

A society is a distribution \(\mu\) over finitely many supported provider/report types; each type carries a supplied posterior pair \((q_t,r_t)\) over finite \(\Theta\). Evaluate the paper’s PMI score for each type, apply the per-capita budget normalization, and sum payments weighted by type mass.

The case FOR (proponent)

The strongest honest positive case is narrow: scale the paper’s one-time peer-prediction payment calculation to a high-multiplicity population of data providers.

My anchor is Lemma 4.1, proved in the paper. It says that when the latent parameter space \(\Theta\) is finite, the pointwise mutual information \(PMI(D_i,D_{-i})\) can be computed in \(O(|\Theta|)\) time. For conjugate exponential-family posteriors, it also gives a closed form: if the prior and the two posteriors have parameters \((\nu_0,\bar{\tau}_0)\), \((\nu_i,\bar{\tau}_i)\), and \((\nu_{-i},\bar{\tau}_{-i})\), then
\[ PMI(D_i,D_{-i})= \frac{g(\nu_i,\bar{\tau}_i)g(\nu_{-i},\bar{\tau}_{-i})} {g(\nu_0,\bar{\tau}_0)\, g\!\left(\nu_i+\nu_{-i}-\nu_0, \frac{\nu_i\bar{\tau}_i+\nu_{-i}\bar{\tau}_{-i}-\nu_0\bar{\tau}_0} {\nu_i+\nu_{-i}-\nu_0}\right)}. \]
The finite-state computation is the direct sum in the definition; the exponential-family identity is derived in the paper’s Appendix, including the proof of Lemma A.3. The paper has no named hardness result. Theorem 5.1, which proves that the one-time mechanism is individually rational, truthful, budget feasible, and symmetric, is relevant motivation, but it is not a complexity anchor.

A concrete mirror is Continuous-Population Log-PMI Payment Evaluation. Consider a data platform with many authenticated contributors, each supplying a short categorical measurement about a common latent parameter. Contributors in the same type have the same data-generation model, dataset size, relevant costs, and payment terms; their private dataset is from a bounded alphabet. Let \(t\) denote such a type, including its private signal, and let \(\mu_t\) be its population mass, with \(\sum_t\mu_t=1\). In a plausible regime, the number \(N\) of contributors is very large while the number \(\tau\) of supported types is modest.

A report profile is a mass flow \(x_{t,a}\), where \(x_{t,a}\) is the mass of true type \(t\) reporting dataset \(a\), and \(\sum_a x_{t,a}=\mu_t\). For a given profile, the Bayesian model supplies each report type’s posterior \(q_{t,a}\) and its peer population’s posterior \(r_{t,a}\). With finite latent state set \(\Theta\), prior \(\pi\), and positive PMI values, define
\[ K_{t,a}=\sum_{\theta\in\Theta} \frac{q_{t,a}(\theta)r_{t,a}(\theta)}{\pi(\theta)}. \]
Given valid score bounds \(\ell<u\) and per-capita budget \(b\), the payment per unit of mass is
\[ \rho_{t,a}=b\,\frac{\log K_{t,a}-\ell}{u-\ell}, \]
and the total payout is \(\sum_{t,a}x_{t,a}\rho_{t,a}\). The computational problem is: given the supported types, rational masses, posterior summaries, score bounds, and a current report flow, compute the PMI values, per-type payments, and total payout. A solution can return exact rational \(K_{t,a}\) values and payment estimates to a requested precision. This is the payment-evaluation subproblem used by their mechanism, expressed over a society of masses rather than a list of individually named providers.

I expect this mirror to be tractable: the PMI sums take \(O(|\Theta|\tau |A|)\) arithmetic operations for report alphabet \(A\), with polynomial bit complexity in the input size and requested precision for the logarithms. The paper’s Section 5 makes this primitive part of an actual one-time data-acquisition mechanism, so a continuum of short-measurement contributors is a plausible setting its authors would recognize. For example, millions of devices could submit one measurement each, with a small number of device protocols and measurement outcomes. The same conditional-independence structure the paper assumes gives the peer posterior its meaning.

This covers the one-time log-PMI payment calculation, not the full mechanism-design theorem and not the multi-time setting. A natural next question is whether the peer posterior \(r_{t,a}\) can itself be computed efficiently from the aggregate report masses and likelihood model. Another is whether the paper’s truthfulness and sensitivity guarantees persist for infinitesimal deviations in a continuum population.

My weakest point is that this is a modest algorithmic mirror: Lemma 4.1 already makes each PMI calculation a short sum, and the paper does not classify the complexity of a difficult underlying problem. The continuum version mainly aggregates that calculation across \(\tau\) types. It is therefore a credible narrow Class A case, not evidence that the paper contains a broader complexity landscape or that discrete hardness dissolves in the limit.

The case AGAINST (opponent, writing after the proponent)

Lemma 4.1 is a real computational result, so I would not dismiss the case by saying the paper has no named result to mirror. The difficulty is that it is a result about evaluating one payment from supplied posterior summaries: for finite \(\Theta\), compute a sum; for the stated exponential families, use a closed form. There is no search or optimization problem whose complexity changes when providers are grouped into types.

The proposed mirror takes those posterior summaries as input. Given them, each \(K_{t,a}\) is the same calculation as in Lemma 4.1, repeated for the supported report types; the masses only weight the payments. That gives a clean bound such as \(O(|\Theta|\tau |A|)\), but it does not expose new computational structure. If the stronger question is how to derive the peer posterior from the population, the population masses alone are insufficient. For report counts \(c_a=n\mu_a\), the posterior depends on the total population size:
\[ p(\theta\mid\mathbf c)\propto \pi(\theta)\prod_{a\in A}p(a\mid\theta)^{n\mu_a}. \]
The same proportions at different \(n\) give different evidence. In an identifiable model, letting \(n\) grow without bound generally makes the peer posterior concentrate on the parameter identified by the population distribution. The continuum then changes the statistical object behind PMI: an individual has zero mass and the aggregate can reveal the latent parameter essentially exactly.

One can retain an effective evidence scale \(\lambda\) and use fractional counts \(\lambda\mu_a\). That is a plausible model choice, but once \(\lambda\) and the likelihood are specified, finite-state posterior updates can be aggregated directly and the payment calculation remains the short computation of Lemma 4.1. It does not become a distinct complexity question. A richer mass-flow incentive analysis has the same limitation: an infinitesimal provider’s report cannot change the aggregate peer posterior, so unilateral incentives are evaluated against a fixed aggregate signal. That may be an interesting mean-field mechanism-design model, but it is not a new computational result from this paper.

There is also a programme-fit concern: the paper studies peer prediction and data acquisition, with no collective choice outcome or social-choice problem. A continuous population of data providers may be sensible, but the proposed task is scalable evaluation of a scoring mechanism, rather than a continuous computational social-choice problem.

The negative case is strongest against this particular anchor: its faithful mass version is either an elementary aggregation of an already explicit computation or, if the posterior is endogenized, requires a population evidence scale that changes the model and can make the continuum limit degenerate. I would not claim that no worthwhile continuous study of peer prediction is possible; the claim that none could be worthwhile in any scenario is weaker than the evidence supports.
