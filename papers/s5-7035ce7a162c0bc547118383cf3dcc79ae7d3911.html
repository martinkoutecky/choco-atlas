The case FOR (proponent)

The paper contains no named computational-complexity result of the required kind: its numbered results characterize fair rules and their welfare guarantees, but do not establish that a problem is in P, NP-hard, FPT, or similar. So there is no eligible anchor under your criterion.

The strongest candidate for a population mirror is Theorem 17, proved in the paper: for every \(n\ge2\), the Bottom-Heavy rule \(\varphi^1\) dominates every other symmetric, almost prior-independent rule for bads that satisfies Fair Share. Here, dominance means weakly lower total normalized disutility for every realized profile, and strictly lower disutility for some profile. This is a useful positive anchor for a *mathematical* mirror, but it is not a computational-complexity anchor.

A plausible high-multiplicity setting is a large workforce repeatedly assigned undesirable tasks. A type is a complete normalized disutility function \(x_t:\Omega\to\mathbb R_+\) over task states; agents of the same type share that function and all other relevant attributes. Let \(\rho_t\) be each type’s population fraction, with \(n\gg\tau\). To keep the per-agent Fair Share condition meaningful as the workforce grows, measure allocation in per-capita units: write \(z_i=n\varphi_i\), so the continuum feasibility condition is \(\sum_t\rho_t z_t=1\).

One precise candidate question is Continuum Bottom-Heavy API Design. Given finitely many types with rational masses, finitely many task states with rational probabilities, and normalized disutilities satisfying \(\mathbb E_q[x_t]=1\), find an anonymous allocation functional \(Z(\rho,x)\). It must use the realized profile, not the prior \(q\); satisfy \(\mathbb E_q[Z_t(\rho,x)x_t]\le1\) for each type under every admissible prior; and minimize \(\sum_t\rho_t Z_t(\rho,x)x_t\) pointwise over realized profiles among all such rules. A solution is the universal rule, which outputs a per-capita allocation for each observed profile. The natural candidate is the limit of the paper’s Bottom-Heavy cutoff rule: allocate in proportion to \(\bar x/x_t\) among the lowest-disutility types until the resource is exhausted, splitting any boundary allocation symmetrically across tied types.

The authors would likely recognize this as their bad-allocation problem under a high-multiplicity regime, since it preserves API, ex-ante Fair Share, and the normalized-disutility objective. I would expect the finite-support allocation step to be tractable by sorting types and finding a cutoff. The open part is whether the rule retains the paper’s universal fairness and dominance guarantees in the continuum.

The soft spot is substantive: this mirror requires per-capita resource supply to scale with population, and requires Fair Share to become a condition for almost every type. That is a defensible co-modification, but it is where a referee could say the model has moved beyond Theorem 17. The mirror covers that theorem’s bads result only. Further questions include the exact limit with tied or zero disutilities, and whether the continuum rule is the limit of the finite-\(n\) Bottom-Heavy rules.

This is a plausible positive case for a continuous-population extension. It does not meet the required anchor condition, so I would not present it as an anchored computational-complexity case for this paper.

The case AGAINST (opponent, writing after the proponent)

The strongest case against this paper as a ChoCo computational anchor is that it contains no named computational result. Theorem 17 characterizes which fair API rule dominates the others; Theorem 13 does the same for goods. Propositions 20 and 21 give competitive-ratio and price-of-fairness bounds, and the later results analyze asymptotics. These are mathematical characterizations and performance analyses, not complexity or algorithm results for an encoded computational problem. The paper’s mention of an LP for the prior-dependent benchmark does not supply such an anchor.

The proposed workforce model is coherent. Workers with identical disutility functions can form types with masses \(\rho_t\); scaling an individual’s share by \(n\) gives a per-capita allocation \(z_t=n\varphi_i\), with feasibility \(\sum_t\rho_t z_t=1\). That scaling preserves a meaningful Fair Share condition as \(n\) grows. Repeated undesirable tasks also provide a plausible high-multiplicity setting. Individual identity and vanishing fairness constraints are not convincing objections here.

The difficulty is that the mirror proposed for Theorem 17 asks for a universal rule: a mapping over realized profiles that remains fair across admissible priors and dominates every competing API rule. The theorem states a property of that function space; it does not give a finite input and output whose running time could be studied. A finite list of task states and disutilities could make rule synthesis computationally concrete, but then the question is a finite-domain robust policy-design problem. If instead the input is one realized profile and the output is its allocation, the task computes one action, not the universal dominance characterization.

Other natural finite formulations change the question too. Giving the full prior and optimizing allocations across its states produces the prior-dependent allocation LP discussed in the paper, with a different information regime from API design. A finite-state API rule-synthesis problem could be a worthwhile new high-multiplicity project, but it would need its own formal input model and computational result; it is not an algorithmic result already established by Theorem 17.

So the negative case is strong at the programme boundary: this paper offers no eligible computational anchor, and the proponent’s candidate is explicitly a rule characterization. It is weak as a universal modelling claim. The workforce construction survives the substantive objections, and a finite-domain computational extension is plausible. I would reject the paper as a computational mirror candidate on the evidence given, without claiming that no worthwhile continuous-population research can be built from it.
