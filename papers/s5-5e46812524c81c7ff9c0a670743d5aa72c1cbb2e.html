  • Proposition 3 — survived: The OWA clause extends to a credible population of repeated users receiving type-specific recommendations, with one RIGA run per supported type.

The continuous mirror question

Given a finite-support rational distribution \(\mu\) over user types, where each type \(t\) specifies a MOCO instance, its criterion values, an initial admissible OWA-weight polytope, and a pairwise-comparison oracle, can a protocol run RIGA for each type and return a policy \(t\mapsto x_t\) in polynomial total computation and queries, with candidate-set maximum regret at most \(\delta\) for every type? The policy’s expected candidate-set regret is \(\sum_t \mu_t\,\mathrm{MR}_t(x_t,Q_t,\Omega_t)\).

The model it lives in

A large route-planning service represents its users by complete recurring profiles. Each type has its own feasible routes, criterion values, and hidden OWA preferences; its mass \(\mu_t\) is its share of users. RIGA elicits preferences and returns a route per type, while the service’s expected candidate-set regret is mass-weighted.

The objection that survived

The masses do not affect which route is returned or which comparisons RIGA asks, so the result covers repeated independent recommendation sessions; the proponent acknowledges this, but the population-scale setting remains a thin extension.

fatal: False

What the mirror covers

The mirror covers Proposition 3’s OWA polynomial-time and polynomial-query guarantee, applied independently to each supported type. It does not extend the guarantee to regret over the full feasible set, and it leaves the paper’s experimental comparisons and other results aside.

Open questions for a prover

  • Can a shared query budget be allocated across types to minimize mass-weighted candidate-set regret while retaining a polynomial guarantee?
  • Can a RIGA-based protocol guarantee regret over each type’s full feasible set rather than only its generated candidate set?

The case FOR (proponent)

The positive case I believe is a typewise population of users of an interactive MOCO recommender. Think of a route-planning service with many commuters and a finite set of recurring origin–destination, time-window, and preference profiles. A type is a complete profile for the route problem: its feasible routes, their criterion values, and the user’s true OWA weights. Users of one type are interchangeable, so a query to one representative applies to that group. The mass \(\mu_t\) is the fraction of users of type \(t\); millions of users may therefore be represented by a much smaller support of \(\tau\) types. The service returns a route \(x_t\) for each type.

My anchor is Proposition 3, proved in this paper. It states that for any MOCO problem with OWA preferences, if the problem can be solved exactly or approximately in polynomial time when the preference parameters are known, then RIGA can be implemented in polynomial time and asks at most a polynomial number of preference queries. The proposition gives the same result for Choquet integrals. I rely on its OWA clause. The paper has no numbered hardness result to anchor a hardness mirror; its discussion of knapsack and TSP hardness does not supply one.

The mirror problem is Continuous Typewise RIGA. An instance gives a finite-support rational distribution \(\mu\), and for every supported type \(t\), a MOCO instance \(X_t\) with criterion vector \(y^t\), an initial rational polytope \(\Omega_t\) of admissible normalized OWA weights, a pairwise-comparison oracle for that type, and a tolerance \(\delta\). Assume the known-weight optimization condition of Proposition 3 holds for every type. Run the prescribed RIGA search for each type, producing its finite candidate set \(Q_t\). For \(x\in Q_t\), define its candidate-set maximum regret by
\[ \mathrm{MR}_t(x,Q_t,\Omega_t) = \max_{\omega\in\Omega_t}\max_{z\in Q_t} \bigl(f_\omega(y^t(x))-f_\omega(y^t(z))\bigr). \]
The question is whether a protocol can return a policy \(t\mapsto x_t\) that minimizes this regret within each \(Q_t\), has \(\mathrm{MR}_t(x_t,Q_t,\Omega_t)\le\delta\), and uses polynomial computation and comparisons in the encoded type instances, \(\tau\), and their bit lengths. Its population objective is expected candidate-set regret, \(\sum_t\mu_t\mathrm{MR}_t(x_t,Q_t,\Omega_t)\), which is then at most \(\delta\).

The expected answer is tractable, under the proposition’s conditions: run RIGA separately on each supported type. Proposition 3 supplies the polynomial resource bound per run, so the total remains polynomial in the support size and the input lengths. This preserves the paper’s underlying task for each group—searching a combinatorial solution space while eliciting rank-dependent preferences through pairwise comparisons. The paper also observes that OWA can be natural when criteria represent individual points of view in a collective decision problem, which helps make the population setting recognizable to its authors.

The scope is deliberately narrow: this mirrors Proposition 3’s resource guarantee for type-conditioned recommendations. It does not claim that RIGA finds a globally minimax-regret solution over all feasible routes. Its regret guarantee is over its generated candidate set, and the paper itself says RIGA has no theoretical performance guarantee. Further questions include whether a shared query budget should be allocated across types according to their masses, and whether useful regret guarantees can be obtained over the full feasible sets.

My weakest point is that this is a population of personalized decision makers, rather than a population choosing one common social outcome. The mass-weighted objective is separable across types, so the lift is mostly a high-multiplicity batching of RIGA. If the authors require a single collective recommendation, they may regard it as a different problem. The case rests on their accepting a large population served by a type-conditioned recommendation policy as a natural setting for their interactive MOCO problem.

The case AGAINST (opponent, writing after the proponent)

Proposition 3 is the paper’s one strong computational anchor. The stated “Continuous Typewise RIGA” mirror is plausible as a service for many users, but its computation is a collection of separate RIGA runs. Each type has its own candidate set, preference polytope, query oracle, and recommendation. The policy objective \(\sum_t \mu_t \mathrm{MR}_t\) separates by type: changing a type’s mass does not change its recommendation or which questions its RIGA run asks. Identical users share one answer; distinct types amount to separate instances. The population is present in the bookkeeping, but it does no work in the problem.

A stronger mirror might have the system choose one public route for everyone, using a mass-weighted aggregate of users’ preferences. If users share the same criterion values and differ only in their OWA weights, then
\[ \sum_t \mu_t\,\mathrm{OWA}(y(x),\omega_t) = \mathrm{OWA}\!\left(y(x),\sum_t\mu_t\omega_t\right). \]
The population reduces to one effective preference vector. If types instead have different criterion values, or the group uses a fairness or worst-case objective, the aggregate objective and query protocol change. That could be a worthwhile collective optimization problem, but it adds a social aggregation model absent from the paper; Proposition 3 does not establish it as the authors’ problem.

So the best negative case is that the proposed direct mirror is high-multiplicity batching, while the more collective version either collapses to one decision maker or changes the problem being studied. This is not an airtight case against every scenario: a public planning application with type-specific data and an explicit group objective could be a compelling extension, and its authors might recognize it as theirs. I would reject the proponent’s anchor as stated, but I cannot honestly claim to have ruled out every worthwhile continuous mirror.
