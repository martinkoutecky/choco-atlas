The continuous mirror question

Given a shared ontology \(O=(D,\Sigma)\), a conjunctive query \(q\), a candidate answer \(a\), a finite supported set \(T\) of consistent user types with possibilistic networks \(\Gamma_t\), binary-rational masses \(\mu_t>0\) summing to \(1\), and a rational threshold \(\theta\), decide whether \(\sum_{t:\,a\in S_t(q)}\mu_t\ge\theta\), where \(S_t(q)\) is the set of skyline answers under \((O,\Gamma_t)\).

The model it lives in

A society is a distribution \(\mu\) over complete user preference-network types; each type keeps the paper's ontology-mediated skyline semantics, and the objective is the mass of types for which \(a\) is a skyline answer.

The objection that survived

The population objective aggregates independent per-type skyline tests, so it adds a weighted coverage statistic without changing the paper's underlying query reasoning.

fatal: False

What the mirror covers

The mirror lifts Theorem 6's CQ skyline-membership question to population coverage; it leaves the consistency results, \(k\)-rank answers, and the remaining complexity table results aside.

Open questions for a prover

  • What is the complexity of threshold coverage as the supported type count \(\tau\), query, and preference networks vary, including for fixed ontology programs?
  • Can shared structure across preference networks reduce the cost of computing coverage or coverage values for many answers?

The case FOR (proponent)

A defensible mirror is Population Skyline Coverage for personalized Semantic Web search. Imagine a large car-booking service where millions of users search the same catalog with the same conjunctive query. Each user’s complete type is their possibilistic preference network \(\Gamma_t\): users with the same network, including the same possibility values, belong to the same type. The ontology and query are shared, while \(\mu_t\) is the fraction of users of type \(t\). A realistic regime might have millions of users but only hundreds or thousands of recurring preference profiles. If users differ in a preference or other feature that affects the problem, they belong to different types.

Here is the continuous problem. An instance consists of a common ontology \(O=(D,\Sigma)\), a conjunctive query \(q\), a candidate answer \(a\), a finite supported set of consistent user types \(T\), each with a network \(\Gamma_t\) over the shared variables and domains, binary-rational masses \(\mu_t>0\) summing to \(1\), and a threshold \(\theta\). Let \(S_t(q)\) be the set of skyline answers to \(q\) under \((O,\Gamma_t)\). Compute
\[ M_\mu(a\mid q)=\sum_{t:\,a\in S_t(q)}\mu_t, \]
or decide whether \(M_\mu(a\mid q)\ge\theta\). The answer count for each user remains discrete; the continuous object is the population mass whose preference type makes \(a\) a skyline answer. This matches the paper’s aim of retrieving resources that fit users’ preferences while making the population, rather than the outcome space, continuous.

My lead anchor is Theorem 6, proved in this paper. It states that for OP-nets whose ontology language allows negative constraints, deciding CQ skyline membership is \(\Delta_2^P\)-hard in fixed-program combined complexity, where the dependency set is fixed. The proof reduces from deciding whether the lexicographically maximal satisfying assignment of a satisfiable 3-CNF formula sets its last variable to true: the possibility values impose lexicographic order, and the query tests that last variable. The reduction produces consistent OP-nets, so the hardness applies within the valid instances used in the mirror.

I expect Population Skyline Coverage to fall in Class B: hardness transfers. With one supported type of mass \(1\) and \(\theta=1\), the population question is exactly the paper’s skyline-membership question. The hard combinatorics already occur in reasoning about the ontology, preferences, and query; they do not depend on having many distinct user types. In ontology fragments where per-type skyline membership has the paper’s \(\Delta_2^P\) upper bound, computing coverage for explicit support takes at most \(\tau\) such evaluations followed by a rational weighted sum. This mirror covers Theorem 6’s skyline-membership result, not the paper’s consistency results, \(k\)-rank answers, or full complexity tables.

It also suggests follow-on questions: can a service find an answer with maximum population coverage; how hard is computing coverage for all answers or for top-\(k\) results; and can shared structure across preference types speed up repeated skyline tests? With an explicit support, shifting masses changes the weighted total, while adding or removing types changes which tests must be performed.

The weak point is that the population layer aggregates independent users; it does not model interaction among them, and the continuous mass does not make the underlying membership test easier. So this is a population-level extension of the paper’s personalized query-answering problem, not a claim that its per-user computation becomes tractable. The case still holds because the paper’s motivation is explicitly user-centred, the skyline semantics are preserved for each type, and a service deciding what share of its users regards a result as a skyline answer is a plausible computational question about a society.

The case AGAINST (opponent, writing after the proponent)

Theorem 6 is the strongest anchor: it gives a named computational problem, and a one-type population of mass \(1\) reproduces its skyline-membership question exactly. That makes the proposed mirror well-posed, but it also exposes the weakness in its population contribution. With multiple types, Population Skyline Coverage runs the same membership test once per type and adds the masses of the successful types. The users do not affect one another, and changing one type’s mass changes only the final weighted sum.

A stronger version would ask which answer has the greatest coverage, or whether any answer is a skyline result for at least a specified share of users. Those are plausible service questions, but the population calculation still wraps independent per-user results in a weighted aggregation. More ambitious versions—such as choosing among answers using users’ full rankings, or changing preferences to promote an answer—would give the population a more substantive role. They would also require a collective choice rule or intervention model that this paper does not define. The paper’s central computational subject is ontology-mediated query answering under one preference model, not a society choosing or altering a common outcome.

There is also a demanding multiplicity assumption: a type must include the user’s whole possibilistic network, including its structure and possibility values. A service could reuse standardized profiles, but the paper’s motivation also allows preferences learned from user data, where exact network repetition is less assured. The case against cannot rest on that concern alone; standardized profiles and a shared catalog and query are possible.

So the best negative case is that the proposed mirror adds a thin population statistic around Theorem 6 rather than exposing a new interaction, optimization structure, or continuous-optimization question. That may make it a modest extension rather than a strong ChoCo target. But it is not a decisive objection: the service scenario is credible, the paper is explicitly user-centred, and the coverage question is computationally meaningful. I cannot honestly defend the universal claim that no worthwhile continuous mirror exists in any scenario.
