The case FOR (proponent)

There is no eligible complexity anchor in this paper, so I can’t honestly build the required positive case around a numbered result. The only numbered result is Lemma 1, which says that an implementation \((CS,A)\) is in the \(\epsilon\)-core if and only if its pairwise regret against the possible defections satisfies \(PR(A,A_p)\le\epsilon\). The paper gives this lemma itself, with the proof omitted; it is a characterization, not a claim that a problem is in P or is hard. The anytime and convergence claims for MCF appear in the prose, while the speedups are experimental. Neither supplies the required named complexity result.

The best candidate mirror I see is a pair-constrained high-multiplicity version of MCF. That restriction has a foothold in the paper: its experiments include settings where only coalitions of size two may form. A plausible regime is a large population of network devices that can cooperate only in pairs. A type records a device’s action set and its complete, nontransferable utility profile for every possible partner type and pair of actions. There may be millions of devices but only \(\tau\) distinct types; \(\mu_t\) is the fraction of the population of type \(t\).

Call the problem Pair-MCF\(_\infty\). Its input is a finite type support \(T\), rational masses \(\mu_t\) summing to one, finite action sets, and rational utility tables \(u_t(s,a,b)\), giving type \(t\)’s utility when paired with type \(s\) and the two agents choose actions \(a,b\). A pair template \(\theta\) specifies the two types and their actions. The solution is a set of nonnegative rational masses \(\lambda_\theta\), where \(\lambda_\theta\) is the mass of pair coalitions using template \(\theta\), satisfying
\[ \sum_\theta r_t(\theta)\lambda_\theta=\mu_t \]
for each type \(t\), with \(r_t(\theta)\) the number of type-\(t\) members in the pair.

Each template gives its members an incumbent utility. A possible defecting pair may recruit positive mass from incumbent template roles of the matching types, provided every recruited member weakly prefers the proposed pair and at least one strictly prefers it. Define its regret as the largest utility gain among its participants, and \(R(\lambda)\) as the largest regret over feasible defections. The problem is to return a feasible \(\lambda\) minimizing \(R(\lambda)\), together with the optimum and a certificate that no feasible implementation has lower regret. Its decision version asks, given \(\epsilon\), whether such a \(\lambda\) exists with \(R(\lambda)\le\epsilon\).

This is a credible mirror of the paper’s underlying question: choose a coalition structure and actions to minimize the worst feasible defection regret. Types retain all the utility information relevant to the restricted game; mass replaces counts of otherwise indistinguishable agents; and the action and utility structure remains nontransferable. For a discrete population with \(n_t\) agents of each type, an implementation maps to \(\lambda_\theta\) equal to its number of pairs of template \(\theta\), divided by \(n=\sum_t n_t\). The continuous version relaxes those pair counts to rational masses. Whether that relaxation preserves the optimum, or only approximates it, is a natural next question.

My initial expectation is tractability when the number of types and action choices are bounded: there are finitely many pair templates, and the available incumbent utility states—and hence possible defections—depend on which templates have positive mass. Enumerating template supports and checking their mass constraints looks like a parameterized route. That is a research hypothesis, not a result of this paper; polynomial time when \(\tau\) and the action sets vary would need separate analysis. Further questions include the exact discrete-to-continuous approximation guarantee and whether allowing larger coalitions changes the complexity.

The weakest point is also the main one: Pair-MCF\(_\infty\) narrows the paper’s general algorithm to its pair-only experimental regime, and the paper supplies no named complexity result to anchor it. So this is a plausible computational mirror of a portion of the paper, but it does not meet the requested anchor standard.

The case AGAINST (opponent, writing after the proponent)

The strongest case against is that this paper supplies no named computational complexity result to continuize. Its only numbered result, Lemma 1, characterizes \(\epsilon\)-core membership through pairwise regret. The paper’s algorithmic guarantee is stated in prose, with no running-time bound as the number of agents or actions grows; its speedups are experimental. So the proposed Pair-MCF\(_\infty\) is not a continuous counterpart of a proved complexity result. It is a new computational problem built from the paper’s objective.

The pair model is still the proponent’s strongest version. Large populations of standardized network devices could plausibly have finitely many utility types, and restricting cooperation to pairs matches an experimental regime in the paper. That clears the high-multiplicity plausibility test. But the proposal adds type-level partner utilities and fractional pairings, then asks for an exact optimum and certificate. The paper instead studies arbitrary coalition structures and presents an anytime algorithm based on relaxed regret, supported by finite simulations. A broader mass model using coalition templates might track more of the paper, but it would still pose a new problem without a complexity result here to anchor it.

I can’t make the universal claim airtight. A continuous regret-minimization problem for such populations may be worth studying on its own, and the absence of a theorem does not make that question inherently uninteresting. The honest negative case is narrower: this paper does not offer an established computational-complexity result whose continuous mirror the programme can assess. The proponent’s candidate survives as a plausible research direction, but not as a mirror of a named result in the paper.
