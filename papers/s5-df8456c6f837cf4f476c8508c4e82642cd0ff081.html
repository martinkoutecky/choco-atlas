What the mirror covers

The candidate model covers type-level TTC core allocation; it leaves the stationary-probability characterization, noise claims, and spectral runtime claims without a mirror.

The case FOR (proponent)

The strongest honest positive case is for a high-multiplicity version of the underlying TTC core-allocation problem. The paper does not provide a numbered result that establishes a complexity classification for it: its \(O(Ln)\) runtime claim appears in prose, not in a numbered theorem.

The closest named result is Theorem 4.6, proved in the paper. It claims that if the core contains agents \(k_1,\ldots,k_m\), those agents have the \(m\) highest stationary probabilities, with each of their probabilities strictly greater than every non-core agent’s. That is a computationally intended characterization, but it is not a result that the problem is in \(P\), NP-hard, or otherwise has a stated complexity. It also has a basic modeling problem: in the paper’s own TTC definitions, the core is an allocation, and every agent receives an object in the unique core allocation. So “the core contains \(m\) agents” is not standard TTC terminology. I would not treat Theorem 4.6 as a qualifying complexity anchor.

The continuous problem I would defend is High-Multiplicity TTC Core Allocation. A type is \(\theta=(e_\theta,\succ_\theta)\): an initial endowment class and a strict ranking of a finite set \(O\) of object classes. The input is a finite list of \(\tau\) such types with rational masses \(\mu_\theta\) summing to \(1\). The supply of class \(o\) is \(q_o=\sum_{\theta:e_\theta=o}\mu_\theta\). The question is to output an exact allocation \(x_{\theta,o}\), where \(x_{\theta,o}\) is the mass of type \(\theta\) receiving class \(o\), such that \(\sum_o x_{\theta,o}=\mu_\theta\) and \(\sum_\theta x_{\theta,o}=q_o\), and no positive-mass coalition can strictly improve every member by trading its endowed objects among itself. A solution is this mass-allocation matrix \(x\); each person still receives one whole object class, while \(x\) records how the population divides across outcomes. There is no optimization objective—the task is to find a core allocation.

A plausible regime is a large housing exchange with many residents but relatively few standardized dwelling classes and repeated preference-and-endowment types. If \(N\) is the number of residents, this regime has \(N\) much larger than \(\tau\). It is plausible only where units within a class really are interchangeable and residents with the same type have the same relevant preferences. This is the allowed co-modification from individually named objects to per-capita supplies of object classes.

I would expect this problem to be tractable in \(\tau\), \(|O|\), and the input bit length, through a type-level TTC procedure or a suitable flow formulation. That is a direction to investigate, not a result established by this paper. It does not show that discrete hardness dissolves: TTC itself is already polynomial-time. The further questions are whether the continuous core is unique, whether a type-level TTC procedure returns it in polynomial support-sensitive time, and whether any stationary-distribution summary can predict the order in which type mass is traded.

This covers the paper’s underlying TTC allocation problem, not its claimed spectral shortcut or its \(O(Ln)\) bound. It also does not cover Theorem 7.1’s continuous preferences over objects: that continuizes the preference or outcome representation, not the population.

The weakest point is the gap between this credible high-multiplicity exchange model and the paper’s stated “core membership” result. Repeated object classes require replacing unique objects and strict rankings over those objects with classes and rankings over classes; moreover, a TTC core allocation assigns everyone, so there is no standard set of “core agents” for a stationary vector to identify. The paper’s own example—school choice—also lacks the initial endowments required by its housing-market TTC model. Thus I see a defensible continuous mirror for the underlying allocation problem, but no sound anchor-based case for the paper’s central spectral claim.

The case AGAINST (opponent, writing after the proponent)

The paper has no named computational-complexity result to continuize. Its numbered results concern a Markov property, stationary distributions, claimed characterizations, TTC properties, and preference noise. The \(O(Ln)\) and \(O(n)\) claims appear in prose. Theorem 4.6 is the closest anchor, but it neither classifies a computational problem nor gives an algorithm. Worse, it speaks of “core” agents: under the paper’s own definition, the core is an allocation, and the unique TTC allocation assigns every agent. There is no subset of agents for a leading eigenvector to identify.

The proposed high-multiplicity housing model is nevertheless sensible. Repeated endowment and preference types, rational masses, and per-capita supplies make a coherent population limit; the fractional type-level allocation can represent whole-object assignments to individuals. I would not dismiss it because object classes are repeated or because its answer may be easy.

But that model asks for a different output: an allocation of all mass, or perhaps the sequence of trades that produces it. Neither is the paper’s claimed query of identifying core members from stationary probabilities. Its utility matrix is static, while TTC’s choices depend on which objects remain and change as trades proceed. Adding endowments, supplies, and those changing stages gives a type-level TTC problem; it does not give a continuous version of Theorem 4.6. And because everyone receives an object in the core allocation, the paper’s proposed separation between identifying “core” agents and computing the full TTC allocation has no corresponding query to preserve.

So my strongest case is that this is a poor mirror of the paper’s results, not that high-multiplicity TTC is an incoherent or useless research problem. That is where the negative case is weak: someone could reasonably treat the paper as motivating a new complexity study of type-level TTC. But that would be a separate project, not a continuization of a sound named computational result in this paper.
