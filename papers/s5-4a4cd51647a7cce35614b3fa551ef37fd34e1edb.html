The continuous mirror question

Given a finite alternative set \(A\) with \(|A|=m\ge 3\), and a known support \(T\) of \(\tau\) types with positive rational masses \(\mu_t\) summing to \(1\), each type has a known strict preference order \(\succ_t\) and an unknown intensity relation from the paper’s strict representable class. A type-level oracle compares improvements \((a,b)\) and \((c,d)\) with \(a\succ_t b\) and \(c\succ_t d\). Recover each type’s complete intensity ordering, equivalently its canonical rank function on \(A\times A\), using at most \(\tau\bigl(\binom{m}{2}-2\bigr)\) queries.

The model it lives in

The society is a distribution \(\mu\) over a finite support of types, each type carrying mass and a shared preference order and intensity relation. The decision is which pairwise intensity comparisons to query for each type; the output is its canonical ordinal intensity ranking, with query complexity measured in \(m\), \(\tau\), and the input bit length \(L\).

The objection that survived

The mirror adds no population-level query interaction: with known types it is \(\tau\) independent runs, and the masses do not affect the query bound.

fatal: False

What the mirror covers

The mirror covers Proposition 1’s intensity-elicitation result. It does not cover Theorems 1–3 on existence, Proposition 2’s allocation algorithm, or the incentive analysis.

Open questions for a prover

  • Is Proposition 1’s worst-case query bound optimal for this class of intensity relations?
  • Can information be shared across types under additional restrictions on their intensity profiles?

The case FOR (proponent)

The strongest positive case I can make is narrow: Proposition 1, proved in this paper, gives a clean algorithmic result that lifts to a continuous population by grouping agents into high-multiplicity types.

Proposition 1 says that, given a strict preference order on \(n\) alternatives, a strict ordinal intensity relation that induces that order can be elicited in \(\binom n2\) steps, hence in \(O(n^2)\) time, using \(\binom n2-2\) queries. A query compares the intensity of two preference improvements. The result uses the structure of the paper’s intensity relations to recover the ordering with fewer queries than checking every pair of improvements. It is an in-\(\mathrm P\) result, proved here rather than cited.

Here is the continuous problem I would hand to a prover. Call it Type-Intensity Elicitation\(_\infty\). The input is a finite alternative set \(A\), with \(|A|=m\), and a known support \(T\) of \(\tau\) agent types. Type \(t\) has mass \(\mu_t\in\mathbb Q_{>0}\), with \(\sum_{t\in T}\mu_t=1\), and a known strict preference order \(\succ_t\). Its strict ordinal intensity ordering over improvements is unknown. An oracle, queried for type \(t\), compares two improvements \((a,b)\) and \((c,d)\), where \(a\succ_t b\) and \(c\succ_t d\). The task is to recover, for every supported type, its complete intensity ordering—or equivalently its canonical rank function \(s_t\) on \(A\times A\), with values in \(\{-k,\ldots,k\}\) for \(k=\binom m2\). These are ordinal rank labels, not cardinal utilities. A solution is an adaptive query procedure that returns the correct canonical ordering for every intensity profile in the paper’s representable strict class.

The regime is a large, standardized allocation programme with a shared finite menu of options: for example, a placement programme with many applicants in a relatively small number of known cohorts. Cohort members must share the complete information relevant to this elicitation problem, including both their preference order and their intensity ordering; the cohort partition must be known or supplied as part of the instance. If there are \(N\) applicants and \(\tau\) such types, the intended regime has \(N\) large relative to \(\tau\). The mass \(\mu_t\) says what fraction of the population each recovered type represents. One representative’s answers then supply the intensity ordering for that type’s entire mass.

Applying Proposition 1 separately to each type gives at most \(\tau\bigl(\binom m2-2\bigr)\) oracle queries and \(O(\tau m^2)\) elicitation steps, plus the cost of reading the rational masses. Thus this mirror is tractable, with running time polynomial in \(m\), \(\tau\), and the input bit length \(L\). It covers the paper’s intensity-elicitation result, not its existence theorems, allocation algorithm, or incentive analysis. The authors should recognize it as their problem: eliciting ordinal intensities is explicitly part of the paper’s proposed application, and the continuous version asks the same question once per type rather than once per person.

The weak point is substantial: exact agreement on intensity rankings may be a demanding homogeneity assumption, and the type labels cannot be inferred from preference similarity alone. Also, the continuous lift compresses repeated elicitation; it does not show that finding an intensity-efficient allocation is easy for a continuous society. That limits the breadth of the case, but not the specific mirror: under a well-defined high-multiplicity regime, it turns the paper’s named elicitation problem into a precise support-size-sensitive algorithmic question.

Further questions include whether Proposition 1’s query bound is optimal for this class, and how elicitation changes when type labels are uncertain or answers are noisy.

The case AGAINST (opponent, writing after the proponent)

Proposition 1 is a genuine computational anchor, so I can’t defeat it by saying the paper has no algorithmic result. The strongest objection is that the proposed setting changes the assignment model: the paper has \(n\) agents and \(n\) distinct indivisible items. A fixed finite menu cannot serve a growing one-to-one market. If the number of items grows with the population, then each type’s preference and intensity rankings grow with it.

Even granting that repaired setting, the query bound for a known cohort partition is simply \(\tau\) independent runs of Proposition 1: \(\tau\bigl(\binom{m}{2}-2\bigr)\) queries. The masses \(\mu_t\) do not affect which questions are asked or the answers. This is a useful compression when many agents share exactly the same unknown intensity ordering, but it adds no population-level optimization, interaction between types, or new computational bottleneck. Its substance is the paper’s existing elicitation result plus reuse of answers among identical agents.

A more ambitious version could ask the planner to discover the types or estimate the population’s distribution over intensity orders. But Proposition 1 assumes a given preference order and elicits one agent’s intensity ordering; it does not study clustering or population sampling. If the cohort partition is known, the mirror reduces to the independent runs above. If it is unknown, recovering it is an added information problem. And exact recovery of an arbitrary distribution from queries to individuals in an atomless population would need a new sampling or approximation objective.

So the negative case is strongest on payoff, not validity. The proposed finite-menu scenario does not fit the paper’s literal one-to-one model, and the repaired version is a thin, mass-insensitive query-compression result. But a known-cohort elicitation problem is author-recognizable and concerns a society represented by types. Under the programme’s stated rules, that may be enough for the anchor to survive; I can’t honestly claim the universal negative is airtight.
