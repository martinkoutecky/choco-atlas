The continuous mirror question

Given finitely many types \(T\), rational masses \(\mu_t\) summing to \(1\), waiting costs \(\theta_t\), a priority poset on types, and a specified block order for tied costs, arrange type \(t\) on an interval \(I_t\subseteq[0,1]\) of length \(\mu_t\) in nonincreasing order of \(\theta_t\). Compute each type’s limiting per-capita Priority-value utility \(p_t=-\sum_{u\in T}\mu_u h(t,u)\min\{\theta_t,\theta_u\}\), where \(h(t,u)=1\) if \(t\) has priority over \(u\), \(0\) if \(u\) has priority over \(t\), and \(1/2\) otherwise, including \(h(t,t)=1/2\); and its transfer profile \(z_t(q)=p_t+\theta_t q\) for \(q\in I_t\). Prove these are the limits of the discrete utilities and transfers scaled by population size, and that \(\sum_{t\in T}\int_{I_t}z_t(q)\,dq=0\).

The model it lives in

A fixed-support queueing population with type masses \(\mu_t\), waiting costs \(\theta_t\), and a poset over types. The outputs are per-capita utilities \(p_t\) and position-dependent transfers \(z_t(q)\); there is no optimization objective, and direct evaluation takes \(O(\tau^2)\) arithmetic operations after ordering the types.

What the mirror covers

The mirror covers Proposition 6’s queueing allocation and transfer formulas. It leaves the axiomatic characterizations, the general TU-game setting, Proposition 7’s bankruptcy application, and the paper’s other comparisons untouched.

The case FOR (proponent)

The strongest population mirror is the queueing application in Proposition 6, proved in this paper. For a chosen optimal queue \(\sigma\), it computes the Priority value for each agent from the pairwise dividends \(-\min\{\theta_i,\theta_j\}\): agent \(i\) receives the full dividend from a pair if \(i\) has priority over \(j\), none if \(j\) has priority over \(i\), and half if they are incomparable. Equivalently,
\[ P_i=-\sum_{j\ne i} h(i,j)\min\{\theta_i,\theta_j\}, \]
where \(h(i,j)\) is \(1\), \(0\), or \(1/2\) in those three cases. The proposition also gives the transfer implementing utility \(P_i\):
\[ t_i=P_i+(\sigma(i)-1)\theta_i. \]
This is the content of its displayed formulas (8) and (9).

A plausible regime is a very large service queue—say, a city processing recurring requests—with many requests but few classes. A type records a request’s waiting cost \(\theta_t\) and its priority relations to the other classes. Agents of the same type are incomparable with one another and otherwise share the same characteristics. Thus the population size \(n\) can be much larger than the support size \(\tau\).

Here is the continuous problem I would propose, as a mirror of that application. The input is a finite set of types \(T\), rational masses \(\mu_t\geq 0\) summing to \(1\), waiting costs \(\theta_t\), a strict partial order \(\succ\) on distinct types, and a specified type-block optimal queue for resolving ties in waiting cost. Each type occupies an interval \(I_t\) of queue positions \(q\in[0,1]\), of length \(\mu_t\); the queue orders types by nonincreasing \(\theta_t\). Set \(h(t,u)=1\) if \(t\succ u\), \(0\) if \(u\succ t\), and \(1/2\) if they are incomparable, including \(t=u\). The task is to return the per-capita utility \(p_t\) and transfer profile \(z_t(q)\) that implement the continuum limit of Proposition 6:
\[ p_t=-\sum_{u\in T}\mu_u h(t,u)\min\{\theta_t,\theta_u\}, \qquad z_t(q)=p_t+\theta_t q\quad(q\in I_t). \]
A solution must give those exact values, so that utility at position \(q\) is \(z_t(q)-\theta_t q=p_t\), and total transfers balance:
\[ \sum_{t\in T}\int_{I_t}z_t(q)\,dq=0. \]
This is the \(n\to\infty\) limit of dividing the discrete utilities and transfers by \(n\). With rational finite-support input, the values are computable in \(O(\tau^2)\) arithmetic operations, plus ordering the types. I expect this particular mirror to be tractable.

The model is close to the paper’s queueing application: it retains its waiting costs, priority structure, queue, Priority value, and budget-balanced transfers. It covers only that application, not the paper’s axiomatic characterizations. A large service cohort with stable request classes is a credible high-multiplicity setting, though the queue position still determines each request’s transfer.

There is a strict limitation: the paper contains no named computational result in the sense required here. Its propositions characterize allocation rules or give allocation formulas; none asserts a problem is in P, NP-hard, FPT, or similar. So Proposition 6 is the nearest mathematical foothold, but it is not a qualifying complexity anchor under your stated rule. The main weakness is also substantive: this mirror turns an already explicit pairwise calculation into a population limit. It is recognizable as an extension of the authors’ application, but it supplies little of the complexity question or optimization-driven motivation that ChoCo is meant to study.

The case AGAINST (opponent, writing after the proponent)

The strongest case against is that this paper has no computational result to continue. Propositions 1–5 characterize an allocation rule or derive its axioms; Propositions 6–7 give formulas for queueing and bankruptcy applications. None poses a computational problem or establishes a complexity result. There is no discrete algorithmic question here whose high-multiplicity version could reveal a tractability boundary.

Proposition 6 is the best possible foothold, and the proposed queueing model is coherent. A large queue with recurring request classes is a plausible high-multiplicity regime, and the position-dependent transfer profile is a sensible mass-scaled version of the paper’s application. The model does not fail because it treats agents of a type alike.

Its limitation is what it asks us to compute. Proposition 6 already gives the allocation through pairwise dividends, and the optimal queue is obtained by sorting waiting costs. The proposed continuous output follows from pairwise sums over the \(\tau\) types, in \(O(\tau^2)\) arithmetic operations. That is a valid continuous reformulation, but it does not mirror a computational result in the paper or expose an algorithmic obstacle of the kind ChoCo is meant to chart.

A broader attempt—to compute the Priority value for general TU games—runs into a modeling problem. The value depends on Harsanyi dividends for named coalitions. In a general game, agents’ coalition interactions can differ even when their other attributes match, so a small list of types need not preserve the information needed to compute the value. If worth instead depends only on type masses, then in an atomless population every finite coalition has mass zero. Recovering a nontrivial value would require a new continuum game model and a new allocation rule, rather than a direct continuation of the paper’s finite-coalition construction.

That leaves the queueing limit as a plausible and perhaps useful extension. I cannot honestly argue that it is an incoherent question or that no researcher could find it worthwhile. The negative case is narrower: under ChoCo’s stated focus on computational questions and complexity landscapes, this paper offers no computational result to mirror, and the queueing anchor supplies a formula-evaluation problem rather than one drawn from the paper’s computational theory. If a continuous limit of an explicit allocation formula counts as sufficient, this anchor remains the weak point in the case against.
