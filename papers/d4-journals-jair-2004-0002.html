What the mirror covers

The proposal concerns Theorem 1's preference-optimal model selection. It leaves the model-space construction, ecological examples, and the paper's informal complexity analysis outside the mirror.

The case FOR (proponent)

The strongest case is a continuous population of model-construction requests, not a continuum of ecological outcomes. Imagine a very large regional simulation needing a model for each landscape unit. Many units can share the same scenario structure, repository, hard requirements, and preference calculus: for example, cells in the same habitat and management class. The cells are the repeated requests; the organisms inside the ecological models are not the agents in this mirror. A plausible regime is hundreds of thousands of cells but only tens or hundreds of distinct request types.

My lead question is High-Multiplicity Repository Model Selection\(_\infty\). An instance gives a finite support \(T\) of request types and rational masses \(\mu_t\ge 0\), with \(\sum_{t\in T}\mu_t=1\). Each type \(t\) specifies a complete scenario, the model-fragment repository, the hard requirements, and its preference assignments. Let \(F_t\) be the set of complete scenario models that the repository can construct for that type while satisfying its dynamic and compatibility constraints. For every \(M\in F_t\), let \(v_t(M)\) record the basic preference quantities (BPQs) contributed by the model’s active design decisions.

The decision is a rational mass allocation \(x_{t,M}\ge 0\), where \(x_{t,M}\) is the fraction of the whole population of requests of type \(t\) assigned model \(M\). Require \(\sum_{M\in F_t}x_{t,M}=\mu_t\) for every \(t\). Each individual site still receives one complete model; the fractional allocation represents how many sites in a large group receive each model. Compare allocations using the paper’s order-of-magnitude preference calculus, extending BPQ occurrence counts from natural numbers to rational weights. The task is to return a feasible allocation for which no other feasible allocation has strictly greater aggregate preference. This is a population-level version of the model-selection problem the repository is built to solve.

The anchor is Theorem 1, proved in this paper. It states that SOLVE(X, D, C, A, P) is admissible: given an aDPCSP, it returns a consistent assignment to the attributes active under the activity constraints, satisfying the applicable compatibility constraints, whose combined OMP is maximal among the aDPCSP’s solutions. The theorem establishes the correctness of the paper’s A* search for preference-optimal model selection. It does not establish polynomial running time: the paper’s complexity discussion says the search can grow exponentially with the number of assumptions and that the A* method has exponential space complexity. The underlying question being mirrored is the choice of a consistent, preference-maximal ecological model—not the encoding of that choice as an aDPCSP.

I expect hardness to transfer in the general mirror, rather than the population size itself to create new hardness. In the one-type case, with mass \(1\) and a total preference order, an optimal allocation has a deterministic optimum: it assigns all mass to an optimal complete model. That case retains the original model-search problem. Repeating the same request many times therefore need not make the design search harder, but making the society continuous does not remove the combinatorics already present in each type. The resulting questions are whether pricing over feasible models can be done efficiently for useful repositories, whether runtime can be bounded in \(\tau\) and the largest type’s design description, and whether fractional allocations ever improve the optimum under the paper’s partial preference order. The paper itself proves no NP-hardness result for its ecological model-selection instances, so this is a prediction about the mirror’s likely boundary, not a hardness theorem attributed to the authors.

The mirror covers Theorem 1’s preference-optimal model selection, in a batch setting with many repeated ecological requests. It does not continuize the ODEs, the ecological populations, or the preference scale for its own sake; fractional BPQ counts arise because the request population is continuous. The weakest point is that the paper constructs a model for a given scenario, while my mirror batches many scenarios. Its repository goal and large-scale ecological application make repeated model-construction requests plausible, but the paper does not study cross-request allocation or aggregation. A referee could reasonably accept this as a high-multiplicity deployment of the authors’ problem, while also judging it a modest extension rather than the paper’s original setting.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is the only strong anchor, but its claim is about the correctness of a generic search procedure: for a given aDPCSP, it returns a preference-maximal consistent assignment. It says nothing about running time or a complexity class. The paper’s own complexity discussion instead describes exponential growth in the number of assumptions. So the proposed mirror has no complexity result to continuize; its nearest target is the same correctness guarantee for a batch of requests.

The batch scenario is plausible—the paper mentions building models for large-scale simulations—but the proposed allocation turns repeated uses of a model repository into a collective decision problem. In the paper, a user specifies requirements and preferences for one scenario, and the repository selects a model for it. The paper gives no shared limit, trade-off, or other coupling across scenarios that would make allocating different models to different sites a decision the user needs to make. For identical requests, a split among models is just a portfolio imposed on the workflow; for distinct requests, aggregating their preferences requires a new common objective that the paper does not define. Adding capacity limits or portfolio goals could make an interesting problem, but it would supply the missing decision structure rather than mirror Theorem 1.

A stronger alternative would treat the ecological populations in one scenario as the repeated units. But the repository’s model choices depend on which populations are linked by predation and competition, and the output contains equations for those particular participants and relations. A type would therefore need to preserve each unit’s relational context. If it does, the type support retains the scenario’s structural distinctions; if it does not, a distribution of local types no longer determines which model fragments can compose. A continuum interaction model might address that issue, but it would change the modeling formalism and the computational problem.

The negative case is weakest where the paper itself points to large-scale model construction: repeated, independent scenarios are a credible deployment regime. That supports batching and deduplication as useful engineering. It does not give this paper a compelling continuous mirror of its main result: the population would be a collection of model-building jobs, while the theorem concerns one job’s search for a preferred model.
