The case FOR (proponent)

There is a plausible continuous-population version of this paper’s offline TSF allocation problem, but I cannot honestly tie it to a qualifying anchor. The paper’s numbered theorems prove fairness properties and special-case equivalences; none classifies a problem as polynomial-time solvable, NP-hard, or similar. Algorithm 1 computes the finite-user allocation through repeated LPs, but it is not a numbered complexity result.

The closest named support is Theorem 1, proved here: if each user’s dedicated pool lets them run \(k_i\) tasks, then reallocating the shared resources using TSF with weight \(w_i=k_i/h_i\) lets every user run at least \(k_i\) tasks, where \(h_i\) is what that user could run on the whole datacenter without placement constraints. That is a service-guarantee theorem, not a computational-complexity anchor.

A concrete candidate is Continuous TSF Allocation. The instance has machines \(M\), resource types \(R\), rational capacities \(C_{mr}\), total job mass \(P\), and a finite support \(T\) of job types with fractions \(\mu_t>0\) summing to one. A type specifies its task demand \(d_{tr}\), eligible machines \(p_{tm}\in\{0,1\}\), and weight \(w_t>0\). Assume each type has enough ready tasks for the static allocation being computed. The solution assigns each member of type \(t\) an average \(q_{tm}\ge 0\) tasks on machine \(m\), with \(q_{tm}=0\) when \(p_{tm}=0\), and

\[ P\sum_{t\in T}\mu_t q_{tm}d_{tr}\le C_{mr} \quad\text{for every }m,r. \]

Let \(h_t\) be the maximum number of tasks of type \(t\) that could run on the whole datacenter if its placement constraints were removed. The type’s weighted task share is \(s_t=\sum_m q_{tm}/(h_tw_t)\). The question is to return a feasible allocation that achieves TSF: whenever an increase to a type’s allocation is possible, some positive-mass type with an equal or lower weighted task share must lose allocation.

A credible regime is a large fleet with many concurrently active, backlogged jobs drawn from a much smaller set of standard resource profiles, machine whitelists, and service tiers—for example, thousands of jobs across dozens of recurring workload configurations. Those fields define the type; job names do not. The population is the continuous object, while per-type task averages can be fractional even though individual tasks are integral.

For this candidate problem, I expect Class A: compute each \(h_t\), then apply progressive filling over the \(\tau\) supported types using LPs with \(O(\tau |M|)\) allocation variables. With rational input, the number of rounds is bounded by the number of types, so the resulting computation appears polynomial in the support size, machine and resource counts, and bit length. It also generates follow-up questions about exact high-multiplicity rounding and the relation between this static allocation and the paper’s online, indivisible-task scheduler.

The strongest point is that this mirror keeps the paper’s placement constraints, multiple resources, task-share objective, and TSF rule while making the *job population* a distribution over complete job types. The weakest point is decisive for the requested anchor test: the paper already gives a finite-user LP approach for the offline divisible-task setting, so the continuous version looks like a natural aggregation of its allocation method, but not a continuation of a named computational-complexity result. My positive case is therefore for a plausible continuous mirror of the underlying problem, not for an anchored continuization of one of the paper’s numbered results.

The case AGAINST (opponent, writing after the proponent)

The strongest negative point is that the proposed mirror does not actually continue Theorem 1. That theorem proves a service guarantee: given dedicated pools and weights \(w_i=k_i/h_i\), the TSF allocation lets each user run at least \(k_i\) tasks. Its proof compares TSF with the feasible allocation that simply keeps those pools. It makes no claim about computational complexity. The proposed “Continuous TSF Allocation” instead asks how to compute an offline TSF allocation—the subject of Algorithm 1. So it may be a sensible problem, but it is not a computational result anchored in Theorem 1. The paper’s other numbered theorems are likewise fairness properties or special-case equivalences, not complexity classifications.

The best version of the proposal is a high-multiplicity TSF problem: many backlogged jobs share a small number of complete profiles, and the fleet scales with the population. That is a plausible regime, and the resulting type-mass allocation is coherent. But its offline computation aggregates identical rows of the paper’s existing progressive-filling LP; it does not expose a new pricing or optimization obstacle. To make the computational question more substantial, one could add indivisible tasks, finite backlogs, or arrivals. Those features also distinguish jobs that the proposed type definition merges, so the support-sensitive continuous formulation no longer captures the operational problem as stated. Studying the resulting rounding or online behavior could be worthwhile, but it would be a new algorithmic project rather than a mirror of Theorem 1.

That is a strong case against this paper as a *ChoCo-anchored* candidate: there is no named computational result to continuize, and the proposed computation is already the paper’s offline LP method in aggregated form. I cannot honestly make the stronger universal claim that no worthwhile continuous mirror exists in any scenario. The repeated-profile datacenter regime survives the basic objections; the weakness is the missing computational anchor, not an implausible population model.
