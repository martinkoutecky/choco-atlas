The continuous mirror question

Given criteria with binary reference scales and a finite support \(T\) of complete user types, each with rational mass \(\mu_t\), preference data \(P_t\), and a necessary query \((x_t,y_t)\), determine for each type whether an \(E_2\) explanation exists and output one when it does. For batches in which every type is explainable, choose explanations minimizing the expected number of comparison steps, \(\sum_{t\in T}\mu_t q_t\), where \(q_t\) is the explanation length.

The model it lives in

A batch explanation service over a distribution of decision makers: each type includes its binary reference scales, complete preference data, and query; the service returns a valid \(E_2\) explanation per type and minimizes the mass-weighted average explanation length.

What the mirror covers

Covers the binary-scale \(E_2\)-explainability characterization in Theorem 8 and its batch use; leaves the general-scale unbounded-length result and the paper’s broader preference characterizations outside the mirror.

The case FOR (proponent)

The best positive case is a batch explanation service for a high-multiplicity population of decision makers. It keeps each explanation problem intact and continuizes the population the service handles.

My lead anchor is Theorem 8, proved in this paper. For a necessary preference query \(\sigma\) on binary reference scales, it gives four equivalent conditions for an \(E_2\) explanation: such an explanation exists; the query covector is a positive integer multiple of a nonnegative integer combination of necessary two-criterion swap covectors and dominance covectors; the graph of necessary swaps from \(\sigma\)’s positive arguments to its negative arguments has a matching covering every negative argument; or, equivalently, there is an injection from the negative arguments to the positive ones that matches each negative criterion to a criterion whose increase necessarily compensates for it. Here \(E_2\) means a sequence of necessary comparisons, each a dominance step or a preference swap involving at most two criteria. The matching condition is the useful computational content: the paper’s Algorithm 1 tests candidate swaps with LPs and then finds a matching.

I would formulate the continuous mirror as Continuous Batch \(E_2\)-Explanation. An instance has \(d\) criteria with binary reference scales \(V_i=\{\bot_i,\top_i\}\), and a finite support \(T\) of stakeholder types with rational masses \(\mu_t>0\) summing to one. Each type \(t\) specifies its full elicited comparison set \(P_t\) and the recommendation pair \((x_t,y_t)\) to explain. The query is promised to be necessarily preferred under that type’s robust additive model. Members of a type share all the data the explanation problem uses; their mass is their fraction of the population.

For each supported type, the task is to produce a sequence from \(x_t\) to \(y_t\) whose every step is a dominance relation or a necessary two-criterion preference swap under \(P_t\). If no such sequence exists for some type, report that. Among feasible policies, minimize the expected number of comparison steps, \(\sum_{t\in T}\mu_t q_t\), where \(q_t\) is the length of type \(t\)’s explanation. Thus the decision variable is a reusable explanation per type, and the objective is the average explanation length for a randomly selected person.

The scenario is a large public-facing recommendation or decision-support service: many residents or customers receive recommendations over the same small catalog of alternatives, and the service elicits preferences through a standardized set of binary comparisons. If there are \(R\) users but only \(\tau=|T|\) distinct complete elicitation-and-query profiles, then \(R\) can be very large while \(\tau\) remains moderate. The users’ shared type data make them indistinguishable for this task, and \(\mu_t\) expresses the fraction receiving the same explanation. A discrete service with type counts \(r_t\) maps directly to \(\mu_t=r_t/R\).

The matching characterization makes this a credible Class A problem. For each type, test the at most \(d^2\) candidate swap relations, construct the bipartite graph, and find a matching; repeat over the \(\tau\) supported types and weight the resulting lengths by \(\mu_t\). This gives an algorithm polynomial in \(d\), \(\tau\), the preference-data size, and the rational input bit length. The mass-weighted objective is also computable exactly. The continuous extension adds a batch objective, while its per-type explanations remain exactly the paper’s underlying problem.

A second, narrower anchor is Corollary 1, also proved here. It says that with binary reference scales and \(P\subseteq\Delta_2\), every necessary preference has an \(E_2\) explanation: \(N=E_2\). Its continuous counterpart is the same batch problem restricted to types whose elicited preferences are all pairwise swaps. Under the promise that each type’s query is necessary, this version is guaranteed feasible for every positive-mass type. Theorem 8 is the stronger lead because it also characterizes when an explanation exists for more general preference information.

The paper gives no named hardness result or numbered theorem classifying a problem as polynomial-time solvable. These are algorithmic anchors instead: the numbered structural characterization is Theorem 8, and the paper’s actual polynomial computation is described in Algorithm 1. There is no hardness finding here to transfer or dissolve.

The weakest point is that this is a population-level workload of separate explanations, not a single collective preference relation. Mass affects the average service objective, not whether any individual type’s preference is necessary. That distinction may lead the authors to see this as their explanation method deployed at scale, rather than a new aggregate theory of explanation. I think it still clears the mirror’s plausibility gate: the type-level question and explanation steps are unchanged, and the continuous object is genuinely the distribution of people served. Its scope is correspondingly narrow: it mirrors the binary-scale explanation characterization, not the paper’s general unbounded-length result or a theory of collective utility.

Further questions follow naturally: can a service build a shared explanation template across types while preserving validity for each, and how does the picture change if the reference scales are not binary?

The case AGAINST (opponent, writing after the proponent)

Theorem 8 is a real algorithmic result, but its computational object is one decision maker’s query. In a batch version, a complete type would include that person’s preference data \(P_t\) and the pair \(\sigma_t\) to explain. The necessary-swap graph and matching are then constructed separately for each type. Minimizing expected explanation length, \(\sum_t \mu_t q_t\), has independent constraints for each type, so it decomposes into separate explanation problems. Mass records how often each query occurs; it does not affect which explanations are valid or how they are found. Repeated users let a service reuse an answer, while many distinct profiles increase the support size \(\tau\). Neither turns the theorem’s per-person relation into a population-level computational problem.

Corollary 1 makes the same point especially clearly: under its pairwise-input condition, explainability is guaranteed separately for each type, regardless of its mass or the rest of the population. It is not a second population-sensitive anchor.

The stronger possible mirror is a shared explanation policy: choose common templates or swap orderings across different types, perhaps to minimize average explanation length. The paper’s discussion of batch explanations and common reference values gives this idea some footing. But the formal model supplies no common policy constraint or measure of how persuasive a step is to different recipients; it says those choices depend on context and still need empirical study. Adding a shared message budget, readability model, or fairness condition could make population masses matter, but the resulting task is service design layered over the paper’s explanation method. Alternatively, defining one collective preference from the decision makers’ utilities would require interpersonal comparison or an aggregation rule that the paper does not provide; it explicitly avoids assuming that utility scales are commensurate.

So the strongest negative case is that the proposed mirror aggregates requests for individual explanations rather than continuizing the paper’s preference or explanation problem. That is a meaningful boundary, but not an airtight one: the authors’ batch discussion makes shared explanation policies a plausible extension. If they regard that service-design question as their problem, the negative case may not defeat the mirror.
