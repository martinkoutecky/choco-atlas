  • Theorem 4 — survived: The opponent concedes it is a computational result and challenges the population-level value of batching, which the proponent already acknowledges.

The continuous mirror question

Given shared variables and domains and supported types \(t=(L_t,C_t)\) with binary-rational masses \(\mu_t\ge0\), \(\sum_t\mu_t=1\), compute each type's \(L_t\)-maximal feasible outcome \(o_t\), or report that \(C_t\) is infeasible, and report \(\nu_o=\sum_{t:o_t=o}\mu_t\) for each resulting outcome \(o\).

The model it lives in

Each type is a complete pair \(t=(L_t,C_t)\) of an LP-tree and its constraints over shared variables; its mass \(\mu_t\) is its population fraction. The decision variables are the outcomes \(o_t\), each required to satisfy \(C_t\) and be maximal under \(L_t\); the output also gives their masses \(\nu_o\), with no cross-type welfare objective.

What the mirror covers

Covers Theorem 4's constrained LP-tree optimization guarantee; leaves Theorem 3's CPR-net optimization and the Acyclic-CP-DT dominance-testing results alone.

Open questions for a prover

  • What runtime bound does Search-LP achieve as a function of the instance size, and can repeated types be compressed beyond deduplication? The paper describes the constrained LP-tree problem as NP-complete in prose but gives no numbered hardness result.

The case FOR (proponent)

The strongest case is narrow: a population can be a high-multiplicity batch of the constrained preference-optimization problem in Theorem 4. The theorem is proved in this paper. It says that, for an LP-tree \(L\) and hard constraints \(C\) over variables \(V\), Search-LP returns an outcome \(o\) if and only if \(o\) is the most-preferred feasible outcome under \(L\) and \(C\). It is an algorithm-correctness result, not a polynomial-time or hardness classification. I find no numbered result in the paper that establishes such a complexity classification; §4.4 says in prose that the problem is NP-complete.

A plausible regime is a product-configuration or recommendation service with many users choosing from the same catalog under the same feasibility constraints. A user type \(t\) consists of a complete LP-tree \(L_t\) and constraint set \(C_t\), along with the shared variable domains. Users of one type are indistinguishable for this task. The society is a distribution \(\mu\) over the \(\tau\) supported types: \(\mu_t\) is the fraction of users with that preference-and-constraint pair. The intended high-multiplicity regime has many users but relatively few distinct types.

Call the mirror Mass-LP-Tree Best-Feasible Configuration. Its instance is the shared variables and domains, the supported types \(t\), and their binary-rational masses \(\mu_t\). For every type \(t\), find a feasible outcome \(o_t\) such that no feasible outcome is preferred to \(o_t\) by \(L_t\); if \(C_t\) is infeasible, report that. Since an LP-tree represents a total order, each feasible type has a unique answer. The population-level result is the map \(t\mapsto o_t\), together with the outcome masses \(\nu_o=\sum_{t:o_t=o}\mu_t\). The objective is type-wise: give each type its most-preferred feasible configuration. This does not introduce a trade-off between types or a collective welfare objective.

I expect hardness to transfer (Class B), not a continuum-specific complexity shift. Setting \(\mu_t=1\) for one type recovers the original constrained LP-tree problem, so the mass formulation cannot remove its worst-case difficulty. The paper’s §4.4 describes that problem as NP-complete, though that claim is not established by a numbered theorem here. A useful follow-up would be to formalize the discrete-to-mass dictionary and ask whether a small support \(\tau\) enables efficient preprocessing or batch computation when each type’s underlying optimization remains hard.

The authors could plausibly recognize this as their problem applied across a high-multiplicity user base: the per-type question is exactly the one Search-LP solves, and the paper itself names recommendation and product configuration as motivating applications. The weak point is that this is essentially repeated independent optimization. Population mass compresses redundant users, but adds no coupling or new optimization structure. A referee could therefore accept the mirror as a sensible deployment regime while judging it a modest continuization result rather than a new collective problem. It covers Theorem 4’s constrained LP-tree optimization; it does not stretch to the paper’s CPR-net or dominance-testing results.

The case AGAINST (opponent, writing after the proponent)

Theorem 4 is a real computational result: it proves that Search-LP returns the most-preferred feasible outcome. And the proposed customer cohort is plausible. A type consisting of an LP-tree and its constraints is a complete description for this task, so repeated users of that type are a sensible high-multiplicity regime. I would not reject the mirror on the grounds that the people cannot be grouped.

The problem is that its population query is only a direct product of the paper’s individual queries. For each supported type \(t\), run Search-LP once to obtain its unique best feasible outcome \(o_t\), then report \(\nu_o=\sum_{t:o_t=o}\mu_t\). The masses do not affect feasibility, preference comparisons, or which outcome Search-LP selects. The population version of Theorem 4 therefore says that Search-LP is correct for each type, followed by rational additions to compute the outcome masses. That is a valid batch workload, but it adds no population-level computational question.

The strongest rescue is to use the resulting masses to estimate product demand. That could be useful in a recommendation service, but demand estimation is not an objective or query in this paper. Making supply scarce, coordinating users’ choices, or optimizing group welfare would make population composition affect the computation. Those additions define a coupled allocation or aggregation problem; the paper’s constraints govern one person’s configuration, and its qualitative preferences provide no rule for trading off one person’s outcome against another’s.

So the case against is not that the cohort is implausible. It is that the faithful mirror of Theorem 4 remains independent constrained optimization, repeated once per supported type. A nontrivial society-level problem requires new structure beyond the paper’s model. The negative case is weakest on practical relevance: authors could reasonably recognize this as a batch application of their solver. Whether that justifies ChoCo’s time depends on whether batch deployment alone counts as a worthwhile computational mirror.
