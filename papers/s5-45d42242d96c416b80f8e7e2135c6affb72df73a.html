The continuous mirror question

Given a finite candidate set \(C\), rational type masses \(\mu_t\), per-capita weights \(w_t\), and an acyclic type-level delegation forest, an unvoted unit of type \(t\) delegates uniformly across its parent type’s pool. Given an online sequence of events \((t,\delta,c)\), each selecting mass \(\delta\) symmetrically from the still-unvoted mass of type \(t\) to vote for \(c\), compute the exact candidate tally vector after every event. Determine whether this can be done in time polynomial in the number of candidates, the number of types, the event count, and the input bit length, independent of the represented population size.

The model it lives in

A society consists of rational masses \(\mu_t\) over finitely many types, each with a common per-capita weight \(w_t\) and a parent-type role \(p(t)\). For each candidate \(c\), let \(q_t(c)\) be the fraction of type \(t\) that has voted directly for \(c\), and let \(\bar q_t=1-\sum_c q_t(c)\). Under uniform mixing, \(r_t(c)=q_t(c)+\bar q_t r_{p(t)}(c)\), with \(r_{\bot}(c)=0\), and the tally is \(V_c=\sum_t\mu_t w_t r_t(c)\). A mass event updates \(q_t\), after which the exact tally is recomputed along the type forest.

The objection that survived

Theorem 1 handles one address at a time on an arbitrary named forest, while the mirror assumes exchangeable delegation pools and mass events, removing identity-dependent updates.

fatal: False

What the mirror covers

The mirror covers Theorem 1’s tally update and display task in an exchangeable mass regime. It leaves aside the paper’s Merkle proofs, address checks, preparation protocol, and gas accounting.

Open questions for a prover

  • Does exact tallying remain polynomial in the number of types when each type can delegate across multiple parent pools?
  • How does the complexity change if the type-level delegation structure permits cycles handled by an edge-deletion rule?

The case FOR (proponent)

The strongest mirror I see is an exchangeable mass liquid-democracy tally. The anchor is Theorem 1, proved in this paper: for each incoming voting message, the algorithm updates and displays the candidates’ voting status in \(O(\log n)\) time, and the authors claim it can run on Ethereum for more than one million voters despite the gas limit. The paper derives the update bound from its interval-tree operations; the Ethereum deployability claim is supported by the experiments, while the theorem’s text says that part of the proof is left to the experiment section. This is the paper’s only named computational theorem, so there is no comparable hardness result to prefer.

Here is a continuous version of the tally problem. Let \(C\) be the finite candidate set and \(T\) a finite set of voter types. A type records the features relevant to this tally problem: per-capita voting weight \(w_t\), any preference or voting-policy information the model uses, and a delegation role \(p(t)\). The type masses \(\mu_t\) are nonnegative rationals summing to one. The types form a fixed acyclic delegation forest: members of type \(t\) delegate to uniformly mixed members of parent type \(p(t)\), or have no parent. The uniform mixing is part of the model: individual delegate identities are exchangeable within a parent pool.

An instance also gives an online sequence of events \((t,\delta,c)\). An event selects mass \(\delta\) from the still-unvoted mass of type \(t\) to vote directly for \(c\). Selection is symmetric within that type, and no voter’s mass may vote twice. The task is to output the exact candidate tally-mass vector after every event, including the loss to the previous delegate’s tally when mass votes directly. Call this problem Exchangeable Mass Liquid-Democracy Tally. Its solution is an online algorithm returning all \(V_c\) exactly, with running time polynomial in \(m\), \(\tau=|T|\), the event count, and the input bit length \(L\), with no dependence on the number of represented voters.

The mass semantics are explicit. Let \(q_t(c)\) be the fraction of type \(t\) that has directly voted for \(c\), and \(\bar q_t=1-\sum_{c\in C}q_t(c)\). Let \(r_t(c)\) be the fraction of type \(t\)’s own voting weight that currently reaches candidate \(c\) through delegation. Under the exchangeable delegation rule,

\[ r_t(c)=q_t(c)+\bar q_t\,r_{p(t)}(c), \qquad r_{\bot}(c)=0, \]

and the displayed tally is

\[ V_c=\sum_{t\in T}\mu_t w_t r_t(c). \]

An event updates \(q_t\) by \(\delta/\mu_t\); recomputing these values along the type forest gives the new tallies. A direct implementation takes \(O(m\tau)\) arithmetic operations per event. The output is deterministic mass, not a lottery over winners: the population is atomless, so type-level proportions split exactly. Candidates remain discrete.

The intended regime is a large DAO or civic platform with many members routed through a small system of interchangeable proxy pools—for example, members grouped by stake band and delegation role, with assignments within each pool exchangeable. There might be millions of voters but only tens or hundreds of types. For a finite population, \(\mu_t=n_t/n\) and an event’s mass is \(\delta=d/n\); this is the high-multiplicity limit of the corresponding type-cohort process under the same exchangeability assumptions. It does not purport to reproduce every named-delegate graph.

I think the authors would recognize the underlying question: keep the live liquid-democracy tally correct as voters take back their delegated power and vote directly. The mirror changes individual messages into mass events and replaces named proxy identities with exchangeable proxy roles, while leaving the population—not the candidate space—as the continuous object. It covers Theorem 1’s tally-update and display task. It does not mirror the paper’s Ethereum address checks, Merkle proofs, or gas accounting.

I expect this mirror to be tractable: the recurrence over the type forest already gives a polynomial-time algorithm. Further questions include whether the recurrence extends to multiple proxy pools per type, cycles handled by the paper’s edge-deletion rule, or compactly represented nonuniform delegation couplings. A sharper boundary question is whether exact tallying remains polynomial in \(\tau\) when identities matter within a type.

The weak point is real: the paper’s algorithm handles an arbitrary fixed delegate tree and tracks exact named voters, while this mirror assumes exchangeable delegation and computes type-level mass. If the authors require arbitrary identity-specific delegation to remain part of the problem, they may reject it as too restricted. Its positive case rests on a plausible large-population regime where pool identity is deliberately irrelevant—not on a claim that the paper’s general graph is already continuous.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is a real computational anchor, so the negative case cannot rest on the paper lacking a complexity result. The difficulty is that its computational object is an individual transaction on a named delegate forest. The contract authenticates one sender, locates that sender’s place in the tree, and updates the exact tally after that voter takes back their delegated power. Which subtree the sender occupies—and which parts of it have already voted—determines the update.

Preserve that exact behavior and the type has to capture a voter’s relevant place in the delegation structure, not just their ballot or stake. On a long chain, voters at different depths have different effects on future updates, so the support can grow with \(n\). The society is then effectively \(n\) individually specified voters with masses \(1/n\), and a single transaction changes mass \(1/n\). There is no fixed, small type space behind the \(O(\log n)\)-per-transaction result.

Collapse voters into exchangeable types, as the proposed mirror does, and the exact tally is no longer determined by the type-level voting fractions alone. For example, take two identical proxies and two identical delegators, each delegator assigned to one proxy. One proxy votes for \(A\), and one delegator votes for \(B\). If the \(B\)-voter was assigned to the proxy who voted, \(A\) gets no delegated vote; if assigned to the other proxy, the unvoted delegator still gives \(A\) one vote. The type masses and direct-voting fractions are identical in both cases. Uniform mixing can define an expected or limiting tally, but that is not the exact tally after the sender’s transaction. Adding the assignment correlations back into the state restores the information the aggregation removed.

There is a second mismatch in the computational unit. In an atomless population, one voter has zero mass, so one incoming message has zero tally effect. Give an event positive mass \(\delta\), and it represents a cohort update—many messages at once—rather than the single transaction whose gas cost Theorem 1 bounds. That cohort model may be mathematically sensible, and a repeated exchangeable delegation structure may be plausible. But its update question does not retain the paper’s exact per-address self-tallying task.

So this is a strong objection to the proposed mirror as a mirror of Theorem 1: preserving exactness makes the relevant support grow with the graph, while keeping a compact exchangeable model changes the tally semantics or batches the events. I cannot honestly make that airtight for every scenario. A large system with genuinely interchangeable cohorts could support a worthwhile continuous mass-tally problem, and the authors might recognize it as related work. The negative case is strongest on the narrower point that this would be a new aggregate delegation model, not a continuization of the paper’s defining per-transaction result.
