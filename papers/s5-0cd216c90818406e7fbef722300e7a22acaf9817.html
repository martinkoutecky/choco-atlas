The continuous mirror question

Given providers \(N\), supported visitor types \(\mathcal T\subseteq 2^N\), rational masses \(\mu_A>0\) with \(\sum_{A\in\mathcal T}\mu_A=1\), and per-capita-scaled provider costs \(C_i\), compute each type's aggregate charge \(y_A=\mu_A\sum_{i\in A} C_i/d_i\), where \(d_i=\sum_{A\in\mathcal T:i\in A}\mu_A>0\).

The model it lives in

A society is a distribution over service-use types \(A\); provider \(i\)'s cost \(C_i\) is scaled to unit population, and that cost is shared equally across its user mass \(d_i\). Each type receives aggregate charge \(y_A\), or per-member charge \(y_A/\mu_A\).

The case FOR (proponent)

The strongest positive case is for a natural high-multiplicity version of the paper’s cost allocation problem. But there is an important limit: the paper has no named computational result asserting a problem is tractable or hard. Theorem 1, proved here, says the equal allocation method is the unique one satisfying Additivity, Anonymity, and No Blind Cost. Proposition 1, also proved here, says that this method equals the Shapley value of the paper’s cost game. Both are mathematical characterizations; neither classifies the complexity of computing an allocation. So neither qualifies as an anchor for the requested computational mirror.

An unanchored candidate is Continuous Equal-Use Cost Allocation. Let \(N\) be the service providers and let each visitor type \(A\subseteq N\) specify exactly which providers that type uses. The input is a support \(\mathcal T\) of \(\tau\) types, rational masses \(\mu_A>0\) summing to \(1\), and per-capita-scaled provider costs \(C_i\); require each provider to have positive user mass \(d_i=\sum_{A:i\in A}\mu_A\). The output is the total charge allocated to each type:
\[ y_A=\mu_A\sum_{i\in A}\frac{C_i}{d_i}. \]
This divides each provider’s cost equally across the mass using it, and the type allocations sum to \(\sum_i C_i\). In the discrete model, a type with \(n_A\) visitors receives \(n_A\) times the per-visitor charge; taking \(\mu_A=n_A/n\) and \(C_i=c_i/n\) gives precisely the same rule. The question is to compute the vector \(y\), not to optimize an objective: the paper defines an allocation method, not an optimization problem. The formula suggests a polynomial-time computation in the input size.

A plausible regime is a large seasonal visitor population or a large group of residents using shared services, with types given by repeated service-use patterns. The number of people can greatly exceed the number of distinct patterns, while the providers remain fixed or few. That fits the paper’s stated two-group cost-sharing setting, and the authors could plausibly recognize it as their model at high multiplicity.

The weak point is decisive for this assignment: the continuous computation looks like a direct restatement of the paper’s formula, and no numbered computational result anchors it. The paper’s comparative-statics examples are not numbered results either. Thus there is a credible continuous-population object here, but no honest way to present it as a ChoCo computational result established by this paper.

The case AGAINST (opponent, writing after the proponent)

The strongest objection is that this paper supplies no computational result for a continuous mirror to take up. Theorem 1 characterizes an allocation rule by axioms; Proposition 1 identifies that rule with a Shapley value. Neither classifies the complexity of computing an allocation. The comparative-statics section gives examples, while the strategic game it gestures toward is explicitly left for future analysis. Turning any of these into an axiomatic or strategic study of a continuum would not supply the computational question ChoCo is meant to chart.

The proposed continuous allocation is nevertheless a sensible population model. Group visitors by their service-use sets \(A\), assign each type mass \(\mu_A\), and scale provider costs per capita. Its allocation is
\[ y_A=\mu_A\sum_{i\in A}\frac{C_i}{\sum_{B:i\in B}\mu_B}. \]
That is well-defined, and its computation from \(\tau\) supported types and providers is direct. But it mirrors the paper’s explicit formula, not a computational result established by the paper. Asking for its running time would add a complexity label to an evaluation the paper already specifies; asking whether the equal-share rule remains uniquely characterized would be an axiomatic question outside the programme’s scope. A harder question about providers’ strategic choices would require a new game the paper does not formulate.

So the case against is strongest as a programme-selection argument: this is a natural continuous population model, but the paper offers no computational result whose continuous complexity landscape it would be worthwhile to chart. The universal claim is weaker. Large populations with repeated service-use patterns are plausible, and nothing in the paper rules out that regime. I would reject the paper as a ChoCo computational mirror, but I cannot honestly argue that no worthwhile continuous study of its cost-sharing model is possible.
