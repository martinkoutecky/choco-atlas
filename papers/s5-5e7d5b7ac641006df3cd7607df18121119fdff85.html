The case FOR (proponent)

The honest positive case is limited: this paper has no named computational result to anchor a continuous mirror. It proves no complexity classification, algorithm, or hardness result. Its numbered results characterize allocation values through axioms; they do not analyze the computational cost of finding those values.

The closest result is Theorem 4.1, proved here. For every \(\alpha\in[0,1]\), it says there is a unique value on the class \(C_\alpha^N\) satisfying efficiency, symmetry, linearity, and the null player property: the \(\alpha\)-quasi-Shapley value, given by the paper’s formula summing each player’s marginal contributions across coalitions. That is a mathematical characterization, not a claim that computing the value is in P or is hard. The paper gives no computational result for evaluating it.

A plausible high-multiplicity setting would be a large cooperative workforce with \(\tau\) classes of workers who share the same skills, costs, and role in production. One could ask how to allocate value across those classes as their population shares vary. But the paper allows arbitrary coalition-worth functions; aggregation by class would require additional structure, and turning its finite-player value into a continuous allocation problem would require new modeling choices. That could motivate follow-on work, but it would not be a continuous mirror anchored in a computational result of this paper.

The case AGAINST (opponent, writing after the proponent)

The proponent’s sole anchor, Theorem 4.1, proves that four axioms uniquely determine the \(\alpha\)-quasi-Shapley value. It makes no claim about an algorithm, complexity, or hardness. The same is true of the paper’s other numbered results: they characterize values or properties of games. So there is no computational result here for a continuous mirror to carry forward.

The strongest computational reading of Theorem 4.1 is “compute the value.” With the paper’s unrestricted coalition-worth function given as a table, the formula computes all players’ payoffs in \(O(n2^n)\) arithmetic operations, polynomial in the table’s size. The \(\alpha\)-constant-sum condition lets one store roughly half the table, which does not change that conclusion. A compact encoding might make computation hard, but the paper specifies no such encoding; the complexity would come from the chosen representation.

A high-multiplicity version is possible to imagine: workers fall into \(\tau\) classes, and a coalition’s worth depends only on how many workers of each class it contains. That is a sensible model for some production settings, but it adds a substantive symmetry assumption to the paper’s arbitrary coalition-worth functions. With one class, symmetry and efficiency determine equal division directly. With a fixed number of classes and an explicit table indexed by class counts, the Shapley sums can be evaluated by summing over those count vectors. A compact formula for coalition worth could raise new computational questions, but the answers would depend on that new structure and encoding.

The best continuous version would give each class a mass and define worth as a function of coalition masses, then ask for a value density. Individual marginal contributions vanish in a nonatomic population, so this needs a new value notion—typically one built from changes in worth as mass varies—and a specified representation of the worth function before computational complexity can even be assessed. That could become worthwhile follow-on research. It does not rescue this paper as an anchor: its theorem concerns an axiomatic value on finite games, and neither a mass-based computational problem nor its input model appears in the paper.

So the negative case is strong as a verdict on this paper’s suitability for the programme: it supplies no named computational question, and the obvious evaluation task is already straightforward under its natural explicit representation. I cannot make “no worthwhile continuous cooperative-game project exists in any scenario” airtight; the worker-class extension is plausible. Its weakness is that such a project would need to introduce the population structure, value density, and computational representation that this paper leaves open.
