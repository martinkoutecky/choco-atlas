The continuous mirror question

Given explicit time slots \(H\), a finite support \(T\) of request types with rational masses \(\mu_t\) summing to \(1\), per-capita capacities \(\kappa_q\), and one-operation bids with common duration \(p\), prices \(v_t\), release times \(r_t\), and deadlines \(d_t\) satisfying \(d_t-r_t-p\le 2\), compute maximum revenue. For each type \(t\), let \(S_t\) be its feasible start slots and \(I_{t,s}\) the slots occupied at start \(s\). Choose masses \(x_{t,s}\ge0\) to maximize \(\sum_{t\in T}\sum_{s\in S_t}v_tx_{t,s}\), subject to \(\sum_{s\in S_t}x_{t,s}\le\mu_t\) for each \(t\), and \(\sum_{t,s:q\in I_{t,s}}x_{t,s}\le\kappa_q\) for each \(q\in H\).

The model it lives in

A continuum of interchangeable requests represented by finitely many types, each carrying mass and specifying its price and scheduling requirements. Accept and assign fractional mass among feasible starts, while every accepted unit of mass receives a whole, non-preemptive schedule; maximize revenue subject to per-capita slot capacities.

What the mirror covers

The mirror covers Theorem 1's restricted single-operation winner-determination case; it leaves the general multi-operation, multi-resource problem, the branch-and-bound algorithm, and the experiments unmirrored.

Open questions for a prover

  • Can an optimal mass allocation be rounded to whole requests with an additive revenue loss bounded in terms of the support size and maximum bid price?

The case FOR (proponent)

The strongest positive mirror is the paper’s restricted single-operation winner determination problem. Imagine a large cloud or factory service receiving many requests drawn from a modest set of recurring templates. A type specifies a request’s operation, processing time, release time, deadline, and bid price. The population is the distribution \(\mu\) over those types. The number of requests \(N\) can be large while the number of distinct types stays moderate. To keep resource scarcity meaningful as the population grows, let available processing capacity grow with \(N\), at a fixed per-capita rate. That is a natural co-modification for a replicated service fleet.

The sole named complexity anchor, and my lead, is Theorem 1, proved in this paper. It states that the winner determination problem remains NP-hard even when there is a single resource with linearly ordered time slots, each bid concerns one non-preemptive operation, all operations have the same processing time \(\tau\), and each job’s time window satisfies \(d_j-r_j-\tau\le 2\). The paper proves this by reduction from a cited NP-complete job interval selection problem: each equal-length job can start at one of at most three allowed times. The source problem’s hardness is cited from reference [15]; the reduction to winner determination is given here.

I would ask the prover to study Single-Operation Mass Winner Determination. The instance has an explicit finite set \(H\) of time slots; a finite support \(T\) of bidder types with rational masses \(\mu_t\), where \(\sum_{t\in T}\mu_t=1\); and per-capita resource capacities \(\kappa_q\) for slots \(q\in H\). Each type \(t\) has a bid price \(v_t\), a release time \(r_t\), a deadline \(d_t\), and one non-preemptive operation of common duration \(p\). For the anchor’s restricted case, require \(d_t-r_t-p\le 2\). Let \(S_t\) be the feasible start slots for that operation, and let \(I_{t,s}\) be the slots it occupies if it starts at \(s\).

A solution chooses how much mass of each type to accept and assigns that mass to feasible start slots. With \(x_{t,s}\) denoting the mass of type \(t\) assigned to start at \(s\), the question is to compute maximum revenue:

\[ \max \sum_{t\in T}\sum_{s\in S_t}v_t x_{t,s} \]

subject to

\[ \sum_{s\in S_t}x_{t,s}\le \mu_t \quad(t\in T), \qquad \sum_{\substack{t\in T,\ s\in S_t\\q\in I_{t,s}}}x_{t,s}\le\kappa_q \quad(q\in H), \qquad x_{t,s}\ge 0. \]

The variables divide a nonatomic group of interchangeable bidders among different schedules; each bidder who is accepted still receives one whole, non-preemptive schedule. Time slots stay discrete, so population is the continuous object here. Prices and scheduling requirements are part of the type, as required for a high-multiplicity interpretation.

I expect this mirror to be tractable. It is a linear program, with at most three feasible starts per type under the theorem’s restrictions. With the slots explicit as in the paper’s formulation, the LP has polynomial size in \(|H|\), the support size \(|T|\), and the rational input bit length. This makes the mirror a credible Class A candidate: the discrete problem’s bid-selection integrality gives way to allocating mass among feasible schedules. It addresses the underlying winner determination task—the accepted requests, their revenue, and schedule feasibility—rather than treating the paper’s MILP or search procedure as the problem.

The scope is deliberately narrow: it covers Theorem 1’s single-operation restricted case, not the paper’s general multi-operation, multi-resource winner determination problem, its branch-and-bound algorithm, or its experiments. Natural follow-up questions are whether the mass formulation stays tractable with precedence constraints and multiple resources, whether schedule-column pricing can control the resulting LP, and how much error arises when a finite high-multiplicity allocation is rounded to whole bidders.

My weakest point is that Theorem 1’s hardness reduction uses job-specific allowed start times, while the paper itself does not scale resource capacity with the bidder population or study nonatomic acceptance. The proposed setting is therefore a plausible high-multiplicity regime for the same winner determination problem, rather than a literal limit of the paper’s one-machine instances. I think it survives that objection because the type description preserves the paper’s central choices and constraints, and large services with recurring request templates and capacity that grows with their customer base are a sensible setting for those choices.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is the only named computational complexity result here. Its reduction builds hardness from a collection of jobs with individually specified feasible start times. Those windows are part of each bidder’s complete type, so the hard instances can have \(\tau\) grow with the number of bidders. The theorem therefore gives little evidence that the paper’s hard regime contains many copies of a modest set of types.

That weakens the anchor, but it does not defeat its best mirror. A service receiving many requests from recurring templates is plausible: each type can include its price, duration, release time and deadline, and a nonatomic cohort can be divided among feasible start times while each request still receives a whole, non-preemptive schedule. Scaling capacity with the population is a co-modification the programme explicitly allows. For Theorem 1’s restricted case, the resulting mass problem really is a small linear program. Calling it a different question or dismissing it as too easy would not be a sound objection under the programme’s criteria.

The strongest negative point is that this LP describes a narrower regime than the one establishing Theorem 1’s hardness: repeated request types with capacity growing proportionally to the population. With fixed capacity, the accepted fraction can vanish as the population grows; with scaled capacity, the model becomes a fluid version of a replicated service. Neither observation rules out the mirror, since the second regime is both allowed and plausible. Nor does the paper’s branch-and-bound algorithm and small benchmark study supply another named complexity result to challenge.

So my negative case does not reach the requested universal conclusion. Theorem 1 is a weak guide to the high-multiplicity regime, but the repeated-template winner-determination mirror survives that criticism and appears worth classifying.
