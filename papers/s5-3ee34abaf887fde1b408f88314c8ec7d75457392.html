The case FOR (proponent)

This paper contains no named computational-complexity result to anchor a continuous mirror to. Its numbered results concern axioms: for example, Theorem 8 proves that every win-loss combining scoring procedure on indivisible preference profiles violates self-consistent monotonicity; Proposition 11 says the generalized row sum procedure satisfies it; and Theorem 12 gives a sufficient condition for satisfaction. None asserts a running time, hardness, or parameterized complexity. The paper’s note that some methods are “usually solved with iterative algorithms” is not such a result.

There is a natural population model here: a type is a judge’s complete pattern of pairwise responses, including equivalences and unreported comparisons; \(\mu_t\) is the fraction of judges of type \(t\). Given rational masses for the supported types, one could ask for the aggregate score vector or ranking. That fits the paper’s anonymous aggregation setting, but it is an unanchored candidate question, not a mirror of a named computational result. So the strongest honest positive case is that the population object is plausible; this paper supplies no eligible anchor for the requested complexity programme.

The case AGAINST (opponent, writing after the proponent)

The strongest case against a mirror is that the paper has no computational result to continuize. Theorem 8 is the closest candidate, but it proves an axiomatic impossibility; Proposition 11 and Theorem 12 are axiomatic too. A continuous-population version of one of these remains a question about self-consistent monotonicity, outside ChoCo’s computational scope. Theorem 8 also ranges over procedures built from arbitrary functions, without an encoding or cost model that would make its result a complexity statement.

The proposed distribution over judge types is sensible, but it does not supply a computational problem from the paper. Every procedure discussed takes the aggregate comparison matrix as its input. From type masses one can form \(\bar A=\sum_t\mu_t A(t)\), and the individual type list then disappears: the scores depend on \(\bar A\), not on the support size \(\tau\). Computing scores from that matrix could be a separate numerical-algorithm study. The paper, however, neither poses that task nor gives a complexity result to mirror; for procedures with arbitrary defining functions, even the computation model would need to be chosen from scratch.

One could add manipulation or control to create a harder population problem, but that would introduce a new task rather than continuize a result in this paper. The negative case is therefore strongest as a claim about this paper’s contribution: its plausible continuous input model does not turn its axiomatic findings into computational anchors. It is not airtight as a claim that no worthwhile follow-on could ever be built from the subject.
