What the mirror covers

The proposed mirror covers outcome computation for \(\textsc{MesRank}\) on repeated-role networks; it leaves the entitlement axioms, other selection rules, and empirical performance results aside.

Open questions for a prover

  • Does the selected type-mass vector converge to a unique limit under a specified tie-breaking rule?
  • Can that limit be computed exactly or approximated with runtime polynomial in the type count, input bit length, and \(\log(1/\varepsilon)\)?

The case FOR (proponent)

The positive case is narrow, and it has an anchor problem. The paper has no numbered Theorem, Lemma, Corollary, or Proposition asserting a complexity classification, and it reports no hardness result. The closest computational anchor is an unnumbered claim in Section 5: the authors say that PageRank utilities can be computed in polynomial time (giving \(O(mn)\) via power iteration), MES runs in \(O(kn^2)\), and therefore the outcomes of \(\mesrank\) and \(\meskatz\) can be computed in polynomial time. The PageRank claim is attributed there to Langville et al. (2006); the paper states the MES runtime and its consequence. This is a computational result in the text, but it does not meet the requested numbered-anchor rule. So the following is the strongest continuous question I can offer, but it is anchored only to that prose claim.

Call it High-Multiplicity \(\mesrank\) Outcome Computation. Take a large online participation or delegation network whose nodes fall into a fixed, relatively small set \(T\) of repeated structural roles: nodes of a type have the same connectivity pattern to each type and the same PageRank-derived utility for every candidate of a given type. Let \(\mu_t\in\mathbb Q_{>0}\) be the population share of type \(t\), with \(\sum_t\mu_t=1\). A rational block kernel \(W_{ts}\) specifies the directed connectivity between types, and \(\alpha\in(0,1)\) is the PageRank decay factor. For \(d_t=\sum_s\mu_sW_{ts}>0\), the type-level walk transition is \(P_{ts}=\mu_sW_{ts}/d_t\). The discounted walk utility density from voter type \(t\) to candidate type \(s\) is
\[ U_{ts}=\frac{1}{\mu_s}\sum_{\ell\geq 1}\alpha^\ell(P^\ell)_{ts}. \]
This is the population-scale version of the paper’s utility from a voter to a candidate: with \(N\) replicated nodes, a voter of type \(t\) assigns utility \(U_{ts}/N\) to each candidate of type \(s\).

Given also a committee share \(\kappa\in\mathbb Q\), replicate the population to sizes \(N\) for which \(N\mu_t\) and \(N\kappa\) are integers. Run the paper’s \(\mesrank\) procedure on the resulting type-homogeneous election, with initial voter budgets \(\kappa\), unit candidate costs, and a fixed tie-breaking rule. Let \(x_s^{(N)}\) be the number of selected candidates of type \(s\). The problem is: given \((T,\mu,W,\alpha,\kappa)\) and an accuracy \(\varepsilon>0\), return a vector \(y\) within \(\varepsilon\) in \(\ell_1\) distance of a limit point of \((x_s^{(N)}/N)_{s\in T}\) as \(N\) grows. Here \(y_s\) is the selected mass of type \(s\); the total selected mass may be below \(\kappa\) if MES stops early. This retains the paper’s underlying task—computing its selection rule on a network-derived election—while making population mass, rather than named individuals, the decision variable. MES is procedural, not an optimization objective, so the mirror should preserve its affordability rounds instead of inventing a welfare maximization objective.

The regime is deliberately specific: a very large platform with many participants but few repeated delegation or interaction roles, so \(N\) is much larger than \(|T|\). Type means full indistinguishability for the model’s network utilities, not a demographic label. In that restricted regime I think the authors could recognize the question as a high-multiplicity version of computing \(\mesrank\): it keeps the same PageRank-derived utilities, the same voters and candidates, and the same MES selection procedure. It replaces a finite committee of named nodes with a mass of representatives as the population grows.

I would expect this problem to be Class A, subject to a new proof. The type-level walk utilities reduce to a finite matrix calculation, and the replicated election has only \(|T|\) distinct voter and candidate roles. That suggests a compressed price-and-budget algorithm whose running time depends on \(|T|\), input bit length, and \(\log(1/\varepsilon)\), rather than on \(N\). The paper does not establish that compression or a convergence rate. Natural follow-up questions are whether the limit is unique under fixed tie-breaking, whether the continuous process can be computed exactly, and whether the same result holds for Katz or BOS utilities.

The scope is just the Section 5 polynomial-time claim for computing \(\mesrank\) outcomes. I would not use the paper’s entitlement axioms as anchors: they are not numbered computational results, and continuizing an axiom is outside the programme’s scope. The weakest point is that a generic network may give almost every node a distinct utility profile, making \(|T|\) close to \(N\); the mirror is persuasive only for the repeated-role regime. More basically, the paper provides no numbered complexity theorem and no hardness result, so this is a modest algorithmic mirror, not a strong test of whether discrete hardness dissolves in the continuum.

The case AGAINST (opponent, writing after the proponent)

The strongest point against the proposed anchor is that it does not meet the requested anchor standard. The paper has no numbered computational result: its numbered results concern axioms, while the Section 5 runtime paragraph gives a polynomial-time claim in prose, citing PageRank computation and stating an MES runtime. That is the closest computational hook, but it is not a named complexity result of the paper.

The proposed type kernel also does not, by itself, preserve the paper’s MES instance. MES updates each voter’s budget using that voter’s utility for each candidate, through the nonlinear payment rule \(\min(b_i,\mu_i(c)\rho)\). Aggregate type-to-type transition probabilities need not determine those individual utilities. If types are required to capture the full utility profile, ordinary networks may need nearly one type per node, eliminating the proposed compression. If instead the input is a block model with a fixed small number of roles, the mirror studies MES on an assumed block-symmetric network; it no longer captures the paper’s general, feature-blind input in which groups must emerge from the graph.

There is a better repair: define the input to be an exact weighted block network, scale \(k\) with population size, and ask for the limiting mass of selected candidates by type. That could preserve the PageRank-to-MES procedure and support a finite-dimensional limit analysis. It is the strongest version of the mirror, and I cannot rule out that the authors would recognize it as worthwhile. But it is a new, restricted model, not a mirror of a named computational result in this paper.

So the negative case is strong against the submitted anchor as an answer to this assignment, but weak against the universal claim. The exact block-model version is the unresolved soft spot; claiming that no scenario could yield a worthwhile mirror would overstate what the paper supports.
