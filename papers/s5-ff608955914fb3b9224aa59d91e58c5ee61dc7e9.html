The continuous mirror question

Given a finite type set \(T\), positive rational masses \(\mu_t\) summing to \(1\), and a symmetric link-cost table \(w_{tu}\in\{c_1,c_2\}\) with \(c_1<c_2\), suppose every type has direct source cost \(c_2\) and the graph of \(c_1\)-links on supported types is connected. For each denominator-compatible replication with \(q\mu_t\) agents of type \(t\), compute the limit, as \(q\) grows, of the finite Folk charge to an agent of each type.

The model it lives in

Use a distribution \(\mu\) over finitely many cost-profile types. Replicate each type \(t\) into \(q\mu_t\) agents with direct source cost \(c_2\) and pairwise costs \(w_{tu}\); choose a minimum-cost spanning tree, then apply the finite Folk rule. The output is the vector \(\phi\) of limiting per-agent charges by type, with the tree minimizing total edge cost at each finite replication.

The case FOR (proponent)

The strongest honest anchor is Theorem 1, proved in this paper. It gives an explicit Folk allocation for simple MCST problems; the paper does not state a complexity-class result such as “in P,” and it has no hardness anchor. The theorem says: for an elementary cost matrix with costs \(c_1<c_2\), where all agents form one autonomous component, an agent with \(c_{ii}=c_1\) pays \(c_1\); an agent whose cheapest connection to another agent costs \(c_2\) pays \(c_2\); and an agent with \(c_{ii}=c_2\) and \(c_{i*}=c_1\) pays \(c_2-\frac{C_\omega-C_m}{n_3}\), where \(n_3\) is the number of agents in that last category. In particular, all agents in that category receive the same charge. This is a closed-form computation result, rather than a theorem about worst-case complexity.

A plausible high-multiplicity setting is a utility or communications network serving many households in a few engineering classes. A type records everything the model uses: its direct cost to the source and its link costs to every other type. A large number \(n\) of households share these few profiles, so \(n\) is large relative to the support size \(\tau\). The society is the rational distribution \(\mu\) over those types. This preserves the paper’s cost-allocation problem: the minimum spanning tree is still chosen to minimize construction cost, and the Folk solution still allocates that cost. The allocation itself has no separate welfare objective; it is the prescribed output of the Folk rule.

My lead continuous problem is High-Multiplicity Simple Folk Allocation. An instance consists of a finite type set \(T\), positive rational masses \(\mu_t\) summing to one, and a symmetric type-link cost table \(w_{tu}\). Every type has direct source cost \(c_2\), and each \(w_{tu}\) is either \(c_1\) or \(c_2\), with \(c_1<c_2\). Require the graph of low-cost links \(w_{tu}=c_1\) on the supported types to be connected; for a single type, require its within-type link cost to be \(c_1\).

The question is: what is the limiting Folk charge per unit mass for each type? For its precise meaning, take exact replications with \(q\mu_t\) agents of type \(t\), for \(q\) ranging over multiples of the mass denominators. For each replication, choose a minimum-cost spanning tree and compute the finite Folk solution. A solution is the vector \(\phi\) whose coordinate \(\phi_t\) is the limit of the charge to a type-\(t\) agent as \(q\) grows. Equivalently, network choices can be recorded by limiting type-to-type edge frequencies: minimize normalized tree cost over frequency vectors that arise as limits of finite rooted spanning trees, then apply the Folk rule to the replicated cost game.

This regime really is within Theorem 1’s simple class. The low-cost graph connects all agents, while every source link costs \(c_2\). A minimum tree therefore costs \(C_m=c_1(n-1)+c_2\), while \(C_\omega=nc_2\). Also, any proper split into \(S\) and its complement costs at least \(c_1(n-2)+2c_2\) when treated separately, so the whole population is one autonomous component. Each agent has \(c_{i*}=c_1\), and \(n_3=n\). Theorem 1(c) gives the finite charge \(c_1+\frac{c_2-c_1}{n}\), hence the continuous answer is \(\phi_t=c_1\) for every type. The aggregate charge is \(\sum_t\mu_t\phi_t=c_1\), matching the limiting minimum network cost per person.

I expect this mirror to be tractable: once the type table is read and the low-cost graph is checked for connectivity, the answer is explicit and independent of the population size. The mirror covers Theorem 1(c) in a high-multiplicity regime; it does not claim to cover the theorem’s other clauses, arbitrary cost matrices, or the rest of the paper. Further questions include whether a useful type-support algorithm survives arbitrary rational link costs, and how Folk charges behave for high-multiplicity versions of simple-decomposable problems.

The weak point is the narrowness of the result. The continuous limit in this regime is particularly clean, and Theorem 1 already supplies nearly all the needed finite calculation. More broadly, the paper is an economic cost-allocation study rather than a computational-complexity paper, so this mirror offers a genuine population-continuous question but a modest entry into ChoCo’s complexity landscape.

The case AGAINST (opponent, writing after the proponent)

Theorem 1 is the only serious anchor: it gives a closed form for the Folk allocation on simple MCST problems. Its weakness as a ChoCo anchor is that it concerns a narrowly specified cost matrix, not a complexity result. A continuous question can still be asked about it, but the paper itself offers little evidence that population size is the computational obstacle.

The strongest objection is that a small type space for this problem imposes a demanding symmetry on the network. Since a type must capture every cost relevant to the problem, agents of type \(t\) must have the same link cost to every agent of type \(u\). Thus a fixed number of types requires the pairwise cost matrix to be block-constant. In a network where link costs reflect locations, that assumption usually fails: agents in the same broad class can face different costs to the same other agent. Including enough location and cost information to preserve those differences can make the number of types grow with the population, removing the high-multiplicity compression.

The proposed household story does not resolve that mismatch. If households are at distinct locations, engineering classes alone do not determine pairwise connection costs. If they are effectively co-located, treating each household as a separate vertex with the same fixed link costs raises a different modeling question: infrastructure may serve the whole location through shared facilities, rather than requiring a separate spanning-tree connection for each household. The block-constant model is mathematically coherent, but its interpretation as an ordinary utility network needs more than the proposed class labels.

A stronger mirror could allow arbitrary rational link costs between a fixed set of types and take limits of exact replications. That preserves the graph model, but it still restricts the population to repeated copies in a block-constant network. A continuous type space rich enough to represent distinct locations avoids that restriction, but then the limiting object needs a cost kernel and a scaling rule for edges and total cost. In that setting, agents have zero mass individually, while the Folk allocation is defined for individual agents in finite coalitions. Choosing a normalization and defining the limiting allocation are substantial modeling decisions, not consequences of the paper’s theorem.

That is the best case against: every finite-support mirror preserves the model only under a strong symmetry assumption, while richer type spaces require a new network-limit model with no uniquely compelled normalization. Still, the case is weak as a universal objection. Exact replications of a finite block-constant network are a legitimate high-multiplicity regime, and the paper’s authors could recognize that cost-allocation question. I can argue that it is a narrow fit for the programme; I cannot honestly rule out a worthwhile mirror in every plausible scenario.
