The case FOR (proponent)

I don’t see an eligible computational anchor, so I can’t make a compliant positive case from this paper. It gives no numbered result classifying the complexity of a problem as NP-hard, polynomial-time solvable, FPT, or similar; the conclusion says computational issues are future work.

The nearest numbered results are semantic:

  • Theorem 1, proved here: if a modular system is built from P-MS components using composition, union, feedback, and projection, and each component is a P-MS, the combined system is also a P-MS. This is a closure result, not an algorithm or complexity classification.
  • Theorem 2, proved here: if outcome \(o_1\) is preferred to \(o_2\) in a cp-net’s induced graph, their P-MS translations satisfy \(o_1 \succeq_{MP} o_2\).
  • Theorem 3, proved here: for two feasible plans translated from an ASP planning problem, if \(p_1\) is preferred to \(p_2\) with respect to a basic desire \(\phi\) in PP, their translated structures satisfy \(B \succ_{MP_\phi} B'\).

The paper does mention that the Multiple Knapsack and TSP components in Example 1 are NP-complete. But that is an unnumbered motivating example, not a result about the combined preference-based problem. It also cites a prior algorithm for modular systems without stating a complexity result for it.

A plausible setting to explore would be a logistics provider serving many recurring cohorts of similar orders: a type would include the complete order, route-network, and preference data; mass would be the fraction of deployments of that type; decisions would assign plans to the cohorts. But the paper specifies no population-level objective or aggregate constraints for that problem. Adding them would create a new computational question, not mirror a result proved here.

The weak point is therefore decisive: the paper studies how to represent and combine modules and preferences for a search problem, not a computational problem over a population. There is no lead continuous mirror anchored in a named computational result of this paper.

Example 1 does mention NP-complete Multiple Knapsack and TSP components. The strongest rescue would be a logistics provider serving many recurring cohorts of similar orders, with a per-capita fleet and a mass-based objective for choosing feasible, preferred plans. That could be a worthwhile continuous optimization problem. But the paper gives no population-level objective, shared-resource model, or rule for aggregating its strict partial-order preferences. If each deployment is independent, mass just repeats separate search tasks. If deployments compete for shared resources, the coupling and objective create a new problem. Either way, this would not continuize a result the paper established.
