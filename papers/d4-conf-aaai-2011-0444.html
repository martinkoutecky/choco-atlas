The case FOR (proponent)

The paper has no eligible named computational result to anchor a mirror to. It contains no numbered theorem, lemma, corollary, or proposition asserting a complexity result. Its numbered items are the seven worker features; Equation (1) defines weighted voting, and the reported accuracy gains are experimental findings. So under your anchor rule, there are zero anchors and no per-anchor continuous questions to hand to a prover.

The strongest plausible positive case is about the worker aggregation the paper studies. Imagine a large, sustained crowdsourcing campaign for Web relevance judgments. Many workers come from a small set of stable behavioral types, with \(N\gg\tau\): for example, thousands of workers across dozens of response profiles. A type records everything this model uses about its workers: their feature values and their response probabilities on each task category. Its mass \(\mu_t\) is its share of the workforce. For task \(x\), let \(q_{t,x,c}\) be the fraction of type \(t\)’s responses expected to be label \(c\), and let \(g_x\) be the expert label.

A candidate continuous problem, Type-Mass Z-Score Consensus Selection, would take a finite task set with rational prevalences \(\pi_x\), expert labels \(g_x\), type masses \(\mu_t\), feature values \(f_{t,i}\), and response probabilities \(q_{t,x,c}\), for \(c\in\{0,1,2\}\). Choose a feature subset \(S\) and threshold \(\gamma\). Compute the population Z-scores \(z_{t,i}\), retain types with \(z_{t,i}\le\gamma\) for every \(i\in S\), and give each retained type weight \(\lambda_t=\sum_{i\in S}f_{t,i}\). Predict each task’s label by
\[ \hat c_x\in\arg\max_c\sum_{t:\,z_{t,i}\le\gamma\ \forall i\in S}\mu_t\lambda_t q_{t,x,c}. \]
The solution is a maximizing choice of \(S,\gamma\) and its resulting labels, where the objective is expected graded or binary accuracy, \(\sum_x\pi_x u(g_x,\hat c_x)\). This mirrors the paper’s filter-and-weight procedure at the level of worker types. For the paper’s fixed seven features and finite threshold grid, this selection problem is tractable by enumeration. That is a modest algorithmic question, though: it does not show that continuization removes a discrete hardness, and the paper does not claim to solve this optimization problem.

This mirror covers only worker filtering and weighted consensus labeling. The plausible regime is a large annotation pool with repeated task types and many annotations per task, so the type proportions can stand in for individual votes. The paper itself reports 766 workers but only about six labels per example; that supports workforce scale, but not the large-panel-per-task regime needed for this limit to be persuasive. Questions about finite-panel accuracy, ties, and estimating type response probabilities would follow.

That gap is the weakest point, along with the lack of a named computational result: the authors evaluate filtering and weighting experimentally; they do not pose a complexity problem. The type-mass model is recognizable as a continuous version of their aggregation method, but it is a proposed research question attached to their experiment, not a mirror of a theorem they proved.

The case AGAINST (opponent, writing after the proponent)

There is no eligible computational result in the paper to mirror. It proves no theorem about complexity or algorithms; it reports an experimental accuracy improvement from worker filtering and weighted voting. That leaves no named computational anchor, and the proponent’s Type-Mass Z-Score Consensus Selection is a new optimization problem built around the experiment.

That proposed problem is coherent, but its computation is small and direct. The paper has seven features and sweeps a finite set of thresholds. For each feature, a threshold selects one of finitely many sets of worker types; enumerating feature subsets and thresholds, then summing weighted votes for each task, computes the result. Replacing counts with rational type masses changes those sums, not the algorithmic structure. A larger feature set could make feature selection difficult, but that would add a new source of combinatorial complexity rather than reveal a computational question created by the continuous population.

A more faithful limit would give each task a very large panel of workers drawn from stable types. As panel size grows, the weighted vote approaches the type-mass-weighted expected vote, so the winning label is usually just the largest of a few sums. That limit removes the sampling variation central to the paper’s finite-panel accuracy measurements; the paper had only about six labels per example. Keeping that variation means modeling finite stochastic panels, while choosing arbitrary type weights or removal policies would add an intervention problem the authors did not study. Either could be worthwhile research, but neither is a computational result of this paper.

So the negative case is strong against a continuous *computational mirror of the paper*: there is no complexity theorem to anchor it, and the closest proposed algorithmic question appears to reduce to a finite sweep. It cannot honestly prove that no related population model could ever be worthwhile. A large crowdsourcing system with repeated worker types is a plausible regime; the weaker point is that studying its population consensus would be a new question, with its value depending on goals beyond the paper’s reported result.
