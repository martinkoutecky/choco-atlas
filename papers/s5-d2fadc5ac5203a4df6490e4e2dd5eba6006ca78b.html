The case FOR (proponent)

The strongest plausible setting is a large water or utility network serving cohorts of customers at the same locations. A type would specify a customer’s complete connection-cost profile; \(\mu_t\) would be the fraction of customers of type \(t\). This is a credible high-multiplicity regime for the paper’s spanning-tree cost-sharing problem: many customers, relatively few distinct cost types, and a network whose edge costs do not grow with the number of users.

One possible follow-up would ask for the limiting value shares in replicated versions of the paper’s folk or cycle-complete games. Given type costs \(\kappa\) and rational masses \(\mu\), create \(n\mu_t\) interchangeable customers of each type, with zero-cost links between customers of the same type. Compute the chosen solution on each finite instance, aggregate each type’s value shares, and ask whether the vector has an exact limit as \(n\) grows and how to compute it. The continuous population is the object here; the output remains a value allocation for the network cost-sharing problem. This looks like a sensible computational question the authors could recognize, though it is a proposed extension, not a result established by the paper.

The obstacle is the required anchor. The paper has no numbered result asserting a computational complexity or algorithmic bound for a value-sharing problem. Theorem 1, proved here, says that both solutions fail full public and private Value Equivalence; the folk solution satisfies weak public but not weak private Value Equivalence, while the cycle-complete solution satisfies weak private but not weak public Value Equivalence. Theorem 2, proved here, characterizes the folk solution by weak public Value Equivalence, Piecewise Linearity, Symmetry, and Group Independence. Theorem 3, also proved here, characterizes the cycle-complete solution by Core Equivalence in Values, Piecewise Linearity, Symmetry, and Clique Decomposition. These are substantive anchors for axiomatic questions, but they do not assert that a computational problem is tractable or hard. The paper’s brief statement that minimum-cost spanning trees are polynomial-time solvable, citing Prim and Kruskal, is background about finding the tree—not a numbered result about computing the paper’s value-sharing solutions.

So the continuous-population scenario is plausible, but I cannot honestly attach the required prover-ready mirror question to a qualifying anchor in this paper. My weakest point is exactly that gap: the candidate would extend the paper’s subject rather than continuize one of its named computational results.

The case AGAINST (opponent, writing after the proponent)

The decisive weakness is the anchor. Theorems 1–3 concern value equivalence and axiomatic characterizations of the folk and cycle-complete solutions. None asserts a complexity bound for computing a value-sharing solution. The polynomial-time statement about finding a minimum-cost spanning tree is background on tree construction; it does not analyze the paper’s cost allocations. Continuizing the three theorems would ask new axiomatic questions, which ChoCo’s stated scope excludes.

The proposed utility-customer scenario is plausible, and its strongest version deserves a direct answer. Give each location a type, set the cost between locations by a fixed cost kernel, and connect co-located customers at zero cost. Then the cost of serving a coalition depends on which locations it contains, while the proposed limit of aggregate shares can depend on customer masses through the order in which types first appear in a random ordering. That limit might be worth studying. But it is a new replication-limit question for the paper’s solutions, not a continuous version of a computational result in the paper.

A direct continuum game creates a further modeling choice: with fixed construction costs, a coalition’s cost can jump when its mass at a location moves from zero to positive. The finite-player Shapley value still uses individual agents and random orderings; a continuum of mass has no such ordering built into the model. A clone-limit can supply one, but it selects a particular limiting value concept. Treating each location type as a player instead removes the masses from the allocation problem. Either route could support a separate project, but neither gives these axiomatic results a computational mirror.

So the case against is strong on programme fit: no paper result supplies the required computational anchor, and the best repair proposes a new limit problem. It is weaker as a universal claim that no scenario could be worthwhile. A carefully specified algorithmic study of aggregate limiting shares for large utility cohorts could interest the authors. I would reject it as a mirror of this paper’s named results, while acknowledging that a broader ChoCo remit might admit it as a new problem.
