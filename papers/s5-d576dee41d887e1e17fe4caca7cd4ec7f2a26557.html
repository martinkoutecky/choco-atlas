What the mirror covers

Theorem 3.6 is the proposed anchor; the paper's multi-item extension, adaptive-deviation guarantees, and lower-bound analysis are not covered by a qualifying computational mirror.

The case FOR (proponent)

There is a plausible, narrow population mirror here: a repeated public resource used by large cohorts whose members have the same per-capita share and value pattern. Let each cohort be a type with mass \(\mu_t\), and let \(\tau\) be the number of types. The number of people can be very large while \(\tau\) stays small. A common public state can determine each type’s value for that round; small value perturbations can represent near-identical cohort members.

The closest named result is Theorem 3.6 (Pacing Equilibrium), proved in this paper. It says that, using the proportional mechanism in the paper’s monetary-to-non-monetary reduction, there is a profile of value-scaling strategies whose expected payments equal agents’ shares; every such profile is an approximate Nash equilibrium among value-scaling strategies, and its allocation has the stated \((0,o(1))\) approximate-core guarantee. That is a meaningful anchor for the *underlying core-outcome question*, but it does not assert an algorithm or a complexity classification. Strictly under your anchor rule, the paper has no eligible named computational-complexity result. I would not present Theorem 3.6 as one.

The concrete continuation I would offer is Continuum Core-Blocking for Paced Public-Good Allocations. Given types \(t\in[\tau]\) with rational masses \(\mu_t\), share densities \(a_t\) satisfying \(\sum_t\mu_ta_t=\alpha\), a finite set of public states \(\Omega\) with probabilities \(p_\omega\), type values \(v_{t\omega}\), and a current allocation policy \(x_{t\omega}\), set
\[ U_t=\sum_{\omega\in\Omega}p_\omega v_{t\omega}x_{t\omega}. \]
The question is whether there is a blocking coalition and policy, or a certificate that none exists. A coalition \(S\subseteq[\tau]\) has resource budget \(\sum_{t\in S}\mu_ta_t\). In each state \(\omega\), its alternative policy draws a subset \(A\subseteq S\) from a distribution \(\pi_\omega\), giving type \(t\) alternative utility
\[ U'_t=\sum_{\omega\in\Omega}p_\omega v_{t\omega}\Pr_{A\sim\pi_\omega}[t\in A]. \]
It blocks if
\[ \sum_{\omega\in\Omega}p_\omega\Pr_{A\sim\pi_\omega}[A\ne\varnothing] \le \sum_{t\in S}\mu_ta_t \quad\text{and}\quad U'_t>(1+\gamma)U_t\ \text{for every }t\in S. \]
This keeps the paper’s public-good cost, type utilities, share-based coalition budget, and multiplicative core test. Because members of a type are clones in this model, including only part of a type in a blocking coalition cannot help: expanding to the full type preserves per-member utility and does not increase the cost of an active round.

For this finite-state version, I expect FPT in \(\tau\). Enumerate type subsets \(S\); for each, the policy distributions \(\pi_\omega\) and the budget and utility conditions form a linear feasibility problem. The subset expansion makes the dependence exponential in \(\tau\), while the remaining LP size is polynomial in the explicit state description and input bit length. This is a new core-verification question, not a result established by the paper. Computing pacing factors for a continuum of cohorts, or extending the check to heterogeneous members and the paper’s arbitrary value correlations, would be further questions.

The authors could plausibly recognize this as a computational version of the core benchmark in Theorem 3.6. My weakest point is also decisive for the requested anchoring standard: the paper proves equilibrium and core guarantees, but does not study the complexity of finding or verifying them. So this is a credible direction for a continuous-population computational paper, not a compliant mirror of one of this paper’s computational results. It covers only the single-good core setting; it does not claim a mirror of the multi-item, submodular-cost results.

The case AGAINST (opponent, writing after the proponent)

The strongest objection is that Theorem 3.6 is not a computational result. It establishes existence of value-scaling strategies with a core guarantee and approximate Nash properties; it gives no complexity claim or algorithm to mirror. The paper treats the one-shot monetary mechanism as a black box. That leaves no named computational problem whose complexity landscape a continuous version could chart.

The best extension of that theorem would ask how to compute pacing factors for large cohorts. But the equilibrium part changes as the population becomes nonatomic: one person has zero mass and cannot affect aggregate bids or allocation, so the individual-deviation incentive central to the theorem loses its force. Treating each cohort as a strategic player preserves that influence, but then the strategic units are the cohorts themselves. Either way, the proposed mirror needs a new equilibrium model; it does not carry over the theorem’s computational content.

The proposed core-blocking problem is a legitimate finite-support population model, but its FPT result looks too direct to make a strong ChoCo case. In each state, if a blocking policy allocates the public good to any part of a coalition, it can allocate it to the whole coalition at the same cost and weakly increase everyone’s utility. So for each coalition, the policy reduces to choosing an allocation probability per state, a small linear feasibility problem. Enumerating the \(2^\tau\) coalitions gives the stated parameterized algorithm. That is a useful baseline for a core benchmark, but it does not compute the paper’s equilibrium, model its budget depletion, or analyze its adaptive deviations.

The negative case is therefore strongest at the boundary of the programme: this paper offers analytical equilibrium and core guarantees, not a computational result to continuize. The proposed blocker is plausible, and replicated cohorts could be a sensible regime, so I cannot honestly rule out every worthwhile continuous question. But the proponent’s own anchor does not meet the computational-result standard, and their replacement appears to be a separate, simple core-verification problem rather than a computational mirror of the paper.
