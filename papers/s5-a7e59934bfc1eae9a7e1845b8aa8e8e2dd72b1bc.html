The strongest candidate mirror is the cycle-and-chain selection problem the package implements, but it is an unanchored extension. Let \(T\) be types of donor–recipient pairs, with population mass \(\mu_t\) for each \(t\), and let \(A\) be altruist types with masses \(\nu_a\). Types would need to share all relevant clinical features, objective values, and compatibility relations; compatibility between types would be deterministic. Given the type-level compatibility graph, maximum cycle length \(K\), maximum chain length \(H\), and the programme’s ordered objectives, let \(x_Q\geq 0\) be the mass of exchanges using each admissible cycle or altruist-started chain \(Q\). Require that the total mass of exchanges using each pair type \(t\) is at most \(\mu_t\), and the total using each altruist type \(a\) is at most \(\nu_a\). The task is to find a feasible packing maximizing the objectives lexicographically. Each person in an exchange still receives an integral transplant; fractional quantities describe averages over a type’s mass.

A plausible regime would be a large regional or national programme, or a simulation of one, where many pairs fall into a modest number of clinically defined profiles and those profiles determine the compatibility and objective data used by the model. Then the number \(N\) of pairs could be much larger than the number \(\tau=|T|\) of types. For fixed \(K\) and \(H\), type-level cycle and chain patterns can be enumerated and the resulting problem written as an LP. That suggests a tractable continuous version of this selection problem; variable length limits raise a separate pricing or enumeration question.

The mirror is plausible as a continuation of the package’s graph-and-packing model, but the main weakness is substantial: compatibility can depend on individual crossmatch details, so grouping pairs may either lose important edges or require nearly one type per pair. The paper’s simulation functionality offers a more credible setting for repeated profiles than an actual clearing run, but it does not establish that such a regime is useful. This candidate also covers only cycle-and-chain selection, not the package’s file handling, validation, instance generation, or broader research workflow.

The proposed type-level packing problem is the best candidate, but it is a new problem assembled from that functionality. Its types, mass constraints, exchange patterns, and lexicographic objective would all need to be specified; adding altruist types extends the model further. A plausible large programme or simulation could make those choices sensible. But that would make a continuous KEP model worth studying, not make it a mirror of a named result in this paper.

There is also a real modelling tradeoff in that candidate. Grouping pairs by broad clinical categories can erase compatibility distinctions that affect which cycles exist. Defining each type by a complete compatibility and objective profile preserves those distinctions, but may leave nearly as many types as pairs, so the aggregate formulation gives little compression. A regime with repeated complete profiles could avoid that problem, but the paper does not establish such a regime or study the resulting LP.

So the negative case is strong for the paper-relative verdict: no anchor survives because the paper supplies none. It is much weaker as the universal claim that no worthwhile continuous KEP model exists in any scenario. A repeated-profile simulation or programme could support one. The case against is that pursuing it would be a separate research question, not a continuous mirror of this paper’s computational results.
