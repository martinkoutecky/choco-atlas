The continuous mirror question

Given a finite satellite set, a finite rational time grid, and a society supported on \(\tau\) request types with rational masses \(\mu_t\) summing to \(1\), each type specifies a complete OSAP request template. For each type \(t\), let \(Q_t\) be its valid single-client OSAP allocations. Given rational satellite-time capacities \(\kappa_{sj}\) per unit of population mass, choose allocation masses \(x_{tq}\ge 0\) summing to \(\mu_t\) for each type, subject to aggregate use of every satellite-time cell \((s,j)\) not exceeding \(\kappa_{sj}\). Compute the maximum aggregate mode utility, or decide whether it is at least a given threshold \(U\).

The model it lives in

A configuration-allocation LP: types carry mass \(\mu_t\), each configuration \(q\) is a complete valid OSAP allocation for one client, and variables \(x_{tq}\) assign mass to configurations. The objective sums mode rewards weighted by assigned mass; satellite-time capacities scale with population mass and constrain aggregate resource use.

The objection that survived

The proposed regime does not specify how orbit geometry, eligible satellites, and reservation windows scale together when opportunities are replicated.

What the mirror covers

The mirror covers Theorem 1’s mode-utility allocation problem; it does not cover leximin fairness or the secondary window-utility objective.

Open questions for a prover

  • Can the per-type pricing problem be solved in polynomial time, particularly for global requests with total-duration requirements?
  • How does the continuous optimum compare with finite high-multiplicity OSAP instances having the same type proportions, and how does any approximation gap depend on \(\tau\) and the time grid?

The case FOR (proponent)

The strongest case is a continuous mode utility OSAP for a large market of standardized satellite booking requests.

The anchor is Theorem 1 (NP-hardness), proved in this paper. It says that deciding whether an OSAP has a feasible allocation with mode utility at least \(U\) is NP-complete; checking a proposed allocation is polynomial. The proof reduces RCPSP with disjunctive resources, activities using at most one resource, and no precedence constraints: each resource becomes a satellite, and each activity becomes a global request with one mode of reward \(1\), minimum slot duration equal to the activity’s duration, and a reservation window \([0,C_{\max}]\). All activities can be scheduled within \(C_{\max}\) exactly when the OSAP can achieve utility at least the number of activities. The paper cites [15] for the source problem’s hardness and gives the reduction here.

Here is the mirror I would put to a prover. Call it Continuous Mode-Utility OSAP. An instance has a finite set of satellites, a finite rational time grid, and a support of \(\tau\) request types with rational masses \(\mu_t\), summing to \(1\). A type is a complete OSAP request template: it includes the request kind, reservation windows and eligible satellites, minimum slot duration, time references if any, modes and their rewards, and any other feature affecting its feasible allocations. Each client assigned to type \(t\) must receive one ordinary, valid OSAP allocation for that type.

Let \(Q_t\) be the set of such single-client allocations. Choose nonnegative masses \(x_{tq}\), where \(x_{tq}\) is the share of type \(t\) receiving allocation \(q\). Require
\[ \sum_{q\in Q_t}x_{tq}=\mu_t. \]
For each satellite-time cell \((s,j)\), let \(\kappa_{sj}\) be its available booking capacity per unit of population mass, and let \(a_{q,sj}\) indicate how much of that cell allocation \(q\) uses. Require
\[ \sum_t\sum_{q\in Q_t} a_{q,sj}x_{tq}\le \kappa_{sj} \quad\text{for every }(s,j). \]
The \(\kappa_{sj}\) values describe a regime where satellite opportunities scale with the client cohort—for example, repeated standardized booking cycles across a growing constellation. The question is whether the maximum
\[ \sum_t\sum_{q\in Q_t}\Omega(q)x_{tq} \]
is at least \(U\), where \(\Omega(q)\) is the mode reward from the paper. A solution is a finite list of type-allocation pairs and rational masses satisfying these constraints and reaching the threshold. Each infinitesimal client gets a whole allocation; only the aggregate mass assigned to each allocation is fractional.

A plausible regime is a large constellation marketplace serving thousands or millions of clients through a comparatively small catalogue of booking products. Clients within a type share their target region or visibility class, timing template, duration requirements, mode ladder, and reward structure. Thus \(N\) can greatly exceed \(\tau\), while the replicated orbit opportunities keep per-capita capacity meaningful. This is a specific regime, not a claim that every OSAP order book has few types.

I expect this mirror to be Class A, provisionally. Its mode choice and resource use become a linear allocation problem over request configurations, inviting column generation. The key algorithmic question is whether the pricing problem for one type—choosing its best valid mode and slot pattern given satellite-time prices—is polynomial. Time-tagged requests look promising; global requests with a total-duration threshold may make pricing more difficult. If pricing is hard even for one or a few types, that could instead reveal continuum-specific hardness. A second question is how the continuous optimum relates quantitatively to a finite high-multiplicity OSAP with the same type proportions: does it give an additive approximation, and how does the gap depend on \(\tau\) and the grid?

This mirror covers Theorem 1’s mode-utility allocation question. It does not claim a complexity result for leximin fairness or the secondary window utility objective.

The soft spot is the resource scaling: positive population mass cannot keep receiving exclusive, fixed-duration reservations on a fixed finite collection of satellite windows. The mirror therefore co-scales the supply of opportunities, an assumption the authors would need to accept for this regime. The hardness reduction also uses a collection of activities whose distinct scheduling constraints may require many types, so Theorem 1 alone says little about hardness at moderate \(\tau\). Those limits are real, but the mirror retains the paper’s request modes, valid per-client schedules, and satellite-time conflicts while making the per-capita version of the same allocation question explicit.

The case AGAINST (opponent, writing after the proponent)

The only computational anchor is Theorem 1, and it is a real one: OSAP’s mode-utility decision problem is NP-complete. The strongest case against a continuous mirror is that its units cannot grow independently. Each positive-reward allocation occupies actual satellite time for a positive duration.

For one fixed constellation and operating period, total available satellite time is finite. If the number of clients grows while that supply stays fixed, the share that can receive any positive-duration allocation tends to zero. In the normalized continuous model, the per-capita capacity therefore tends to zero too. Since the paper permits an empty, zero-reward mode, the limiting allocation can put everyone in that mode. That limit does not describe a useful market for allocating orbit slots; it describes a fixed-capacity system overwhelmed by a growing population.

The proposed fix is to scale satellite opportunities with the client cohort. But if those opportunities come from repeated independent booking cycles, the model is a collection of copies of the original finite-horizon problem. If they come from expanding the constellation, the added satellites change the supply system and its geometry. Either way, the scaling rule does much of the modeling work: it must specify how orbit slots, eligible satellites, and request windows grow together. The paper supplies no such rule, and its experiments concern a fixed eight-satellite constellation and one operating period.

A standardized-client scenario does not resolve this supply issue. It can make \(\tau\) small, but it cannot create more exclusive time on the satellites. Conversely, scaling capacity can make a continuous configuration model coherent, but then the mirror depends on an added supply regime rather than on continuizing the population in the paper’s OSAP. That is the strongest negative case: the paper’s physical allocation question has a fixed scarce resource, while a nondegenerate population limit requires a separate, consequential theory of how that resource scales.

This case is not airtight. A marketplace with standardized requests and a constellation that expands proportionally could be a sensible regime, and its configuration LP would pose a genuine computational question. I cannot honestly rule out every such scenario. So the objection weakens the proposed mirror’s connection to this paper’s setting; it does not establish that no worthwhile mirror exists.
