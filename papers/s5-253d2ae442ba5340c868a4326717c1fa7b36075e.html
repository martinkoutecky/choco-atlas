The continuous mirror question

Given a finite transaction set \(X\), an ordered subset \(H=(h_1,\ldots,h_k)\), and a rational distribution \(\mu\) over strict rankings of \(X\), where every supported ranking puts \(h_i\) before \(h_j\) whenever \(i<j\), form the weighted pairwise graph using \(w_\mu(x,y)=\sum_{t:\,x\prec_t y}\mu_t\) and apply the paper’s ranked-pairs procedure with fixed tie-breaking. Compute its output ordering \(\sigma\): does \(\sigma\) preserve the order of \(H\)?

The model it lives in

Validator report types are strict rankings of the round’s transaction set \(X\), with rational masses \(\mu_t\) and support size \(\tau\). Their pairwise masses form the weighted graph input to ranked pairs; the requested output is a permutation \(\sigma\) of \(X\), which must preserve the unanimous order of \(H\).

What the mirror covers

The mirror covers Proposition 1’s ordering guarantee only; it leaves the attack framework, mitigation methods, and simulation findings alone.

The case FOR (proponent)

The strongest positive case is Proposition 1, proved in this paper. It says: if a Condorcet cycle contains honest transactions \(tx_1,\ldots,tx_m\), every node is honest, and every node reports \(tx_i\) before \(tx_j\) whenever \(i<j\), then the proposed ranked-pairs batch-ordering scheme returns an order that preserves that true ordering of the honest transactions. The proposition’s proof uses the unanimous edges: they are acyclic, so ranked pairs locks them before considering weaker edges.

This is an algorithmic correctness result, not a named classification such as NP-hardness or membership in P. The paper has no named complexity-class result to anchor a continuization. Proposition 1 is still a usable, modest anchor because the paper defines and computes with the ranked-pairs ordering algorithm, then proves a guarantee about its output.

Lead mirror: Continuous Ranked-Pairs Batch Ordering. An instance consists of a finite transaction set \(X\), an ordered subset of honest transactions \(H=(h_1,\ldots,h_k)\), and a rational distribution \(\mu\) over complete reports: strict rankings of \(X\). Its support has size \(\tau\), and each positive mass \(\mu_t\) is the fraction of the committee with report \(t\). For each pair \(x,y\), compute the reported support
\[ w_\mu(x,y)=\sum_{t:\,x\text{ precedes }y\text{ in }t}\mu_t. \]
Build the weighted majority dependency graph from these supports, resolving exact ties by a fixed public rule, and run the paper’s ranked-pairs procedure with fixed tie-breaking. The decision variable is the output permutation \(\sigma\) of \(X\); the problem is to compute that ordering. There is no optimization objective in Proposition 1, so I would not add one.

The continuous version of the proposition has the promise that every type in the support ranks \(h_i\) before \(h_j\) for every \(i<j\). The guarantee to prove is that the resulting \(\sigma\) preserves this order of \(H\). This is a direct mass version of the paper’s claim: unanimous support has weight \(1\), and the unanimous honest edges form an acyclic subgraph. The expected classification is tractable: pairwise supports can be accumulated from the \(\tau\) reports, then the edges can be sorted and cycle-checked in time polynomial in \(|X|\), \(\tau\), and the rational masses’ bit length.

A plausible regime is a large replicated transaction-ordering service with many honest validators but relatively few reporting patterns—for example, validators grouped by a small number of network or ingress configurations. A type is a validator’s complete reported ordering of the round’s transactions; mass is the fraction of validators with that report. The high-multiplicity assumption is that validators sharing a report are indistinguishable for this ordering question. That seems recognizable to these authors: the paper itself treats node orderings as the inputs to a social-choice aggregation rule. The mirror continuizes the population of reporting nodes, not the transaction set or the output order.

This case covers Proposition 1 only. It does not anchor the paper’s two-transaction attack, its simulation findings, or its other mitigations; those are not presented as numbered computational results. The continuous problem also suggests follow-up questions about how much mass must change before the ranked-pairs output changes, and how much adversarial mass is needed to trap honest transactions in a cycle. Those would be new questions, not results of this paper.

The weak point is substantial: the paper studies permissioned committees and simulates \(21\) and \(101\) nodes, so the large, low-\(\tau\) committee regime is an extrapolation. And Proposition 1’s unanimity promise makes the continuous guarantee close to a rescaling of its discrete proof. This is therefore a credible, narrow mirror of a named result—not evidence that the paper’s main attack analysis opens a rich continuous complexity landscape.

The case AGAINST (opponent, writing after the proponent)

Proposition 1 is the only named result that could anchor a computational mirror, and it proves an ordering guarantee rather than classifying the complexity of a problem. More decisively, the proposed mirror adds no new computation to that result. A distribution \(\mu\) over rankings affects ranked pairs only through the pairwise weights
\[ w_\mu(x,y)=\sum_{t:\,x\prec_t y}\mu_t. \]
Those weights are exactly the input to the paper’s weighted-graph procedure. Replacing node counts by fractions changes no comparison: multiplying every weight by the committee size preserves the edge order and ties. Conversely, rational masses can be scaled to integer counts. The distribution is a way to describe the weighted graph, not a new computational object the algorithm needs to solve for.

The proposition’s promise makes the mirror especially direct. If every supported report places \(h_i\) before \(h_j\), then \(w_\mu(h_i,h_j)=1\). These unanimous edges are acyclic and are processed before weaker edges, just as in the paper’s proof. Computing the output remains the stated ranked-pairs procedure on a finite weighted graph. There is no pricing problem, optimization problem, or unresolved complexity question here for continuization to expose. This is stronger than saying the continuous answer would be the same: the proposed continuous input is already reduced to the exact weighted input the paper’s algorithm handles.

A more ambitious proposal would ask how much report mass must change to make ranked pairs reverse an honest pair or form a trapping cycle. But that removes Proposition 1’s unanimity condition and adds an objective and adversarial constraints that the proposition does not study. The paper’s attack depends on a client’s transaction schedule, network delivery, and round structure; a free distribution over rankings does not say which profiles that mechanism can produce. Adding those constraints could define an interesting new project, but it would be a new attack-optimization problem, not a continuous mirror of the named result. The paper’s attack and mitigation findings are simulations and a framework, not additional named computational results to anchor that project.

I would not argue that high multiplicity is inherently implausible: a large validator population with relatively few report patterns is a coherent regime. The negative case is narrower. For the one named result, the continuous society collapses to the weighted graph already consumed by the algorithm. A mass-based robustness study might still be worthwhile, but this paper does not establish it as a worthwhile continuous mirror.
