What the mirror covers

The anchors concern additive-subutility consistency conditions; the paper's construction and runtime discussion address a single input rule set and have no surviving population mirror.

The case FOR (proponent)

The paper has no numbered computational result that meets your anchor requirement. Its nearest candidates are Theorem 1 and Corollary 1, both stated in this paper; Theorem 1’s proof is omitted. Theorem 1 says that for an additive utility \(u(m)=\sum_i t_i u_i(m)\), if every pair \((m_1,m_2)\) satisfying a rule \(r\) has
\[ \sum_{i\in S_a(r)} t_i\bigl(u_i(m_1)-u_i(m_2)\bigr) > \sum_{j\in S_d(r)} t_j\bigl(u_j(m_2)-u_j(m_1)\bigr), \]
then \(u\) is consistent with \(r\). Here \(S_a(r)\) and \(S_d(r)\) index the subutilities that agree and disagree with \(r\). Corollary 1 says that, in an additive utility consistent with the rule set, every rule must agree with at least one subutility. These are structural correctness facts, not complexity results or formulations of a computational problem. The efficiency claims—including polynomial time when each utility-independent feature set has size \(\log N\)—appear in unnumbered prose. So there is no eligible result to anchor a positive case.

The most plausible population setting would be a large cohort of users of a product, sharing a common vocabulary of binary features but falling into a small number \(\tau\) of recurring preference profiles. A type \(t\) would be a complete set \(C_t\) of ceteris-paribus rules, and \(\mu_t\) the fraction of users with that profile. A possible question is: given the feature set \(F\), the profiles \(C_t\), and rational masses \(\mu_t\), find a utility function \(u:\{0,1\}^{F}\to\mathbb R\) and a set of profiles \(A\) that maximize \(\sum_{t\in A}\mu_t\), subject to \(u\) representing every rule in every \(C_t\) for \(t\in A\). This is a concrete continuous-population problem: many users, relatively few complete types, and the output remains a numerical utility built from ceteris-paribus constraints.

But it is only a plausible extension, not a sound mirror of the paper’s problem. The paper constructs a utility for one supplied rule set; it does not aggregate heterogeneous rule sets or optimize the share of people whose preferences one utility represents. If the task instead requires representing every positive-mass type, mass has no effect beyond support. If it maximizes covered mass, it has become a new consensus problem. The paper’s feature assignments are also outcomes, not people, so making those assignments continuous would miss the programme’s scope.

For that proposed extension, a natural follow-up would be whether it admits a useful algorithm when \(\tau\) is small or the utility-independent sets are small. A finite electorate embeds by assigning each distinct preference profile its voter fraction, but the paper proves no hardness result for the corresponding finite consensus problem; I would not claim a complexity class from its results. The weak point is decisive: the population model makes sense, but its aggregation objective is not what these authors compute. My positive case therefore reaches a plausible research extension, not an anchored continuous mirror of a named result in this paper.

The case AGAINST (opponent, writing after the proponent)

The proponent is right that Theorem 1 and Corollary 1 are structural correctness statements, not complexity results. The paper’s runtime claims—including the polynomial-time case when each utility-independent feature set is small—appear in unnumbered prose. So there is no named computational result of the kind the proposed mirrors are supposed to anchor on. The paper does have an algorithmic problem, but it is to construct a utility function for one decision maker’s rule set \(C\).

A cohort of users with recurring rule profiles is plausible. But for each profile \(C_t\), the construction depends on \(C_t\), not its mass \(\mu_t\). Computing one utility per type just runs the paper’s construction once for each of the \(\tau\) profiles; the masses record how often each result applies. That is a useful compression of repeated instances, but it adds no population-level computation to the paper’s problem.

Requiring one utility to represent every included type does not make mass do more work. The requirement is simply to represent the union of their rules, \(\bigcup_t C_t\); every positive-mass type constrains the utility equally. The proposed maximum-covered-mass variant makes mass matter, but it adds a new collective objective: select the largest subpopulation whose rules admit a common utility. A majority preference or population-average utility would likewise require an aggregation rule absent from the paper; moreover, its input preferences are ordinal, so combining utilities would require a choice of cardinal scales the paper does not supply.

The honest negative case is therefore about fit, not impossibility. A maximum-mass common-utility problem could be worthwhile in its own right, but it is a new preference-aggregation problem rather than a continuous mirror of a named result here. The paper offers no population-level task for continuization to preserve.
