What the mirror covers

The proposed aggregation reproduces Theorem 9.3 for the margin-based approval variant; it leaves the general CLC rating procedure, other incomplete-vote variants, and the paper’s structural properties aside.

The case FOR (proponent)

The best positive case is a narrow population-level computation for the paper’s margin-based approval variant. Fix \(m\) options and let each type be an approval set \(S\subseteq C\). An instance is a finite-support distribution \(\mu\) over approval sets, with rational masses summing to \(1\); the task is to output the variant’s social ranking. A plausible regime is a large membership election with many voters but relatively few distinct approval patterns, so the number of voters greatly exceeds the support size \(\tau\). The output is a ranking, not an intervention or optimization decision.

The closest named result is Theorem 9.3, proved in this paper. It states that for approval voting the margin-based CLC ranking agrees exactly with approval-score order: \(R_x<R_y\) if and only if \(\alpha_x>\alpha_y\). Thus, for this mirror, the ranking can be computed by aggregating approval mass for each option and sorting the resulting scores. The authors would likely recognize the model: equation (1) already represents the collective Llull matrix as a weighted average of individual vote types. Corollary 6.2, also proved here, further says the rates depend continuously on the relative frequencies of vote types.

That is a plausible computational mirror, but it does not meet the required anchor standard. Theorem 9.3 is a ranking equivalence; it does not assert that a named problem is in P or give a complexity classification. Corollary 6.2 is a continuity result, not a complexity result. The article gives a procedure involving quadratic programming, but does not state a named complexity result for computing CLC ratings. I would therefore expect the approval-ranking computation to be tractable, while treating that as an inference from Theorem 9.3, not as the paper’s proved complexity result.

The weak point is substantial: the paper already works with relative vote frequencies, so the proposed population input largely restates its aggregate representation. Moreover, the paper’s named results concern rating properties, not computational complexity. Under the stated anchor rule, this paper has no qualifying named computational result to anchor a positive case; Theorem 9.3 is only the nearest, unqualified candidate.

The case AGAINST (opponent, writing after the proponent)

The proposed anchor does not meet the programme’s standard: Theorem 9.3 proves an equivalence between two rankings, not the complexity of a computational problem. Corollary 6.2 is even more explicit about the overlap: it proves that the rates vary continuously with the relative frequencies of vote types.

Here the better approval mirror is also the weakest one. Give each approval set a type and its mass; compute each option’s approval mass and sort. Theorem 9.3 says the margin-based variant already gives exactly that ranking. This is a sound question about a distribution over types, but the paper already formulates its input through relative frequencies and weighted averages, requires scale invariance, and proves continuity in those frequencies. The population is already the continuous object. Adding named voters or changing the scenario does not create a new population model: vote content is the type, and the paper’s results depend on the frequencies of those types.

A stronger proposal would ask for the bit complexity of computing the full CLC ratings from a finite-support distribution, including its incomplete-vote variants. The paper gives a procedure for that computation, including indirect-score closure and a quadratic program for projected turnouts, but it does not state a complexity classification. That leaves a possible complexity-analysis project. It does not, however, supply a discrete computational result whose high-multiplicity mirror is missing: the procedure already takes the aggregate vote data as input and operates on it directly. For approval ranking, Theorem 9.3 reduces the output to sorting aggregate scores.

So the negative case is strongest on the anchor actually raised: neither result is a computational-complexity theorem, and the underlying population model is already continuous in the relevant sense. It is not a proof that a formal bit-complexity analysis of the CLC procedure could never be useful. But that would be analysis of an existing continuous method, rather than a worthwhile continuous mirror of this paper’s discrete problem.
