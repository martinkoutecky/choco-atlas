The continuous mirror question

Given candidates \(C\), known rational masses \(\mu_t\) summing to \(1\) for \(\tau\) ranking types, and pairwise-comparison oracles that reveal each type’s shared strict ranking, determine the exact \(k\)-plurality approval winner set. Compute \(p(c)=\sum_{t:\,\top_t=c}\mu_t\); each type approves the smallest prefix whose cumulative \(p\)-mass is at least \(k\), and the output is the set of candidates maximizing total approving mass.

The model it lives in

A population distribution \(\mu\) over ranking types, with each type’s mass known and its shared ranking available only through pairwise queries. The task is exact winner computation; the resource being bounded is the number of comparisons, and the proposed upper bound is \(O(\tau m)\), plus polynomial exact arithmetic in the mass bit length.

The objection that survived

The mirror assumes that the grouping into identical-ranking classes and their masses is already known while the rankings remain hidden, so its query savings depend on a pre-existing registry.

fatal: False

What the mirror covers

The mirror covers the comparison-query cost of computing the \(k\)-plurality approval winners. It leaves the metric-distortion bounds, fallback-bargaining results, and sampling guarantees unmodeled.

Open questions for a prover

  • Is an \(\Omega(\tau m)\) comparison lower bound necessary in the worst case?
  • Can the exact winner set be computed without finding every type’s approval cutoff?
  • How does the query bound change when the ranking-class registry or masses are estimated?

The case FOR (proponent)

The strongest honest mirror is narrow: it concerns the cost of eliciting the paper’s \(k\)-plurality approval winner, not its main metric-distortion guarantee. The anchor is the pairwise-comparison theorem in §3, cited later as \(\Cref{thm:query_complexity}\). The supplied text does not display that theorem’s numeral, so I would not invent one. The result is proved in this paper, using Reiser’s cited linear-selection algorithm as a subroutine: for every \(k\in(0,1)\), \(O(m)\) pairwise comparisons per voter suffice to determine the winners of the \(k\)-plurality approval protocol. The paper has no named NP-hardness or standard running-time result; this query-complexity theorem is its clearest computational anchor.

A plausible high-multiplicity setting is a large election with a small candidate set, where millions of voters submit ballots drawn from a much smaller set of complete rankings. Each type is one strict ranking; its mass \(\mu_t\) is the fraction of the electorate with that ranking. For example, with a few candidates there are only \(m!\) possible rankings, and the support size \(\tau\) can be far below the electorate size \(n\). This is a population continuization: the input is a distribution over preference types, not a fractional outcome or a random perturbation.

Continuous \(k\)-Plurality Winner Elicitation is the corresponding query problem. The instance gives candidates \(C\), type indices \(t\in[\tau]\), rational masses \(\mu_t\geq 0\) summing to \(1\), and rational \(k\in(0,1)\). The masses and type indices are public, but each type’s ranking is accessible only through pairwise-comparison queries. A query asks whether \(c\succ_t c'\); because everyone of type \(t\) shares that ranking, the answer applies to mass \(\mu_t\).

The task is to output the exact winner set. For each type, its top candidate contributes its mass to the plurality distribution
\[ p(c)=\sum_{t:\,\top_t=c}\mu_t. \]
Type \(t\) approves the smallest prefix \(A_t\) of its ranking for which \(\sum_{c\in A_t}p(c)\geq k\). The approval mass of candidate \(c\) is \(\alpha(c)=\sum_{t:\,c\in A_t}\mu_t\), and the required output is \(\arg\max_{c\in C}\alpha(c)\), including all ties.

I expect this problem to be tractable: \(O(\tau m)\) pairwise comparisons, plus polynomial exact arithmetic in the masses’ bit length \(L\). Find each type’s top candidate, aggregate \(p\), then identify each type’s approval cutoff using the weighted linear-selection step from the paper and compare candidates with that cutoff. The continuous threshold is exactly the mass analogue of the paper’s \(kn\) threshold, and the algorithm processes each ranking type once rather than querying every person. This is the same winner-selection task and the same information restriction as the anchor, expressed over type masses; it should be recognizable to the authors as a continuous version of their query problem.

This mirror covers only the comparison cost of computing the \(k\)-plurality approval winners. It does not claim to continuize Theorem 1’s distortion bound, the fallback-bargaining results, or the paper’s sampling guarantees. Natural follow-up questions are whether \(O(\tau m)\) comparisons are necessary in the worst case, whether winner computation can avoid fully identifying some types’ approval cutoffs, and what guarantees hold when the masses or plurality poll are only estimated.

The weak point is the access model. If the continuous input supplies each ranking explicitly, there is no elicitation problem; the winner can be computed by weighted aggregation. This mirror therefore depends on preserving the paper’s pairwise-query setting while replacing the named electorate with type masses. It is a credible mirror of one result, but it does not turn the paper’s primary distortion analysis into a computational-complexity programme.

The case AGAINST (opponent, writing after the proponent)

The paper does have a computational anchor: its theorem that the \(k\)-plurality approval winner can be found with \(O(m)\) pairwise comparisons per voter. The strongest objection is that its query model does not transfer automatically to the programme’s continuous input. There, a society is supplied as a distribution over rankings. Once each ranking and its mass are given, the ranking information has already been elicited; computing plurality and approval masses is ordinary weighted aggregation. The paper’s query bound has nothing left to measure.

The proposed mirror restores a query problem by supplying public type labels and masses while hiding each type’s ranking behind a comparison oracle. That is coherent, but it makes a strong assumption: the population is already grouped by *identical complete rankings*. If those groups must be discovered from the voters’ answers, the cost of discovering them may erase the \(O(\tau m)\) saving. If the grouping is provided by a prior registry or poll, the mirror is a narrow query-theoretic model of that information pipeline, rather than a consequence of the continuous-society input itself.

Even granting that model, the result is a direct weighted version of the paper’s existing selection algorithm: query each known type once, then aggregate by its mass. It gives an upper bound, but no evident new complexity landscape or use for the continuous-optimization methods motivating ChoCo. That makes it a thin addition to this programme, though not an invalid question.

The honest negative case is therefore weak against the universal claim. Large electorates with known preference classes and a representative ranking oracle are plausible, and the authors could recognize that as their query problem. I can argue that the mirror depends on extra information and offers limited payoff; I cannot honestly rule out every worthwhile continuous mirror of this paper.
