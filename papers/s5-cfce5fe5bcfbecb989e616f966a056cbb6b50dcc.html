The continuous mirror question

Given providers \(C\), requests \(Q\), epoch steps \([T]\), supported user types \(i\in[\tau]\) with rational masses \(\mu_i\) summing to \(1\), type-specific request probabilities \(p_{i,t}(q)\), rewards \(r_i(q,c)\), nonnegative weights \(\alpha_t\), and per-capita provider thresholds \(\beta_c\), choose viable-provider indicators \(y_c\in\{0,1\}\) and routing probabilities \(\pi_{i,q,t,c}\in[0,1]\). Maximize per-capita welfare \(\sum_{i,t,q,c}\mu_i p_{i,t}(q)\alpha_t\pi_{i,q,t,c}r_i(q,c)\), subject to \(\sum_c\pi_{i,q,t,c}=1\), \(\pi_{i,q,t,c}\le y_c\), and \(\sum_{i,t,q}\mu_i p_{i,t}(q)\pi_{i,q,t,c}\ge\beta_c y_c\). Does this problem admit a \(1/e\)-factor approximation in time polynomial in \(\tau,|C|,|Q|,T\), and the binary input length \(L\)?

The model it lives in

A recommender population is a distribution over observable user types, each type carrying its request distribution and rewards, with type \(i\) having mass \(\mu_i\). Choose the viable-provider set \(y\) and type- and request-specific routing probabilities \(\pi\) to maximize per-capita additive welfare, subject to full request assignment, routing only to viable providers, and per-capita engagement thresholds \(\beta_c\).

What the mirror covers

Covers Theorem 1’s additive-utility approximation in the type-mass regime; leaves the nonlinear-utility column-generation model, regret trade-offs, and empirical evaluations outside the mirror.

Open questions for a prover

  • Does the \(1/e\)-factor guarantee hold with running time polynomial in \(\tau,|C|,|Q|,T\), and binary input length \(L\) for rational type masses and thresholds?
  • Can restricted type support yield exact optimization or a better approximation factor?

The case FOR (proponent)

The strongest anchor is Theorem 1, proved in this paper. It says that the additive-utility matching problem in Problem (4) has a polynomial-time \(1/e\)-factor approximation. Problem (4) chooses time-dependent stochastic recommendations \(\pi_{q,c,t}\) and binary provider viability variables \(y_c\): every query is assigned, recommendations go only to viable providers, and each selected provider must receive enough expected engagement to meet its threshold. The objective is total user welfare for nonnegative time weights \(\alpha_t\). The paper’s text mentions NP-hard facility-location cases, but does not state that as a numbered complexity result, so I use Theorem 1 as the anchor.

A plausible regime is a large recommender platform whose users fall into a small number of stable, observable request cohorts: for example, many accounts share the same query distribution, provider reward values, and other recommendation-relevant parameters. Let \(\mu_i\) be the fraction of users in cohort \(i\), with \(\sum_i\mu_i=1\). Each cohort member generates a request from the same finite query distribution \(p_{i,t}(q)\) at step \(t\), and has the same reward \(r_i(q,c)\). Thus the type is the complete user-side description used by the problem, while \(\tau\), the number of supported types, can be much smaller than the number of users.

I would hand a prover Continuous Viability-Constrained Recommendation. Its input is finite sets of providers \(C\), requests \(Q\), and epoch steps \([T]\); rational type masses \(\mu_i\); rational request probabilities \(p_{i,t}(q)\); rewards \(r_i(q,c)\); nonnegative weights \(\alpha_t\); and provider thresholds \(\beta_c\), all with binary encodings. The thresholds are engagement required per unit of population mass. If the original threshold is an absolute \(\nu_c\) for a population of size \(N\), take \(\beta_c=\nu_c/N\).

Choose \(y_c\in\{0,1\}\) and routing probabilities \(\pi_{i,q,t,c}\in[0,1]\) to maximize per-capita welfare
\[ \sum_{i,t,q,c}\mu_i p_{i,t}(q)\alpha_t\pi_{i,q,t,c}r_i(q,c) \]
subject to
\[ \sum_c\pi_{i,q,t,c}=1,\qquad \pi_{i,q,t,c}\le y_c,\qquad \sum_{i,t,q}\mu_i p_{i,t}(q)\pi_{i,q,t,c}\ge\beta_c y_c. \]
A solution is the selected viable-provider set and a feasible routing policy. The complexity question is whether this problem admits a \(1/e\)-factor approximation in time polynomial in \(\tau,|C|,|Q|,T\), and the input bit length \(L\), or whether there is an obstruction to that guarantee. I expect the approximation question to have a Class A answer: for a fixed provider set, the routing problem is an LP, and the paper’s approximation argument uses diminishing returns in welfare as providers are added. Further questions include whether exact optimization is tractable for restricted type support, whether the factor can be improved, and what hardness bounds apply.

This is a credible mirror of the paper’s underlying problem. The authors already optimize long-run user welfare through stochastic matching subject to provider viability, and they justify deterministic engagement expectations by appeal to a large user population. Aggregating users who share all relevant parameters into rational masses preserves that objective and those viability constraints. The LP variables in the paper are fractional recommendation decisions; the mirror’s continuization is specifically the population measure \(\mu\). It covers the additive-utility model and Theorem 1, not the nonlinear-utility column-generation model, the regret trade-off, or the paper’s entire set of experiments.

The weakest point is the regime assumption. The paper’s learned embeddings give users individualized representations, and its experiments do not establish that real platforms have few *exact* behavioral types. A convincing application therefore needs a setting with genuine shared profiles or request cohorts, rather than merely grouping nearby users approximately. There is also a complexity detail for the prover: expanding rational masses into a replicated finite electorate could take time polynomial in the denominator rather than in \(L\), so the desired bit-polynomial guarantee needs a direct weighted argument. The paper’s discussion of weighted constraints points toward one, but the finite-user theorem alone does not settle that continuous input-size question.

The case AGAINST (opponent, writing after the proponent)

The proponent chose the right anchor: Theorem 1 is a named computational result, so the case against cannot rest on there being nothing to mirror. The strongest objection is that its additive-utility problem is already expressed in the aggregate traffic quantities a continuous-population mirror would introduce. The paper assumes that, for a large population, query counts equal their expectations; in Problem (4), users contribute through expected query traffic and reward coefficients. With additive utility, the objective and viability constraints do not need to retain who made each request.

For the proposed cohort model, give each type \(i\) mass \(\mu_i\), and each request \(q\) within it mass \(\mu_i p_{i,t}(q)\). If rewards differ by cohort, label the request \((i,q)\). These weighted request classes supply the coefficients for the paper’s matching formulation; scaling engagement by population size converts per-capita thresholds \(\beta_c\) to the paper’s thresholds \(\nu_c\). Thus even a carefully chosen type space changes the representation of the traffic, not the computational object being optimized. This is not an objection to fractional recommendation variables: the relevant point is that the paper already treats the population’s expected traffic as aggregate mass.

The best reply is that binary-rational masses can encode huge cohorts compactly, so the desired running time should be polynomial in \(\tau\) and bit length \(L\), without expanding them into individual users. That is a legitimate bit-complexity detail, but it looks like a weighted-input refinement of this same matching problem rather than a new continuous mirror. The paper’s appendix also points toward weighted constraints. A version preserving nonlinear utility over each user’s sequence or individual regret might retain population information that aggregate request mass loses, but it would no longer mirror Theorem 1’s additive objective.

This is the strongest negative case I can make, and it is limited: large recommender populations with repeated request profiles are plausible, and the authors could recognize the cohort formulation as theirs. The objection is that, for this anchor, the paper has already made expected population traffic the object of its computation. If that modeling equivalence is not treated as a collision, the continuous mirror survives.
