The anchor — algorithmic

Theorem 2.1

The continuous mirror question

Given a finite hospital set \(\mathcal H\), a finite set \(T\) of complete resident types, rational masses \(\mu_t\) with \(\sum_{t\in T}\mu_t=1\), and rational per-capita quotas \(0\leq \ell_h\leq u_h\), decide whether there is a feasible assignment of the atomless mass of each type to an acceptable hospital or to \(\bot\) that is robustly mass-popular. Each type specifies its resident ranking and its priority class at every hospital; hospitals rank classes, with residents in the same class tied. An assignment is a measurable function from each type's mass space \(\Omega_t\), of measure \(\mu_t\), to an acceptable hospital or \(\bot\), with hospital assignment mass between \(\ell_h\) and \(u_h\). Compare two assignments by integrating resident votes pointwise and, for each hospital, padding to \(u_h\) with \(\bot\), canceling common assigned mass, and pairing the remaining outgoing and incoming mass by any measure-preserving correspondence; hospital votes follow its priority classes. Find an assignment that no feasible alternative defeats under any admissible set of correspondences, or report that none exists. Determine whether this can be done in time polynomial in \(|\mathcal H|\), \(\tau=|T|\), and the input bit length \(L\), with a finite rational description of the assignment.

The model it lives in

A large, atomless applicant cohort represented by rational mass over \(\tau\) complete resident types, with per-capita hospital quotas and ordered hospital priority classes. A solution assigns each unit of mass to one acceptable hospital or leaves it unmatched; its popularity is tested by resident mass votes and hospital mass votes under all admissible pairings.

The objection that survived

The mirror needs tied hospital priority classes even though the paper assumes strict rankings; the proponent acknowledges this change, but does not establish that the authors would accept that variant as their problem.

fatal: False

What the mirror covers

The mirror covers only Theorem 2.1's algorithm for finding a popular feasible matching in HRLQ. It leaves out the maximal envy-free matching theorem, the empirical comparisons, and the paper's discussion of minimizing blocking pairs or blocking residents.

Open questions for a prover

  • Does a robustly mass-popular feasible assignment always exist for rational type masses and per-capita quotas with tied priority classes?
  • Can the assignment and all popularity comparisons be represented by finite rational variables so the decision and search problems have algorithms polynomial in \(|\mathcal H|\), \(\tau\), and \(L\)?

The case FOR (proponent)

The best anchor is Theorem 2.1, proved in this paper. It says that for an HRLQ instance, Algorithm 1 returns a feasible matching popular among all feasible matchings; when a feasible stable matching exists, it returns a stable matching. The paper gives the algorithm’s running time as \(O((|\mathcal R|+|\mathcal H|+|E|)\,|\mathcal R|)\). This is the paper’s direct algorithmic result for popularity. [Theorem 2.1 in the paper](https://arxiv.org/abs/1805.01311)

Here is a continuous question that keeps that objective. Let \(\mathcal H\) be a finite set of hospitals and \(T\) a finite set of complete resident types. A type specifies a resident’s acceptable hospitals and strict ranking, plus the resident’s hospital-priority class at each hospital. Residents in type \(t\) have rational mass \(\mu_t\), with \(\sum_t\mu_t=1\). Each hospital \(h\) ranks the types and has rational lower and upper quotas \(\ell_h,u_h\), measured as fractions of the population. The input is promised to admit a feasible assignment.

Represent each type’s mass by an interval \(\Omega_t\) of length \(\mu_t\). A solution is a measurable assignment \(f\) of every point in \(\Omega=\bigcup_t\Omega_t\) to an acceptable hospital or to \(\bot\), the unmatched outcome. Its mass summary is \(x_{t,h}=\lambda(\{z\in\Omega_t:f(z)=h\})\), with \(\ell_h\leq\sum_t x_{t,h}\leq u_h\). Thus each resident gets one hospital; a type’s mass may be split across hospitals.

Define popularity by the paper’s vote comparison. Residents vote according to their own rankings. For each hospital, pad its assignment to its upper quota with \(\bot\), cancel resident mass assigned there in both assignments, and pair the remaining outgoing and incoming mass using a measure-preserving correspondence, as in the paper’s \(\mathrm{corr}_h\). The hospital’s mass votes follow its type priorities. Call \(f\) robustly mass-popular if no feasible assignment \(g\) defeats it under any admissible set of these hospital correspondences: the total mass voting for \(g\) over \(f\) is never greater. The continuous problem is: given the rational type masses, rankings, and quotas, find such an assignment, or report that none exists. Its solution should have a finite rational description, and the complexity question is whether it can be solved in time polynomial in \(|\mathcal H|\), \(\tau=|T|\), and the input bit length \(L\). There is no cost objective in Theorem 2.1; the witness is a feasible assignment satisfying this popularity condition.

A plausible regime is a large residency or course-placement cohort: many applicants, a relatively small set of institutions, and a small number of recurring preference and eligibility profiles. Per-capita quotas express staffing or placement capacity at population scale. For example, a cohort may have many thousands of residents but only dozens or hundreds of complete profiles. That scenario depends on hospitals using a small number of priority classes. If individual exam scores determine strict, distinct hospital rankings, those scores belong in each resident’s type and \(\tau\) may grow with the population.

My tentative expectation is tractability: the discrete proposal algorithm has a natural type-level counterpart, with rational masses and finite type-by-hospital states. That is a research conjecture, not a consequence of their running-time bound. The theorem’s bound depends on the number of residents, and the popularity condition compares an assignment against every feasible alternative; neither fact establishes a polynomial algorithm in \(\tau\) and \(L\).

This case covers only Theorem 2.1’s search for a popular feasible matching. It does not mirror the paper’s maximal envy-free theorem or its empirical comparisons, and it does not claim a continuous version of minimizing blocking pairs or residents. The paper reports those minimization problems as NP-complete based on Hamada et al., but does not give that claim as one of its numbered results, so I do not use it as an anchor.

The weakest point is the type model’s fit with the paper’s strict hospital rankings. Under those rankings, a hospital can distinguish every pair of acceptable residents, so residents with identical preferences may still differ in a relevant priority position. A small-support regime therefore needs hospitals to rank coarse resident classes, with indifference within each class; that is a meaningful co-modification, though it changes the paper’s strict-preference model. Popularity also depends on how exchanged mass is paired, which is why the formulation keeps the paper’s correspondence rule explicit and asks for robustness over all such pairings.

The case AGAINST (opponent, writing after the proponent)

Theorem 2.1 is a genuine computational anchor, so the negative case cannot rest on the paper having only empirical or axiomatic results. Its strongest weakness is that a “complete resident type” must include not just the resident’s preferences but their position in every hospital’s strict ranking. Two residents acceptable to the same hospital cannot share that type: the hospital ranks them at distinct positions. In the paper’s Master and Shuffle data models, those rankings distinguish residents even when some share the same preference list. Thus, in the paper’s own regimes, \(\tau\) grows with the cohort, and the proposed mass model mostly renames the individual market rather than compressing it.

The best repair is to use repeated preference profiles and coarse hospital priority classes, with quotas scaled per capita. That is a coherent population model, and the matching and popularity definitions can be adapted to it. But it replaces the paper’s strict individual rankings with ties within classes. Those ties change the very priority comparisons that drive its proposal algorithm and hospital votes. The resulting question is therefore about a new HRLQ variant; Theorem 2.1 provides no direct reason to expect its algorithmic result to carry over. Alternatively, keeping strict priorities by adding each resident’s priority ranks to the type restores the paper’s model but loses the small-support premise. Allowing continuously varying priority scores avoids that loss only by moving beyond the paper’s finite-support model and requiring a new input representation.

This is the best case against the anchor, but it is not decisive: authors might regard coarse-priority HRLQ as a natural version of their problem, and large cohorts with repeated profiles are plausible. The objection makes the mirror’s fit to this paper’s strict-preference results doubtful; it cannot honestly establish that no worthwhile scenario exists.
