The continuous mirror question, as graded

Given candidates \(C\), known rational masses \(\mu_t\) summing to \(1\) for \(\tau\) ranking types, and pairwise-comparison oracles that reveal each type’s shared strict ranking, determine the exact \(k\)-plurality approval winner set. Compute \(p(c)=\sum_{t:\,\top_t=c}\mu_t\); each type approves the smallest prefix whose cumulative \(p\)-mass is at least \(k\), and the output is the set of candidates maximizing total approving mass.

Packaged proof task (what the prover saw — nothing else)

A society is given by its support: a list of \(\tau\) ranking types with positive binary rational masses \(\mu_t\), summing to \(1\). Here \(\tau\) is the support size, not the number of possible rankings.
Let \(C\) be a nonempty set of \(m\) candidates. Each type has a fixed strict linear order, accessible only through an exact pairwise-comparison oracle; a query specifies a type and two candidates and returns their relative order at unit cost.
The threshold \(k\in(0,1)\) is an input binary rational. Let \(L\) be the total bit length of the explicit input, including the masses and \(k\); count oracle queries and ordinary bit operations separately.
Write \(\operatorname{top}_t\) for type \(t\)'s first choice and define \(p(c)=\sum_{t:\operatorname{top}_t=c}\mu_t\). Type \(t\) approves the smallest prefix \(A_t\) of its order satisfying \(\sum_{c\in A_t}p(c)\ge k\). Candidates with zero plurality mass remain in the order and may be approved.
The required output is the full winner set \(W=\arg\max_{c\in C}\sum_{t:c\in A_t}\mu_t\), retaining every tie.

Is exact winner-set computation for this continuous \(k\)-plurality approval problem possible with polynomially many oracle queries and bit operations in \(m,\tau,L\), or is it NP-hard?

For a finite electorate, the corresponding protocol's exact winner set can be determined using \(\mathcal O(m)\) pairwise comparisons per voter.
That discrete comparison guarantee does not specify a bit-complexity bound for binary rational type masses.

  • Make the oracle model explicit: rankings are fixed strict linear orders, each exact pairwise query has unit cost, and ordinary bit operations are counted separately.
  • Require a nonempty candidate set and define L as the total explicit input bit length, including masses and k.
  • Explicitly retain candidates with zero plurality mass in approval prefixes, as required by the discrete protocol.

Prover output (gpt-6.1-sol / high, Bolzano prover prompt)

Result

Exact winner-set computation is possible with polynomially many oracle queries and ordinary bit operations in \(m,\tau,L\). In particular, sorting the supported rankings gives an algorithm using \(\mathcal O(\tau m\log(m+1))\) oracle queries.

The essential arithmetic observation is that all masses and the threshold can be scaled to integers of \(\mathcal O(L)\) bits. Expanding the rational masses into a finite electorate is unnecessary.

1. Exact integer scaling

Write the input masses as \(\mu_t=a_t/b_t\), and write \(k=u/v\), with positive integer denominators. Define

\(D=v\prod_{t=1}^{\tau}b_t,\qquad x_t=a_t(D/b_t),\qquad K=u(D/v).\)

All divisions here are exact. Thus \(x_t=D\mu_t\) and \(K=Dk\) are integers satisfying

\(\sum_{t=1}^{\tau}x_t=D,\qquad 0<K<D.\)

The bit length of \(D\) is at most the sum of the input denominator bit lengths, hence is \(\mathcal O(L)\). Every \(x_t\) and \(K\) is at most \(D\), so each also has \(\mathcal O(L)\) bits.

Using ordinary schoolbook integer multiplication and division, these scaled quantities can be computed in \(\mathcal O((\tau+1)L^2)\) bit operations. Intermediate products also have \(\mathcal O(L)\) bits.

2. Recover the supported rankings

For each type \(t\), sort all candidates using its pairwise-comparison oracle, obtaining

\(c_{t,1}\succ_t c_{t,2}\succ_t\cdots\succ_t c_{t,m}.\)

The oracle represents a fixed strict linear order, so it provides a consistent comparator and sorting recovers that order exactly.

For completeness, merge sort uses at most \(m\) comparisons at each merge level and has at most \(\lceil\log_2 m\rceil\) levels. Consequently, all supported rankings require \(\mathcal O(\tau m\log(m+1))\) oracle queries. When \(m=1\), no comparison is required.

Define the scaled plurality mass

\(P(c)=\sum_{t:c_{t,1}=c}x_t.\)

Then \(P(c)=Dp(c)\), and \(\sum_{c\in C}P(c)=D\).

3. Compute the approval prefixes

Initialize an integer score \(S(c)=0\) for every candidate.

For each type \(t\), scan its recovered ranking from first to last. Start with \(B=0\). At candidate \(c_{t,j}\), perform

\(B\leftarrow B+P(c_{t,j}),\qquad S(c_{t,j})\leftarrow S(c_{t,j})+x_t.\)

Stop immediately after the first index \(j\) for which \(B\ge K\).

Such an index exists: scanning the entire ranking gives \(B=D>K\). Moreover, for every index \(j\),

\(\sum_{i=1}^{j}P(c_{t,i})\ge K \quad\Longleftrightarrow\quad \sum_{i=1}^{j}p(c_{t,i})\ge k.\)

Therefore the stopping index is exactly the endpoint of the smallest qualifying prefix \(A_t\).

This scan includes candidates with zero plurality mass. A zero-mass candidate encountered before the stopping point receives approval, as required by the definition.

4. Return every tied winner

After all scans, each candidate satisfies

\(S(c)=\sum_{t:c\in A_t}x_t =D\sum_{t:c\in A_t}\mu_t.\)

Multiplication by the common positive integer \(D\) preserves both comparisons and equality. Hence the required output is precisely

\(W=\{c\in C:S(c)=\max_{d\in C}S(d)\}.\)

Computing the maximum and returning every candidate attaining it retains all ties exactly.

5. Bit complexity

All running prefix sums, plurality masses, and approval scores lie between \(0\) and \(D\). Thus every arithmetic addition or comparison uses \(\mathcal O(L)\) bits. Plurality accumulation, approval scanning, and winner extraction require \(\mathcal O(\tau m+m)\) such operations.

To include index and sorting bookkeeping, set

\(H=L+\lceil\log_2(m+1)\rceil+\lceil\log_2(\tau+1)\rceil.\)

With schoolbook arithmetic and ordinary bit-operation accounting, a conservative total bound is

\(\mathcal O\bigl((\tau+1)H^2+\tau mH\log(m+1)\bigr)\)

ordinary bit operations, separately from the oracle queries. This is polynomial in \(m,\tau,L\).

The given discrete linear-comparison guarantee is therefore not needed to establish polynomial solvability: the explicit sorting algorithm already supplies both a polynomial query bound and a polynomial bound for exact rational arithmetic.

\[ S(c)=D\sum_{t:c\in A_t}\mu_t. \]
