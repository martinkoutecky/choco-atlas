The continuous mirror question, as graded

Given finite providers \([N]\), finite item menus \(L_j\), a finite support \(T\) of user types with rational masses \(\mu_t\) summing to one, rational satisfaction values \(\sigma_t(l)\), and a fixed provider profile \(X\), compute the expected mass \(a_{t,j}=\mu_t q_{t,j}\) assigned to each provider and \(a_{t,\emptyset}=\mu_t(1-\max_j \sigma_t(X_j))\) assigned to no display. For each type \(t\), sort \(s_{t,j}=\sigma_t(X_j)\) as \(s_{t,(1)}\le\cdots\le s_{t,(N)}\), set \(s_{t,(0)}=0\), and compute \(q_{t,j}=\sum_{r=1}^{\rho_t^j}(s_{t,(r)}-s_{t,(r-1)})/(N-r+1)\), where \(\rho_t^j\) is a rank of \(s_{t,j}\).

Packaged proof task (what the prover saw — nothing else)

There are \(N\ge1\) providers, each with a finite nonempty item menu \(L_j\); let \(m=|\bigcup_j L_j|\). A fixed profile \(X\in\prod_j L_j\) specifies one item per provider. Providers remain distinct even when they select the same item.
A society is given by its support: a list \(T\) of \(\tau\) types with positive binary rational masses \(\mu_t\), satisfying \(\sum_{t\in T}\mu_t=1\). Here \(\tau\) is the support size, not the number of possible types. Each type has an explicitly given rational satisfaction function \(\sigma_t:\bigcup_j L_j\to[0,1]\). Let \(L\) be the total binary input bit length.
For each type, write \(s_{t,j}=\sigma_t(X_j)\), sort these values as \(s_{t,(1)}\le\cdots\le s_{t,(N)}\), retaining duplicates, and set \(s_{t,(0)}=0\) and \(\rho_t^j=\max\{r:s_{t,(r)}=s_{t,j}\}\).
The Shapley mediator assigns provider \(j\) probability \(q_{t,j}=\sum_{r=1}^{\rho_t^j}(s_{t,(r)}-s_{t,(r-1)})/(N-r+1)\). The required output consists of the exact rational masses \(a_{t,j}=\mu_tq_{t,j}\) and \(a_{t,\emptyset}=\mu_t(1-s_{t,(N)})\), where \(\emptyset\) means no display.

Is computing all these expected masses solvable in polynomial time in \(m,N,\tau,L\), or is it NP-hard?

For finite user lists, the Shapley mediator has the displayed closed form for each user's probabilities and an implementation that samples one display in \(O(N)\) arithmetic operations. This sampling guarantee does not specify the bit complexity of producing all exact rational masses.

Modeling choices made when packaging the task

  • Restricted satisfaction values to rational numbers in [0,1], as required by the discrete model.
  • Required at least one provider and nonempty menus so that the supplied profile and maximum satisfaction are defined.
  • Resolved tied ranks by choosing the last occurrence in the sorted list, retaining duplicates.
  • Kept providers distinct when they select the same item, consistent with the provider-indexed probability formula.
  • Specified exact rational output and total binary input bit length L; defined m as the number of distinct available items.

Conclusion

Computing all the exact masses is deterministic polynomial-time solvable in \(m,N,\tau,L\). The closed form can be evaluated using integers whose bit lengths are polynomially bounded, including when providers select identical items.

A common denominator and its bit length

Write every input rational with a positive integer denominator. Let \(D\) be the product of all denominators appearing in the satisfaction values and type masses. Each such denominator divides \(D\), and

\[ \log_2 D\le L, \]

because the sum of their binary encoding lengths is at most the total input length.

Let \(H=N!\). Every integer from \(1\) through \(N\) divides \(H\), and

\[ \log_2 H\le N\log_2(N+1). \]

Consequently, the integer \(E=D^2H\) has bit length \(O(L+N\log(N+1))\). We will represent every output mass using this common denominator.

Exact algorithm and correctness

Fix a type \(t\). Define integers

\[ u_t=D\mu_t,\qquad p_{t,j}=D\sigma_t(X_j). \]

These are integers by construction of \(D\). Since the satisfaction values and masses lie in \([0,1]\), they satisfy \(0\le p_{t,j}\le D\) and \(0<u_t\le D\).

Sort the \(N\) provider records by \(p_{t,j}\), retaining every provider record, including duplicates. Write the resulting values as

\[ p_{t,(1)}\le\cdots\le p_{t,(N)},\qquad p_{t,(0)}=0. \]

Compute the integer prefixes

\[ C_{t,0}=0,\qquad C_{t,r}=C_{t,r-1} +\bigl(p_{t,(r)}-p_{t,(r-1)}\bigr)\frac{H}{N-r+1}, \quad 1\le r\le N. \]

Each division \(H/(N-r+1)\) is exact. For each block of equal sorted values, assign every provider in that block the prefix at the block’s last position. Thus provider \(j\) receives \(C_{t,\rho_t^j}\), with exactly the tie convention specified in the question.

Because \(p_{t,(r)}=Ds_{t,(r)}\), the given closed form implies

\[ \frac{C_{t,\rho_t^j}}{DH} = \sum_{r=1}^{\rho_t^j} \frac{s_{t,(r)}-s_{t,(r-1)}}{N-r+1} =q_{t,j}. \]

Therefore output the following numerator-denominator pairs:

\[ a_{t,j}=\frac{u_tC_{t,\rho_t^j}}{E}, \qquad a_{t,\emptyset} =\frac{u_t\bigl(D-p_{t,(N)}\bigr)H}{E}. \]

The first expression equals \(\mu_tq_{t,j}\); the second equals \(\mu_t(1-s_{t,(N)})\). Hence every required output is correct. Providers remain distinct throughout the sorting and output steps.

Bit complexity

Every sorted increment is nonnegative. Since \(H/(N-r+1)\le H\), each prefix satisfies

\[ 0\le C_{t,r} \le H\sum_{h=1}^{r}\bigl(p_{t,(h)}-p_{t,(h-1)}\bigr) =Hp_{t,(r)} \le HD. \]

It follows that both kinds of output numerators are at most \(E=D^2H\). The construction can also keep every intermediate integer at most \(E\): for example, convert an input fraction \(a/b\) to denominator \(D\) by computing \(a(D/b)\).

Thus all arithmetic operands and outputs have bit length

\[ B=O\bigl(L+N\log(N+1)\bigr). \]

Constructing \(D\), \(H\), and the weights \(H/k\) takes polynomially many integer operations. For each type, forming the provider values, sorting them, computing the prefixes, handling equal-value blocks, and producing the masses requires \(O(N\log(N+1))\) comparisons and arithmetic operations. Integer comparison, multiplication, and exact division on \(B\)-bit integers all admit elementary polynomial-time algorithms.

There are \(\tau(N+1)\) output fractions, so their total encoded length is \(O(\tau(N+1)B)\), also polynomial. If reduced fractions are required, dividing each numerator and denominator by their greatest common divisor adds only polynomial time.

This proves polynomial bit complexity for producing all exact masses, independently of the stated sampling guarantee.
