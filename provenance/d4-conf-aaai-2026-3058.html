The continuous mirror question, as graded

Packaged proof task (what the prover saw — nothing else)

Let \(V=\{v_1,\ldots,v_m\}\), with \(m\geq1\), have the fixed label order \(v_1<\cdots<v_m\). A type specifies, for every unordered pair, either a strict preference in one direction or a tie; its judgments need not be transitive, and ties contribute no arcs.
A society is given by its support: the list of the \(\tau\) types with positive mass, each mass \(\mu_t\) a binary rational, with \(\sum_t\mu_t=1\). Here \(\tau\) is the support size, not the number of possible types; let \(L\) be the total input bit length.
Define \(W_\mu(u,v)=\sum_t\mu_t\mathbf{1}[t\text{ strictly prefers }u\text{ to }v]\) for distinct candidates and \(A_0=\{(u,v):W_\mu(u,v)>0\}\). Initialize a working graph \(H=(V,A_0,W_\mu)\) and empty lists \(s_1,s_2\).
Repeat the following round until \(H\) is empty: repeatedly remove a sink, prepending it to \(s_2\); then repeatedly remove a source, appending it to \(s_1\); if vertices remain, remove a vertex maximizing \(\delta_H(u)=\sum_{(u,v)\in A(H)}W_\mu(u,v)-\sum_{(v,u)\in A(H)}W_\mu(v,u)\), appending it to \(s_1\). Each removal deletes all incident arcs; all ties between eligible vertices use the smallest label. An isolated vertex qualifies as a sink.
The required output is \(s=s_1\Vert s_2\), \(R(s)=\{(u,v)\in A_0:\operatorname{pos}_s(u)>\operatorname{pos}_s(v)\}\), and the retained weighted DAG \((V,A_0\setminus R(s),W_\mu)\).

Is computing this output solvable in polynomial time in \(m,\tau,L\), or is it NP-hard?

For discrete ensembles with a fixed number \(k\) of evaluators and integral arc weights in \(\{0,\ldots,k\}\), greedy denoising has a stated linear time and space bound in the number of positive arcs, using connectedness to absorb the vertex count.
For arbitrary real arc weights, a stated bound is \(O(a\log m)\) time and \(O(a)\) space on connected graphs, where \(a=|A_0|\); this is a graph-operation bound rather than a bit-complexity bound for rational support input.

Modeling choices made when packaging the task

  • Interpreted a complete judgment pattern as one outcome per unordered pair: either direction of strict preference or a tie. Allowed cyclic judgments and ignored ties, as the preference-graph model requires.
  • Normalized the positive rational masses to sum to one, interpreting the society as a distribution.
  • Fixed all unspecified choices among sinks, sources, and maximum-degree-difference vertices by the input label order.
  • Classified isolated vertices as sinks, following the algorithm's sink-first phase.
  • Allowed disconnected graphs and single-candidate inputs because the denoising procedure is defined for them; retained the connectedness qualification when stating the anchor's arc-only complexity bound.
  • Interpreted the requested total order as the denoising sequence, rather than the separate descendant-count ranking.

Conclusion

Computing the specified output is polynomial-time solvable in \(m,\tau,L\). The crucial point is that all score comparisons can be performed exactly using integers of polynomial bit length.

Here, rational input uses the usual binary encoding of numerators and denominators; this includes dyadic rational masses.

1. Exact integer representation

Write each positive mass as \(\mu_t=p_t/q_t\), where \(p_t,q_t\) are positive integers. Define

\(D=\prod_{t=1}^{\tau}q_t,\qquad n_t=p_t(D/q_t).\)

Each division is exact, and the normalization hypothesis gives

\(\sum_{t=1}^{\tau}n_t=D.\)

For distinct candidates, define the integer weight

\(C(u,v)=\sum_{t=1}^{\tau}n_t\mathbf{1}[t\text{ strictly prefers }u\text{ to }v].\)

Consequently,

\(W_\mu(u,v)=C(u,v)/D,\qquad 0\leq C(u,v)\leq D.\)

In particular, \((u,v)\in A_0\) exactly when \(C(u,v)>0\).

Although the numerical value of \(D\) can be large, its binary length is small:

\(\log_2 D=\sum_{t=1}^{\tau}\log_2 q_t\leq L.\)

Thus \(D\), every \(n_t\), and every \(C(u,v)\) have \(O(L)\) bits. Constructing \(D\), the \(n_t\), and the matrix \(C\) requires only polynomially many exact integer operations.

2. Exact simulation of every removal

Let \(S\subseteq V\) be the set of remaining vertices. Since removals only delete incident arcs, the working graph is always the subgraph induced by \(S\). Define its integer score by

\(\Delta_S(u)=\sum_{v\in S\setminus\{u\}}C(u,v)-\sum_{v\in S\setminus\{u\}}C(v,u).\)

The prescribed score satisfies

\(\delta_H(u)=\Delta_S(u)/D.\)

Because \(D>0\), maximizing \(\delta_H\) is exactly equivalent to maximizing \(\Delta_S\), including equality of scores. Also,

\(\lvert\Delta_S(u)\rvert\leq (|S|-1)D.\)

Hence every score has \(O(L+\log(m+1))\) bits.

Maintain, for each active vertex, its incoming and outgoing positive-arc counts and its integer score. These determine sinks and sources exactly: a sink has outgoing count zero, and a source has incoming count zero.

When removing \(u\), update each remaining vertex \(v\) as follows:

  • Decrease its outgoing count by one if \(C(v,u)>0\).
  • Decrease its incoming count by one if \(C(u,v)>0\).
  • Replace its score by \(\Delta_{S\setminus\{u\}}(v)=\Delta_S(v)-C(v,u)+C(u,v)\).

The score update follows directly by deleting the outgoing contribution \(C(v,u)\) and the incoming contribution \(-C(u,v)\).

Execute the phases in precisely the stated order: exhaust sinks, then exhaust sources, then perform one maximum-score removal if vertices remain. For each selection, scan active vertices in increasing label order. Choose the first eligible sink or source; for score maximization, replace the current choice only upon finding a strictly larger score. This implements every required label tie-break.

Initially, the maintained counts and scores are correct by construction. The update formulas preserve their correctness after each removal. Induction on the number of removals therefore proves that this simulation makes exactly the prescribed choices.

3. Bit-complexity bound

Set \(B=L+\lceil\log_2(m+1)\rceil+3\), which bounds the lengths of the integers used, including intermediate score updates.

Using ordinary quadratic-time integer multiplication and division:

  • Constructing \(D\) and all \(n_t\) costs \(O(\tau B^2)\) bit operations.
  • Constructing all \(C(u,v)\) costs \(O(\tau m^2B)\) bit operations.
  • Initializing counts and scores costs \(O(m^2B)\) bit operations.

For the simulation, each nonempty round removes at least one vertex: if the sink and source phases leave vertices, the maximum-score phase removes one. There are therefore at most \(m\) rounds and exactly \(m\) removals.

Each successful selection removes a vertex. Each round additionally has at most two unsuccessful scans, one ending each of the sink and source phases. Thus there are \(O(m)\) selection scans, each inspecting at most \(m\) vertices. Each removal also updates at most \(m-1\) remaining vertices. All score comparisons and updates cost \(O(B)\) bit operations.

The simulation consequently costs \(O(m^2B)\) bit operations. An overall bound is

\(O\bigl(\tau B^2+(\tau m^2+m^2)B\bigr),\)

which is polynomial in \(m,\tau,L\). Storage is likewise polynomial.

This argument includes isolated vertices and disconnected graphs; no connectedness assumption is needed.

4. Constructing and verifying the required output

Record source and maximum-score removals in their removal order to form \(s_1\). Record sink removals separately and reverse that record to form \(s_2\), exactly implementing repeated prepending. Since every vertex is removed once, \(s=s_1\Vert s_2\) is a permutation of \(V\).

Compute each vertex’s position in \(s\), then inspect every positive arc. Put \((u,v)\) in \(R(s)\) exactly when \(\operatorname{pos}_s(u)>\operatorname{pos}_s(v)\); otherwise retain it with weight \(C(u,v)/D\). This requires another \(O(m^2B)\) bit operations, including writing the rational weights.

Every retained arc strictly increases position in \(s\). A directed cycle would therefore force a strict increase in position all the way back to its starting vertex, which is impossible. The retained graph is a DAG.

Thus the complete prescribed output—not merely its ordering—is computable in polynomial time. The cited graph-operation bounds are compatible with this result; exact rational arithmetic supplies the additional bit-complexity justification.
