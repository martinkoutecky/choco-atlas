The continuous mirror question, as graded

Given finite type sets \(A\) and \(B\), rational masses \(\mu_a\) and \(\nu_b\) summing to \(1\) on each side, and strict rankings of opposite-side types, each type is a process in the paper's complete bipartite message-passing model. Let \(\delta=\max_{a\in A}(\max_{b\in B} r_b(a)-\min_{b\in B} r_b(a))\), and let \(\tau=\max(|A|,|B|)\). Can every process output its incident entries of a rational coupling \(x\) satisfying \(\sum_b x_{ab}=\mu_a\), \(\sum_a x_{ab}=\nu_b\), and stability— for each \((a,b)\), either the mass of type \(a\) matched to types it prefers to \(b\) is zero or the mass of type \(b\) matched to types it prefers to \(a\) is zero—using \(O(\tau(\delta+1))\) received messages per process, each of \(O(L+\log\tau)\) bits, where \(L\) is the input bit length?

Packaged proof task (what the prover saw — nothing else)

Each side of a society is given by its support: nonempty finite type lists \(A,B\), with positive binary-rational masses \(\mu_a,\nu_b\) satisfying \(\sum_a\mu_a=\sum_b\nu_b=1\). Let \(\tau=|A|+|B|\) be the total support size, not the number of possible types, \(m=\max\{|A|,|B|\}\), and \(L\) the total input bit length.
Each type strictly ranks all opposite-side types; rank \(1\) is best. Write \(r_a(b),r_b(a)\) for these ranks and \(\delta=\max_{a\in A}(\max_{b\in B}r_b(a)-\min_{b\in B}r_b(a))\).
There is one process per supported type on the complete bipartite network. Initially each process knows its own mass and ranking; identifiers, support sizes, and an input-length bound \(L\) are public. In each synchronous round a process either sends to at most one neighbor or receives from at most one neighbor; simultaneous messages to one recipient are all lost.
Every process must output its incident entries of a common coupling \(x\in\mathbb Q_{\ge0}^{A\times B}\), with \(\sum_bx_{ab}=\mu_a\) and \(\sum_ax_{ab}=\nu_b\). Stability means that, for every \((a,b)\), \(\sum_{b':r_a(b')>r_a(b)}x_{ab'}=0\) or \(\sum_{a':r_b(a')>r_b(a)}x_{a'b}=0\).
Polynomial time means polynomially many rounds and total local bit operations in \(m,\tau,L,\delta\).

Is this distributed search problem solvable in polynomial time using \(O(\tau(\delta+1))\) received messages per process, each of \(O(L+\log\tau)\) bits, or is it \(\mathrm{NP}\)-hard under these communication bounds?

For discrete societies with \(n\) participants per side, a deterministic algorithm computes stable partners in \(O(n(\Delta+1))\) rounds using that many received messages per process of \(O(\log n)\) bits ([Khanchandani–Wattenhofer](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.OPODIS.2016.12)).
Centralized stable allocation with real quantities has a strongly polynomial algorithm; the verified result does not specify these distributed communication bounds ([Baïou–Balinski, corrected version](https://pubsonline.informs.org/doi/pdf/10.1287/moor.27.4.662.302)).

Modeling choices made when packaging the task

  • Corrected stability from zero mass on better partners to zero mass on worse partners: the discrete blocking-pair definition requires both endpoints to prefer each other to some currently assigned partners.
  • Required nonempty supports, positive masses, and nonnegative coupling entries; retained normalization to one on each side.
  • Used tau for total support size rather than the maximum side size; these conventions differ by at most a factor of two. Defined m as the maximum side size.
  • Specified private initial masses and rankings, public identifiers and support sizes, and a public bound L on total input bit length.
  • Restored the synchronous send-or-receive restriction and the rule that collisions lose all messages.

The key feature of the stated model is that \(L\) is the total input length: one permitted message can contain a process’s entire local input. The following protocol handles arbitrary supported masses and rankings.

1. Exact centralized computation. Write each input mass as a ratio of positive integers, and let \(D\) be the product of all their denominators. Define
\(u_a=D\mu_a\) and \(v_b=D\nu_b\).
These are positive integers satisfying

\( \sum_a u_a=\sum_b v_b=D. \)

Since the denominator encodings are part of the input, \(D\) has \(O(L)\) bits.

Apply the corrected Baïou–Balinski inductive algorithm with supplies \(u_a\), demands \(v_b\), the given strict preferences, and pair capacities \(c_{ab}=2D\). Its hypotheses are finite preference lists, positive supplies and demands, and nonnegative pair capacities; all hold here. It computes a stable allocation \(y\) using polynomially many additions, subtractions, comparisons, and minimum operations. Its stability condition is

\( y_{ab}<c_{ab} \ \Longrightarrow\ \sum_{b':\,r_a(b')\le r_a(b)}y_{ab'}=u_a \quad\text{or}\quad \sum_{a':\,r_b(a')\le r_b(a)}y_{a'b}=v_b. \)

These properties follow from Section 2 and Theorem 2 of the [corrected paper](https://pubsonline.informs.org/doi/pdf/10.1287/moor.27.4.662.302).

We now verify that this allocation gives precisely the coupling required in the question.

First, every row and column is saturated. Indeed, suppose the allocated total \(T=\sum_{a,b}y_{ab}\) were less than \(D\). Because both total supply and total demand equal \(D\), some row \(a\) and some column \(b\) would be unsaturated. Feasibility gives

\( y_{ab}\le u_a\le D<2D=c_{ab}. \)

Neither cumulative sum in the displayed stability condition could equal its corresponding supply or demand: each is bounded above by an unsaturated total. This contradicts stability. Thus \(T=D\). Since row totals are bounded above by \(u_a\) and their bounds sum to \(D\), every row is saturated; the same argument applies to columns.

Consequently, for every pair \((a,b)\), the displayed stability condition is equivalent to

\( \sum_{b':\,r_a(b')>r_a(b)}y_{ab'}=0 \quad\text{or}\quad \sum_{a':\,r_b(a')>r_b(a)}y_{a'b}=0. \)

Therefore \(x_{ab}=y_{ab}/D\) is a stable coupling with the required marginals.

The algorithm starts from integer data and uses only the arithmetic operations specified above, so its output entries \(y_{ab}\) are integers. Feasibility ensures \(0\le y_{ab}\le D\). Hence each rational entry \(y_{ab}/D\), including zero, has an \(O(L)\)-bit representation.

Exact computation also has polynomial bit complexity. If there are \(K\) arithmetic operations, additions and subtractions increase the maximum operand bit length by at most one per operation, while comparisons and minima do not increase it. Thus intermediate integers have \(O(L+K)\) bits. The centralized theorem bounds \(K\) polynomially in the support sizes.

2. Gathering the input. Put \(p=|A|\) and \(q=|B|\), so \(\tau=p+q\). Using the public identifiers, choose a leader \(a_*\in A\) and a relay \(b_*\in B\). Public positions in the identifier lists provide \(O(\log\tau)\)-bit routing labels.

Each process’s local input occupies at most \(L\) bits. Use a predetermined serial schedule:

  • Each \(b\in B\) sends its local input directly to \(a_*\).
  • Each \(a\in A\setminus\{a_*\}\) sends its local input to \(b_*\), which forwards it to \(a_*\) in the next round.

There is only one transmission per scheduled round, so collisions and simultaneous sending and receiving cannot occur.

The leader receives \(\tau-1\) messages. The relay receives \(p-1\) messages. Gathering takes \(q+2(p-1)\) rounds, with each message containing \(O(L+\log\tau)\) bits.

The leader then performs the centralized computation. A publicly fixed polynomial computation interval, determined by \(\tau\) and the input-length bound \(L\), lets every process know when distribution begins without additional messages.

3. Distributing the coupling. Enumerate all pairs \((a,b)\) in a public order. For each pair, reserve two rounds:

  • The leader sends \((a,b,y_{ab},D)\) to \(b\), which stores its incident entry.
  • If \(a\ne a_*\), process \(b\) forwards that entry to \(a\).

The leader stores its own row locally. The serialized schedule again respects every network restriction. Each packet has \(O(L+\log\tau)\) bits.

Every \(B\)-process receives exactly \(p\) output packets. Every nonleader \(A\)-process receives exactly \(q\) output packets. Thus, including gathering, the received-message counts are

\( \begin{array}{c|c} \text{Process}&\text{Received messages}\\ a_*&\tau-1\\ a\ne a_*&q\\ b_*&2p-1\\ b\ne b_*&p \end{array} \)

All are \(O(\tau)\). Distribution uses at most \(2pq\) rounds, and every process outputs entries of the same coupling.

4. Complexity conclusion. Gathering, exact computation, distribution, and output require polynomially many rounds and total local bit operations in \(m,\tau,L\). No dependence on \(\delta\) is needed. Since \(\delta\ge0\), the proved \(O(\tau)\) received-message bound satisfies \(O(\tau(\delta+1))\).
