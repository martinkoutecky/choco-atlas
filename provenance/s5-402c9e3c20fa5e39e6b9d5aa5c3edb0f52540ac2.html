The continuous mirror question, as graded

Given rational type masses \(\mu_t\) summing to \(1\), complete rich-ad schedules \(t=(D_t,v_t,\ell_t)\), and per-capita line and slot capacities \(q,h\), define coalition welfare \(W(\nu)\) by maximizing \(\sum_{t,d}v_t(d)y_{td}\) over \(y_{td}\ge 0\), subject to \(\sum_d y_{td}\le \nu_t\), \(\sum_{t,d}\ell_{td}y_{td}\le q\), and \(\sum_{t,d}y_{td}\le h\). Can one compute a welfare-maximizing mass allocation, nonnegative per-type utilities \(u_t\), and revenue \(r\) satisfying \(r+\sum_t\mu_tu_t=W(\mu)\) and \(r\ge W(\nu)-\sum_t\nu_tu_t\) for every \(0\le\nu\le\mu\), such that the core utilities are \(\epsilon\)-bidder-optimal, using \(O(\tau\log(\tau/\epsilon))\) calls to a truncated fluid-welfare oracle and \(O(\tau^2\log(\tau/\epsilon))\) additional arithmetic?

Packaged proof task (what the prover saw — nothing else)

A society is given by its support: the list of \(\tau\) types with positive binary-rational masses \(\mu_t\), summing to \(1\). The parameter \(\tau\) is the support size, not the number of possible types.
Each type has an explicitly listed, nonempty finite decoration set \(D_t\), rational values \(v_t(d)\in[0,1]\), and positive integer line requirements \(\ell_{td}\). Nonservice has value zero. Let \(m=\sum_t|D_t|\); positive rational capacities \(q,h\) are measured per capita, and rational \(0<\epsilon<1\) is given. Let \(L\) be the total binary input length.
For every real coalition mass vector \(0\le\nu\le\mu\), define \(W(\nu)=\max_y\sum_{t,d}v_t(d)y_{td}\), subject to \(y_{td}\ge0\), \(\sum_d y_{td}\le\nu_t\), \(\sum_{t,d}\ell_{td}y_{td}\le q\), and \(\sum_{t,d}y_{td}\le h\). Coalition capacities remain \(q,h\), independent of coalition mass.
An output consists of a welfare-maximizing allocation for \(\mu\) and per-capita type utilities \(u_t\ge0\) and seller revenue \(r\ge0\) satisfying \(r+\sum_t\mu_tu_t=W(\mu)\) and \(r\ge W(\nu)-\sum_t\nu_tu_t\) for every \(0\le\nu\le\mu\). Allocations assign no mass to zero-value decorations.
Such utilities are \(\epsilon\)-bidder-optimal if no other core pair \((u',r')\) has \(u'_t\ge u_t\) for all types and \(u'_s>u_s+\epsilon\) for some type \(s\); the tolerance applies to per-capita utilities.
A truncated fluid-welfare oracle accepts rational offsets \(a_t\ge0\) and returns the optimal value and an optimal allocation for the same constraints at \(\mu\), replacing values by \(\max\{v_t(d)-a_t,0\}\); it assigns no mass to zero truncated values, with arbitrary remaining tie-breaking.

Is computing this allocation and an \(\epsilon\)-bidder-optimal core pair polynomial-time in \(m,\tau,L\), or NP-hard?
If polynomial-time, can it be done with \(O(\tau\log(\tau/\epsilon))\) truncated fluid-welfare oracle calls and \(O(\tau^2\log(\tau/\epsilon))\) additional arithmetic operations, apart from input/output handling?

For discrete combinatorial auctions with \(n\) bidders and values in \([0,1]\), a deterministic algorithm computes an \(\epsilon\)-bidder-optimal core point using \(O(n\log(n/\epsilon))\) truncated welfare-oracle calls and \(O(n^2\log(n/\epsilon))\) additional computation. Result

The problem is polynomial-time solvable, with the requested oracle and arithmetic bounds. A sequential binary search over type utilities suffices.

More precisely, put \(K=\lceil\log_2(1/\epsilon)\rceil\). The algorithm uses at most \(1+\tau K\) truncated fluid-welfare oracle calls and \(O(\tau^2K)\) additional arithmetic operations, apart from input/output handling. These imply the stated bounds with the usual constant-floor convention for logarithms; the minor endpoint issue when \(\tau=1\) is detailed below.

The proof treats all real coalition vectors directly. It does not require extending the discrete water-filling theorem of [Niazadeh et al.](https://arxiv.org/pdf/1610.03564).

1. An exact oracle characterization of the continuous core

Write \(P(\nu)\) for the allocation polytope in the question, and put \(W=W(\mu)\). For any nonnegative utility vector \(u\), define the truncated oracle value

\(F(u)=\max_{y\in P(\mu)}\sum_{t,d}\max\{v_t(d)-u_t,0\}y_{td}\).

All allocation maxima exist: the feasible polytopes are nonempty, closed, and bounded, since \(0\le y_{td}\le\mu_t\).

Lemma 1. For every \(u\ge0\),

\(F(u)=\max_{0\le\nu\le\mu}\left(W(\nu)-\sum_t\nu_tu_t\right)\).

Proof. Fix a coalition \(\nu\), and let \(y\) maximize its welfare. Define its served type masses by \(s_t=\sum_dy_{td}\). Because \(s_t\le\nu_t\), \(u_t\ge0\), and \(y\in P(\mu)\),

\(W(\nu)-\sum_t\nu_tu_t\le\sum_{t,d}(v_t(d)-u_t)y_{td}\le\sum_{t,d}\max\{v_t(d)-u_t,0\}y_{td}\le F(u)\).

For the reverse inequality, take an allocation \(y^u\) returned by the truncated oracle and set \(s_t=\sum_dy^u_{td}\). The oracle assigns mass only where \(v_t(d)>u_t\), so

\(F(u)=\sum_{t,d}(v_t(d)-u_t)y^u_{td}\).

Moreover, \(0\le s\le\mu\), and \(y^u\in P(s)\): its resource consumption is unchanged, and its served type masses are exactly \(s\). Therefore

\(W(s)-\sum_ts_tu_t\ge\sum_{t,d}(v_t(d)-u_t)y^u_{td}=F(u)\).

Together with the first inequality, this proves equality and exhibits a maximizing coalition. Arbitrary remaining oracle tie-breaking does not affect the argument. ∎

For any proposed \(u\ge0\), the budget equation determines revenue as

\(r(u)=W-\sum_t\mu_tu_t\).

Lemma 1 consequently gives the exact membership test

\((u,r(u))\text{ is a core pair}\quad\Longleftrightarrow\quad F(u)\le W-\sum_t\mu_tu_t\).

Indeed, this inequality is equivalent to every coalition constraint, and it also implies \(r(u)\ge0\), since \(F(u)\ge0\). Thus one truncated oracle call tests core membership exactly.

2. Downward closure and uniform utility bounds

Let \(C\) be the set of utility vectors belonging to core pairs. Eliminating revenue yields

\(C=\left\{u\ge0:\ \sum_t(\mu_t-\nu_t)u_t\le W-W(\nu)\text{ for every }0\le\nu\le\mu\right\}\).

The coalition \(\nu=0\) ensures nonnegative revenue.

Lemma 2. The set \(C\) contains \(0\), is downward closed, and satisfies \(C\subseteq[0,1]^\tau\).

Proof. Increasing coalition supplies only relaxes allocation constraints, so \(W(\nu)\le W\). Hence \(0\in C\).

Every coefficient \(\mu_t-\nu_t\) in the displayed inequalities is nonnegative. Consequently, if \(u\in C\) and \(0\le z\le u\), every inequality remains valid for \(z\). This proves downward closure.

For the bound, fix a type \(t\) and define \(\nu=\mu-\mu_te_t\), removing that type entirely. From a welfare-maximizing allocation for \(\mu\), remove all its type-\(t\) allocations. The resulting allocation is feasible for \(\nu\), and its welfare loss is at most

\(\sum_{d\in D_t}v_t(d)y_{td}\le\sum_{d\in D_t}y_{td}\le\mu_t\).

Thus \(W-W(\nu)\le\mu_t\). The core inequality for this coalition gives

\(\mu_tu_t\le W-W(\nu)\le\mu_t\).

Because every listed support mass is positive, division by \(\mu_t\) gives \(u_t\le1\). ∎

In particular, binary-search precision can be chosen in per-capita utility units, independently of the smallest type mass.

3. The algorithm

Fix any order of the \(\tau\) types.

  • Query the oracle with all offsets zero. Retain its optimal value \(W\) and allocation \(y^*\). This allocation maximizes original welfare and assigns no mass to zero-value decorations.
  • Initialize \(u=0\).
  • For each type \(t\), perform the following search while keeping every other coordinate fixed:
  • Initialize \(b=0\) and \(c=1\).
  • While \(c-b>\epsilon\), set \(x=(b+c)/2\), and form \(a\) by replacing coordinate \(t\) of \(u\) with \(x\).
  • Query the truncated oracle at \(a\). If \(F(a)\le W-\sum_j\mu_ja_j\), set \(b=x\); otherwise set \(c=x\).
  • At termination, set \(u_t=b\).
  • Output \(y^*\), \(u\), and \(r=W-\sum_t\mu_tu_t\).

At the start of type \(t\)'s search, its utility is still zero. Thus the initial lower endpoint is feasible. The upper endpoint need not be infeasible: Lemma 2 guarantees that no feasible utility exceeds it.

The algorithm is deterministic once the type order is fixed. Its utility calculations depend only on oracle values.

4. Proof of correctness

Each search maintains two invariants:

  • Replacing the current type’s utility by \(b\), with all other utilities fixed, gives a vector in \(C\).
  • Every feasible value of that coordinate, with all other utilities fixed, is at most \(c\).

Initially these follow from feasibility of the current vector and Lemma 2.

If the midpoint is feasible, updating \(b\) preserves both invariants. If it is infeasible, no larger coordinate value can be feasible: downward closure would otherwise imply feasibility of the midpoint. Updating \(c\) therefore also preserves both invariants.

It follows that every completed stage leaves \(u\in C\). Hence the final pair is exactly in the core.

To prove \(\epsilon\)-bidder optimality, suppose another core utility vector \(u'\) satisfies \(u'\ge u\). Fix a type \(t\), and let \(b_t,c_t\) be the final endpoints of its search. We have

\(u_t=b_t\quad\text{and}\quad c_t-b_t\le\epsilon\).

Let \(z\) agree with the utility vector at the end of type \(t\)'s stage, except that \(z_t=u'_t\). Previously processed coordinates equal their final values; subsequently processed coordinates were still zero. Therefore \(0\le z\le u'\). Downward closure implies \(z\in C\).

The upper-endpoint invariant from type \(t\)'s search consequently gives

\(u'_t\le c_t\le b_t+\epsilon=u_t+\epsilon\).

This holds for every type. Thus no dominating core vector improves any coordinate by more than \(\epsilon\), exactly as required. ∎

5. Oracle complexity and polynomial bit complexity

Each search starts with interval length \(1\), and every iteration halves it. Consequently, every type uses exactly \(K=\lceil\log_2(1/\epsilon)\rceil\) membership queries. Including the initial welfare query, the call count is

\(1+\tau\lceil\log_2(1/\epsilon)\rceil\).

Constructing an offset vector and calculating its proposed revenue takes \(O(\tau)\) arithmetic operations per query. The remaining updates and final revenue calculation fit within the resulting bound

\(O\!\left(\tau^2\lceil\log_2(1/\epsilon)\rceil\right)\).

For \(\tau\ge2\), these are literally \(O(\tau\log(\tau/\epsilon))\) calls and \(O(\tau^2\log(\tau/\epsilon))\) additional arithmetic operations. Uniformly, including \(\tau=1\) and \(\epsilon\) approaching \(1\), the corresponding bounds use \(1+\log(\tau/\epsilon)\), or a ceiling. This is the customary constant-floor interpretation of logarithmic complexity bounds.

Finally, the oracle is polynomial-time implementable:

  • Each query is a rational linear program with \(m\) variables, \(\tau+2\) allocation constraints, and nonnegativity constraints.
  • It is feasible and bounded.
  • Every queried offset is a dyadic rational with denominator dividing \(2^K\).
  • The binary encoding length of \(\epsilon\) implies \(K=O(L)\), so all queried objectives have polynomial encoding length.
  • Polynomial-time rational linear programming returns an exact optimal value and a rational optimal allocation of polynomial encoding length. Removing allocations to zero truncated values preserves both feasibility and the objective.

The exact comparisons and all arithmetic outside the oracle likewise involve rationals of polynomial encoding length. Therefore the entire computation is polynomial-time in \(m,\tau,L\).

The proof establishes polynomial-time solvability and an \(\epsilon\)-bidder-optimal core pair. Its mathematical argument is sound. Two minor qualifications concern the interpretation of the logarithmic bounds and the claim of determinism.

1. Allocation maxima and oracle characterization

The allocation polytopes are nonempty because the zero allocation is feasible. They are closed and bounded: nonnegativity and the type constraints imply \(0\le y_{td}\le\mu_t\). Thus their linear objectives attain maxima.

Both directions of Lemma 1 are valid:

  • For any coalition \(\nu\), its welfare-maximizing allocation is feasible at \(\mu\). Replacing the coalition masses by served masses can only increase the net objective because \(u\ge0\). Truncating negative coefficients can only increase it further. This proves the asserted upper bound by \(F(u)\).
  • The oracle’s prohibition on allocations to zero truncated values ensures that its truncated objective equals its untruncated net objective. Its served mass vector \(s\) is an admissible coalition, and its allocation is feasible for that coalition because capacities remain fixed.

The second direction also exhibits a coalition attaining the claimed maximum. Thus the lemma covers every real coalition vector without a discretization or an unstated attainment assumption.

The resulting membership test is correct. The budget equation fixes revenue, Lemma 1 captures all coalition constraints, and \(F(u)\ge0\) ensures nonnegative revenue whenever the test succeeds.

2. Downward closure and utility bounds

The displayed description of \(C\) follows correctly by substituting the budget equation into each coalition constraint.

Monotonicity of welfare under increased type supplies establishes \(0\in C\). All coefficients \(\mu_t-\nu_t\) are nonnegative, so the downward-closure argument is valid.

The bound \(u_t\le1\) is also correct. Removing type \(t\)’s allocations preserves resource feasibility and loses welfare at most \(\mu_t\). The coalition removing that entire type consequently gives
\[ \mu_tu_t\le W-W(\mu-\mu_te_t)\le\mu_t. \]
Division is justified by the explicitly positive support masses.

This bound is in per-capita utility units and does not depend on the smallest mass.

3. Binary-search algorithm and invariants

Each coordinate starts at zero because it has not previously been processed. The current vector is feasible by induction, so the initial lower endpoint is feasible.

The upper endpoint need only bound all feasible coordinate values; it need not be infeasible. Lemma 2 supplies precisely this initial invariant.

Both midpoint updates preserve the stated invariants. In particular, if a larger coordinate value were feasible after an infeasible midpoint, downward closure would imply feasibility of that midpoint, a contradiction.

The final utility vector therefore belongs to \(C\), and the reported revenue satisfies all core requirements. The initial zero-offset oracle allocation maximizes original welfare and satisfies the required exclusion of zero-value decorations.

4. Bidder optimality

The dominance argument is valid with the required quantifiers.

For any dominating core vector \(u'\) and each type \(t\), the constructed vector \(z\) is coordinatewise below \(u'\): earlier coordinates equal their final values, later coordinates remain zero, and coordinate \(t\) equals \(u'_t\). Hence downward closure makes \(z\) feasible.

The upper-endpoint invariant from that stage then gives
\[ u'_t\le c_t\le b_t+\epsilon=u_t+\epsilon. \]
This applies to every coordinate and every dominating core vector. It rules out exactly the strict improvement greater than \(\epsilon\) appearing in the task.

5. Oracle calls, arithmetic, and bit complexity

After \(k\) iterations, the interval length is \(2^{-k}\). Therefore each coordinate uses exactly
\[ K=\left\lceil\log_2(1/\epsilon)\right\rceil \]
queries, including when \(1/\epsilon\) is a power of two. The total \(1+\tau K\) is correct.

Constructing each query vector and computing its proposed revenue requires \(O(\tau)\) arithmetic operations. The remaining search updates and final calculation fit within \(O(\tau^2K)\), since \(\tau\ge1\) and \(K\ge1\).

The polynomial-time implementation is justified by the standard theorem that rational linear programs can be optimized exactly in time polynomial in their binary encoding length, returning a rational optimizer of polynomial encoding length when a finite optimum exists. The hypotheses are satisfied here:

  • The constraint system is rational, feasible, and bounded.
  • Queried offsets have denominator dividing \(2^K\).
  • The positive rational encoding of \(\epsilon\) implies \(K=O(L)\).
  • Truncated objective coefficients therefore retain polynomial encoding length.
  • Deleting allocations to zero truncated coefficients preserves feasibility and objective value.

Exact oracle-value comparisons and the external rational arithmetic also have polynomial bit complexity. No hardness conclusion is needed: the explicit polynomial-time algorithm settles the main classification.

6. Minor issues and actionable feedback

Minor issue: the requested logarithmic bounds require the stated convention. For \(\tau\ge2\), the advertised bounds follow literally. For \(\tau=1\), however, \(\log(1/\epsilon)\) tends to zero as \(\epsilon\) approaches one, while this algorithm uses two oracle calls whenever \(\epsilon>1/2\). Thus there is no uniform literal bound by a constant times \(\log(1/\epsilon)\) over the full parameter domain.

The prover explicitly identifies this endpoint issue and supplies a valid bound using \(1+\log(\tau/\epsilon)\) or a ceiling. This is a minor qualification under the customary constant-floor reading of logarithmic complexity bounds.

Minimum clarification: qualify the opening claim with that convention, rather than stating the requested bounds unconditionally.

Minor issue: determinism applies to the utilities, not necessarily the whole output. The statement “The algorithm is deterministic once the type order is fixed” is too broad because the retained allocation may depend on arbitrary oracle tie-breaking.

For example, one type with mass one and two decorations, both with value one and line requirement one, with \(q=h=1\), admits distinct optimal allocations assigning all mass to either decoration. The permitted oracle can return either.

This does not affect correctness or the complexity bounds. Minimum clarification: state that the utility vector and revenue are deterministic for a fixed type order, while the allocation may depend on oracle tie-breaking.
