Theorem 2 — class: algorithmic

The continuous mirror question, as graded

Given a finite support \(T\) of complete student types with rational masses \(\mu_t>0\), project and lecturer sets, type preference orders and lecturer priority orders, and rational per-capita capacities \(\kappa_p\) and \(\lambda_\ell\), decide whether there are rational assignments \(x_{tp}\ge 0\) satisfying \(\sum_p x_{tp}\le\mu_t\), \(\sum_t x_{tp}\le\kappa_p\), and \(\sum_t\sum_{p\in P_\ell}x_{tp}\le\lambda_\ell\), with no positive mass of any type-project pair forming a super-stability block under the paper’s capacity and priority conditions; return such an assignment or report that none exists.

Packaged proof task (what the prover saw — nothing else)

A society is given by its support: the list of \(\tau\) student types with positive binary-rational masses \(\mu_t\), normalized by \(\sum_t\mu_t=1\). Here \(\tau\) is the support size, not the number of possible types.
There are \(m\) projects and \(h\) lecturers; nonempty sets \(P_\ell\) partition the projects. Positive binary-rational capacities satisfy \(\max_{p\in P_\ell}\kappa_p\le\lambda_\ell\le\sum_{p\in P_\ell}\kappa_p\).
Each type specifies a weak order over an acceptable subset \(A_t\) of projects and its priority position for each relevant lecturer. Each lecturer weakly orders exactly the types accepting at least one of her projects; all individuals of a type have identical preferences and priorities. Ties remain unbroken, and every acceptable project is preferred to being unassigned.
An assignment consists of rational masses \(x_{tp}\ge0\), with \(x_{tp}=0\) for \(p\notin A_t\), satisfying \(\sum_p x_{tp}\le\mu_t\), \(a_p:=\sum_t x_{tp}\le\kappa_p\), and \(b_\ell:=\sum_{p\in P_\ell}a_p\le\lambda_\ell\). Put \(x_{t\bot}=\mu_t-\sum_p x_{tp}\).
A positive-mass block exists if some \(p\in A_t\), offered by \(\ell\), and \(q\in A_t\cup\{\bot\}\), with \(q\ne p\) and \(x_{tq}>0\), satisfy: \(q=\bot\) or type \(t\) weakly prefers \(p\) to \(q\); and one of the following holds:
(i) \(a_p<\kappa_p\) and \(b_\ell<\lambda_\ell\).
(ii) \(a_p<\kappa_p\), \(b_\ell=\lambda_\ell\), and either \(q\in P_\ell\) or there exist \(u,r\) with \(r\in P_\ell\), \(x_{ur}>0\), and \(\ell\) weakly prioritizing \(t\) over \(u\).
(iii) \(a_p=\kappa_p\) and there is a type \(u\) with \(x_{up}>0\) whom \(\ell\) weakly prioritizes below \(t\). In (ii) and (iii), \(u=t\) is allowed: distinct individuals of the same type are tied. An assignment is super-stable if it has no such block.

Is deciding whether a rational super-stable assignment exists polynomial-time solvable or NP-hard? State running times in \(m,\tau,h\) and the total input bit length \(L\); in the polynomial-time case, also return such an assignment when one exists.

For discrete students, super-stable existence and construction take \(O(D)\) time, where \(D\) is total preference-list length ([Olaosebikan–Manlove](https://link.springer.com/article/10.1007/s10878-020-00632-x)).
No result settling exactly the mass problem defined above was identified in the literature search.

Modeling choices made when packaging the task

  • Normalized total student mass to one, interpreting capacities as per-capita quantities.
  • Interpreted complete student types as fully specified preference and priority data, allowing incomplete acceptable-project lists as in the discrete definition.
  • Retained positive capacities, nonempty lecturer project sets, unique project ownership, and the lecturer capacity bounds from the discrete model.
  • Defined blocking using positive mass at a specific current project or the unassigned state, excluding mass already assigned to the proposed project.
  • Retained the same-lecturer transfer condition by testing whether the blocking mass's current project belongs to that lecturer.
  • Translated comparison with worst assignees into existence of positive assigned mass of weakly lower priority, including distinct individuals of the same type.
  • Kept ties on both sides without tie-breaking and treated every acceptable project as preferable to being unassigned.

Result

The problem is polynomial-time solvable, including construction of a rational super-stable assignment.

Let \(E=\sum_t |A_t|\), so \(E\le m\tau\), and put \(n=m+\tau+h+1\). A conservative bound for the algorithm proved below is

\(O\!\left(n^4(E+1)^2(L+1)^2\right)\)

bit operations. Consequently, a bound stated solely in the requested parameters is

\(O\!\left((m+\tau+h+1)^4(m\tau+1)^2(L+1)^2\right)\).

The main point is to simulate the discrete super-stability algorithm on groups of identical students, without explicitly creating the potentially exponentially many students.

1. Super-stability forbids splitting a type

Lemma 1. In every super-stable assignment, each type is either wholly unassigned or wholly assigned to one project.

Proof. Suppose first that \(x_{tp}>0\) and \(x_{t\bot}>0\). Set \(q=\bot\).

Otherwise, suppose that two distinct projects have positive assigned mass of type \(t\). Choose their names \(p,q\) so that \(t\) weakly prefers \(p\) to \(q\). Thus \(x_{tp}>0\), \(x_{tq}>0\), and \(q\ne p\).

In either situation, the student side of the blocking condition holds. Let \(\ell\) offer \(p\).

  • If \(a_p<\kappa_p\) and \(b_\ell<\lambda_\ell\), condition (i) holds.
  • If \(a_p<\kappa_p\) and \(b_\ell=\lambda_\ell\), condition (ii) holds with \(u=t\) and \(r=p\).
  • If \(a_p=\kappa_p\), condition (iii) holds with \(u=t\).

The latter two cases use the stipulated permission to take \(u=t\): the lecturer weakly prioritizes type \(t\) over itself.

These cases exhaust feasibility’s possible capacity statuses. Hence every such split creates a block. Since the masses assigned to projects and to \(\bot\) sum to \(\mu_t\), the conclusion follows. ∎

In particular, every nonzero coordinate of a super-stable assignment equals an input mass \(\mu_t\). No additional denominators are needed in the output.

2. An exact discrete expansion

Let \(Q\) be the product of the denominators appearing in all masses and capacities. Define positive integers

\(N_t=Q\mu_t,\qquad C_p=Q\kappa_p,\qquad D_\ell=Q\lambda_\ell.\)

All these integers have \(O(L)\) bits, and \(\sum_t N_t=Q\).

Consider the following discrete instance, initially only as a mathematical object:

  • Replace type \(t\) by \(N_t\) distinct students.
  • Give every such student the preferences of type \(t\).
  • In each lecturer’s list, replace every type by all its students, tied together; preserve ties between types.
  • Use capacities \(C_p,D_\ell\).

The lecturer capacity hypotheses are preserved because multiplication by \(Q\) preserves the given inequalities.

Lemma 2. The mass instance admits a super-stable assignment if and only if this expanded discrete instance admits a super-stable matching.

Proof. First take any matching in the expanded instance and let \(z_{tp}\) count its type-\(t\) students at \(p\). Its aggregate assignment is \(x_{tp}=z_{tp}/Q\), with unassigned mass defined similarly. Feasibility and all fullness comparisons correspond exactly under scaling.

A discrete blocking pair gives a mass block: use the blocking student’s type and current assignment, together with the type of any displaced student.

Conversely, suppose the aggregate assignment has a mass block witnessed by \(t,p,q\). Choose a type-\(t\) student assigned to \(q\), or an unassigned one when \(q=\bot\). Positive mass guarantees that this student exists. Any required positive mass \(x_{ur}\) likewise supplies a discrete replacement witness.

The replacement witness can be chosen distinct from the blocking student:

  • In (iii), the replacement student is at \(p\), whereas the blocking student is at \(q\ne p\).
  • In (ii), if \(q\in P_\ell\), membership in the lecturer’s assignment already suffices. Otherwise the blocking student is outside that lecturer’s assignment, while the replacement student is inside it.

This remains valid when \(u=t\). Thus discrete and aggregate super-stability are equivalent for every expanded matching.

Finally, if the mass instance has a super-stable assignment, Lemma 1 says each type is entirely assigned to one project or entirely unassigned. Its assigned counts are therefore \(N_t\) or zero, so it lifts to an expanded matching. The preceding equivalence proves both directions. ∎

Explicit expansion is insufficient for polynomial time: \(Q\) may be exponentially large. The remaining task is to simulate the discrete algorithm compactly.

3. The discrete algorithm being simulated

We use Algorithm 1, SPA-ST-super, and Theorem 2 of [Olaosebikan–Manlove](https://link.springer.com/content/pdf/10.1007/s10878-020-00632-x.pdf). Their correctness guarantee covers every permitted execution: the algorithm returns a super-stable matching when one exists and otherwise reports nonexistence.

The relevant algorithmic features are these. An unassigned student applies along her current head tie, possibly holding several provisional projects. Lecturer loads count distinct students. Oversubscription deletes a complete tail tie from the relevant projected or lecturer list; fullness deletes strict successors of a worst provisional assignee. Lecturer deletions extend to all relevant projects. An end-of-round rule can also delete a lecturer’s tail, using the best rejected student of a previously full project. Deletions remove provisional pairs. Historical information consists of previously-full project flags and best rejected priorities. The final provisional assignment is accepted precisely when it is super-stable.

The expanded instance satisfies the theorem’s hypotheses: it has individual students, weak preference lists, positive integer capacities, and the required partition and capacity inequalities. Below we simulate its algorithm exactly, retaining the original order of conditional tests.

4. A compact representation of the execution

Lemma 3. Between completed deletion sweeps, all students of a type have identical reduced preference lists.

Proof. Initially their lists are identical. Every deletion criterion selects a complete priority tie or all strict successors of a specified priority. All students of a type have the same lecturer priority.

Consequently, a project deletion removes that project from every student of each selected type. A lecturer deletion removes all relevant projects from every student of each selected type. These operations preserve identical reduced lists.

A sweep may perform its individual deletions sequentially, but no proposal is interleaved with that sweep. We can therefore complete the sweep before applying this invariant. ∎

A group consists of:

  • a type \(t\);
  • a positive integer multiplicity;
  • a common set \(S\) of provisional projects.

The group represents that many students of type \(t\), each currently holding exactly \(S\). Preference lists are stored once per type.

Initially there is one group \((t,N_t,\varnothing)\) per type. A deletion changes the provisional set of every affected group without splitting that group. Groups with the same type and provisional set can be merged.

For a group of multiplicity \(w\), its contribution to a project load is \(w\) when that project belongs to \(S\). Its contribution to lecturer \(\ell\)’s load is \(w\) when \(S\cap P_\ell\ne\varnothing\), regardless of the number of projects in that intersection. This represents distinct-student lecturer loads exactly.

The remaining information is also compact:

  • Tail ties and worst assignees can be found using type priorities and groups with positive multiplicity.
  • When a deleted pair had provisional assignees, its type priority updates the project’s best rejected priority.
  • Previously-full flags are stored directly.

Only priority comparisons matter; expanded student identities are unnecessary.

5. Batching proposals safely

Consider a point immediately before selecting an unassigned student. Choose a type \(t\) with \(F>0\) unassigned students and a nonempty reduced list. Merge its unassigned groups.

Let \(H\) be its current head tie, and let

\(J(H)=\{\ell:H\cap P_\ell\ne\varnothing\}.\)

Write \(c_p,d_\ell\) for the current discrete provisional loads. Set

\(k=\min\!\left(\{F\}\cup\{\max(0,C_p-c_p-1):p\in H\}\cup\{\max(0,D_\ell-d_\ell-1):\ell\in J(H)\}\right).\)

Lemma 4. When \(k>0\), processing \(k\) unassigned students of type \(t\), consecutively, produces no deletion and can be represented by one group update.

Proof. In the absence of deletions, each such student proposes to every project of \(H\). Each project in \(H\) gains one provisional student per iteration. Each lecturer in \(J(H)\) gains one distinct student per iteration, even if several projects of \(H\) belong to that lecturer.

By the definition of \(k\), after all \(k\) iterations every touched project and lecturer remains strictly below capacity. Their loads are nondecreasing throughout those iterations, so they also remain strictly below capacity at every intermediate proposal.

Thus none of the fullness or oversubscription tests can delete anything. The reduced lists stay unchanged, and every processed student finishes with provisional set \(H\). The update is exactly the addition of a group \((t,k,H)\) and subtraction of \(k\) from the unassigned count. ∎

If \(k=F\), this exhausts the type’s current unassigned students.

If \(k<F\), perform the safe batch when nonempty and then process one further student by the original algorithm, proposal by proposal, including every deletion sweep. This requires isolating at most one student from a group.

After that individual iteration, resume batching. End-of-round processing is simulated directly on the compact state.

Every batch represents consecutive legal individual iterations, and every exceptional iteration follows the original algorithm exactly. Induction over these operations therefore proves that the compact simulation represents a permitted expanded execution.

6. The number of operations is polynomial

A deletion of a surviving type–project pair removes that project from every student of the type. Such a pair never returns. Therefore there are at most \(E\) type–project deletions.

Divide the execution into intervals between these deletions. There are at most \(E+1\) intervals. Within each interval, provisional loads cannot decrease: only proposals occur.

There are three kinds of simulation steps.

Individual iterations containing deletions. There are at most \(E\), since each contains at least one previously surviving type–project deletion.

Individual iterations containing no deletion. Each follows a batch with \(k<F\). At least one touched resource must then reach capacity during the individual iteration.

Indeed, if all touched resources started below capacity, the minimum defining \(k\) places some resource exactly one student short of capacity after the batch. If a touched resource started full or oversubscribed, its subsequent oversubscription test would delete a nonempty tail, contradicting the assumption that this iteration has no deletion.

Between deletions, each project or lecturer can reach capacity from below at most once. Hence there are at most \((m+h)(E+1)\) such individual iterations.

Batches exhausting a type’s unassigned students. Within one deletion-free interval, once such a batch exhausts a type, that type cannot acquire new unassigned students. That would require deleting provisional pairs. Thus there are at most \(\tau(E+1)\) exhausting batches.

Every nonexhausting safe batch is immediately followed by an individual iteration, so it introduces no additional asymptotic count. Altogether, there are

\(O\!\left(n(E+1)\right)\)

batch and individual steps.

The number of end-of-round scans is also at most \(E+1\): every scan followed by another proposal round must have deleted a surviving pair.

Each batch or isolated individual creates at most one new group, and deletions never split groups. Therefore the number of groups is

\(K=O\!\left(n(E+1)\right)\).

These bounds are independent of \(Q\).

7. Bit complexity, correctness, and output

A straightforward implementation can recompute loads, relevant priority extrema, reduced-list tails, and deletion effects by scanning all group project sets and type lists. One such recomputation uses

\(O(Km+E+\tau h+n)=O\!\left(n^2(E+1)\right)\)

elementary operations.

An individual iteration makes at most \(m\) proposals. Each proposal involves only a constant number of deletion rules and recomputations. An end-of-round scan examines at most \(m\) projects. Thus either kind of step costs at most

\(O\!\left(n^3(E+1)\right)\)

elementary operations. Multiplying by the established number of steps gives

\(O\!\left(n^4(E+1)^2\right)\)

operations.

All multiplicities, loads, and scaled capacities have \(O(L)\) bits. Using a conservative \(O((L+1)^2)\) bound per arithmetic operation, including the scaling computations, yields the stated bit-operation bound.

At termination, first check that the represented provisional assignment is a feasible discrete matching. If it is, aggregate its counts by dividing by \(Q\), and check the mass blocking conditions. This is polynomial: project and lecturer priority extrema can be computed from the aggregate assignment, and the possible current projects \(q\) can be scanned for each acceptable pair.

By Lemma 2, this final check agrees exactly with the expanded algorithm’s super-stability check. Since the simulation follows a permitted execution, the discrete correctness theorem proves that rejection means no super-stable matching exists. Lemma 2 then proves that no rational super-stable assignment exists either.

On acceptance, Lemma 1 guarantees that each type is wholly assigned to one project or wholly unassigned. Return \(x_{tp}=\mu_t\) for that assigned project and zero elsewhere. This constructs the required rational assignment within the same polynomial bound.
