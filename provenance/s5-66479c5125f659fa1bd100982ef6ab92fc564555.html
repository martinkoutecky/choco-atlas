The continuous mirror question, as graded

Given applicant types \(\mathcal T\), each with a location \(\ell(t)\) and positive rational mass \(\mu_t\) summing to \(1\), and projects \(P\) with positive rational capacities \(q_p\) summing to \(1\), decide whether there are nonnegative flows \(x_{tp}\) and binary choices \(z_{p\ell}\) satisfying \(\sum_p x_{tp}=\mu_t\), \(\sum_t x_{tp}=q_p\), \(\sum_\ell z_{p\ell}=1\), and \(x_{tp}\leq \mu_t z_{p,\ell(t)}\) for every type and project. Thus each project is filled entirely from one location. Preference rankings may be supplied but do not affect feasibility.

Packaged proof task (what the prover saw — nothing else)

A society is given by its support: a list \(\mathcal T\) of \(\tau\geq 1\) applicant types, each with one location \(\ell(t)\) and positive binary rational mass \(\mu_t\), with \(\sum_{t\in\mathcal T}\mu_t=1\). Here \(\tau\) is the support size, not the number of possible types. Let \(\Lambda=\{\ell(t):t\in\mathcal T\}\).
There are \(m\geq 1\) projects \(P\), with positive binary rational capacities \(q_p\) satisfying \(\sum_{p\in P}q_p=1\). Every type may supply every project; preferences are irrelevant to feasibility. Let \(L\) be the total input bit length.
A feasible allocation consists of real flows \(x_{tp}\geq 0\) and choices \(z_{p\lambda}\in\{0,1\}\) satisfying \(\sum_{p\in P}x_{tp}=\mu_t\), \(\sum_{t\in\mathcal T}x_{tp}=q_p\), \(\sum_{\lambda\in\Lambda}z_{p\lambda}=1\), and \(x_{tp}\leq\mu_t z_{p,\ell(t)}\) for every type and project. Type mass may be split among projects, but each project must be filled entirely from one location.

Is deciding whether a feasible allocation exists solvable in polynomial time in \(m,\tau,L\), or is it \(\mathrm{NP}\)-hard?

For discrete applicants, deciding whether every applicant can be assigned and every project filled entirely from one location is \(\mathrm{NP}\)-complete; feasibility is polynomial-time solvable when all project capacities are equal and every location population is divisible by that capacity. [Source](https://arxiv.org/html/2505.03680v2).
No prior result settling the continuous problem stated here was located.

Modeling choices made when packaging the task

  • The location index set was undefined; use exactly the locations represented by positive-mass types.
  • The flow domain was unspecified beyond nonnegativity; allow real flows and arbitrary splitting of a type's mass.
  • Define m as the number of projects and L as the total input bit length.
  • Make unrestricted applicant–project eligibility explicit, consistent with complete preference lists in the discrete definition.

Result

The decision problem is \(\mathrm{NP}\)-complete, even with exactly two types at distinct locations, each of mass \(\frac12\). Hardness holds even when every capacity is a dyadic rational, meaning a rational whose denominator is a power of two.

Thus a polynomial-time algorithm in \(m,\tau,L\) exists if and only if \(\mathrm{P}=\mathrm{NP}\).

1. Exact characterization of feasibility

For each location \(\lambda\in\Lambda\), define its total mass by
\[ \]
\(M_\lambda:=\sum_{t:\ell(t)=\lambda}\mu_t.\)

Every \(M_\lambda\) is positive because \(\Lambda\) contains precisely the locations appearing in the support.

Lemma. A feasible allocation exists if and only if there is a function \(c:P\to\Lambda\) such that, for every \(\lambda\in\Lambda\),

\(\displaystyle \sum_{p:c(p)=\lambda}q_p=M_\lambda.\)

Proof, necessity. Given a feasible allocation, let \(c(p)\) be the unique location for which \(z_{p,c(p)}=1\). If \(\ell(t)\ne c(p)\), the constraint \(x_{tp}\leq\mu_tz_{p,\ell(t)}\), together with nonnegativity, implies \(x_{tp}=0\).

Consequently, all mass supplied by types at \(\lambda\) goes to projects with \(c(p)=\lambda\), and those projects receive mass only from types at \(\lambda\). Using both sets of flow equalities gives

\(\displaystyle M_\lambda =\sum_{t:\ell(t)=\lambda}\sum_{p\in P}x_{tp} =\sum_{p:c(p)=\lambda}\sum_{t\in\mathcal T}x_{tp} =\sum_{p:c(p)=\lambda}q_p.\)

Proof, sufficiency. Suppose such a function \(c\) exists. Set \(z_{p\lambda}=1\) exactly when \(c(p)=\lambda\). Define \(x_{tp}=0\) when \(c(p)\ne\ell(t)\), and otherwise define

\(\displaystyle x_{tp}:=\frac{\mu_tq_p}{M_{\ell(t)}}.\)

For every type \(t\),

\(\displaystyle \sum_{p\in P}x_{tp} =\frac{\mu_t}{M_{\ell(t)}}\sum_{p:c(p)=\ell(t)}q_p =\mu_t.\)

For every project \(p\),

\(\displaystyle \sum_{t\in\mathcal T}x_{tp} =\frac{q_p}{M_{c(p)}}\sum_{t:\ell(t)=c(p)}\mu_t =q_p.\)

Finally, if \(c(p)=\ell(t)\), then \(q_p\leq M_{\ell(t)}\), since \(q_p\) is one positive summand in the corresponding capacity total. Hence \(x_{tp}\leq\mu_t\). If the locations differ, \(x_{tp}=0\). All required constraints hold. This proves the lemma.

2. Membership in \(\mathrm{NP}\)

A certificate specifies \(c(p)\) for each project. It uses \(O(m\log(\tau+1))\) bits. By the lemma, verification consists of checking the location totals

\(\displaystyle \sum_{p:c(p)=\lambda}q_p=\sum_{t:\ell(t)=\lambda}\mu_t.\)

These equalities can be checked exactly in polynomial time. In particular, the product of all input denominators provides a common denominator whose bit length is at most the sum of their bit lengths, hence \(O(L)\). After clearing denominators, verification uses polynomially many integer operations on integers of polynomial bit length.

Therefore the problem belongs to \(\mathrm{NP}\). No real-valued flow needs to appear in the certificate.

3. Polynomial-time hardness reduction

We reduce from PARTITION, the standard \(\mathrm{NP}\)-complete problem: given positive binary integers \(a_1,\ldots,a_n\), decide whether some index set \(I\subseteq\{1,\ldots,n\}\) satisfies

\(\displaystyle \sum_{i\in I}a_i=\frac12\sum_{i=1}^na_i.\)

The source problem and its \(\mathrm{NP}\)-completeness are stated in [MIT’s complexity lecture notes](https://people.csail.mit.edu/rrw/6.1400-2025/lec19-before-class.pdf).

Write \(S:=\sum_{i=1}^na_i\). If \(S\) is odd, the source instance is a no-instance. Output the fixed infeasible instance having two types at distinct locations, each of mass \(\frac12\), and one project of capacity \(1\). The lemma proves its infeasibility.

Now suppose \(S\) is even. Choose the smallest power of two \(D\) satisfying \(D>2S\), and define the positive integer

\(\displaystyle K:=\frac{D-S}{2}.\)

Construct two types at distinct locations \(\lambda_1,\lambda_2\), both of mass \(\frac12\). Construct \(n+2\) projects: the first \(n\) have capacities \(a_i/D\), and the two additional projects each have capacity \(K/D\).

All capacities are positive dyadic rationals, and

\(\displaystyle \sum_{p\in P}q_p=\frac{S+2K}{D}=1.\)

Forward direction. Suppose \(I\) solves PARTITION. Assign the projects indexed by \(I\), together with one additional project, to \(\lambda_1\). Assign the remaining projects and the other additional project to \(\lambda_2\). Each location receives capacity

\(\displaystyle \frac{S/2+K}{D}=\frac12.\)

The lemma supplies a feasible allocation.

Reverse direction. Suppose the constructed instance is feasible. By the lemma, each location receives project capacities totaling \(\frac12\). The two additional projects cannot go to the same location, because their combined capacity is

\(\displaystyle \frac{2K}{D}=\frac{D-S}{D}>\frac12,\)

where the strict inequality follows from \(D>2S\). Thus each location receives exactly one additional project.

Let \(I\) index the original projects assigned to \(\lambda_1\). Its capacity equality implies

\(\displaystyle \sum_{i\in I}a_i=\frac D2-K=\frac S2.\)

Therefore \(I\) solves PARTITION.

Encoding size. The choice of \(D\) gives \(D\leq4S\), so \(D\) and \(K\) have \(O(\log S)\) bits. Since \(\log S\) is polynomially bounded by the source input length, constructing the \(n+2\) capacities takes polynomial time and produces polynomial output length.

This proves \(\mathrm{NP}\)-hardness under the stated restrictions. Together with membership in \(\mathrm{NP}\), it proves the claimed completeness result.

4. Equal-capacity case

When all capacities are equal, their sum forces \(q_p=1/m\). The lemma then shows that feasibility holds exactly when \(mM_\lambda\) is an integer for every location \(\lambda\).

Necessity follows because \(mM_\lambda\) must count the projects assigned to that location. Conversely, these positive integer counts sum to \(m\), so one can assign exactly \(mM_\lambda\) projects to each location and apply the lemma. The condition is checkable in polynomial time.

Thus allowing applicant mass to split simplifies allocation within a location, but leaves the exact partition of whole project capacities responsible for hardness.
