The continuous mirror question, as graded

Given a finite type set \(T\), rational masses \(\mu_t\) summing to \(1\), ATFG utility tables over types, and a listed assignment of valid finite team profiles \(q\) with rational frequencies \(x_q>0\) satisfying \(\sum_q b_t(q)x_q=\mu_t\), is the assignment Nash stable? Check whether any represented member of type \(t\) in profile \(q\) can strictly improve by leaving that team and joining a team with profile \(r\), with the resulting source and destination teams satisfying the ATFG size and anchor rules; include singleton deviations where permitted.

Packaged proof task (what the prover saw — nothing else)

A society is given by its support: a list \(T\) of \(\tau\) types with positive binary-rational masses \(\mu_t\), where \(\sum_t\mu_t=1\). Here \(\tau\) is the support size, not the number of possible types.
An anchored team formation game has integer size bounds \(0\le c_l\le c_u=m\), with \(m\ge1\), and fully specified signed-integer tables \(v_t(s),d_t(s),p_t(s,u)\), where \(p_t(s,u)=p_t(u,s)\); any member may be an anchor.
A team profile \(q\) is an explicit finite list of member slots with types \(t_i\), together with one designated anchor slot \(a\). It is valid when \(\max\{1,c_l\}\le |q|\le m\); repeated types are allowed. Member slot \(i\) has utility \(U_i(q)=d_{t_i}(t_a)+\sum_{j\ne i}v_{t_i}(t_j)+\sum_{j<k,\ j,k\ne i}p_{t_i}(t_j,t_k)\).
The input lists \(k\) valid profiles with positive binary-rational team frequencies \(x_q\), satisfying \(\sum_q b_t(q)x_q=\mu_t\), where \(b_t(q)\) counts type \(t\) slots. Frequencies describe a nonatomic population of finite teams; sizes and utilities use slot counts, not masses.
A deviation removes one represented member slot from a source team and adds it to a distinct represented destination team, possibly of the same profile. The destination retains its anchor; the source retains its anchor unless that member leaves, in which case any remaining member may replace it. An empty source disappears; every nonempty resulting team must be valid. Alternatively, the mover may form a valid singleton anchored by itself. Resulting profiles need not already be listed, and no other member's consent is required.
The assignment is Nash stable exactly when no such feasible deviation strictly increases the mover's utility; equal utility does not block stability.

Is Nash stability verification for this mass-based problem in \(\mathrm{P}\), or is it \(\mathrm{NP}\)-hard? State running times in \(m,\tau,k,c_l\) and the total input bit length \(L\).

Discrete ATFG Nash stability verification is polynomial-time computable ([verified discrete result](https://www.researchgate.net/publication/351566041_Anchored_Team_Formation_Games)). No published result settling exactly this mass-based verification problem was located.

Modeling choices made when packaging the task

  • Utility tables are fully specified signed integers, following the discrete numerical domain; unspecified 'unknown' entries are excluded because no evaluation semantics is supplied.
  • Profiles are encoded as explicit member-slot lists with a distinguished anchor slot; repeated types denote distinct members, including in pair utilities.
  • The size parameter m is the upper bound c_u; bounds are integers with 0 <= c_l <= c_u and c_u >= 1, and empty teams are excluded.
  • Frequencies measure a nonatomic population of finite teams, rather than fractional membership within a team; positive frequency permits distinct source and destination teams of the same profile.
  • Anchor succession is unspecified: existing anchors remain unless they depart, and a departing source anchor may be replaced by any remaining member. Any member is eligible, since the formal game definition imposes no eligibility restriction.
  • An emptied source disappears; all nonempty resulting teams obey the size bounds. Singleton deviations are allowed exactly when a singleton is valid, and the mover anchors it.
  • Deviation outcomes need not belong to the supplied profile list; that list describes the current assignment, not the set of permitted teams.

Result

Nash stability verification for the stated mass-based problem is in \(\mathrm{P}\). The proof below uses the explicit profile list and the stated deviation rules directly.

Let \(\ell=\max\{1,c_l\}\), let \(n_q=|q|\), and let \(h_q\) denote the anchor’s type. Define \( N=\sum_{q=1}^{k}n_q \), \( M=\max_q n_q \), and \( r=\min\{M,\tau\} \).

An algorithm uses \( O\!\left(N+k\tau r^2\right) \) arithmetic operations after reading the input. Consequently, a bound expressed using the requested parameters is \( O\!\left(km+k\tau\min\{m,\tau\}^2\right) \) arithmetic operations. A conservative bit-complexity bound, including input validation, is \( O\!\left(L^3+\left(N+k\tau r^2\right)L^2\right) \), which is \( O(L^4) \) for this explicit input representation. The lower bound \(c_l\) enters only through size comparisons and singleton feasibility.

1. Exactly which deviations are feasible?

Source feasibility

A member can leave profile \(q\) exactly when \( n_q=1\quad\text{or}\quad n_q>\ell. \)

Indeed:

  • If \(n_q=1\), its source becomes empty and disappears, which is expressly permitted.
  • If \(n_q>1\), its source remains nonempty and has size \(n_q-1\). Its upper size bound remains satisfied, and its lower size bound is satisfied exactly when \(n_q-1\geq\ell\).
  • If the departing member is the anchor and the source remains nonempty, a remaining member can always replace it, because every member may be an anchor.

Thus source feasibility is independent of the departing member’s type and anchor status. No remaining member’s utility needs to be checked.

Destination feasibility

A represented destination profile \(q'\) can accept a mover exactly when \( n_{q'}<m. \)

Its size then becomes \(n_{q'}+1\), which still satisfies the lower size bound because \(q'\) was valid. Its existing anchor remains designated.

A new singleton is feasible exactly when \(\ell=1\), equivalently \(c_l\leq1\).

Distinct teams with the same profile

Positive nonatomic team frequency permits two distinct teams of the same represented profile, even when \(x_q<1\).

For a concrete realization, index the teams of listed profile \(q\) by an interval \((0,x_q)\), with one copy of each member slot at every index. Give each slot’s interval Lebesgue measure. The mass of type \(t\) is then exactly \( \sum_q b_t(q)x_q=\mu_t. \)

Every such interval contains distinct indices. Hence a source and destination may have the same listed profile while being distinct teams. In particular, the algorithm must not exclude a destination merely because its profile equals the source profile.

2. Utilities depend only on type counts and the anchor type

Write \(b(q)=(b_s(q))_{s\in T}\). Fix any ordering of \(T\), and define, for a nonnegative integer count vector \(b\),

\( F_t(b)= \sum_{s\in T}b_s v_t(s) +\sum_{s\in T}\binom{b_s}{2}p_t(s,s) +\sum_{s<u}b_s b_u p_t(s,u). \)

This expression counts every unordered pair of distinct slots exactly once: pairs of type \(s\) occur \(\binom{b_s}{2}\) times, and pairs of different types \(s,u\) occur \(b_s b_u\) times.

If a type-\(t\) mover joins profile \(q\), its utility is therefore

\( A_t(q)=d_t(h_q)+F_t(b(q)). \)

All existing slots of \(q\) are other members from the mover’s perspective.

If \(b_t(q)>0\), a current type-\(t\) member instead has utility

\( C_t(q)=d_t(h_q)+F_t(b(q)-e_t), \)

where \(e_t\) is the unit vector for type \(t\). Equivalently,

\( C_t(q)=A_t(q)-v_t(t) -(b_t(q)-1)p_t(t,t) -\sum_{s\ne t}b_s(q)p_t(t,s). \)

To verify the identity, remove one type-\(t\) slot from the slots counted by \(F_t(b(q))\). This removes its linear contribution \(v_t(t)\), its pairs with the other \(b_t(q)-1\) type-\(t\) slots, and its pairs with the \(b_s(q)\) slots of each other type.

Consequently, all type-\(t\) slots in a fixed profile have the same current utility, including an anchor slot of that type.

A newly formed singleton gives utility \(d_t(t)\).

3. An exact stability criterion

For each type \(t\), define its minimum utility among feasible sources by

\( S_t= \min\bigl\{ C_t(q): b_t(q)>0,\ n_q=1\ \text{or}\ n_q>\ell \bigr\}. \)

Set \(S_t=+\infty\) if the set is empty.

Define its best feasible destination utility by

\( D_t= \max\left( \{A_t(q):n_q<m\} \ \cup\ \begin{cases} \{d_t(t)\},&\ell=1,\\ \varnothing,&\ell>1. \end{cases} \right). \)

Set \(D_t=-\infty\) if there is no feasible destination.

Claim. The assignment is Nash stable exactly when \( D_t\leq S_t \) for every type \(t\) having a feasible source.

Proof. Suppose first that some feasible deviation strictly improves a type-\(t\) member’s utility. Its source \(q\) appears in the definition of \(S_t\), so \( S_t\leq C_t(q). \)
Its destination utility is at most \(D_t\), because it either joins a represented team or forms a singleton. Strict improvement therefore implies \( D_t>C_t(q)\geq S_t. \)

Conversely, suppose \(D_t>S_t\) for a type having a feasible source. Both relevant extrema are attained, since their candidate sets are finite. Choose a source attaining \(S_t\) and a destination attaining \(D_t\). The size conditions established above make the deviation feasible. If the destination has the same profile as the source, choose a distinct team instance, which exists by positive nonatomic frequency. The mover’s utility increases from \(S_t\) to \(D_t\), so the assignment is unstable.

These implications also show that equality does not cause rejection, as required. \(\square\)

Although resulting profiles may be unlisted, this criterion remains exhaustive: every permitted destination is obtained by adding one member to a represented team, or by forming a singleton.

4. Algorithm and running time

Compute every profile’s size, anchor type, and nonzero type counts. Initialize the extrema \(S_t,D_t\), including singleton utilities when permitted.

For each profile \(q\):

  • Compute \(A_t(q)\) for every \(t\in T\).
  • If \(n_q<m\), update \(D_t\) for every type.
  • If \(n_q=1\) or \(n_q>\ell\), compute \(C_t(q)\) for its occurring types and update \(S_t\).

Finally, reject stability exactly when some type has \(D_t>S_t\).

Let \(h_q\) be the number of distinct types occurring in profile \(q\). Computing \(A_t(q)\) costs \(O(h_q^2)\) arithmetic operations per type. Computing all relevant \(C_t(q)\) costs \(O(h_q^2)\) additional operations. Counting slots costs \(O(N)\). The total is therefore

\( O\!\left(N+\tau\sum_q h_q^2\right) \subseteq O\!\left(N+k\tau r^2\right) \subseteq O\!\left(km+k\tau\min\{m,\tau\}^2\right). \)

Bit complexity

Let \(B\) be the maximum bit length of a utility-table entry. Each utility sums at most one anchor term, \(M\) linear terms, and \(\binom{M}{2}\) pair terms. Thus computed utilities and intermediate count products require \( O(B+\log(M+1)) \) bits.

Since profiles are explicit, \(N=O(L)\), even if the binary-encoded upper bound \(m\) is much larger than the profiles actually present. Consequently, all arithmetic operands have \(O(L)\) bits. Schoolbook arithmetic, with conservative allowance for table access, gives

\( O\!\left(L^3+\left(N+k\tau r^2\right)L^2\right) \)

bit operations. The \(O(L^3)\) term suffices to validate the promised input conditions: rational equalities can be checked using a common denominator whose bit length is bounded by the sum of the input denominator lengths.

Finally, fully specifying the pair tables requires \(\Omega(\tau^3)\) input bits, even when only symmetric entries are stored. Hence \(\tau^3=O(L)\). Since \(k=O(L)\) and \(r\leq\tau\),

\( N+k\tau r^2 \leq N+k\tau^3 =O(L^2). \)

This proves the stated \(O(L^4)\) bit bound and membership in \(\mathrm{P}\).

5. Why a single listed profile need not be stable

Take one type \(t\), mass \(\mu_t=1\), and one listed two-member profile with frequency \(x_q=1/2\). Let \(c_l=1\), \(m=3\), \(d_t(t)=0\), \(v_t(t)=1\), and \(p_t(t,t)=0\).

Each member currently receives utility \(1\). Moving to a distinct team of the same profile leaves a valid singleton source and creates a valid three-member destination, giving the mover utility \(2\). Thus this assignment is unstable despite having \(k=\tau=1\). The criterion detects it through \(S_t=1\) and \(D_t=2\).

Assessment

The prover establishes polynomial-time Nash stability verification for the stated mass-based model. The feasibility analysis, utility formulas, stability criterion, and running-time bounds are correct. 1. Feasibility of deviations

The source condition
\[ n_q=1\quad\text{or}\quad n_q>\ell \]
is correct, where \(\ell=\max\{1,c_l\}\).

For a singleton source, the empty team disappears as permitted. For a larger source, the remaining team has size \(n_q-1\), so validity requires exactly \(n_q-1\geq\ell\). Its upper bound remains satisfied. If the anchor leaves, the rule allowing any remaining member to become anchor ensures that anchor replacement introduces no additional restriction.

The destination condition \(n_{q'}<m\) is also correct. Adding a member preserves its lower size bound and satisfies the upper bound exactly under this condition. The retained anchor is consistent with the task.

Singleton formation is feasible exactly when \(\ell=1\). The upper bound presents no additional obstacle because \(m\geq1\).

The proof correctly avoids imposing consent or utility restrictions on other members.

2. Distinct teams of the same profile

The treatment of same-profile destinations is justified by the stated nonatomic interpretation.

The interval construction gives each listed profile a positive measure of team instances. Each slot contributes mass \(x_q\), so the type masses are exactly \(\sum_q b_t(q)x_q=\mu_t\). Because \(x_q>0\), distinct team instances with that profile exist.

Consequently, choosing a source and destination with the same profile does not violate the requirement that they be distinct teams. The magnitude of \(x_q\), including \(x_q<1\), does not impose an integer bound on their number.

This is an essential and correctly handled feature of the mass-based model.

3. Utility calculations

The formula for \(F_t(b)\) correctly counts the relevant slot contributions:

  • There are \(b_s\) linear contributions from type \(s\).
  • There are \(\binom{b_s}{2}\) unordered pairs of distinct slots of type \(s\).
  • There are \(b_sb_u\) unordered pairs with distinct types \(s,u\).

The assumed symmetry of \(p_t\) makes the fixed ordering in the mixed-type sum legitimate. Repeated types are handled correctly.

For a joining member, all destination slots are other members, so \(A_t(q)=d_t(h_q)+F_t(b(q))\) is correct.

For a current member, removing its own slot from the count vector gives \(C_t(q)=d_t(h_q)+F_t(b(q)-e_t)\). The expanded identity subtracts exactly its linear contribution and every pair involving that slot. Its coefficients, including \(b_t(q)-1\) for same-type pairs, are correct.

The conclusion that all type-\(t\) members in one profile have equal current utility is valid even when one is the anchor. The prescribed utility formula uses the anchor’s type, without any separate utility rule for the anchor slot.

The singleton utility \(d_t(t)\) is also correct: both interaction sums are empty.

4. Stability criterion

The extrema \(S_t\) and \(D_t\) range over exactly the permitted source and destination choices.

The forward implication is correct. A strictly improving deviation has current utility at least \(S_t\) and destination utility at most \(D_t\), hence implies \(D_t>S_t\).

The converse is also correct. For a type with a feasible source, \(S_t\) is finite and attained. If \(D_t>S_t\), the destination candidate set is nonempty and its maximum is attained. The selected source and destination satisfy the established size conditions. Same-profile choices can use distinct instances by the preceding nonatomic argument.

No compatibility restriction between source and destination has been omitted: feasibility depends only on their sizes, and the mover’s destination utility depends only on its type and the destination profile.

The empty-set conventions are consistent. A type without a feasible source cannot initiate a deviation. A type without a feasible destination has \(D_t=-\infty\) and cannot satisfy the rejection inequality.

Strict comparison correctly preserves stability when utilities are equal. Allowing unlisted resulting profiles introduces no missing destination category under the stated deviation rules.

The algorithm implements the criterion directly.

Using the number of distinct types in a profile, computing each \(A_t(q)\) takes quadratic arithmetic work in that number. Computing the current utilities for all occurring types also takes quadratic work, using the displayed subtraction identity. Counting slots takes \(O(N)\) work.

Thus the stated bound
\[ O\!\left(N+k\tau r^2\right) \]
is valid, as is its parameter bound
\[ O\!\left(km+k\tau\min\{m,\tau\}^2\right). \]

The dependence on \(c_l\) is correctly confined to feasibility comparisons and singleton availability.

6. Bit complexity and input validation

The utility bit-length estimate is correct. Each utility contains at most one anchor term, \(M\) linear terms, and \(\binom{M}{2}\) pair terms. Signed entries and cancellation do not increase the required bound. Count products likewise require only logarithmically many bits in \(M\).

Because every member slot is explicitly listed, \(N=O(L)\). This remains true when the binary-encoded bound \(m\) is much larger than the represented team sizes. The arithmetic operands therefore have \(O(L)\) bits.

The conservative allowance of \(O(L^2)\) bit operations per arithmetic operation is sufficient. The input-validation allowance \(O(L^3)\) is also adequate: the common denominator can have bit length bounded by the total encoded denominator lengths, and the explicit slot counts permit checking the mass equations within that bound.

Fully specified pair tables contain \(\Omega(\tau^3)\) entries even with symmetry, so \(\tau^3=O(L)\). Together with \(k=O(L)\), \(r\leq\tau\), and \(N=O(L)\), this validates the claimed overall \(O(L^4)\) bit bound.

No external theorem is needed for this conclusion.
