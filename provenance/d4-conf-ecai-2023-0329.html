The continuous mirror question, as graded

Given a product with finite attribute set \(X\) and finite domains, and a distribution over \(\tau\) exact request types with rational masses \(\mu_t>0\) summing to \(1\), where each type \(t\) has a partial configuration \(u_t\) and a conditionally acyclic CO-net \(N_t\), choose a complete product \(f(t)\supseteq u_t\) for each type to maximize \(\sum_{t=1}^{\tau}\mu_t\mathbf{1}[f(t)=\operatorname{FSopt}(u_t,N_t)]\).

Packaged proof task (what the prover saw — nothing else)

Let \(X\) be a set of \(m\) attributes, each with an explicitly listed domain \(D_A\) satisfying \(2\leq |D_A|\leq d\); a complete product assigns a value to every attribute.
A society is given by its support: the list of its \(\tau\) positive-mass types, with binary rational masses \(\mu_t>0\) summing to \(1\). Here \(\tau\) is the support size, not the number of possible types.
Each type consists of a partial assignment \(u_t\) and a CO-net \(N_t\). A CO-net specifies, for each attribute \(A\), parents \(\operatorname{Pa}(A)\subseteq X\setminus\{A\}\) and an explicit complete table assigning one optimal value in \(D_A\) to every assignment of its parents.
Define \(\operatorname{FSopt}(u,N)\) as follows. Start with an empty assignment \(s\). Repeatedly select an unassigned attribute \(A\) whose table entries compatible with \(s\) all specify the same value; assign \(u[A]\) if \(A\) is fixed by \(u\), and otherwise assign that common value. Return the complete assignment, or fail if no attribute is eligible before completion. Resolve attribute choices by a fixed input ordering.
Every input net is promised conditionally acyclic: this procedure completes for every partial assignment and every sequence of eligible attribute choices; recognizing this promise is outside the task.
Choose a complete product \(f(t)\supseteq u_t\) for each supported type to maximize \(\sum_{t=1}^{\tau}\mu_t\mathbf{1}[f(t)=\operatorname{FSopt}(u_t,N_t)]\). Let \(L\) be the total binary input length, including domains, tables, partial assignments, and masses; state running times in \(m,\tau,d,L\).

Is this mass-weighted completion optimization problem solvable in polynomial time, or is it NP-hard?

Known discrete result: for a single request, Forward Sweep computes the most preferred completion of any partial assignment when the CO-net induced by a strict total preference order is conditionally acyclic; the procedure is polynomial-time with explicit tables (Gimenez and Mengin, 2023).

Modeling choices made when packaging the task

  • Specified explicit complete conditional optimality tables and explicitly listed attribute domains, making the input representation and its bit length precise.
  • Carried over the domain restriction that every attribute has at least two values, and introduced d as the maximum domain size.
  • Defined conditional independence operationally: all table entries compatible with the current assignment must specify the same optimal value.
  • Specified that Forward Sweep starts with the empty assignment and applies requested values only when their attributes are selected.
  • Interpreted conditional acyclicity as a promise covering every partial assignment and every eligible attribute-choice sequence; promise recognition is excluded.
  • Fixed an input ordering to resolve the unspecified attribute-selection choices.

Prover output (gpt-6.1-sol / high, Bolzano prover prompt)

The problem is polynomial-time solvable, and its maximum objective value is always \(1\). The decisive feature is that each supported type receives its own independently chosen completion.

For each type \(t\), define \(g_t=\operatorname{FSopt}(u_t,N_t)\), using the prescribed attribute ordering. The conditional acyclicity promise guarantees that this procedure completes. Moreover, \(g_t\) extends \(u_t\): whenever an attribute fixed by \(u_t\) is selected, the procedure assigns precisely its prescribed value. Every other assignment uses a value from the attribute’s domain. Thus \(g_t\) is a feasible complete product for type \(t\).

Choose \(f(t)=g_t\) for every supported type. Every indicator in the objective then equals \(1\), so the resulting objective value is \(\sum_{t=1}^{\tau}\mu_t=1\). Conversely, for any feasible choices, each indicator is at most \(1\); since all masses are positive and sum to \(1\), the objective is at most \(1\). This proves optimality.

To justify polynomial running time directly, consider one eligibility test for an unassigned attribute \(A\). Scan its explicitly listed table. A row is compatible with the current assignment \(s\) exactly when it agrees with \(s\) on every already assigned parent. Among compatible rows, retain the first optimal value encountered and check whether every other compatible row specifies that same value.

There is always at least one compatible row: \(s\) restricts only some parents, all parent domains are nonempty, and the table contains every parent assignment. Consequently, this scan implements exactly the eligibility condition in the question.

For each supported type, repeat the following at most \(m\) times:

  • Scan unassigned attributes in the prescribed ordering and perform the eligibility test.
  • Select the first eligible attribute and assign its prescribed value from \(u_t\), if fixed, or its common table value otherwise.

The promise guarantees an eligible attribute whenever the assignment is incomplete. Hence this algorithm computes every \(g_t\) and returns the optimal mapping \(f\).

For an explicit conservative complexity bound, each type has at most \(L\) table rows, each containing at most \(m\) parent values. Each sweep stage scans each attribute’s table at most once. Across all types, there are therefore at most \(O(\tau m^2L)\) parent-value checks. Even allowing \(O(L)\) bit operations for each check, lookup, or value comparison, the entire computation takes \(O(\tau m^2L^2)\) bit operations, including straightforward parsing and output. This bound is polynomial in the stated input parameters. The dependence on \(d\) is already included in \(L\), because domains and tables are explicitly listed; no enumeration of the complete-product space is needed. The masses require no optimization arithmetic, since the constructed solution satisfies every supported type.

The supplied discrete preference theorem is not needed here: the completion promise and the stated definition of \(\operatorname{FSopt}\) suffice.
