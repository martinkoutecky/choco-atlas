The continuous mirror question, as graded

Given a finite alternative set \(A\) with \(|A|=m\ge 3\), and a known support \(T\) of \(\tau\) types with positive rational masses \(\mu_t\) summing to \(1\), each type has a known strict preference order \(\succ_t\) and an unknown intensity relation from the paper’s strict representable class. A type-level oracle compares improvements \((a,b)\) and \((c,d)\) with \(a\succ_t b\) and \(c\succ_t d\). Recover each type’s complete intensity ordering, equivalently its canonical rank function on \(A\times A\), using at most \(\tau\bigl(\binom{m}{2}-2\bigr)\) queries.

Packaged proof task (what the prover saw — nothing else)

Let \(A\) have \(m\geq3\) alternatives. A society is given by its support: \(\tau\geq1\) types with positive binary-rational masses \(\mu_t\) summing to \(1\); \(\tau\) is the support size, not the number of possible types. Each type has a known strict preference order \(\succ_t\). Let \(L\) be the total bit length of this explicit input and \(K=\binom{m}{2}\).
For each type, let \(Q_t=\{(a,b):a\succ_t b\}\). Its unknown canonical intensity function \(s_t\) bijectively maps \(Q_t\) onto \(\{1,\ldots,K\}\), satisfies \(s_t(a,a)=0\) and \(s_t(b,a)=-s_t(a,b)\), and obeys \(s_t(a,c)>\max\{s_t(a,b),s_t(b,c)\}\) whenever \(a\succ_t b\succ_t c\). Intensity comparisons are comparisons of these ranks; no utility-difference representation is required.
One oracle query specifies a type and a set of between \(2\) and \(m-1\) improvements from \(Q_t\), and returns the unique improvement with greatest intensity. Responses are truthful and consistent with a fixed unknown \(s_t\); each oracle call costs one unit, with query construction charged separately.
The elicitation problem is to recover every \(s_t\) exactly using at most \(\tau(K-2)\) oracle queries in the worst case.

Is this elicitation problem solvable by a deterministic algorithm in time polynomial in \(m,\tau,L\), subject to the stated query bound, or is it NP-hard?

For one discrete agent with known strict preferences, elicitation is established in \(O(m^2)\) steps using \(K-2\) queries, including selections among up to \(m-1\) improvements. [Gerasimou, Efficient Allocation with Ordinal Preference Intensities](https://arxiv.org/html/2011.04306v9).
No separate result for the explicitly supported mass-society formulation was located.

Result

The elicitation problem is deterministically solvable in polynomial time, using at most \(\tau(K-2)\) oracle queries.

The single-agent maximal-pair procedure appears in [Gerasimou, Proposition 1](https://arxiv.org/html/2011.04306v9#S5). Below is a self-contained proof, including an explicit polynomial-time implementation of query construction.

1. Interval containment forces intensity comparisons

Fix one type, suppress its subscript, and write its known preference order as
\(a_1\succ a_2\succ\cdots\succ a_m\).

Identify improvement \((a_i,a_j)\) with its index pair \((i,j)\), where \(i<j\). Define a partial order by containment: \((h,k)\) contains \((i,j)\) when
\(h\leq i<j\leq k\).

Lemma 1. If \((h,k)\) properly contains \((i,j)\), then
\(s(a_h,a_k)>s(a_i,a_j)\).

Proof. If \(h<i\), the assumed inequality for the preference triple \(a_h\succ a_i\succ a_k\) gives
\(s(a_h,a_k)>s(a_i,a_k)\).
If \(h=i\), these two quantities are equal.

Similarly, if \(j<k\), the triple \(a_i\succ a_j\succ a_k\) gives
\(s(a_i,a_k)>s(a_i,a_j)\).
If \(j=k\), these quantities are equal.

Proper containment means at least one of \(h<i\) and \(j<k\) holds. Combining the comparisons proves the claim. \(\square\)

For a nonempty set \(R\) of remaining improvements, let \(C(R)\) consist of those elements of \(R\) that are not properly contained in another element of \(R\).

Lemma 2. The greatest-intensity element of \(R\) belongs to \(C(R)\), and
\(1\leq |C(R)|\leq m-1\).

Proof. The greatest-intensity element exists and is unique because the intensities are distinct. If it were properly contained in another remaining improvement, Lemma 1 would give a strictly greater intensity, a contradiction. Thus \(C(R)\) is nonempty and contains the greatest-intensity element.

Two distinct pairs having the same first index are comparable by containment. Consequently, at most one pair with each first index can belong to \(C(R)\). The possible first indices are \(1,\ldots,m-1\), proving the upper bound. \(\square\)

Therefore, whenever \(C(R)\) has at least two elements, it is a legal query set. Its oracle winner is the greatest-intensity element of all of \(R\).

2. Exact elicitation and the query bound

For this type, execute the following deterministic algorithm.

  • Initialize \(R=\{(i,j):1\leq i<j\leq m\}\).
  • For \(r=K,K-1,\ldots,2\):
  • Construct \(C(R)\).
  • If \(C(R)\) has one element, select that element without a query.
  • Otherwise, query this type on the improvements corresponding to \(C(R)\), and select the returned winner.
  • For the selected pair \((i,j)\), record \(s(a_i,a_j)=r\), and remove \((i,j)\) from \(R\).
  • Assign intensity \(1\) to the sole remaining improvement.
  • Record \(s(a_i,a_i)=0\) and \(s(a_j,a_i)=-s(a_i,a_j)\) for every \(i<j\).

Correctness. At the beginning of the iteration indexed by \(r\), maintain the invariant that the unknown intensities of the remaining improvements are exactly \(\{1,\ldots,r\}\).

Initially this holds by the canonical bijection assumption. By Lemma 2, the selected improvement has greatest intensity among the remaining improvements, whether selection uses a query or the singleton rule. Its intensity is therefore \(r\). Removing it establishes the invariant for the next iteration.

After the iteration indexed by \(2\), the remaining improvement has intensity \(1\). The prescribed diagonal and skew-symmetry rules then recover the entire function \(s\).

Query count. Initially, \((1,m)\) properly contains every other improvement, so
\(C(R)=\{(1,m)\}\).
Thus the iteration indexed by \(K\) requires no query. The final assignment of intensity \(1\) also requires no query.

Only the \(K-2\) iterations indexed by \(K-1,\ldots,2\) can make queries, and each makes at most one. Hence this type requires at most \(K-2\) queries. Every query has between \(2\) and \(m-1\) improvements, as required.

3. Polynomial-time query construction

We now give an implementation that charges explicitly for constructing each query.

For each first index \(i\in\{1,\ldots,m-1\}\), maintain an endpoint \(b_i\) such that the remaining pairs in that row are exactly
\(\{(i,j):i<j\leq b_i\}\).
The row is empty when \(b_i=i\).

Initialize every \(b_i=m\). For each nonempty row, its only possible containment-maximal pair is \((i,b_i)\): every other remaining pair in that row is properly contained in it.

Moreover, \((i,b_i)\) is contained in a pair from an earlier row precisely when some nonempty row \(h<i\) satisfies \(b_h\geq b_i\). A later row cannot contain it because its first index is greater than \(i\). Consequently,

\(C(R)=\{(i,b_i):b_i>i\text{ and }b_i>b_h\text{ for every nonempty row }h<i\}.\)

This set is constructed by scanning the rows in increasing order and maintaining the largest endpoint encountered among nonempty earlier rows. The scan requires \(O(m)\) operations.

Every selected pair has the form \((i,b_i)\). Removing it simply decrements \(b_i\), preserving the row representation. Thus the representation and the construction rule remain valid throughout the algorithm.

There are \(K-1=O(m^2)\) iterations. Constructing all candidate sets, writing all query sets, and updating the representation therefore take \(O(m^3)\) elementary operations per type. Recording the full intensity function takes \(O(m^2)\) additional operations. All ranks and endpoints use \(O(\log m)\) bits.

After polynomial-time parsing and indexing of the explicit input, this yields polynomial bit complexity as well. If oracle queries require copying the original alternative identifiers, their lengths are bounded by \(L\), so this also adds only polynomial overhead.

4. Extension to the explicitly supported society

Apply the algorithm separately to each of the \(\tau\) listed types, using that type’s known preference order and its own oracle.

No premise couples the unknown intensity functions of different types. The masses \(\mu_t\) therefore do not affect the elicitation procedure: each listed type must have its function recovered once, regardless of its mass.

Summing the proved bounds gives at most
\(\sum_{t=1}^{\tau}(K-2)=\tau(K-2)\)
oracle queries and \(O(\tau m^3)\) elementary operations after input parsing. Including encoding and output costs, the running time is polynomial in \(m,\tau,L\).

This establishes the requested polynomial-time algorithm under the stated query bound.
