The continuous mirror question, as graded

Given a finite support \(T\) of one-attribute profiles with rational supply masses \(\mu_t>0\) summing to \(1\), choose selected masses \(x_t\in[0,\mu_t]\). Replace each paper-style count property on \(\phi\) by a quota predicate \(\sum_{t\models\phi}x_t\bowtie q\), where \(q\) is rational and \(\bowtie\) includes equality and inequalities. Given a GAI utility over the resulting Boolean property values, compute a mass vector \(x\) that maximizes that utility.

Packaged proof task (what the prover saw — nothing else)

A society is given by its support: a list \(T\) of \(\tau\) distinct types with positive binary-rational masses \(\mu_t\) summing to \(1\). Here \(\tau\) is the support size, not the number of possible types. Each type specifies the value of one categorical attribute \(A\) in an explicitly listed finite domain.
There are \(m\) Boolean properties. Each formula \(\phi_i\) consists of equality atoms \(A=a\) and at most one logical connective from \(\{\land,\lor,\neg\}\); no empty formula is allowed.
A selection is a vector of real masses \(0\le x_t\le\mu_t\), with no prescribed total selected mass; the zero vector is allowed. Define \(P_i(x)=\mathbf{1}[\sum_{t\models\phi_i}x_t\bowtie_i q_i]\), where \(q_i\) is a nonnegative binary rational and \(\bowtie_i\in\{=,\ne,<,\le,>,\ge\}\). Comparisons are exact.
The input GAI utility is \(U(x)=\sum_{j=1}^{r}u_j((P_i(x))_{i\in I_j})\), with explicitly listed scopes \(I_j\subseteq\{1,\ldots,m\}\) and complete tables of signed binary-rational values. Let \(L\) be the total input bit length. Any maximizing selection is acceptable.

Is computing an exact utility-maximizing mass vector solvable in time polynomial in \(m,\tau,r,L\), or is it NP-hard?

For finite item sets, exact subset optimization is NP-hard even with one categorical attribute, Boolean properties containing at most one connective, and additive unary utilities (Binshtok et al., 2009).
That discrete result does not establish the complexity of the normalized mass problem defined above.

Result

Computing an exact utility-maximizing mass vector is NP-hard, even with additive unary utilities, thresholds all equal to zero, and only the comparison \(>\).

We prove this by a polynomial-time reduction from Vertex Cover. We use its standard NP-completeness: given a finite simple undirected graph \(G=(V,E)\) and an integer \(k\) with \(0\le k\le |V|\), deciding whether some set of at most \(k\) vertices meets every edge is NP-complete.

Construction

Let \(n=|V|\ge 1\), and let \(N\) be the smallest power of two satisfying \(N\ge n\).

Give the categorical attribute \(A\) one distinct value \(a_v\) for each vertex \(v\in V\). Include a corresponding type \(t_v\) of mass
\(\mu_{t_v}=1/N\).

If \(N>n\), also include a distinct value \(a_*\) and corresponding type \(t_*\) of mass
\(\mu_{t_*}=(N-n)/N\).
If \(N=n\), omit this extra type.

Thus all listed masses are positive dyadic rationals and sum to one. The support size is at most \(n+1\).

Introduce the following properties, all with threshold zero and comparison \(>\):

  • For each vertex \(v\), use the formula \(\phi_v=(A=a_v)\). Its property is \(P_v(x)=\mathbf{1}[x_{t_v}>0]\).
  • For each edge \(e=\{u,v\}\), use the formula \(\phi_e=((A=a_u)\lor(A=a_v))\). Its property is \(P_e(x)=\mathbf{1}[x_{t_u}+x_{t_v}>0]\).

Every formula is nonempty and has at most one permitted connective.

There is one unary utility factor for each property. Its complete table is:

| Factor | Value at \(0\) | Value at \(1\) |
|---|---:|---:|
| Vertex \(v\) | \(0\) | \(-1\) |
| Edge \(e\) | \(-(n+1)\) | \(0\) |

Consequently, \(m=r=n+|E|\), and every scope is a singleton.

The categorical domain, formulas, masses, scopes, and tables all have polynomial encoding length in the graph input. In particular, \(N<2n\), the mass encodings require \(O(\log n)\) bits each, and the utility entries require \(O(\log n)\) bits.

Exact correspondence with vertex subsets

For any feasible mass vector \(x\), define its active vertex set by
\(C(x)=\{v\in V:x_{t_v}>0\}\).

Because selected masses are nonnegative, for every edge \(e=\{u,v\}\) we have
\(x_{t_u}+x_{t_v}>0\) if and only if at least one of \(x_{t_u},x_{t_v}\) is positive. Therefore
\(P_e(x)=1\) if and only if \(e\cap C(x)\ne\varnothing\).

Let \(h(C)\) denote the number of edges having neither endpoint in \(C\). Substituting the utility tables gives the exact identity
\(U(x)=-|C(x)|-(n+1)h(C(x))\).

Conversely, every subset \(C\subseteq V\) is realizable: choose \(x_{t_v}=\mu_{t_v}\) for \(v\in C\), choose \(x_{t_v}=0\) otherwise, and choose \(x_{t_*}=0\) if the extra type exists. This is feasible and has active vertex set exactly \(C\).

Thus optimizing over the continuous mass vectors is exactly equivalent, for these instances, to optimizing this expression over all vertex subsets. In particular, a maximum exists and has a rational representative.

Every maximizer yields a minimum vertex cover

The set \(V\) covers every edge, so its representative has utility \(-n\).

If \(C(x)\) fails to cover some edge, then \(h(C(x))\ge 1\), and hence
\(U(x)\le -(n+1)<-n\).
Such a vector cannot maximize utility, because the representative of \(V\) has strictly greater utility.

Every maximizing vector therefore has a vertex cover as its active vertex set. For a vertex cover \(C\), the identity above simplifies to
\(U(x)=-|C|\).

It follows that every maximizing vector has a minimum vertex cover as its active vertex set. Writing \(\kappa(G)\) for the minimum vertex-cover size, we obtain
\(\max_x U(x)=-\kappa(G)\).

Complexity conclusion

An algorithm computing any exact maximizing vector would solve Vertex Cover: construct the instance above, obtain its maximizing vector, extract the vertices whose masses are positive, and compare their number with \(k\). These are exact comparisons of the kind stipulated in the question.

Equivalently, the constructed instance satisfies
\(\max_x U(x)\ge -k\) if and only if \(G\) has a vertex cover of size at most \(k\).

This proves NP-hardness under a polynomial-time reduction. Therefore a polynomial-time algorithm in \(m,\tau,r,L\) would imply \(\mathrm{P}=\mathrm{NP}\).
