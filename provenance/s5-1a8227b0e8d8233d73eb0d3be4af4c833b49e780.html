Conclusion and encoding convention

Under the standard LP-tree encoding, the computation is \(\mathrm{NP}\)-hard, even when \(\tau=1\), \(d=2\), every constraint has arity at most \(4\), and the CSP is guaranteed feasible. Consequently, it has a polynomial-time algorithm in \(m,\tau,d,L\) if and only if \(\mathrm{P}=\mathrm{NP}\).

Here I interpret an unconditional preference table as one explicit row specifying an order that applies in every ancestor context. Thus “for every applicable ancestor assignment” requires the preference order to be fully specified, without requiring duplicate rows for an unconditional order. A compulsory fully expanded interpretation changes the answer; Section 4 proves this distinction.

For \(d=1\), there is only one outcome, so checking its feasibility for each type and summing the corresponding masses is polynomial-time.

1. Hardness even with guaranteed feasibility

We reduce from the standard \(\mathrm{NP}\)-complete decision problem \(\mathrm{3SAT}\).

Let \(\varphi\) be a conjunction of clauses over Boolean variables \(x_1,\ldots,x_n\), each clause containing at most three literals. Introduce an additional Boolean variable \(z\). Construct a society with one type, of mass \(\mu_t=1\).

The explicit CSP

All variables have domain \(\{0,1\}\).

For each clause \(K\), let \(S_K\) be its set of distinct variables. Add a constraint with scope \((z,S_K)\) and allowed relation
\[ R_K= \{(0,a):a\in\{0,1\}^{S_K}\} \;\cup\; \{(1,a):a\in\{0,1\}^{S_K},\ a\models K\}. \]

Here \(a\models K\) means that the assignment \(a\) makes the clause true. Repeated variables or literals cause no difficulty because the scope uses distinct variables.

Each constraint has arity at most \(4\), and its allowed list has at most \(2^4=16\) tuples. We can therefore construct all allowed lists in polynomial time.

The construction has two immediate properties:

  • Every complete assignment with \(z=0\) is feasible.
  • A complete assignment with \(z=1\) is feasible exactly when its restriction to \(x_1,\ldots,x_n\) satisfies \(\varphi\).

In particular, the CSP is always feasible.

The explicit LP-tree

Use a chain that tests the variables in the order
\[ z,\ x_1,\ldots,x_n. \]

At each test node, its single outgoing edge is labelled by the full domain \(\{0,1\}\), which is an allowed one-part partition. After the last test, the edge reaches a terminal leaf. Every root-to-leaf path therefore tests each variable exactly once.

Specify the unconditional orders
\[ 1\succ_z 0, \qquad 0\succ_{x_i}1\quad(1\leq i\leq n). \]

Under the encoding convention above, these are explicit one-row tables. The tree, its edge labels, and its tables have polynomial size.

Recovering satisfiability from the required output

If \(\varphi\) is satisfiable, some feasible outcome has \(z=1\). Every such outcome is preferred to every outcome with \(z=0\), because \(z\) is tested first. Hence the unique maximal feasible outcome has \(z=1\).

If \(\varphi\) is unsatisfiable, every feasible outcome has \(z=0\), so the maximal feasible outcome has \(z=0\).

Thus, for the returned outcome \(o_t\),
\[ o_t(z)=1 \quad\Longleftrightarrow\quad \varphi\text{ is satisfiable}. \]

There is exactly one resulting outcome, with mass \(\nu_{o_t}=1\). Reading its \(z\)-coordinate decides satisfiability.

This is a polynomial-time reduction using one invocation of the requested computation followed by polynomial-time decoding. Therefore the computation is \(\mathrm{NP}\)-hard, including under the stated restrictions and the promise of feasibility. The hardness does not depend on detecting infeasible types or on difficult mass arithmetic.

2. A polynomial-time algorithm with an \(\mathrm{NP}\) oracle

To establish the converse conditional statement, define the feasibility-extension predicate
\[ E(C,p)\quad\Longleftrightarrow\quad \text{some complete assignment extending }p\text{ satisfies }C, \]
where \(p\) is a partial assignment.

This predicate belongs to \(\mathrm{NP}\). A certificate is a complete assignment. Its encoding has polynomial length because domains are explicitly listed. We verify its domain membership, agreement with \(p\), and satisfaction of each constraint by scanning the corresponding explicit allowed-tuple list. Unrestricted constraint arity does not invalidate this verification: all scopes and tuples are included in \(L\).

For each type, proceed as follows:

  • Query \(E(C_t,\varnothing)\). If false, report infeasibility.
  • Otherwise maintain a partial assignment \(p\) with a feasible extension, initially empty.
  • At the current LP-tree node, let \(X\) be its variable and read the strict value order applicable to \(p\).
  • Query \(E(C_t,p\cup\{X=a\})\) for values \(a\) in preference order. Choose the first value receiving a positive answer.
  • Extend \(p\), follow the edge selected by that value, and continue until all variables have been assigned.

A value must be available at each step: by the invariant, some feasible extension of \(p\) assigns a value to \(X\). Choosing a positively answered value preserves the invariant. After \(m\) choices, the resulting complete assignment is feasible.

To prove optimality, let \(o\) be the returned outcome. Suppose a feasible outcome \(q\) satisfied \(q\succ_{L_t}o\). At their first differing test node, both outcomes share the preceding assignment \(p\), while the applicable order ranks \(q(X)\) above \(o(X)\). The algorithm therefore tested \(q(X)\) earlier. Since \(q\) witnesses
\[ E(C_t,p\cup\{X=q(X)\}), \]
that test would have received a positive answer, contradicting the choice of \(o(X)\). Thus no feasible outcome is preferred to \(o\), and the strict total order makes it uniquely maximal.

The algorithm uses at most
\[ \tau(1+md) \]
oracle queries, with polynomial-time work between queries. Hence the requested function belongs to \(\mathrm{FP}^{\mathrm{NP}}\).

If \(\mathrm{P}=\mathrm{NP}\), every query can be answered in polynomial time, giving a polynomial-time algorithm for the whole task. Together with Section 1, this proves the claimed equivalence.

3. Exact supported masses and the cited results

At most \(\tau\) distinct outcomes are returned. Grouping equal complete assignments is polynomial-time.

For exact arithmetic, write each input mass as \(\mu_t=a_t/b_t\), with positive integer denominator \(b_t\), and use the common denominator
\[ B=\prod_{t=1}^{\tau}b_t. \]

Its bit length is at most the sum of the denominator bit lengths, plus a constant, hence polynomial in \(L\). For an outcome \(o\), compute
\[ \nu_o= \frac{\displaystyle\sum_{t:\,o_t=o}a_t(B/b_t)}{B}. \]

The numerator lies between \(0\) and \(B\), because the masses are positive and sum to \(1\). Integer arithmetic and fraction reduction therefore take polynomial time. Infeasible types are omitted. Exact mass aggregation adds no further hardness once the individual outcomes are known.

The original paper states that Search-LP returns the most preferable feasible outcome without dominance testing; this establishes correctness, not polynomial running time. [Ahmed and Mouhoub, original account](https://arxiv.org/abs/2109.12179)

The revised account calls constrained LP-tree solving \(\mathrm{NP}\)-complete. For the present task, the precise distinction is that feasibility is a decision problem, whereas computing maximal outcomes and their masses is a function problem. The reduction and oracle algorithm above establish \(\mathrm{NP}\)-hardness and membership in \(\mathrm{FP}^{\mathrm{NP}}\) directly. [Ahmed and Mouhoub, revised account, Section 4](https://www.researchsquare.com/article/rs-4259901/latest.pdf)

4. If every full ancestor assignment requires a separate table row

If the wording instead mandates a separate explicit row for each full applicable ancestor assignment, even when the preference is unconditional, the task is polynomial-time under that different encoding.

Fix a type. At every node testing the last variable on its path, all other \(m-1\) variables have already been tested. A full applicable ancestor assignment \(p\) determines that node uniquely. Together with any value of its last variable \(X\), it determines exactly one complete outcome.

Consequently, if \(R_t\) is the number of such separately listed rows at last-variable nodes, the total number \(N\) of complete outcomes satisfies
\[ N = \sum_{\text{last-variable nodes }v} \sum_{\text{applicable full contexts }p} |D(X_v)| \leq dR_t. \]

Because those rows are explicitly listed, \(R_t\) is bounded by the input length. All outcomes can therefore be enumerated in polynomial time in \(d,L\), checked against each CSP, and compared using the explicit trees. Section 3 then supplies polynomial-time mass aggregation.

Thus the encoding distinction is substantive: standard tables permitting one unconditional row give the \(\mathrm{NP}\)-hard answer; compulsory expansion over all full ancestor assignments gives a polynomial-time answer.
